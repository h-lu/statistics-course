# 第09课 · 筛查阳性之后怎样安排复核

设备保障部门要给明天1500台设备安排初筛和90个复核名额。误把阳性理解为确定故障会浪费复核，忽略未复核阳性中的故障又会低估损失。部门需要一张能照着执行的分组初筛与复核政策。

**本课问题：同样一张阳性通知，在检验前故障比例（基础率）不同的设备组中意味着同样的故障风险吗？**

所有数据均为教学合成。AI可以完成方案、代码、分析、写作和提交，不要求编程先修、提示词日志或额外答辩。先用本页明确目标，再自行选择工作方式；[LEARN](LEARN.md)解释概念，[SUPPORT](SUPPORT.md)按卡点提供帮助，不要求按统一操作顺序完成。

## 数据、条件与选择

正式数据用alert_groups.csv（两组设备数、故障比例、漏掉一台故障的损失）和screening.csv（两种初筛的性能与单价）。初筛是先做一次检查，阳性表示需要进一步确认，不等于已知故障；复核是再确认，本题假设复核无误且查出的故障均可修复。初筛预算2000只付初筛，每个复核另付3。

[数据说明](../data/inference-09-14/README.md)写明字段、预算和方法边界；本课只需看其中第09课的部分。最小程序为[analysis.py](analysis.py)，Python 3.10+标准库即可。可以使用程序或电子表格计算，两套政策都要使用同一份设备数据和检验性能。

读CSV时，先认清这些名字：routine是常规组，priority是重点组；daily_devices是设备数，base是本课使用的故障比例，miss_cost是每留下一台未发现故障造成的损失。sensitive和precise是两种初筛方法，sensitivity、specificity、cost_per_device分别是敏感度、特异度和每台初筛费用。base_low、base_high本课必做暂时不用。

你决定各组采用哪种初筛，以及复核按预期避免损失排序还是为各组保留最低名额。第二个决定须说明服务保障的用途；也可以提出自己的可行规则。优先照顾风险更高的组与保障另一组机会可能冲突。

## 基础练习（可信起点）

1000台中10台故障；故障中90%会检出阳性（敏感度90%），非故障中95%会判阴性（特异度95%）。9台故障阳性，990台非故障中49.5台预计阳性，阳性中的故障比例9/58.5≈15.38%。49.5是重复规划的平均，不是半台实物。 可以手算、读代码或请AI换一个例子解释。基础例子的运行不代表完成标准任务。

## 标准任务（本课应完成）

只用基准基础率（CSV的base列），固定同一批设备、检验性能、预算和损失口径，比较你主张的政策与另一套可行政策。追踪一次“故障且阳性（真阳性）、没故障却阳性（假阳性）→阳性中的故障比例”的计算，说明分母是谁；用简表列出两政策的分组复核数、预计未发现故障和损失，核对初筛预算2000与90名额。解释一个真实取舍和一项限制，并说出哪项条件变化可能改变建议；必做不要求重算其他情境。

比较表可用期望人数规划：名额取整数，例如以预计阳性数向下取整为各组上限，并说明这一近似。现场则以实际阳性人数为上限，剩余名额按所选规则分配；期望人数不是每日人数的硬上限。

最低证据是：**追踪一个例子、做一个公平比较、说明限制**。这里公平比较指清楚写出保持什么相同、只改变什么；不是各方案必须得出同样结论。至少两项有后果的决定由你选择并解释：初筛方法与复核分配规则。它们可体现在同一对政策中，不要求为每项选择各增一套政策；若两项同时改变，只解释整套政策差异，不把差异单独归因于其中一项。结论不同、有证据的保留意见或暂缓建议均可。

本课先解释“阳性中的故障比例怎样影响复核后果”；90名额是给定约束，不要求全局优化、穷举政策或每日容量随机模拟；随机需求与容量的进一步分析留给第10课。若从频数到政策仍接不上，可看[LEARN中的20台设备小例](LEARN.md#一个20台设备的小政策)，再自行构建正式比较。

## 不知道怎样开始比较时

可以先画一张两行的草表，每行是一套政策。依次填写：常规组用哪种初筛、重点组用哪种初筛、常规组复核几台、重点组复核几台。分组人数仍分别是1000和500；全部设备都先初筛。先检查初筛支出不超过2000、复核总数不超过90，再计算效果。

每组按同一顺序算：设备数×故障比例，得到预计故障数；由真阳性和假阳性算出阳性中的故障比例；再用复核名额×这个比例，得到预计查出的故障数。两者相减，就是预计仍未发现的故障数。组内复核对象须从阳性设备中随机选取，因为目前没有信息把同组阳性再分出高低风险。

最后把两组未发现故障分别乘以各组miss_cost，再相加，得到“未发现故障造成的损失”。初筛费用和复核费用另外列清楚；若还给出三项相加的总成本，要在两套政策中使用同样的算法。先不要急着找最优方案，比较两套可行政策并解释取舍即可。

## 提高与拓展（提前完成后）

完成必做后，可把同样两套规则分别代入低、基准、高基础率重算，保持规则、按新风险重算名额，检查建议是否改变；也可改变“敏感度或特异度在新设备中仍保持不变”的假设，找出政策切换条件。三情境数值扫描属于提高，不是必做或隐含评分条件。不要在没有联合验证数据时假设两种检验独立并连用。
