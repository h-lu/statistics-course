# 第09课 · 运行和提交遇到问题时看这里

这页解决操作问题。概念不清楚时，先看[LEARN](LEARN.md)；想知道本课要做什么，回到[任务说明](README.md)。

## 1. 命令要在哪里运行？

打开你自己的学生仓库。终端当前目录中应能看到 `lesson-09`、`data` 和 `scripts` 三个文件夹。

如果打开的是教师课程源码，学生仓库的文件位于 `student-template` 目录。进入这个目录以后再运行命令。

本课使用Python 3.10或以上版本，不需要额外安装第三方库。可以先检查版本：

```bash
python3 --version
```

然后运行教学示例：

```bash
python3 scripts/course.py start 09
python3 scripts/course.py run 09
```

## 2. 运行以后，结果在哪里？

打开 `lesson-09/artifacts/example.json`。JSON是保存数据的一种文件格式，可以直接用编辑器查看，也可以请AI帮你把内容整理成表格。

其中 `example_only` 内的 `positive_predictive_value` 应约为0.153846，也就是15.38%。它对应LEARN中1000台设备的小例。

文件还记录了20台设备的两套安排：预计未发现故障数约为5.4167台和5台。你可以对照LEARN中的计算检查。

这个文件是教学示例。正式任务使用1500台设备，需要你自己选择初筛和复核安排，再写程序或计算表进行比较。

## 3. CSV中的英文名字是什么意思？

CSV是可以用表格软件打开的数据文件。本课只用下面两个文件。

### alert_groups.csv：设备组

|字段|含义|
|---|---|
|group|设备组名称：routine为常规组，priority为重点组|
|daily_devices|这一组每天要检查的台数|
|base|本课必做使用的故障比例；0.02表示2%|
|base_low、base_high|较低、较高的故障比例，供选做使用|
|miss_cost|每台未发现故障造成的损失|

### screening.csv：初筛方法

|字段|含义|
|---|---|
|method|方法名称：sensitive或precise|
|sensitivity|敏感度，即故障设备检出阳性的比例|
|specificity|特异度，即正常设备判为阴性的比例|
|cost_per_device|每台初筛费用|

两份文件都在 `data/inference-09-14` 中。不要修改原始数据；自己的结果存入 `lesson-09/artifacts`。

## 4. 怎样把小例改成正式分析？

可以先让程序读入两张表，再按LEARN第7节的五步计算每套安排。你可以修改本课的 `analysis.py`，也可以另写程序。AI可以帮助实现。

若使用已有工具，`data/inference-09-14/toolkit.py` 中的 `natural_frequencies` 能根据设备数、故障比例、敏感度和特异度计算初筛结果。导入方式可参考 `analysis.py`。

注意工具返回的 `missed` 只表示**初筛时漏检的故障**，还不是复核结束后的全部未发现故障。后者要用“原有预计故障数−复核查出的预计故障数”计算。

不必阅读同一工具文件中供后续课程使用的抽样和置信区间函数。

## 5. 算出来的数字不对，先检查哪里？

- 把0.02当成2%，不要再除一次100，也不要直接当成2。
- 真阳性从故障设备中算；假阳性从正常设备中算。
- 特异度95%表示正常设备有95%判阴性，误报比例是5%。
- 阳性中的故障比例，用真阳性除以“真阳性+假阳性”。除以全组台数，回答的是另一个问题。
- 未发现故障既包括初筛阴性的漏检，也包括没有复核的阳性故障。
- 初筛预算与复核费用分开检查。不要把复核费用从2000中扣掉，又在另一套安排里不扣。
- 复核名额不能超过组内阳性台数。规划表采用预计台数时，要说明整数名额怎样处理。

本课的基本计算不需要随机模拟。如果你另外做了模拟，随机结果不必每次等于公式算出的预计值。

## 6. 怎样提交自己的结果？

把建议写在 `lesson-09/report.md`，把程序生成的表格或JSON保存到本课的 `artifacts` 目录。

再打开 `lesson-09/submission.json`：

- `report` 指向你的报告，通常不用改；
- `run` 填运行正式分析的命令；
- `artifacts` 列出该命令生成的结果文件；
- 做完后，把 `status` 改为 `complete`。

`run` 中每个命令词单独写一项。例如，若正式分析仍写在 `analysis.py`，运行命令就是文件中原有的 `["python3", "lesson-09/analysis.py"]`。若换了程序名称，声明也要一起修改。

然后运行：

```bash
python3 scripts/course.py check 09
```

检查通过表示提交文件符合要求，不代表统计结论已经正确。请再核对报告中的一个计算，以及表格中的数字是否与结果文件一致。

最后按[提交流程](../docs/WORKFLOW.md)提交个人仓库，课堂最终标签沿用 `v2-l09-final`。
