# 第5课知识准备 · 怎样评价每天的复核名单

每天只能复核一部分设备。**风险分数**是系统用来提示相对风险的分数：分数较高，表示系统认为这台设备相对更值得关注；它不表示设备一定会故障，也不自动等于故障概率。

决定名单时，还要考虑**复核容量**（当天最多能复核多少台）、**故障损失**（一次故障造成的损失）和**复核成本**（检查一次设备需要付出的成本）。只能使用行动前已经知道的信息。**信息时点**指作出决定的时刻及当时已经能知道的信息；例如当天的故障结果要到事后才知道。评价名单的后果时，再按课程给定的复核效果假设计算损失。

学完本页，你应能回答：

1. 什么是设备日，为什么同一设备可以出现多条记录？
2. 固定选择规则后，为什么每天的名单仍会变化？
3. 假阳性率和假阴性率的分母分别是什么？
4. 为什么漏掉的故障更少，不一定表示总损失更低？
5. 为什么规则制定期的数据和留出评价期的数据要分开？

## 1. 一条记录表示一个设备日

**分析单位**是统计结果所针对的基本对象。本课数据中，一行表示“一台设备在一天的一次判断机会”，称为一条**设备日记录**。因此，本课计算每日容量、复核次数和分类结果时以设备日为分析单位。

同一台设备连续出现14天，会产生14条设备日记录，因为每天都要重新决定是否复核。报告“涉及多少台不同设备”时，再按 `device_id` 去重。复核次数和不同设备数回答的问题不同，不能混用。

## 2. 选择规则只能使用行动前的信息

**选择规则**是在作出行动前写明怎样从当天记录中选出设备的方法。它要在查看当天故障结果之前，写清：

- 使用哪些字段；
- 怎样排序或设置**阈值**，即决定记录是否入选的界限；
- 出现并列时怎样继续排序，这称为**并列处理规则**；
- 是否允许少用名额；
- 每天最多选择多少条记录。

固定的是选择方法，不是设备名单。假设第一天四台设备的分数为80、40、40、20，第二天变为10、20、90、80。规则始终是“分数降序、同分按设备编号升序、最多选2台”，第一天会选D1、D2；第二天使用同一排序规则就会选D3、D4。名单改变了，规则没有改变。

`failure_within_24h` 是事后才知道的故障结果。它可以用于评价名单，不能用于生成当天名单。若看见D3后来故障，就把同分顺序改成优先D3，再把结果说成原规则表现，就发生了**信息泄漏**，也就是在生成名单时使用了当时尚不知道的未来信息。

## 3. 经验累积分布函数和分位数能说明什么

**经验累积分布函数**（empirical cumulative distribution function，ECDF）表示本次纳入计算的记录中，数值“不超过某个给定数值”的比例。这里计算的是已有设备日记录的分数分布；它本身不说明这些记录能否代表其他日期的设备。

仍用分数80、40、40、20的四台设备。在40处分数的经验累积分布函数为：

`3 ÷ 4 = 75%`

因为20、40、40三个分数都不超过40。这个75%描述分数的累计比例，不表示分数为40的设备有75%会故障，也不表示应该复核75%的设备。

**分位数**是把数据从小到大排列后，用来描述某个累计位置的数值。它可以帮助提出阈值，但不能替代每日容量和并列处理规则。本例若选择“分数不少于40”的设备，会得到3台，超过2个名额；选择“分数大于40”只得到1台。因此还要说明边界是否包含等号，以及同分时选谁。

按需使用分位数时要写明算法。一种算法是**最近秩法**：把 `n×q` 向上取整，再取从小到大排序后对应位置的数值，其中 `n` 是记录数，`q` 是大于0且不超过1的累计比例。四个分数的第75百分位数，按此算法取第3个数，即40。第2课使用的**线性插值法**会在两个相邻位置之间按比例计算数值，可能得到不同结果；两种算法不能不加说明地混用。

在正式项目中，经验累积分布函数可以帮助你查看规则制定期的分数分布，分位数可以作为提出候选阈值的依据。例如，若想优先考虑分数较高的一部分记录，可先说明参考了哪个时期、哪个分位数，再把阈值用于逐日选择。分位数只提供候选界限，不会自动满足每日复核容量；阈值附近有并列分数时，仍要使用事先写好的并列处理规则。也可以不用分位数，直接提出有理由的排序规则。

## 4. 用四格表区分四种结果

本课把“选中复核”看作规则判定为阳性，把“事后实际故障”看作实际阳性。这里的“阳性”只表示满足本课规定的分类条件，不表示设备在复核前已经被诊断为故障。把规则判断与实际结果交叉计数，得到**四格表**，也称为**混淆矩阵**：

| | 事后实际故障 | 事后实际未故障 |
|---|---:|---:|
| 选中复核 | 真阳性（true positive，TP） | 假阳性（false positive，FP） |
| 未选中复核 | 假阴性（false negative，FN） | 真阴性（true negative，TN） |

对规则判断而言，“阳性”是选中复核，“阴性”是未选中；对事后实际结果而言，“阳性”是发生故障，“阴性”是未发生故障。“真”表示规则判断与事后结果一致，“假”表示两者不一致。

在四台设备的例子中，每天最多复核2台，每台复核成本为3，故障损失为100：

| 设备 | 分数 | 事后故障结果 |
|---|---:|---:|
| D1 | 80 | 1 |
| D2 | 40 | 0 |
| D3 | 40 | 1 |
| D4 | 20 | 0 |

按“分数降序、同分按编号升序”选D1、D2：

- D1选中且故障，是真阳性；
- D2选中但未故障，是假阳性；
- D3未选中但故障，是假阴性；
- D4未选中且未故障，是真阴性。

所以TP、FP、FN、TN各为1。

## 5. 假阳性率和假阴性率的分母不同

**假阳性率**（false positive rate，FPR）回答：在实际未故障的记录中，有多少被选中复核？

`FPR = FP ÷ (FP + TN)`

**假阴性率**（false negative rate，FNR）回答：在实际故障的记录中，有多少没有被选中复核？

`FNR = FN ÷ (FN + TP)`

四台设备的例子中，两种错误率都是50%。但“名单中未故障的比例”是 `FP ÷ (TP + FP)`，分母是全部入选记录数，不是假阳性率所用的全部实际未故障记录数。本例两个数碰巧都为50%，不能据此认为它们是同一个指标。

再看一个不会碰巧相等的例子：100条设备日记录中有10条实际故障；复核20条，其中6条实际故障。此时：

- TP=6；
- FP=20−6=14；
- FN=10−6=4；
- TN=100−6−14−4=76；
- 假阳性率为 `14 ÷ 90 ≈ 15.56%`；
- 假阴性率为 `4 ÷ 10 = 40%`；
- 复核名单中未故障的比例为 `14 ÷ 20 = 70%`。

如果实际未故障记录数或实际故障记录数为0，相应错误率没有分母，应写“不能计算”，不能写成0%。

## 6. 按假设计算的总损失

本课的**情境总损失**是根据历史故障结果和“复核可避免一部分损失”的假设计算出的数值，不是实测的复核后损失。它包含三部分：

1. 所有被选中设备的复核成本；
2. 未选中而发生故障的全部故障损失；
3. 被选中且发生故障时，复核后仍然剩余的故障损失。

课程情境假设复核可以避免85%的故障损失，所以剩余比例为15%。四台设备例子的总损失为：

- D3未复核且故障：100；
- D1复核后仍剩余：`100×15%=15`；
- D1、D2两次复核成本：`2×3=6`；
- 合计：`100+15+6=121`。

若完全不复核，两次故障损失为200。在给定假设下，名单对应的计算损失少79。这里减少的是损失，不是故障记录数量，也不是把故障标记改成0。这个结果不能写成“实验已经证明复核会减少79”，因为85%的效果是情境给定的假设，历史故障标记也没有因复核而改变。

100条记录的例子中，若每次故障损失100、每次复核成本3：

- 复核避免80%损失时，总损失为 `4×100 + 6×100×20% + 20×3 = 580`；
- 复核避免85%损失时，总损失为 `4×100 + 6×100×15% + 20×3 = 550`。

名单和四格表没有变化，效果假设变化后总损失仍会变化。

## 7. 为什么未选中的故障少，损失仍可能更高

假阴性率按发生故障的设备日记录数计算，不区分单次故障损失的大小。规则甲漏掉1次损失10000的关键设备故障，规则乙漏掉2次每次损失800的一般设备故障。甲漏掉的故障次数更少，漏掉故障造成的损失却更高。

因此至少要同时查看错误率、复核成本、故障损失和设备类别。总体损失较低，也可能伴随某一类别长期没有复核机会；这需要单独报告和监测。

## 8. 前42天和后14天各做什么

前42天是**规则制定期（开发期）**：提出候选规则、比较结果并选定后期使用的方法。同一批数据参与了规则制定和评价，所以这种**样本内评价**可能偏乐观；样本内评价是指在参与规则制定的同一批记录上评价规则。

随后的14天是**留出评价期**：这段数据不参与规则选择，先使用已经确定的规则生成名单，再用事后故障结果核算后果。这种按时间保留后期数据的方法称为**时间留出评价**。固定的是字段、排序、阈值、并列处理方法和容量使用方法，不是每天选择同一批设备。

若看过后14天结果后调整规则，这次调整属于**探索性修订**，即由已经看到的结果启发、尚需用新数据评价的改动。仍然可以报告，但同一批14天数据不再是未参与新规则选择的留出数据。

若要模拟真正的逐日使用过程，某一天的风险估计只能使用此前已经完成观察的记录。日期早于今天，不自动表示所需的24小时故障观察已经结束。

## 9. 敏感性分析要说明名单是否改变

**敏感性分析**是有理由地改变一个方法或假设，再观察结果和建议是否改变。改变复核容量、故障损失或复核效果时，有两种不同问题：

- **固定名单重新计算损失**：问同一批行动在另一种假设下会有什么后果；
- **按新条件重新选择名单**：问条件改变后，决策本身是否应改变。

两种分析都可以使用，但必须明确区分。只写“把85%改成60%”还不够，需要说明排序、阈值和最终名单是否重新计算。

## 按需阅读：期望净收益

本课不要求先建立故障概率模型。**故障概率模型**是用已有变量估计某条设备日记录发生故障概率的统计模型。若确实有依据估计故障概率为 `p`，复核可避免损失的比例为 `e`，故障损失为 `L`，复核成本为 `c`，则复核的**期望净收益**是“预期避免的故障损失减去复核成本”：

`p × e × L − c`

`p` 和 `e` 都在0到1之间，结果单位与成本相同。结果大于0表示在这些估计和假设下，预期避免的损失超过复核成本。

风险分数除以100不自动成为故障概率。没有可靠概率估计时，可以采用有依据的排序或阈值规则，并如实说明它是**启发式方法**，即实用但没有被证明等于最优决策或真实概率的方法。

## 回到项目

你的项目需要把以下链条完整连接起来：

`行动前信息 → 可重复执行的选择规则 → 每日名单和名额 → 四格表与损失 → 前后时期比较 → 条件变化 → 使用建议`

程序输出是证据，不是建议本身。报告要说明结果适用于哪个时期、哪些设备和哪些效果假设，以及何时需要调整或停止使用规则。

# learning-example
import json

rows = [
    ("D1", 80, 1),
    ("D2", 40, 0),
    ("D3", 40, 1),
    ("D4", 20, 0),
]
selected = {row[0] for row in sorted(rows, key=lambda row: (-row[1], row[0]))[:2]}
counts = {"TP": 0, "FP": 0, "FN": 0, "TN": 0}
loss = 0
for device, score, failure in rows:
    chosen = device in selected
    outcome = "TP" if chosen and failure else "FP" if chosen else "FN" if failure else "TN"
    counts[outcome] += 1
    loss += 3 + failure * 100 * 0.15 if chosen else failure * 100

result = {
    "selected": sorted(selected),
    "ecdf40": sum(score <= 40 for _, score, _ in rows) / len(rows),
    "counts": counts,
    "loss85": loss,
    "large_fpr": 14 / 90,
    "large_list_nonfault": 14 / 20,
    "large_loss80": 4 * 100 + 6 * 100 * 0.20 + 20 * 3,
    "large_loss85": 4 * 100 + 6 * 100 * 0.15 + 20 * 3,
}
print(json.dumps(result, ensure_ascii=False, allow_nan=False))
