# 知识准备 · 把告警分数转成行动

## 为什么阈值不是一个孤立数字

名单太长会超过复核能力；名单太短可能遗漏高损失故障。分数用于排序，是否复核还取决于损失、成本、资源和估计可靠性。我们要比较规则的后果，而不只追求一个准确率。

## 必须理解

| 概念 | 含义 | 项目用途 |
|---|---|---|
| 经验累积分布函数（ECDF） | Fₙ(t)＝样本中分数≤t的条数/n | 估计某条分数线覆盖多少记录，不是t点发生故障的概率 |
| 分位数 | 对应累计位置的分数 | 可帮助选容量附近的分数线；并列分数可能让名单超容量 |
| 假正例（误报）与假负例（漏报） | 无故障却复核；有故障却未复核 | 前者耗费复核资源，后者可能产生故障损失 |
| 错误率及其分母 | 比率在哪类记录中计算 | 假阳性率FP/(FP+TN)，假阴性率FN/(FN+TP)；分母为0时未定义 |
| 损失与容量 | 每种行动的后果；最多能做多少行动 | 不能把所有错判看成同等代价，按日检查人数 |
| 方案制定与后续评估 | 先用已知历史定规则，再看后来的表现 | 后期标签不能进入当时的名单生成 |

TP是真故障且被复核，FP是不故障却被复核，FN是真故障未复核，TN是不故障也未复核。注意：FP/(TP+FP)是复核名单中的无故障比例，不是假阳性率；“漏了几台”也不等于假阴性率。

分数20、40、40、80的ECDF在40处等于3/4；重复值会一起跳跃。本课若用最近秩分位数，则p分位数取排序后第ceil(np)个值，序号从1开始。算法与线性插值不同，应明确记录。选最高k台时还需要确定并列处理。

## 微型例子

100条设备记录中实际故障10条。复核20条，其中6条故障，则TP=6、FP=14、FN=4、TN=76。假阳性率14/90≈15.6%，假阴性率4/10=40%；不能用14/20代替前者。

若每次故障损失100、复核成本3，且复核可避免80%故障损失，则这批记录的情境总损失为：

4×100＋6×100×20%＋20×3＝580。

不复核的损失是10×100＝1000。在给定效果假设下，按这些记录模拟执行复核规则，可使损失降低420；这不是通过随机实验估计的因果收益。项目使用的数据约定为85%，不要直接照搬例子中的80%。

## 回到项目

写出每日规则和并列办法。用方案制定期比较成本与错误后果，固定规则后评价后一期。若关键设备损失更大，分数相同也可能值得不同优先级；但分数×损失不自动等于预期收益，因为分数不一定是概率。

## 借助AI分析与进一步学习

AI可实现分组校准、成本敏感排序或优化。必须能解释输入何时可知、概率怎样估计、容量怎样满足。按需深入PR曲线和概率校准；复杂模型不是最低要求。

可请AI换成库存复核情境，给一张四格表让你练习识别分母，并解释何时准确率会掩盖损失。
