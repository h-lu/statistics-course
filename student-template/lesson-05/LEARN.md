# 第5课知识准备 · 怎样选择每天要复核的设备

每天能够复核的设备有限。分数可以帮助排序，但还要考虑故障损失、复核成本和每天的名额。本课学习怎样评价一份复核名单，而不是只比较分数高低。

## 1. 先确定名单，再查看故障结果

下表是另设的学习例子。每天最多复核2台设备，每台复核成本为3，发生故障的损失为100。假设复核可以避免85%的故障损失，剩余15%仍会发生。金额均为教学成本单位。

| 设备 | 复核前已知的分数 | 事后获知的故障结果：1为故障，0为未故障 |
|---|---:|---:|
| D1 | 80 | 1 |
| D2 | 40 | 0 |
| D3 | 40 | 1 |
| D4 | 20 | 0 |

先只看前两列。规定“按分数从高到低选择，同分时按设备编号从小到大选择”，得到D1、D2。编号只是这个例子事先规定的办法；不能看到D3发生故障后再换规则，然后把结果当成原规则的表现。

## 2. 累计比例与复核名额

**经验累积分布函数（ECDF）**表示数据中不超过某个值的比例。本例在40处为3÷4＝75%，因为20、40、40都不超过40。它不表示分数为40的设备有75%的故障概率。

一般记作 `F_n(t)＝不超过t的记录数÷n`，其中n是全部记录数，t是要查看的分数。这里得到的是分数的累计比例。

**分位数**可以帮助选择分数阈值，但并列分数会影响名单长度。本例选“分数不少于40”会得到3台，超过名额；选“分数大于40”只有1台。因此规则还需要说明同分时怎样选择，并逐日检查名额。两天平均不超名额，不能代替每一天都不超名额。

## 3. 用四格表分清两类错误

将复核与否和故障与否交叉，可以列出下表。括号内是软件输出中常见的缩写。在本课中，“阳性”对应规则选中复核，不表示设备已经被诊断为故障；“实际故障”列采用文件中已有的历史故障标记。

| | 实际故障 | 实际未故障 |
|---|---|---|
| 选中复核 | 真阳性（TP） | 假阳性（FP，也称误报） |
| 未选中复核 | 假阴性（FN，也称漏报） | 真阴性（TN） |

**假阳性率（FPR）**是实际未故障的记录中，被选中复核的比例，计算为 `FP÷(FP＋TN)`。**假阴性率（FNR）**是实际故障的记录中，没有被选中复核的比例，计算为 `FN÷(FN＋TP)`。没有相应记录作为分母时，该比率不能计算，不应填0。

在四台设备的例子中，四格各为1，两种错误率都是50%。再看另一例：100条记录中有10次故障；复核20条，找到6次故障。此时TP＝6、FP＝14、FN＝4、TN＝76。假阳性率为14÷90，约15.56%；假阴性率为4÷10＝40%。名单中未故障比例为14÷20＝70%，它不是假阳性率，因为分母不同。

## 4. 错误数量与总损失不同

四台设备例子的总损失为：未复核故障损失100，加上复核后仍发生的损失100×15%＝15，再加两次复核成本2×3＝6，共121。不复核的损失为200。因此，在给定效果假设下减少了79，不能写成“已经通过实验证明减少79”。这里减少的是损失，不是把故障标记改写为0；四格表仍将D1记为已选中且历史标记为故障。85%是0.85，剩余15%是0.15。

100条记录的例子中，假设每次故障损失100、每次复核成本3。复核避免80%损失时，总损失为4×100＋6×100×20%＋20×3＝580；采用本项目的85%假设时为550。相同的记录和名单，改变效果假设也会改变结果。

若设备故障损失不同，漏报次数较少的规则未必总损失较低。还应查看不同设备类别是否长期没有机会被复核。

## 5. 为什么要分开两段数据

一台设备连续两天入选，是两次复核，但仍只涉及一台不同设备。计算次数和成本时以设备每天的记录为单位；报告涉及多少台不同设备时，再按设备编号去重。

前42天用于制定和选择规则。规则确定后不再调整，再用后14天的数据评价。后14天的故障结果只能用于核算后果，不能进入当时的名单生成。

固定的是采用哪些信息、怎样排序、怎样处理同分，以及怎样使用当天名额，不是要求每天选择同一批设备。沿用前面的四台设备，若下一天D1—D4的分数依次为10、20、90、80，仍有2个名额，同一排序规则就会选D3、D4。名单变了，选择方法没有变。

可以直接使用分数排序等有依据的规则，不要求先建立故障概率模型。若另外估计故障概率，再说明估计方法、数据来源和使用限制。

若一批数据既用于估计风险，又用于评价同一规则，结果可能过于乐观。用整个前42天估计风险后，再计算这42天的表现，不等于模拟了每天只知道此前资料的实际使用过程。看过后14天结果后再调整规则，应说明这是进一步探索，不再称这14天是未参与选择的评价数据。

按时间模拟实际使用时，只有已经完成后续观察的记录，其故障标记才算已知。日期早于今天，不一定表示所需的24小时观察已经结束。

## 在项目中使用

写清每日规则、同分处理、名额限制和备选方案。比较错误率、复核成本和故障损失，并研究一个重要条件变化。说明是在固定名单下重新计算损失，还是按新条件重新选择名单。根据结果提出试运行、限制使用或暂不采用的建议，并说明何时需要调整。

## 按需阅读：概率、成本与分位数算法

假如有依据估计故障概率为p，复核避免损失的比例为e，故障损失为L，复核成本为c，则每次复核的**期望净收益**为 `p×e×L−c`。p和e都在0到1之间，结果的单位与成本相同。风险分数除以100不自动成为概率；也不必因为还有名额就选择预计收益为负的设备。

按排序位置取分位数的一种常用约定是：将n个分数从小到大排列。若所求位置比例为q，先把n×q向上取整，再取排序后这个位置的数值。例如4个分数求第75百分位数，取第3个数。这里0＜q≤1。这与前课的线性插值不同，使用时应说明算法。无论哪种算法，都不能省略同分处理。

# learning-example
import json
rows = [("D1", 80, 1), ("D2", 40, 0), ("D3", 40, 1), ("D4", 20, 0)]
selected = {r[0] for r in sorted(rows, key=lambda r: (-r[1], r[0]))[:2]}
counts = {"TP": 0, "FP": 0, "FN": 0, "TN": 0}
loss = 0
for device, score, label in rows:
    chosen = device in selected
    key = "TP" if chosen and label else "FP" if chosen else "FN" if label else "TN"
    counts[key] += 1
    loss += 3 + label * 100 * .15 if chosen else label * 100
result = {"selected": sorted(selected), "ecdf40": sum(r[1] <= 40 for r in rows) / len(rows),
          "counts": counts, "loss85": loss, "large_fpr": 14 / 90,
          "large_list_nonfault": 14 / 20, "large_loss80": 4*100+6*100*.20+20*3,
          "large_loss85": 4*100+6*100*.15+20*3}
print(json.dumps(result, ensure_ascii=False, allow_nan=False))
