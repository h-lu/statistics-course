# 第5课支持路线：有限名额下怎样选择复核名单

## 先做一个小判断

只看风险分数从高到低选设备，是否一定能让总损失最低？如果两台设备分数相同，谁先被选会不会影响每天名额？先写预计，再运行程序。

## 这课的概念和原理

- **风险分数**是排序信息，不自动等于故障概率；
- **名额约束**要求每天选中的设备数不超过当天上限，平均不超不代表每天都不超；
- **真阳性、假阳性、假阴性、真阴性**把“是否选中”和“事后是否故障”交叉起来；
- **假阳性率**的分母是真实未故障记录，**假阴性率**的分母是真实故障记录；分母为0时不能计算；
- **损失**还要包括复核成本和未避免的故障损失，错误率低不一定总损失低。

规则制定时只能使用当时已经知道的分数和设备信息，不能偷看事后故障标签。

## 入门跟做

### 1. 先写一条规则

在 `report.md` 写清排序字段、阈值或名额、同分处理、是否每天用满名额。把前42天作为规则制定期，后14天作为规则确定后的评价期。

### 2. 运行并认识起点

```bash
python scripts/course.py start 05
python scripts/course.py run 05
```

查看 `artifacts/starting_overview.json` 中的 `daily_rows_and_capacity`，确认每天记录数和 `max_reviews`。先不要把历史故障列用于生成名单。

### 3. 手算四格表

学习例子中每天最多选2台，按分数选D1、D2；D1故障、D2未故障、D3故障、D4未故障。因此TP=1、FP=1、FN=1、TN=1。FPR=1/(1+1)=50%，FNR=1/(1+1)=50%。名单中未故障比例1/2不是FPR，分母不同。

### 4. 做一次方案比较

生成前42天名单，固定规则后评价后14天。报告每天选中数、TP/FP/FN/TN、FPR/FNR、复核成本、避免后的损失和剩余损失。再改变一个条件：名额、损失或85%的避免比例，并说明是固定名单重算还是重新选名单。

运行 `python scripts/course.py check 05`，确认结果按日期可追溯。

## 反思与提高

反思：如果看过后14天结果后改了规则，还能把这14天称为独立评价吗？提高任务可以比较不同同分规则或按设备类别检查机会是否长期不均，但不靠增加模型数量制造难度。

## 卡住和提交

先核对日期分割、可用字段和每日名额；数值不一致先查分母和成本假设。提交前确认 `submission.json`、结果文件和 `check 05` 正确。
