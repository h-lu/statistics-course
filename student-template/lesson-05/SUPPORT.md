# 第5课支持路线：从一张每日名单到可评价的复核规则

这份支持路线帮助你从“我知道每天有名额”走到“我能生成名单、核对后果并写出建议”。它提供做事顺序和核对方法，不提供正式项目的唯一规则或标准结论。

## 先知道今天要交出什么

标准任务至少要留下四类证据：

1. 两套可按日执行的选择规则；
2. 每天的选中数量和名额核对；
3. 前42天的规则比较与后14天的固定规则评价；
4. 一项条件变化分析和有调整、停止条件的建议。

你可以自行命名结果文件。一个便于检查的安排是：

- `artifacts/daily_selection.csv`：日期、设备、是否选中、选择依据；
- `artifacts/daily_capacity_check.csv`：每天选中数、每日名额、是否超额；
- `artifacts/policy_summary.csv`：各时期、各规则的分类结果和成本结果汇总；
- `report.md`：解释规则、结果、限制和建议。

这些文件名只是建议，不是额外评分要求。

## 先回答三个小问题

暂时不要写程序，先写下答案：

1. 某台设备今天分数很高，是否表示它今天一定会故障？
2. 工作日少用5个名额，能否把这5个名额留到周末？
3. 规则已经固定，为什么每天的名单仍可能不同？

读完本课后，你应能说明：分数不是确定结果；名额需要逐日遵守；固定的是选择方法，不是固定设备名单。

## 核心概念先用一句话说清楚

- **分析单位**：统计结果所针对的基本对象。本课的分析单位是设备日。
- **设备日**：某台设备在某一天的一次判断机会。
- **复核容量**：某一天允许复核的最大设备数量。
- **选择规则**：在行动前规定使用哪些字段、怎样排序或设阈值、同分怎么办，以及何时停止选取。
- **阈值**：决定一条记录是否入选的界限；要说明是否包含恰好等于阈值的记录。
- **规则制定期（开发期）**：前42天，用于提出、比较和选择规则。
- **留出评价期**：随后保留的14天，不参与规则选择，用于评价已经确定的规则。
- **四格表（混淆矩阵）**：把是否选中复核与事后是否故障交叉计数。
- **假阳性率**：实际未故障记录中被选中复核的比例。
- **假阴性率**：实际故障记录中未被选中复核的比例。
- **总损失**：复核成本、漏掉故障的损失和被复核故障的剩余损失之和。
- **敏感性分析**：改变一个有理由的方法或假设，再观察结果和建议是否改变。

## 基础练习（可信起点）：一步一步跟做

### 第1步：运行起始程序

**动作：**在仓库根目录运行：

```bash
python scripts/course.py start 05
python scripts/course.py run 05
```

打开 `lesson-05/artifacts/starting_overview.json`。

**目的：**先确认数据规模和每日名额，不急着生成名单。

**成功信号：**你能看到42个规则制定期日期、每个日期90条设备日记录；例如 `2026-05-04` 的 `max_reviews` 为20。

**反思：**90条记录表示90台不同设备，还是90个设备日？如果同一设备第二天再次出现，应不应该再次占用当天名额？

### 第2步：核对一天的原始记录和名额

**动作：**打开：

- `data/alerts/development.csv`
- `data/alerts/daily_capacity.csv`
- `data/alerts/devices.csv`

选定一天，例如 `2026-05-04`。数出该日设备日记录数，并在名额表中找到当天上限。再从设备表找到任意一台设备的类别、故障损失和复核成本。

**目的：**理解三个文件怎样连接，也确认一天的名单不能跨日期借名额。

**成功信号：**同一天的数据记录数与起始概览一致；设备编号能在 `devices.csv` 中唯一找到一行。

**反思：**生成名单时，`failure_within_24h` 是否已经知道？这个字段何时才可以使用？

### 第3步：手算四台设备的名单

知识准备中的四台设备分数为80、40、40、20，每天最多选2台。规则是“分数从高到低，同分按设备编号从小到大”。

1. 不看故障列，先写出名单；
2. 再查看故障结果，填写四格表；
3. 分别写出假阳性率和假阴性率的分子、分母；
4. 计算总损失。

**成功信号：**名单为D1、D2；TP、FP、FN、TN各为1；两种错误率都是50%；总损失为121个教学成本单位。

**反思：**本例中“名单内未故障比例”和假阳性率碰巧都是50%。它们的分母分别是什么？换一批数据后是否仍会相等？

### 第4步：把候选规则写完整

先不要追求最复杂的方法。用下面六句话检查规则是否能够执行：

1. 我按哪一天分别处理记录？
2. 我只使用哪些行动前已经知道的字段？
3. 第一排序字段是什么，方向是什么？
4. 第一排序字段相同时，继续按什么排序？
5. 是否设置最低阈值，是否允许少用名额？
6. 选到什么时候停止，怎样保证不超过 `max_reviews`？

例如，“按风险分数降序、同分按设备编号升序，最多选择当天名额数”是一条完整的简单规则。它是学习起点，不是要求所有人采用的最终方案。

**成功信号：**另一个同学或AI只看你的文字，就能在同一数据上得到完全相同的名单。

**反思：**如果使用“分数×故障损失”排序，乘积相同时怎样处理？这个乘积只是帮助排序的**启发式指标**，即实用但没有被证明等于真实概率或最优决策的指标，还是有依据解释为故障概率或按概率加权的平均损失（期望损失）？

### 第5步：先生成每日名单，再计算后果

程序可以按下面顺序组织：

```text
按日期分组
→ 每一天按事先写好的规则排序
→ 最多取当天 max_reviews 条记录
→ 保存 record_id、日期、设备编号、是否选中和选择依据
→ 合并事后故障结果，计算四格表与损失
```

先用一天运行并人工核对，再扩展到42天。不要一开始只输出一个总数，否则很难发现某一天超额或并列处理不同。

**成功信号：**每日核对表中每一天都有 `selected_count <= max_reviews`；名单只由复核前可用字段产生。

**反思：**如果42天合计复核数没有超过总名额，是否足以证明每一天都合规？

### 第6步：从名单计算四格表和损失

对每条设备日记录，根据“是否选中”和“事后是否故障”归入一格：

| | 事后故障 | 事后未故障 |
|---|---:|---:|
| 选中复核 | 真阳性 TP | 假阳性 FP |
| 未选中复核 | 假阴性 FN | 真阴性 TN |

核对关系：

- `TP + FP` 应等于复核次数；
- `TP + FN` 应等于实际故障记录数；
- `TP + FP + FN + TN` 应等于设备日记录总数；
- 假阳性率为 `FP / (FP + TN)`；
- 假阴性率为 `FN / (FN + TP)`。

总损失按记录累加：

- 选中且未故障：复核成本；
- 选中且故障：复核成本＋故障损失×15%；
- 未选中且故障：全部故障损失；
- 未选中且未故障：0。

**成功信号：**四格总数与记录数一致，总损失能拆成三项重新相加得到同一个结果。

**反思：**假阴性较少的规则，总损失是否一定较低？如果故障损失不同，结论可能怎样变化？

## 标准任务（本课应完成）

### 第7步：在前42天比较规则并作出选择

对至少两套有实际理由的规则重复第5、6步。比较时使用相同的数据、名额、成本和效果假设。先写你更重视什么，例如总损失、假阴性率、复核成本或最低覆盖，再根据证据选择后期要使用的规则。

结果表至少写出：规则名称、设备日数、复核数、真阳性（TP）、假阳性（FP）、假阴性（FN）、真阴性（TN）、假阳性率、假阴性率和总损失。分开说明“制定规则”和“在同一42天内评价规则”。后者属于样本内评价，即在参与规则制定的同一批记录上评价，不能称为独立验证。

### 第8步：固定方法，用留出的后14天评价

将规则的字段、排序、阈值、同分办法和名额使用方法固定下来。然后把同一方法用于 `evaluation.csv`：先生成名单，再合并事后故障结果。

留出评价期的名单可以每天变化。判断规则是否改变，要看方法是否改变，而不是设备编号是否相同。

**成功信号：**后期结果单独报告，程序没有用后期故障标签生成名单；每天仍满足名额限制。

**反思：**如果看完后期结果后改变规则，接下来应把这次改动称为什么？还需要什么新证据才能再次评价？

### 第9步：完成一次敏感性分析

只改变一个有实际意义的条件，再观察结果和建议是否变化。例如：

- 名额减少一半；
- 可避免损失比例由85%改为60%；
- 某类设备的故障损失改变。

先写明是固定原名单重新计算，还是按新条件重新选择名单。两种做法回答不同问题，都可以做，但不能混写。

**成功信号：**结果表能看出改变了什么、保持了什么、名单是否变化、建议是否变化。

### 第10步：写有条件的建议

建议至少回答：

- 在哪个时期、哪些成本和效果假设下得到结果；
- 对哪些设备或设备类别适用；
- 建议试运行、限制使用还是暂不采用；
- 试运行中监测什么；
- 达到什么可观察条件时调整或停止。

“数据有限”“继续观察”还不是完整条件，需要写成可以检查的记录、比例、损失或时间范围。

## 提高与拓展（提前完成后）

完成标准任务后任选一项：

- **决策稳定性：**预先设置多个名额和损失组合，找出建议发生变化的边界；
- **设备类别后果：**分别报告各类别的入选比例、假阴性和损失，检查总体较优是否伴随某类设备长期没有机会；
- **时间顺序重放：**按日期模拟可用信息，检查风险估计或阈值是否使用未来标签；
- **独立复算：**用另一段程序从原始数据重新生成几天名单与损失，解释任何差异来自筛选、排序、并列还是公式。

## 卡住时按顺序排查

1. 确认当前目录包含 `scripts/`、`data/` 和 `lesson-05/`；
2. 确认四个告警数据文件存在；
3. 若名单数量不对，先查日期分组、排序方向、并列规则和 `max_reviews`；
4. 若四格表不对，检查“选中”和“故障”两个0/1条件有没有写反；
5. 若错误率不对，先写出分子和分母，不要先看百分数；
6. 若损失不对，将复核成本、漏报损失和剩余损失分别求和；
7. 若后期结果过于理想，检查名单是否偷用了 `failure_within_24h`；
8. 若报告无从下手，先写规则、一个逐日核对结果和一项改变建议的比较。
