# 第5课可选支持 · 按遇到的问题查阅

本页是遇阻时的帮助，不是全班必须照做的分析路线。可以独立设计规则、改变方法或用 AI 生成自己的分析；只要满足 README 的容量、信息时点与证据要求。学习小例子不代替正式项目。

## 先知道今天要交出什么

维护团队需要一份能执行、能追查后果的规则建议，以及支持建议的程序与结果。文件名称和分析顺序自定，保存到本课目录即可。报告应能找到两规则、开发与后期、逐日名单和容量、条件变化及使用范围。

## 核心概念与原理

- 分不清名额与阈值时：读 LEARN 的经验累积分布函数、分位数及并列例子。分布信息能提出阈值，不自动解决每天选谁。
- 分不清两个错误率时：先圈四格表中的全部实际未故障、全部实际故障；它们分别是分母。
- 不知道如何比较代价时：复核成本、漏报损失、已复核故障的剩余损失分别累加；85%只是效果假设。

## 基础练习（可信起点）：需要时选一项

**读表或路径受阻。** 从学生仓库根目录（含 `scripts/` 与 `data/`）运行：

```bash
python3 scripts/course.py run 05
```

打开 `lesson-05/artifacts/starting_overview.json`。这项动作只核数据起点；成功信号是42天、3,780条设备日，每天90条，`2026-05-04`容量20。反思：同一设备出现两天，为什么是两次机会而非两台设备？

**不懂信息时点。** 用 LEARN 四台设备例子，先遮故障列写名单，再揭示标签评价。这项动作分开行动与后果；成功信号是你能说明什么字段可用于选名单。反思：见D3故障后换并列规则，这一批还评价原方法吗？

**不懂分母或损失。** 手算小例子的四格表与三项损失，必要时展开 LEARN 反馈。成功信号是四格各1、总损失121，并能解释每项单位与分母。反思：错误率相同是否意味着描述同一群体？

## 入门反思

先预测你所设计规则的取舍，再用自己的正式结果检验。小例子只确认你知道怎么算，不规定最终规则、目标或建议。

## 标准任务（本课应完成）：可用资源，不规定路线

`analysis.py` 默认只生成概览；可复用下列通用函数，也可全部自行实现：

| 帮助 | 输入与用途 | 需要自己决定 |
|---|---|---|
| `load(batch)` | 读取`development`或`evaluation`，核编号、数值与容量 | 何时用哪一时期，哪些资料参与规则制定 |
| `capacity_check(rows, selected, capacities)` | 检查给定记录编号集合的逐日名额 | 谁入选、同分怎样处理、是否少用名额 |
| `evaluate(rows, selected, effectiveness)` | 对给定名单算四格与三项情境损失 | 目标、效果假设、比较办法和解释 |
| `write_json`、`write_csv` | 保存自己的结果 | 表的结构与支持哪一结论 |

这些函数不生成名单，不选规则，不排列方案。可以修改本课 `analysis.py`，也可新建自己的运行入口并在 `submission.json` 指向它。无需补齐指定函数，评价的是统计分析。

自主选择至少两个会影响结果的重要决定，先在报告写依据，再给备选结果。例如，优先减少故障次数还是大额损失；是否规定类别保障；允许少用名额的依据；如何判断后期结果支持试运行。示例是帮助理解选择的性质，不是限定菜单。

## 提高与拓展（提前完成后）

从自己报告中找尚未解决、可能改变建议的问题，可重新提出方法或资料需求。README 的效果临界值、类别保障、时期变化只是可能方向；可做其它有依据的深入研究。把新增计算对应到建议变化，避免重复运行同一设置。

## 卡住时按顺序排查

目录与文件 → 退出是否成功、结果是否最新 → 日期和编号 → 名单与容量 → 条件分母 → 三项损失 → 报告中的对象与假设。若不会写建议，先写“在哪些条件下这份证据支持什么，哪些后果还需处理”，再选择监测与停止条件。

## 提交前自检

原始数据未改；两时期分开；规则由行动前信息产生；每天容量可查；重要选择有理由和备选；条件变化说明是否重选名单。将真正的复算命令与所生成结果写入 `submission.json`，运行 `python3 scripts/course.py run 05` 和 `python3 scripts/course.py check 05`。文件检查不证明统计结论，仍复算一个记录或一天。保存与修订按 WORKFLOW 保留历史版本。
