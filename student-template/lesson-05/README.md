# 第5课 · 有限复核名额下的告警策略

维护团队要决定每天先复核哪些设备。选中更多故障、降低总损失和照顾不同类别的设备，可能要求不同的名单。你要提出能按日执行的规则，解释资源取舍，再用没有参与选择的后期数据评价它。

本课全部数据是**教学合成数据**，设备、成本和效果均用于学习，不是真实机构记录。可以全程使用 AI 理解、计算和写作；最终报告要让读者能复算规则、分母、损失与使用条件。

先用本页理解任务；需要操作帮助时查 [SUPPORT](SUPPORT.md)，需要概念与小例子时查 [LEARN](LEARN.md)，再按自己的路线完成标准任务。初次使用仓库可读[阅读指南](../docs/READING_GUIDE.md)。

## 数据与问题

[告警数据说明](../data/alerts/README.md)包含四张表：前 42 天 `development.csv` 用于制定与比较规则，后 14 天 `evaluation.csv` 用于选定规则后的**留出评价**；`devices.csv` 给出类别、故障损失和复核成本；`daily_capacity.csv` 给出每天最多复核数。工作日最多 20 台、周末 15 台，各天名额分别遵守。

**分析单位**是结果所针对的基本对象，这里是“设备日”：一台设备在一天的一次判断机会。同一设备连续出现 14 天是 14 条记录，不能当成 14 台不同设备，也不能默认这些记录彼此独立。

行动前能知道分数、设备类别、成本和当天名额。`failure_within_24h` 是随后 24 小时是否故障，生成名单时不能使用，事后才用来评价。**风险分数**只提供相对排序，不自动等于故障概率。

本课给定：复核每次支付成本；若设备原本会故障，假设复核避免 85% 的故障损失。85% 是情境假设，没有由这些历史记录证明。对已复核的故障仍计 15% 剩余损失，未复核故障计全部损失。故障标记不因这项假设改写。

## 基础练习（可信起点）

运行默认概览，核对一天的设备日数和名额；用 LEARN 的四台设备例子解释两种错误率和总损失；写一条包含排序、同分办法和停止条件的候选规则。这一层建立可信起点，标准任务仍须完成两套规则、两个时期和条件变化。

## 标准任务（本课应完成）：用途与证据要求

1. **规则与目标的依据。** 为维护团队写出主要目标和需要同时监测的后果。提出至少两套有实际理由的规则，逐套说明行动前字段、排序方向、最低阈值及等号、完整同分办法、是否允许少用名额、每天如何停止。可以比较分数优先与重视高损失设备的启发式排序，也可自行设计。组合分数须说明含义；把风险分数除以 100 并不能使它成为概率。
2. **只用前 42 天制定和选择。** 比较规则的每日名单、四格表、假阳性率、假阴性率、复核成本、漏掉故障的损失、复核故障的剩余损失与总损失。以不复核的情境损失为参照。至少指出一种“漏报次数”与“损失大小”可能不同的取舍。若用同一 42 天的标签估计风险再评价，这属于制定期内的结果，可能偏乐观；不能称为逐日样本外评价。
3. **固定方法，评价后 14 天。** 查看后期标签前写明选定规则和开发期依据；随后只使用行动前字段生成每天名单，再加入标签评价。逐日保存“选中数 ≤ 当天名额”，同时保存名单以便追查。固定的是方法，名单仍可每日变化。若先看后期再改方法，如实称为探索性修订，还需要新数据评价。
4. **比较合理的条件变化。** 改变一个影响建议的容量、损失或复核效果条件，说明依据。分清固定名单重算后果与按新条件重新选名单；容量缩小时原名单可能不可行，需重新选取。对每种情况报告结果及建议怎样变化。假阳性率的分母为全部实际未故障记录，假阴性率的分母为全部实际故障记录；分母为零写未定义。
5. **给出有范围的使用建议。** 在后期按设备类别报告入选数、故障数、漏报数与损失。解释总体较优是否同时让某类设备更少获得复核。可以建议试运行、限制使用或暂不采用，但需写出可观察的监测、调整和停止条件；不能以“总损失最低”自动代表所有类别都改善。

提交的报告要能让维护团队知道采用什么规则、在什么假设下有优势、会牺牲什么，以及何时重新评估。无需复杂模型，也无需用满名额。

路线、实现和呈现方式由你决定。至少自主作出两个会影响结果含义或使用建议的重要决定，说明依据并实际比较合理备选。上面的例子和下面的深入方向不是方法菜单，也不限定唯一结论。

## 提高与拓展（提前完成后）

可以从自己的分析中提出一个可能改变决定的深入问题，比较新增证据对建议的影响；新证据支持保留原建议同样成立。以下仅是例子，也可以采用其它有依据的方法或问题：

- **效果未知时是否值得复核。** 固定两套名单，以效果比例为变量，找出两规则损失相等的位置，并与不复核比较。检查“换一个赢家”与“根本不值得采用”是否发生在同一范围；再解释重新选名单会怎样改变这个问题。
- **总损失与类别保障。** 提出一个有用途的类别最低复核保障，保持逐日总容量不变，与原规则比较总损失、漏报和保障对象后果。说明保障代价与允许取消保障的条件，不能把新增名额当作免费资源。
- **后期变化的来源。** 区分故障基础比例、设备类别故障构成及规则命中情况的变化，判断下一批应监测哪一项。后期结果启发的修订须标为探索，不能再次称为独立验证。

课后可把选择规则移到另一个成本情境，说明需要重新测量什么，而不是重复运行同一命令。

## 运行、核对与提交

所有命令从学生仓库根目录（含 `scripts/`、`data/` 和 `lesson-05/`）运行，使用 Python 3 标准库，不需要安装：

```bash
python3 scripts/course.py run 05
```

默认生成 `lesson-05/artifacts/starting_overview.json`，只核对开发期规模与名额。SUPPORT介绍可选通用读表、核算与检查；程序不生成规则或全套方案，你自行组织比较。可修改或替换 `analysis.py`，保留原始数据。

完成后，在 `submission.json` 中填写 `complete`、报告路径、支持结论的结果路径和能重新生成它们的命令。路径从学生仓库根目录写起。自行设置统一运行入口，能重新生成你所列的结果。

```bash
python3 scripts/course.py run 05
python3 scripts/course.py check 05
```

`check` 只核对完成状态和非空文件，不证明方法或结论合理。按[提交步骤](../docs/WORKFLOW.md)保存成果与版本，已有最终标签保留，修订另建版本。评分沿用[成果与评分](../docs/ASSESSMENT.md)。进入[知识自查](https://hblu.top/stat-check/)确认第 5 课，完成 A、概念学习、B 与反馈；离线时先用 LEARN 的本地变式自检，不把它当成线上作答记录。
