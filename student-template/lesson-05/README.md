# 第5课 · 有限复核名额下的告警策略

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你要解决的问题是：每天的复核名额有限，怎样用当天已经知道的信息选出复核设备，并评价这套选择方法的后果？

你可以全程使用AI帮助理解、编程、分析和写作。提交前需要自己核对每日容量、第4项中两种分类比率的分母、损失计算和结论范围。

第一次使用课程文件时，先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。开始项目之前阅读[知识准备](LEARN.md)；不知道下一步做什么时，打开本课的[支持路线](SUPPORT.md)，从“入门跟做”开始。

## 先理解项目中的对象和时间

维护团队每天观察同一批90台设备。**分析单位**是统计结果所针对的基本对象。本课的分析单位是“设备日”，即某台设备在某一天的一次判断机会。同一台设备连续出现14天，表示14条设备日记录，不表示14台不同设备。

工作日最多复核20台，周末最多复核15台。这个每天允许复核的最大数量称为**复核容量**。不同设备的故障损失和复核成本不同。你需要写出一套**选择规则**，即只根据复核前已经知道的信息，规定当天怎样选出设备。规则应说明排序方法、**阈值**（决定是否入选的界限）、并列时的处理办法和最多复核数量。规则固定后，每天的分数和容量可以变化，所以每天的具体名单也可以变化。

[数据说明](../data/alerts/README.md)介绍四个文件：

| 文件 | 在本课中的用途 |
|---|---|
| `development.csv` | 前42天的设备日记录，称为**规则制定期（开发期）**，用于制定、比较和选择规则 |
| `evaluation.csv` | 随后的14天记录，称为**留出评价期**，用于评价已经确定的规则 |
| `devices.csv` | 每台设备的类别、故障损失、复核成本，以及复核可避免多少故障损失的效果假设 |
| `daily_capacity.csv` | 每天最多可以复核多少台设备 |

`failure_within_24h` 表示该设备在随后24小时内是否发生故障。虽然它已经保存在历史数据中，但生成当天名单时还不知道这个结果，只能在事后评价规则时使用。`risk_score` 是**风险分数**，即系统给出的相对风险排序信息；分数越高表示系统认为风险相对越高，但它不自动等于故障概率。

## 本课要完成的五项任务

### 1. 写出两套可以执行的选择规则

每套规则都要说明：

- 使用哪些复核前已知的字段；
- 先按什么排序，若仍然并列再按什么排序；
- 是否设置最低阈值；
- 是否一定用满当天名额；
- 每天怎样保证不超过 `max_reviews`。

至少提出一套主要规则和一套有实际理由的备选规则。若使用“风险分数×故障损失”之类的组合指标，要说明它只是**启发式指标**，即帮助形成合理排序、但没有被证明等于真实概率或期望损失的实用指标。这里的**期望损失**是按各种结果的发生概率加权得到的平均损失。不能把风险分数除以100后直接称为故障概率。若另外估计故障概率，还要说明估计方法、使用的数据和限制。

### 2. 只用前42天制定和选择规则

在规则制定期比较两套规则。可以使用前42天的故障结果来评价和选择规则，但要如实说明：同一批数据既参与了规则制定，又参与了规则比较，因此这里得到的是制定期内的结果，可能偏乐观。

若声称模拟每天真实使用，就必须按日期顺序处理，每一天只能使用当时已经取得的信息。**样本外评价**是指在没有参与规则制定或模型估计的记录上评价表现。使用整个42天估计风险后再评价这42天，不能称为逐日样本外评价。

### 3. 固定规则，再用留出的后14天评价

在查看后14天的故障结果之前，先确定选择方法。**留出评价**是把一段未参与规则选择的数据保留下来，用于评价已经确定的规则。评价时仍按当天的分数和名额（复核容量）生成名单，再用事后故障结果核算后果。固定的是选择方法，名单仍可随当日分数和名额变化。

查看结果后可以继续修改规则，但要标为**探索性修订**，即由已经看到的结果启发、尚需用新数据评价的改动。不能先看后14天结果、重新选择最有利的规则，再把同一结果称为留出评价结果。

### 4. 核对每日名额、分类结果和总损失

逐日保存选中设备数与当天名额，确认每一天都没有超额。两天合计或平均没有超额，不能代替逐日检查。

本课把“选中复核”视为规则判定为阳性，把事后实际故障视为实际阳性。把两种状态交叉计数得到**四格表（混淆矩阵）**。四种结果是：真阳性（选中且故障）、假阳性（选中但未故障）、假阴性（未选中但故障）和真阴性（未选中且未故障）。在此基础上计算：

- **假阳性率**：实际未故障记录中，被选中复核的比例；
- **假阴性率**：实际故障记录中，没有被选中复核的比例。

两种比率的分母不同。分母为0时写“不能计算”，不填0。

总损失要分别列出复核成本、未选中故障造成的损失，以及已选中故障在复核后仍剩余的损失。关键结果应能追溯到日期、设备编号或设备类别。

### 5. 完成一次敏感性分析并提出建议

**敏感性分析**是有理由地改变一个方法或假设，再观察结果和建议是否改变。选择一个会影响决定的条件，例如每日容量、故障损失或复核可以避免的损失比例。说明采用哪一种分析：

- **固定名单重新计算**：名单不变，只计算另一种假设下的损失；
- **按新条件重新选择**：条件变化后，重新运行选择规则，名单可能改变。

根据结果提出试运行、限制使用或暂不采用的建议，并写出可以观察或计算的调整条件和停止条件。

## 三层学习路线

### 基础练习（可信起点）

1. 运行起始程序，任选一天核对设备日记录数和 `max_reviews`；
2. 用知识准备中的四台设备例子手算四格表、假阳性率、假阴性率和总损失；
3. 写出一条只使用复核前信息、包含完整同分办法的候选规则。

完成基础练习表示你已经能开始项目，还没有完成两套规则比较、后14天评价和条件变化分析。

### 标准任务（本课应完成）

完成上面的五项任务：比较至少两套规则，只用前42天制定和选择，固定规则后评价留出的14天，逐日核对容量，报告分类结果与总损失，并完成一项会影响建议的敏感性分析。本课不要求复杂模型，也不要求每天用满复核容量。

### 提高与拓展（提前完成后）

标准任务完成后任选一项：

- 预先设置多个合理的容量和损失组合，制作**决策稳定性表**，也就是记录建议在哪些已检查条件下保持不变、在哪些条件下发生改变；
- 按设备类别检查入选机会、假阴性和损失是否集中；
- 按日期顺序重放规则，检查任何一天是否使用了未来信息；
- 用独立程序复算一段日期的名单、四格表和总损失。

提高部分要说明新增证据使原建议保持不变、增加条件还是发生改变，不以模型或图表数量评价。

## 本课采用的损失假设

每次复核都要支付复核成本。若被复核设备原本会故障，课程情境假设复核可以避免85%的故障损失，其余15%仍然发生；没有复核的故障承担全部损失。

85%是用于比较方案的情境假设，不是历史数据已经证实的**干预效果**。干预效果是采取复核相较于不复核造成的结果变化。这个假设也不是把85%的故障标记改成0；四格表始终使用原有历史故障标记，效果假设只进入损失计算。

## 建议保存的结果

文件名可以自行安排，至少应能找到：

- 每日名单与名额核对；
- 前42天的方案比较；
- 后14天的评价结果；
- 条件变化前后的结果；
- 支持最终建议的报告。

仅提交这个概览还没有完成作业。

## 课堂安排

0—13分钟理解情境并核算小例子；13—24分钟写两套规则；24—53分钟比较制定期结果并评价后期；53—68分钟改变条件并写建议；68—75分钟检查提交；75—90分钟完成知识自查。

## 运行和提交

在学生仓库根目录运行，也就是包含 `scripts/`、`data/` 和 `lesson-05/` 的文件夹：

```bash
python scripts/course.py start 05
python scripts/course.py run 05
```

初次运行生成 `lesson-05/artifacts/starting_overview.json`。其中：

- `device_days` 是设备日记录总数；
- `days` 是日期数；
- `daily_rows_and_capacity` 列出每一天的记录数和最多复核数。

起始程序只核对前42天的数据和名额，还没有生成名单或评价规则。根据本课任务修改或替换 `analysis.py`，把支持结论的结果保存在 `lesson-05/artifacts/`，并在 `report.md` 中解释。

完成后更新 `submission.json`：将 `status` 改为 `complete`，填写报告路径、结果文件和运行命令。然后运行：

```bash
python scripts/course.py run 05
python scripts/course.py check 05
```

本地 `check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不会判断统计结论。按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送，创建标签 `v2-l05-final`，再查看自动检查结果。自动检查能够核对程序能否重新生成所列结果，仍不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖；修订时保留原版本。评分办法见[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第5课。先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。自查用于发现概念混淆，不替代项目报告。
