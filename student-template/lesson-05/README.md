# 第5课 · 有限复核名额下的告警策略

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

第一次使用这些资料时，可先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。

如果你不知道下一步做什么，打开本课的[支持路线](SUPPORT.md)，先完成“入门跟做”。

## 项目背景与数据

维护团队每天要从90台设备中选出一部分进行复核，工作日最多20台，周末最多15台。不同设备的故障损失和复核成本不同。你的任务是制定下一周期可以试用的规则。

[数据说明](../data/alerts/README.md)介绍前42天的 `development.csv`、后14天的 `evaluation.csv`、设备成本表 `devices.csv` 和每日名额表 `daily_capacity.csv`。每行记录一台设备在一天的情况，同一设备会多次出现，不是每天都换成新设备。

风险分数只是排序信息，不等于故障概率。历史故障结果虽然已放在表中，生成当日名单时却不能使用当时尚未知道的结果。先阅读[知识准备](LEARN.md)，理解名单、错误率和损失怎样计算。

## 分析任务

1. **写出规则和备选办法。** 说明采用哪些复核前已经知道的字段，怎样排序或设阈值，同分怎样处理，是否使用全部名额。至少提出一个有实际意义的备选方案。
2. **只用前42天制定并选择规则。** 说明规则制定与选择用了哪些数据；若另外估计故障概率，还需说明估计方法和所用数据。若同一批数据既用于制定规则又用于评价，结果可能过于乐观，不能称为每天只用此前资料的表现。需要模拟逐日使用时，只能使用当时已取得的信息。
3. **保持规则不变，评价后14天。** 固定的是选择方法，名单仍可随当日分数和名额变化。按日期生成名单，后期故障结果只用于核算后果。可以报告事先确定的备选方案；看结果后重新选规则，应说明进一步探索，不能仍把这些结果称为未参与选择的独立评价。
4. **核算每日名额、错误和损失。** 每天都要检查选中数量不超过当天上限。报告四格表中的真阳性、假阳性、假阴性、真阴性，以及假阳性率和假阴性率；这些名称和分母见知识准备。另报复核次数与成本、遗漏故障及损失、复核后剩余损失。没有相应分母时说明无法计算。关键结果应能查到日期、设备类别或记录。
5. **改变一个重要条件并提出建议。** 可改变名额、损失或复核效果。说明是名单不变时重新计算，还是按新条件重新选择名单。提出试运行、限制使用或暂不采用的建议，并写清可观察或有数值的调整、停止条件。

## 难度分层

下面三层按顺序使用。基础练习帮助你确认名单、分母和每日名额，不能代替标准任务；标准任务保留上面的五项要求；提高与拓展供提前完成者继续检验规则。

### 基础练习（可信起点）

运行起始程序，读懂每日记录数和最多复核数；再用知识准备中的四台设备例子手算真阳性、假阳性、假阴性、真阴性及两种错误率。最后写出一条只使用复核前已知字段的候选规则。这一层还没有完成规则选择、后14天评价和条件变化分析。

### 标准任务（本课应完成）

完成上面的五项分析任务：至少比较两套有意义的规则，只用前42天制定和选择，固定规则后评价后14天，逐日核对名额与损失，并改变一个重要条件提出有停止标准的建议。这一层不要求复杂模型，也不要求用满每天名额。

### 提高与拓展（提前完成后）

标准任务完成后任选一项：预先设定多个合理的名额与损失组合，制作决策稳定性表；按设备类别检查长期入选机会、假阴性和损失是否集中；按日期顺序重放规则，核对任何一天都没有使用未来信息；或用独立实现复算一段日期的名单、四格表和总损失。提高部分要说明新增检查是否让试运行建议保留、增加条件或改变，不以模型数量评价。

## 损失计算采用的假设

本项目规定每次复核都支付成本；若设备原本会故障，复核可避免85%的故障损失，其余15%仍发生。没有复核的故障承担全部损失。这是比较方案时采用的情境假设，不是已经由历史数据证实的干预效果。85%指避免的损失比例，不是“85%的故障标记改为0”。历史故障标记保持不变，四格表仍按这些标记和模拟名单计算。

可以少用名额，但不能超出当天上限。漏报少不一定总损失低，总损失低也可能伴随某类设备长期不被复核，应说明这种取舍。用同一批后期记录改变假设，不会产生一批新的验证数据。

## 需要提交什么

提交可按日执行的规则、与备选方案的比较、前42天和后14天分开的结果、逐日名额检查、条件变化分析和监测建议。以上都是本课任务，不要求复杂模型或必须用满名额。

报告应让使用者看清：在什么假设下，对哪些设备，规则值得试用；遇到什么变化需要重新考虑。

## 课堂安排

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`device_days` 是设备每日记录的总条数，`days` 是天数；`daily_rows_and_capacity` 列出每天的记录数和最多复核数 `max_reviews`。示例只读取前42天的分数和名额信息，还没有生成名单、计算错误率或评价后14天。

先阅读输出中与你的问题有关的内容，再按上面的分析任务扩展程序。自己的计算结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。若使用完整课程资料库，先进入 `student-template/`。

```bash
python scripts/course.py start 05
python scripts/course.py run 05
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据本课问题修改或替换程序，将结果和图表保存到本课 `artifacts/` 文件夹，并在 `report.md` 中解释和引用。原始数据保持不变；程序使用的新软件包写入 `requirements.txt`。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起；更换程序时要相应更新命令。然后重新运行并检查：

```bash
python scripts/course.py run 05
python scripts/course.py check 05
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送到个人仓库，创建本课最终标签 `v2-l05-final`，再查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，但不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖，修改时保留原版本。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令、结果文件设置和修订办法见上述操作说明，评分见[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第5课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
