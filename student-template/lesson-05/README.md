# 第5课 · 有限复核名额下的告警策略

**以下数据全部为教学合成数据，不代表真实机构、个人或实际效果。** 可以全程使用AI提出候选问题、编程、分析、写作和协助提交；你需要确认最终采用的选择，核对结果、依据和适用范围。无需提交AI对话或证明代码由谁输入。先阅读[知识准备](LEARN.md)，再展开正式分析。

## 项目背景与数据

维护团队每天从90台设备中选择复核对象，工作日最多20台、周末15台。损失和复核成本因类别不同。你要制定下一周期可以试运行的规则，而不是单独寻找最高准确率。

[告警数据说明](../data/alerts/README.md)包含前42天 `development.csv`、后14天 `evaluation.csv`、成本与损失字典 `devices.csv` 和日容量 `daily_capacity.csv`。一条记录是一个设备日，不是独立的一台新设备。历史标签完整可见，但行动当时不可知；风险分数不等于故障概率。

## 分析任务

1. **明确目标与可执行规则。** 写清使用哪些行动前字段、优先级如何计算、同分怎样处理、是否用满名额；可以选择阈值、排序、历史风险估计或有理由的覆盖保障。至少提出一个有实际意义的备选。
2. **只用前42天制定并选择。** 记录最终规则、风险转换或拟合所用资料，以及确定规则的依据。若用整个开发期拟合后又在这42天计算表现，应称开发期回代，不能称每天只使用此前资料的样本外结果。确需逐日开发验证时，只使用当日之前已经取得的标签。
3. **冻结后评价后14天。** 保持规则和已拟合的转换不变，按日期生成名单。后期标签只用于核算后果，不用于当日排序、并列处理或选择最喜欢的规则。可并列报告预先确定的备选，但不能看结果后重新选优，仍称本期是未使用过的独立评价。
4. **核算容量、错误与损失。** 逐日验证选中数不超当天上限，不能只看跨日平均或总数。给出TP、FP、FN、TN、FPR、FNR、复核数量与成本、漏报故障及损失、被复核故障的剩余损失；分母为0时记未定义。结果可追溯到日、设备类别或记录。
5. **改变一个重要条件并作决定。** 例如容量、损失或可避免比例。说明固定名单重算后果，还是按新假设重新生成名单；条件变化不是一套新的验证数据。给出试运行、限范围使用或暂不采用建议，以及数值明确或可观察的更新/停止条件。

## 损失约定与解释

本项目假设复核可避免85%的故障损失，每次复核都付成本，真故障仍有15%损失。未复核故障承担全部损失。它是情境约定，不是历史数据证明的干预效果；学习例子中的其他比例不能照搬。

若有依据估计故障概率为p，情境期望净收益为 `p×0.85×故障损失−复核成本`；分数除以100不自动是p。允许少用名额。漏报少不一定损失低，总体损失低也可能掩盖某类设备长期不被覆盖，应据用途说明取舍。

## 成果与提交前自核

提交可按日执行的规则、同口径备选比较、开发与后期分开的结果、逐日容量记录、条件变化及监测建议。以上均是主任务，不是把后期评价或条件变化留给选做。

进一步完善可用群体结果说明需要哪些保障及其代价；不要求复杂模型，也不以把名额用满或匹配某个数值为目标。关键是规则、假设、结果和使用条件一致。

## 90分钟建议安排

0—13分钟情境、名单与损失小例子；13—24分钟写规则和备选；24—53分钟开发比较、冻结与后期评价；53—68分钟条件变化和建议；68—75分钟核对提交；75—90分钟自查。可由AI实现计算，不取消关键分析环节。

## 运行、核对与提交

以下“仓库根目录”指你自己的学生仓库中包含 `scripts/`、`data/` 的目录；在合并资料库中阅读时，对应 `student-template/`。先运行：

```bash
python scripts/course.py start 05
python scripts/course.py run 05
```

`analysis.py` 是可运行的数据概览，不是完整项目答案。按问题修改或替换它，将关键数值结果和图表写入本课 `artifacts/`，在 `report.md` 中引用。可以调整报告结构，不能只保留提示或粘贴默认输出。原始数据不改写；新增依赖写入 `requirements.txt`。

完成后，在本课 `submission.json` 中将 `status` 设为 `complete`，填写 `report`、支持结论的 `artifacts` 和非空命令参数列表 `run`。所有路径相对于学生仓库根目录。再执行：

```bash
python scripts/course.py run 05
python scripts/course.py check 05
git diff --check
git status
git diff
git add lesson-05 requirements.txt
git diff --cached
git commit -m "完成第05课项目"
git push
git tag v2-l05-final
git push origin v2-l05-final
```

**`run` 执行分析；`check` 只检查完成声明、路径和文件是否存在且非空，不会重新运行分析或判断结论。** 推送后查看 Actions 的重跑结果；配置了重现检查时，它会在临时副本移除所列结果文件、运行程序并比较内容。固定随机种子、排序和输出精度，避免将带生成时间的文件列入逐字节比较。程序运行成功和文件检查通过，都不等于统计解释正确。

新增共用程序也须核对后纳入提交。已有最终标签不要覆盖；修订保留原版本。网络、环境或检查故障时保存本地文件与提交，向教师说明，不把失败写成已通过。完整步骤见[项目工作流](../docs/WORKFLOW.md)和[成果与评分](../docs/ASSESSMENT.md)。
