# 第23课 · 风险预测与复核决策

## 项目背景

人工复核团队每月最多复核25%的新登记工单。按情境设定，每漏报一条升级工单计8单位损失，每额外复核一条未升级工单计1单位损失；这些损失数值用于比较决策方案，不是对实际干预收益的估计。

根据工单登记时可得的信息制定复核规则：是否用满名额，如何处理相同风险分数，怎样权衡地区服务需求与误报、漏报损失？

可用资料为[预测分析数据集](../data/prediction/README.md)中的`requests.csv`。**资料全部为教学合成数据。** 数据字典说明记录单位、字段、时点和局限；同时阅读`feature_availability.csv`。你可以全程使用AI完成编程、分析、写作与提交，也可以复用前课代码。

## 分析任务

1. 只用工单登记时可得字段，月0—11训练、12—15比较策略；明确escalated为事后标签，工单处理时长、满意度等不能进入工单登记时预测。

2. 形成概率或风险分层，解释逻辑回归中的概率、优势及优势比。用PR或ROC和基础率说明排序能力，不能只报准确率。

3. 在逐月25%容量约束下比较有业务理由的行动策略，如统一概率阈值、按月排序与地区最低服务保障。逐月核对实际人数、漏报和误报代价；比较至少一种代价或容量变化会怎样改变决定。

4. 提交可以执行的规则和验证批次结果，说明预测风险不等于干预效果；如果缺少干预有效性信息，给出试运行需要补充的证据。

以上均为本课需要完成的任务，分析方法和报告形式可以自行选择。评价不以图表或模型数量为依据。使用外部资料时注明来源，补充的业务假设应明确标注，不得当作已知事实。

## 课堂安排（90分钟）

- 0—12分钟：阅读[知识准备](LEARN.md)和项目背景，明确分析问题；需要时可延长到17分钟，相应减少重复操作和排版时间。
- 12—55分钟：选择方法、开展分析或研究设计，并比较不同方案；遇到不熟悉的概念可随时查阅知识准备或询问AI。
- 55—68分钟：核对一项主要结论的计算结果、假设与替代解释，完成分析报告。
- 68—75分钟：重新运行程序，检查结果并提交；提前完成时，可进一步检验报告中的重要结论。
- 75—90分钟：[知识自查](https://hblu.top/stat-check/)，确认页面为当日V2课次，建议先完成A版基础题，再向AI学习不熟悉的概念，随后完成B版变式题。

## 示例代码与运行方法

从仓库根目录运行：

```bash
python scripts/course.py start 23
python scripts/course.py run 23
```

本课`analysis.py`读取数据并生成`artifacts/starting_summary.json`，用于熟悉数据结构。**请在此基础上完成本课分析任务，形成自己的分析方案和结论。** 可使用Python标准库、numpy/scipy、pandas、statsmodels、scikit-learn或其他合适工具；说明新增依赖与运行命令。

## 成果要求与提交

- `report.md`：面向报告使用者，写清分析问题、方法依据、主要结果、适用范围和建议。
- 可复现的分析程序或研究设计文件，以及报告引用的计算结果和图表；不要手工修改原始数据。
- `submission.json`：将`status`设为`complete`，`report`指向分析报告，`artifacts`列出支持报告结论的结果文件路径，`run`填写可复现分析的命令。

仅运行示例代码或粘贴模型输出，还没有完成本课分析任务。合格方案应只使用预测时可得的变量，每月复核量不超过上限，评价指标的分母正确；更好的方案还会解释为何保留或用满名额，并比较各地区的服务安排及损失假设变化后的选择。

完成后执行`python scripts/course.py check 23`，按[项目工作流](../docs/WORKFLOW.md)提交并创建`v2-l23-final`标签；有修订时保留原标签。自查按[知识自查说明](../docs/KNOWLEDGE_CHECK.md)进行。项目分析允许全程使用AI，不要求提交AI对话记录。
