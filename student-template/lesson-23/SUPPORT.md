# 第23课陪做支持 · 风险预测与复核决策

这份材料帮助你在不知道下一步时建立可信起点。它不提供本课正式数据的答案，也不能代替 [README 主任务](README.md)；概念的完整解释见 [LEARN.md](LEARN.md)。

## 先知道今天要交出什么

- `report.md`：说明每月怎样选出复核对象及其代价。
- 登记时风险预测、逐月容量与混淆计数的可重跑结果。
- `submission.json`：列出规则和验证结果文件。

最低出口是：别人能够按你的命令重新生成报告引用的数字，并知道这些数字可以和不可以用于什么决定。

## 核心概念与原理

| 规范术语 | 通俗解释 | 怎样在自己的结果中检查 |
|---|---|---|
| 事件概率 | 在相同输入条件下发生升级的模型概率，不是对单条工单的确定结论。 | 用概率排序或设置行动阈值。 |
| 基础率 | 评价资料中实际升级记录所占比例。 | 解释准确率、查准率和曲线指标。 |
| 查准率 | 被复核记录中实际升级的比例，分母是被复核数。 | 说明复核资源有多少用于真实升级记录。 |
| 查全率 | 实际升级记录中被复核的比例，分母是实际升级数。 | 说明漏掉了多少升级记录。 |
| 容量约束与损失 | 每月最多复核25%，漏报和额外复核后果不同。 | 把风险分数转成可执行名单。 |

### 先用一个小例子想清楚

100条工单中有10条实际升级。规则选20条复核，其中8条升级：查准率为8/20=40%，查全率为8/10=80%。如果当月只能复核10条，这条规则即使指标不错也不能直接执行。

这个例子只用于核对概念，不是正式数据的结论。正式项目必须使用自己的运行结果。

## 基础练习（可信起点）：入门跟做

以下命令都从仓库根目录运行，也就是同时能看到 `scripts/`、`data/` 和 `lesson-23/` 的目录。

```bash
python scripts/course.py start 23
python scripts/course.py run 23
```

第二条命令成功后，应看到终端提示结果已经生成，并能打开 `lesson-23/artifacts/starting_summary.json`。这个文件只是数据起点，不是本课完整答案。

若终端明确提示 `python: command not found`，按仓库首页说明，把上面两行开头的 `python` 换成 `python3`，其余内容不变。

### 第1步：锁定可用字段

- **动作：** 运行起点程序并逐行阅读 `feature_availability.csv`，把字段分为“登记时可用”“结单后才有”。
- **目的：** 防止用未来信息预测过去的风险。
- **成功信号：** 模型输入清单不含 `resolution_minutes`、`after_close_minutes`、`satisfaction_after` 或结果标签。
- **想一想：** 如果部署当天拿不到某字段，验证分数还有意义吗？

### 第2步：建立风险起点

- **动作：** 用月0—11训练，在月12—15输出每条记录的风险概率、月份和实际结果。
- **目的：** 把预测和评价资料分开。
- **成功信号：** 每条验证记录只有一行预测，概率在0到1之间。
- **想一想：** 概率0.7表示什么，不能表示什么？

### 第3步：按月执行容量规则

- **动作：** 在每个月按风险排序，最多选择25%；手工复算一个月的复核数、真阳性和假阴性。
- **目的：** 总体25%可能掩盖某月超额，必须逐月检查。
- **成功信号：** 每月名单不超上限，计数能由原记录复核。
- **想一想：** 并列分数落在名额边界时怎样处理？

### 第4步：比较行动方案

- **动作：** 比较统一阈值与逐月排序，或加入地区最低保障；再改变一次容量或漏报损失。
- **目的：** 说明统计指标怎样转成资源决定。
- **成功信号：** 候选策略在相同月份和代价定义下比较。
- **想一想：** 用满名额一定更好吗？什么证据支持你的选择？

完成这四步后，你已经有可信起点，但还没有完成整项主任务。

## 标准任务（本课应完成）

回到 [README](README.md) 完成全部标准任务，特别核对：

- 只使用登记时可得字段。
- 同时解释概率、基础率、排序能力、查准率和查全率。
- 逐月满足25%容量，并比较有理由的行动策略。
- 说明风险不等于干预收益，并提出试运行所需证据。

把程序输出翻译成完整统计句子：对象是谁，比较什么，数值和单位是什么，哪些假设成立时可以怎样使用，哪些结论仍不能作出。

## 提高与拓展（提前完成后）

先完成标准任务，再选一项。提高的标准是让证据、适用范围或行动更可靠，而不是增加代码或图表数量。

- 比较地区保障对总体损失与地区服务量的影响。
- 寻找容量或损失变化下的策略切换点。
- 评价概率校准和并列分数规则。

## 卡住时按顺序排查

- **复核比例超过25%：** 检查容量是逐月计算还是全期计算，以及取整和并列分数规则。
- **命令提示找不到文件：** 先运行 `pwd`，确认当前位置是仓库根目录；这里应同时看见 `scripts/` 和本课目录。
- **程序能运行但结果还是旧的：** 检查结果文件的修改时间，确认修改并运行的是本课 `analysis.py`；必要时删除自己生成的旧结果后重跑，但不要删除原始数据。
- **报告数字和程序输出不一致：** 从报告中的一个关键数字反向找到结果文件、筛选范围、分子和分母；不要手工把报告改成“看起来合理”的数字。
- **不知道怎样开始写报告：** 先写五句：谁使用、要决定什么、数据覆盖谁、一个主要结果、一个不能支持的结论，再补方法和证据。
