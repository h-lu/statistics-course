# 第26课陪做支持 · 风险模型的校准与试运行评价

这份材料帮助你在不知道下一步时建立可信起点。它不提供本课正式数据的答案，也不能代替 [README 主任务](README.md)；概念的完整解释见 [LEARN.md](LEARN.md)。

## 先知道今天要交出什么

- `report.md`：值班人员能够执行的模型使用说明。
- 月16—19校准记录、冻结规则和月20—23后续评价结果。
- `submission.json`：列出校准、群体结果和监测规则。

最低出口是：别人能够按你的命令重新生成报告引用的数字，并知道这些数字可以和不可以用于什么决定。

## 核心概念与原理

| 规范术语 | 通俗解释 | 怎样在自己的结果中检查 |
|---|---|---|
| 区分能力 | 模型把实际升级记录排在未升级记录前面的能力；受试者工作特征曲线下面积（AUC）常用于概括排序。 | 检查优先顺序，不代表概率准确。 |
| 概率校准 | 预测为某一概率的一组记录，其实际发生比例是否接近该概率。 | 判断概率能否直接用于资源和成本决定。 |
| Brier分数 | 预测概率与0/1结果之差平方的平均，越小通常越好。 | 与排序指标一起评价。 |
| 分布漂移 | 输入分布、基础率或输入与结果关系随时间改变。 | 区分无标签监测和有标签评价。 |
| 撤回条件 | 预先写明何种证据触发人工复核、降级或暂停。 | 把“持续监测”变成可执行规则。 |

### 先用一个小例子想清楚

100条记录都预测0.20，后来40条实际升级。这组概率明显低估风险；即使排序不变、AUC相近，用0.20安排预算仍可能失真。若某地区只有10条记录，看到4条升级还需同时说明样本量和不确定性。

这个例子只用于核对概念，不是正式数据的结论。正式项目必须使用自己的运行结果。

## 基础练习（可信起点）：入门跟做

以下命令都从仓库根目录运行，也就是同时能看到 `scripts/`、`data/` 和 `lesson-26/` 的目录。

```bash
python scripts/course.py start 26
python scripts/course.py run 26
```

第二条命令成功后，应看到终端提示结果已经生成，并能打开 `lesson-26/artifacts/starting_summary.json`。这个文件只是数据起点，不是本课完整答案。

若终端明确提示 `python: command not found`，按仓库首页说明，把上面两行开头的 `python` 换成 `python3`，其余内容不变。

### 第1步：重新标记资料用途

- **动作：** 运行起点程序；把月16—19写成已经看过的历史校准资料，月20—23写成冻结后的后续评价。
- **目的：** 避免把重复使用的资料再次包装成独立测试。
- **成功信号：** 报告明确记录每批资料影响了什么选择。
- **想一想：** 如果根据月20—23重选校准方法，它还在评价什么？

### 第2步：建立校准表

- **动作：** 在月16—19按预测概率分箱，列每箱记录数、平均预测概率和实际升级比例。
- **目的：** 用同一组记录比较“预测多少”和“发生多少”。
- **成功信号：** 各箱分母之和等于纳入校准的记录数。
- **想一想：** 小箱中的大差异应怎样解释？

### 第3步：冻结并评价

- **动作：** 固定校准方法、行动阈值和允许使用范围，再在月20—23计算AUC、Brier分数、校准和分地区结果。
- **目的：** 后续资料只评价，不再帮助选择。
- **成功信号：** 总体和地区结果都带样本量与基础率。
- **想一想：** 排序稳定但概率偏低，会改变哪项值班行动？

### 第4步：写成行动规则

- **动作：** 分别为字段缺失、取值越界、概率偏差和结果标签延迟写复核频率及触发动作。
- **目的：** 让值班人员知道何时继续、降级或停止。
- **成功信号：** 每个指标都有对象、阈值、检查频率和动作。
- **想一想：** 没有结果标签时能发现什么，不能确认什么？

完成这四步后，你已经有可信起点，但还没有完成整项主任务。

## 标准任务（本课应完成）

回到 [README](README.md) 完成全部标准任务，特别核对：

- 明确历史校准与后续评价资料。
- 同时检查区分、校准、基础率和分群表现。
- 区分输入漂移监测与有标签性能评价。
- 给出适用范围、人工责任、复核频率与撤回规则。

把程序输出翻译成完整统计句子：对象是谁，比较什么，数值和单位是什么，哪些假设成立时可以怎样使用，哪些结论仍不能作出。

## 提高与拓展（提前完成后）

先完成标准任务，再选一项。提高的标准是让证据、适用范围或行动更可靠，而不是增加代码或图表数量。

- 比较一种校准方法是否改变实际阈值决策。
- 为不同地区设计样本量不足时的复核方案。
- 建立输入、预测与结果标签的分阶段监测表。

## 卡住时按顺序排查

- **校准箱结果相互矛盾：** 先检查每箱样本量、分箱边界和是否在同一批资料上计算；不要只看折线形状。
- **命令提示找不到文件：** 先运行 `pwd`，确认当前位置是仓库根目录；这里应同时看见 `scripts/` 和本课目录。
- **程序能运行但结果还是旧的：** 检查结果文件的修改时间，确认修改并运行的是本课 `analysis.py`；必要时删除自己生成的旧结果后重跑，但不要删除原始数据。
- **报告数字和程序输出不一致：** 从报告中的一个关键数字反向找到结果文件、筛选范围、分子和分母；不要手工把报告改成“看起来合理”的数字。
- **不知道怎样开始写报告：** 先写五句：谁使用、要决定什么、数据覆盖谁、一个主要结果、一个不能支持的结论，再补方法和证据。
