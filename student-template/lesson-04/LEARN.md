# 知识准备 · 评价指标会改变我们看重的结果

## 从描述数据走向制定办法

评价制度把许多经历压缩成可比较信息。压缩会保留一部分内容，也会遗漏另一部分。统计方法能说明后果，但不能代替使用者决定重视普通体验、总负担、长等待还是业务覆盖。

## 必须理解

| 概念 | 含义 | 对评价制度的影响 |
|---|---|---|
| 集中趋势 | 数据通常处在哪个位置，常用均值与中位数描述 | 均值联系总量，中位数联系中间位置，两者目标不同 |
| 离散程度 | 同一中心内部记录差异多大 | IQR主要看中间跨度，标准差受远端记录影响更明显 |
| 尾部与分位数 | 少数较大或较小取值所处区域 | P90、超时比例有助于表达长等待，但需要数量和阈值定义 |
| 稳健性 | 少量极端变化下结果能否保持 | 防止个别记录支配结果，也可能弱化重要的极端体验 |
| 指标与评价目标 | 数字如何对应所重视的结果 | “易测量”不是选择指标的充分理由 |
| 规则敏感性 | 权重、阈值、范围改变时评价如何变 | 判断某个名次是普遍差异还是特定规则下的结果 |

不同单位的指标不能直接相加：分钟＋百分比没有自然量纲。若构造总分，需要定义缩放方法、好坏方向和权重，并说明某项好表现能否补偿另一项严重问题。多指标面板可以避免假装所有目标都存在统一交换比例。

## 微型例子

A的等待为4、5、5、6、40分钟；B为8、9、10、11、12分钟。你愿意把哪组称为“服务更好”？先说明目标。

A均值12、中位数5、IQR为1；B均值10、中位数10、IQR为2。A有20%超过15分钟，B为0%。A中部更快，但尾部更重，IQR小并不意味着没有长等待。只按中位数奖励A，与按总等待或超时比例奖励B，都能算对，却表达不同偏好。

若制度允许直接删除最慢记录，中心可能被激励把困难案例排除；若只看办结率，可能诱导拒接复杂业务。这些不是计算错误，而是指标使用后的行为后果。

## 回到项目

将评价目标写在规则前。每个指标说明含义、单位、分母、方向和局限。比较另一套有依据的制度，展示真实后果。对有底线意义的尾部体验，可以单列红线而不与其他指标完全相互抵消。

## 借助AI分析与进一步学习

复用前课均值、中位数和分位数代码。可请AI制作权重敏感性图、分层面板或达标图；不要求做网站。按需学习多准则决策，但不要把软件默认权重当客观事实。

向AI求助：“给我一个平均表现与最差群体体验冲突的例子，帮助我说明不同指标分别会奖励什么，不要直接替我选目标。”
