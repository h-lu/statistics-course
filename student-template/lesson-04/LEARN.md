# 知识准备 · 评价指标会改变我们看重的结果

## 必须理解：统计量不能代替使用目标

基础阅读建议7—10分钟。**集中趋势**用均值、中位数等描述位置；均值联系总等待负担，中位数联系中间位置。**离散程度**说明记录差异，IQR主要看中部，标准差对远端观测更敏感。**尾部**可用较高分位数和明确阈值的超时比例表达；IQR小并不保证没有长等待。

**稳健性**指少量极端变化是否大幅影响结果，不等于把极端经历当不存在。**指标与目标**要匹配：日常体验、总负担、尾部底线与业务覆盖不是同一目标。**规则敏感性**检查阈值、权重或范围改变后结果怎样变化。

## 完整例子：算对以后仍要取舍

另设两组已服务工单：X为4、5、5、6、40分钟，Y为8、9、10、11、12分钟。

| 指标 | X | Y |
|---|---:|---:|
| 均值（分钟） | 12 | 10 |
| 中位数（分钟） | 5 | 10 |
| IQR（分钟，线性插值） | 1 | 2 |
| 超过15分钟的比例 | 1/5=20% | 0/5=0% |

X中部更快，但尾部更重；只按中位数会遗漏这点。可以并列发布中位数与超时比例，也可以报告均值并单列尾部复核条件。若演示“超15分钟比例大于10%需复核”，10%必须标为另设使用者要求，而不是从五个值估出的客观标准。

删除40后，X均值变5、超时比例变0，但服务经历没有因此改善。规则可能诱发排除困难记录，这是需要监测的风险，不是本例已证明的行为。

## 分子、分母与阈值必须写进规则

“超过15分钟”使用严格大于号，等于15不计超时；改成“不少于15分钟”会改变规则。已服务超时比例用有效已服务工单为分母；放弃比例用目标登记工单为分母。

若定义“放弃或超过业务等待线”为不良经历，应对每张登记工单计算两条件的并集；符合两项也只计一次。换成已服务分母就是另一目标。零分母应标未定义，不能填0参加排名；数值精确相同保留并列，不能凭名称或显示时四舍五入强行分优劣。

业务分别用15/30分钟线，是不同目标要求，不等于把业务构成标准化。阈值、权重应由用途支持，不为让某中心第一而选择。

## 组合指标与防护

分钟和百分比没有天然可相加的量纲。构造总分需定义缩放、方向、权重及哪些差表现不能用另一项好表现抵消；多指标面板可避免假装所有目标都有固定交换比例。

防护应可执行，例如比较原始登记量和分析纳入量、保留排除理由、单列放弃和复杂业务覆盖，而不只写“防止造假”。描述性排序不能解释成工作人员的因果贡献。

## 回到项目

给出规则及实际结果，比较另一套有理由的制度，并分析一个与制度相关的敏感性问题。二者可使用同一组有实质内容的比较，不必重复做表。进一步完善是根据后果修改规则、适用条件或防护，不是加模型。可让AI解释两种规则遗漏的信息，无需提交对话。

## 按需核算：位置、尾部与删除的后果

```python
# learning-example
import json
import statistics as st
x, y = [4, 5, 5, 6, 40], [8, 9, 10, 11, 12]
def profile(values):
    ordered = sorted(values)
    return {"mean": st.mean(values), "median": st.median(values),
            "iqr": ordered[3] - ordered[1],
            "over15": sum(v > 15 for v in values) / len(values)}
# 这里IQR的下标仅适用于本例五个值的线性插值位置。
result = {"x": profile(x), "y": profile(y),
          "x_mean_after_exclusion": st.mean(x[:-1]),
          "x_over15_after_exclusion": sum(v > 15 for v in x[:-1]) / len(x[:-1])}
print(json.dumps(result, ensure_ascii=False, allow_nan=False))
```
