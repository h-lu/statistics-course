# 第4课 · 设计服务质量评价办法

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

第一次使用这些资料时，可先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。

## 项目背景

服务委员会准备公布评价并安排改进。均值会受到长等待的影响，但只报均值仍看不出有多少次长等待、最长有多久；只看中位数也可能遗漏这些情况。你需要为明确的使用者设计一套可以照着计算的评价办法。

## 可用数据

使用第一期 `data/service/tickets.csv`、窗口与业务类型表，可按问题补充满意度和排班资料。先读[数据说明](../data/service/README.md)及[知识准备](LEARN.md)。

常规业务15分钟、复杂业务30分钟是情境中的参考等待时间，不是统计学规定的标准。阈值就是判断是否达到某个条件的数值界限。采用其他阈值或自定管理门槛时，说明所服务的目标，将未给定的要求标为假设，并比较其他有理由的选择；具体例子见知识准备。

## 分析任务

1. **说明评价目标。** 评价给谁看，用于什么决定？可以分别报告多个指标，也可以发布等级或有条件的排名，不必合成总分。
2. **定义指标并计算。** 同时描述日常表现与较长等待。说明各指标的含义、单位、数值越大是否越好、分子、分母、缺失处理，以及阈值是否包含等号。保留放弃数量、业务构成和记录数。
3. **比较另一套合理办法。** 在说明清楚的数据范围内计算两套结果，解释哪些评价改变及原因。至少研究一项与长等待、业务构成或指标权重有关的敏感性问题。一次充分的比较可以同时用于评价办法比较和敏感性分析，不必重复做表。
4. **提出防范措施。** 分析办法可能鼓励哪些不合理行为，例如排除复杂业务或忽略放弃者。提出可以执行、可以检查的防范措施，以及何时需要调整或暂停使用。把可能的风险与已经观察到的行为分开。

## 指标怎样解释

若合成总分，应说明不同单位怎样转换、权重怎样确定，以及严重的长等待是否可以被其他好表现抵消。分钟与百分比不能未经处理直接相加。

“已服务工单中的超时比例”和“全部登记工单中的放弃比例”有不同分母。若把“放弃或超过业务参考时间”作为一个指标，同一工单符合两项也只计一次。分母为0的比例不能填0参加排名；数值相同时可以并列。

采用各业务不同等待阈值，不等于按相同业务构成进行直接标准化。删除最慢记录后指标改善，也不证明服务改善。中心排序不能直接解释为工作人员造成的效果。

## 需要提交什么

提交一页评价规则、按规则得到的结果、替代办法和敏感性分析结果，以及风险与防范措施。报告要能让别人理解并重新计算，不以模型数量或页面美观作为重点。

证据不足时可以不发布单一排名，但仍要完成实际比较并解释原因。

## 课堂安排

0—12分钟阅读知识并讨论目标；12—24分钟提出规则；24—53分钟计算和比较；53—68分钟分析风险并完善办法；68—75分钟检查提交；75—90分钟知识自查。

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`statistics` 列出各中心已服务工单的数量、均值、中位数和最大值；`maximum` 表示最大等待时间。它没有规定评价办法，也没有计算放弃比例或替代办法。最大值不能单独说明有多少工单等待很长。

先阅读输出中与你的问题有关的内容，再按上面的分析任务扩展程序。自己的计算结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。若使用完整课程资料库，先进入 `student-template/`。

```bash
python scripts/course.py start 04
python scripts/course.py run 04
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据本课问题修改或替换程序，将结果和图表保存到本课 `artifacts/` 文件夹，并在 `report.md` 中解释和引用。原始数据保持不变；程序使用的新软件包写入 `requirements.txt`。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起；更换程序时要相应更新命令。然后重新运行并检查：

```bash
python scripts/course.py run 04
python scripts/course.py check 04
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送到个人仓库，创建本课最终标签 `v2-l04-final`，再查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，但不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖，修改时保留原版本。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令、结果文件设置和修订办法见上述操作说明，评分见[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第4课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
