# 第4课 · 设计服务质量评价办法

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

第一次使用这些资料时，可先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。

## 项目背景

服务委员会准备公布评价并安排改进。均值会受到长等待影响，却不能单独告诉我们有多少次长等待；只看中位数也可能遗漏少数等待很长的工单。你需要为明确的使用者设计一套可以计算、可以据此作判断的评价办法。

本课从“描述数据”进入“按目标评价”。列出几个统计量还不等于完整办法：还需说明如何解释这些数值，什么情况下应调查、调整或暂缓使用。可以不发布单一排名。

## 可用数据与阅读顺序

先读[知识准备](LEARN.md)，尝试其中的小例子，再核对[服务数据说明](../data/service/README.md)。正式项目以第一期为范围，不要混入第三课的第二期原始导出。

| 文件（学生仓库根目录下） | 本课用途 |
|---|---|
| `data/service/tickets.csv` | 2026年3月2日至4月10日的3,600张已登记工单，每工单一行 |
| `data/service/windows.csv` | 根据窗口编号查所属中心 |
| `data/service/business_types.csv` | 核对业务类型及其参考等待时间 |

按所选问题可以补充满意度或排班资料，不是必用全部表。它们覆盖两期，使用时必须限定到相同日期或工单范围。本课不要求先完成第8课的全部多表整合。

常规业务15分钟、复杂业务30分钟是情境中的参考等待时间，不是统计学标准。采用其他时间阈值或整组管理门槛时，说明目标，将未给定要求标为假设，并比较其他有理由的选择。

## 分析任务

1. **说明评价目标。** 评价给谁看，用于什么决定？可以分别报告多个指标，也可以发布等级或有条件的排名，不必合成总分。
2. **定义指标并计算。** 同时描述日常表现与较长等待。说明指标含义、单位、好坏方向、分子与分母、缺失处理，以及阈值是否包含等号。保留放弃数量及比例、业务构成和记录数。统计对象是工单，不是去重后的人数。
3. **比较另一套合理办法。** 在说明清楚的数据范围内实际计算两套结果，解释哪些评价改变及原因。至少研究一项与长等待、业务构成或指标权重有关的敏感性问题。一次充分的比较可以同时用于评价办法比较和敏感性分析，不必重复做表，也不要求一定出现排名反转。
4. **提出使用建议与防范措施。** 选择办法并说明依据；分析可能出现的排除复杂业务、忽略放弃者等风险，提出可执行、可检查的防范措施，以及何时应调整或暂停使用。区分风险与已经观察到的行为。

## 计算和解释时注意什么

已服务等待只用明确未放弃且等待有效的工单。放弃比例采用所声明范围内放弃状态已知的登记工单；第一期这些状态均已知。不要把两项指标的分母混在一起。

若定义“放弃或超过业务参考时间”，同一工单符合两项也只计一次。比例需明确哪些记录可判断；未知不等于事件没有发生。零分母的比例为不能计算，不是0%，不参加排名；精确相同可并列，不能通过显示时的四舍五入暗中改变判断。

若合成总分，说明尺度转换、权重、好坏方向以及是否允许一项好表现抵消另一项严重问题。分钟与百分比不能未经处理直接相加。未触发某项调查条件，不等于服务全面合格。

按业务采用不同等待阈值，没有把各中心的业务构成变成相同；不能将它称为已经完成直接标准化。删除最慢记录使数字变好，不证明服务改善；中心排序也不能直接解释为工作人员造成的效果。

资料没有未登记的申请与拒接记录。可以提出下一期补记方案，但不能假造拒接率，也不能声称已经排除了选择容易业务的可能。

## 需要提交什么

提交一页评价规则摘要、按规则得到的结果、替代办法与敏感性分析结果，以及使用建议、风险和防范措施。详细分析和表格可以放在报告正文或结果文件，不要求整份报告只能一页。

证据不足时可以不发布单一排名，但仍要完成实际比较并解释原因。第4课计入模块一的完成评价；是否评价为代表作品由模块末选择决定，评分见[成果与评分](../docs/ASSESSMENT.md)。

## 课堂安排

0—12分钟阅读知识并讨论目标；12—24分钟提出规则；24—53分钟计算和比较；53—68分钟分析风险并完善办法；68—75分钟检查提交；75—90分钟知识自查。时间为建议安排，不是已测得的完成时间。

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`statistics` 列出各中心已服务工单数 `served_n`、等待均值 `mean`、中位数 `median` 和最大值 `maximum`，后三项单位均为分钟。它没有制定评价规则，也没有计算放弃比例、业务构成或替代办法。最大值不能单独说明多少张工单等待很长。

空组的统计量显示为 `null`，不是0分钟。根据本课任务扩展程序，结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。使用完整课程资料库时，先进入 `student-template/`。

```bash
python scripts/course.py start 04
python scripts/course.py run 04
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据问题修改或替换程序，将结果保存到本课 `artifacts/`，并在 `report.md` 中解释和引用。原始数据保持不变；使用的新软件包写入 `requirements.txt`。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起，更换程序时也要更新命令。重新运行并检查：

```bash
python scripts/course.py run 04
python scripts/course.py check 04
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送，创建最终标签 `v2-l04-final`，查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令与修订办法见上述操作说明。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第4课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
