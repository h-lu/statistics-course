# 第4课：怎样评价服务质量

本课使用教学合成数据。数据中的中心、工单和来访者都是虚构的，分析结果不能写成现实机构的事实。你可以让 AI 帮助读表、计算和写程序，但需要核对每个数字是怎样算出来的。

第一次使用这个仓库时，可以先看[阅读与运行指南](../docs/READING_GUIDE.md)。如果不知道从哪里开始，先按[支持路线](SUPPORT.md)操作；遇到不懂的统计术语，再查看[知识准备](LEARN.md)。

## 先看两个具体例子

第一个例子有两个窗口，每个窗口都有5张已服务工单：

- 甲窗口等待时间是2、2、2、2、22分钟，算术平均数是6分钟；
- 乙窗口5张工单都等待7分钟，算术平均数是7分钟。

甲窗口的平均等待比乙窗口短，但甲窗口仍有一张等待22分钟的工单。因此，“平均等待较短”不等于“没有特别长的等待”。评价服务时，通常要同时看一般工单的等待和少数长等待。

第二个例子只有一张工单，恰好等待15分钟：

- 规则写“**超过15分钟**”时，这张工单不算超时；
- 规则写“**不少于15分钟**”时，这张工单算超时。

这里的15分钟叫作**阈值**，也就是用来划分是否超时的界限。有没有等号，会直接改变超时工单的数量。

## 项目背景

服务委员会想知道哪些中心需要优先调查和改进。只公布一个平均数可能漏掉特别长的等待，只公布一个排名也不能说明问题出在哪里。

你的任务是设计一套服务质量评价办法。它需要说明：给谁看、计算哪些统计指标、怎样判断需要调查，以及这套办法可能遗漏什么。你可以分别公布多个指标，不要求把所有信息合成一个总分，也不要求给中心排出唯一名次。

## 本课使用哪些数据

正式分析只使用第一期数据：

- `data/service/tickets.csv`：一行是一张登记工单，包含等待时间、业务类别和是否放弃排队；
- `data/service/windows.csv`：把窗口编号对应到A、B、C三个中心；
- `data/service/business_types.csv`：说明业务类别以及情境给出的参考等待时间。

常规业务的参考时间是15分钟，复杂业务是30分钟。这两个数是本教学情境给出的管理规则，不是统计学规定的通用合格线。若自行选择其他阈值，要说明选择理由。

## 需要完成什么

1. **说明用途。** 写清谁会阅读评价，以及他们要据此决定调查、改进、试运行还是暂缓发布。
2. **设计主要办法。** 至少同时描述一般等待和长等待。例如，可以使用中位数描述中间位置，用第90百分位数或超时比例描述较长等待。
3. **写清计算范围。** 对每个指标说明使用哪些工单、分子和分母是什么、单位是什么，以及数值越大通常表示更好还是更差。
4. **实际计算结果。** 按中心报告指标，同时保留登记数、已服务数、放弃数量和业务构成。
5. **比较另一套合理办法。** 例如，把统一的15分钟阈值改为常规业务15分钟、复杂业务30分钟，再观察结果和建议是否改变。这种有理由地改变规则并比较结果的做法叫作**敏感性分析**。
6. **提出建议。** 说明哪些中心或问题需要调查、还缺少什么信息，以及什么情况下应修改或暂停使用这套评价办法。

## 难度分层

下面三层按顺序使用。基础练习帮助你熟悉数据和概念，不能代替标准任务；标准任务是本课的默认要求；扩展练习在标准任务完成后任选一项。

### 基础练习：先把一个指标说清楚

使用起始概览和三张小练习工单，完成以下三件事：

1. 说明 `mean`、`median` 和 `maximum` 分别回答什么问题；
2. 用等待 `2、5、10` 分钟的三张工单，手算均值、中位数，以及“严格超过5分钟”和“不少于5分钟”的比例；
3. 为一个中心写出一条完整规则：指标是什么、分母是谁、数值多大时采取什么行动。

基础练习的结果可以写在报告开头，作为标准任务的准备。

### 标准任务：完成一套可执行评价

按上面的六项要求完成正式数据分析：明确使用者，计算一般等待和长等待，保留放弃数量和业务构成，比较另一套规则，完成敏感性分析，并提出有条件的建议。

### 扩展练习：选择一个问题深入

完成标准任务后任选一项：

- **规则稳定性：**把调查门槛分别设为8%、10%、12%，列出每种门槛下会调查哪些中心，说明门槛是管理选择，不是数据自动推出的标准；
- **业务构成：**分别计算常规和复杂业务的等待或超时比例，再比较统一阈值与按业务阈值的差异，说明业务构成改变了什么；
- **综合指标：**设计一个总分，写清分钟如何换成无量纲分数、各项权重和是否允许相互抵消，并同时保留原始指标；
- **风险防范：**列出评价办法可能鼓励的行为，说明现有数据能检查什么、还需要记录什么。

扩展练习不要求使用更复杂的模型；重点是说明改变了什么、为什么改变，以及结果能支持到什么范围。

计算等待时间时，只使用 `abandoned=0` 且等待时间有效的已服务工单。计算放弃比例时，分母是放弃状态已知的全部登记工单。这两个分母回答的问题不同，不能混在一起。若某个分母为0，应写“不能计算”，不能写成0%。

使用不同业务阈值并没有消除各中心业务构成的差异。中心之间的结果差异也只能描述这批记录，不能直接说明差异是工作人员造成的。

## 运行起始程序

以下命令都在学生仓库根目录运行，也就是能看到 `lesson-04/`、`data/` 和 `scripts/` 的目录。

```bash
python3 scripts/course.py start 04
python3 scripts/course.py run 04
```

如果你的系统使用 `python` 作为 Python 3 命令，把命令中的 `python3` 换成 `python`。

打开 `lesson-04/artifacts/starting_overview.json`。起始程序只计算各中心的已服务工单数、等待均值、中位数和最大值，帮助你确认数据已经读入；它还没有计算超时比例、放弃比例，也没有替你设计评价办法。

完成分析后，把支持结论的结果文件保存到 `lesson-04/artifacts/`，填写 `lesson-04/report.md`，并在 `submission.json` 中：

1. 把 `status` 改为 `complete`；
2. 在 `artifacts` 中列出实际生成的结果文件。

然后运行：

```bash
python3 scripts/course.py run 04
python3 scripts/course.py check 04
```

`check` 只检查报告和所列结果文件是否存在，不会判断统计结论是否正确。检查通过后，按[课程工作流](../docs/WORKFLOW.md)提交并创建 `v2-l04-final` 标签，最后完成第4课知识自查。
