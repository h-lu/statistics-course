# 第4课：怎样评价服务质量

服务委员会要决定哪些中心或问题需要优先调查。一个平均数可能漏掉少数长等待，一个总排名也可能掩盖业务构成和放弃。请设计一套适合明确使用者的评价办法，并用**另一套合理办法**检验其取舍。

本课使用**教学合成数据**，中心、工单和来访者均为虚构。可全程用AI协助分析；你负责依据、单位、分母和结论。指标、阈值、发布形式及建议由你选择，不要求总分、唯一名次或结论反转。

## 情境和资源

正式项目使用第一期 `data/service/tickets.csv`：2026-03-02至04-10的3600张登记工单。`windows.csv`将窗口对应到A/B/C中心；`business_types.csv`给业务名称和常规15、复杂30分钟的参考等待。参考时间是教学情境的管理规则，不是统计学通用标准。

[数据说明](../data/service/README.md)解释字段和覆盖范围；[LEARN](LEARN.md)有集中趋势、离散、尾部、尺度和规则的小例子；[SUPPORT](SUPPORT.md)是遇阻后可选的分层提示。你可以自行组织分析，复用前几课代码，不需要沿统一操作路线。

## 目标产物

形成一份服务评价报告或规则摘要及其计算证据。另一位分析者应能从原表重建结果，委员会应能看懂规则用于什么决定、哪些信息尚未测到。规则摘要可以简短，证据不必强塞一页；成果形式由你选择。

本课标准任务需要回答：

- 明确使用者与实际决定。
- 设计主要办法，同时说明一般等待和长等待。
- 每项指标说明记录范围、分子分母或计算方法、单位和好坏方向。
- 按中心给实际结果，保留登记数、已服务数、放弃数量和业务构成。
- 实际比较另一套有理由的办法，解释结果和建议怎样受选择影响。一项充分比较可同时完成替代办法与敏感性分析。
- 提出有条件的建议、局限、防范及何时修改或暂停规则。

## 至少两类重要决策

1. **评价目标和指标。**你更重视一般等待、少数长等待、放弃，还是把不同目标并列报告？为什么这些信息适合使用者？选择要反映目标冲突，不只因为某项指标有利于某中心。
2. **从数字到行动的规则。**你采用怎样的时间线、分母、调查条件或发布方式？另一办法改变什么，理由是什么？可以比较统一与按业务时间线，也可提出其他合理指标或条件。

你可以分别公布指标、调查名单、等级或总分。总分需要说明尺度转换、权重、能否相互抵消，同时保留原指标与严重问题门槛。不使用总分同样可完成高质量成果。

## 约束与证据边界

已服务等待只用 `abandoned=0` 且等待有效的工单；放弃比例用放弃状态已知的全部登记工单。放弃者的等待是离开前时间，不是获得服务等待。分母为零时写不能计算。阈值要说明是否包含等号，百分比差说明单位是百分点还是相对变化。

分位数方法应注明；基础函数使用排序位置 `(n−1)p` 的线性插值。按业务给不同时间线没有消除业务构成差异，中心差异也不自动证明人员造成的效果。未触发一项调查条件不等于全面合格。

现有表没有未登记申请和拒接信息，不能凭空计算拒接率。你可以指出规则可能鼓励什么行为，并提出可记录的核查方案；潜在风险不是已发生事实。原始CSV保持不变，报告主要数字应可追溯到计算证据。

## 三层选择

**基础练习（可信起点）：**需要概念帮助时看LEARN另设的短等待与长尾例子，或自行选一中心的一项指标核对分母。获得可信起点不等于完成本课。

**标准任务（本课应完成）：**完成上面六项。分析路线、方法和表达方式自主，两套实际结果与行动取舍不可省略；不把标准比较移为选做。

**提高与拓展（提前完成后）：**自选一个会影响使用建议的问题深入。可以研究行动门槛边界、业务构成、极端值信息、总分补偿、独立复算或选择性登记的监测，也可自拟。记录新增结果是否让原建议改变或增加条件，不靠堆图、堆模型或重复运行。

## 工具和提交

在能看到 `lesson-04/`、`data/`、`scripts/` 的学生仓库根，可运行：

```bash
python3 scripts/course.py start 04
python3 scripts/course.py run 04
```

默认 `analysis.py` 只生成 `lesson-04/artifacts/starting_overview.json`，计算各中心已服务等待数量、均值、中位数和最大值。它不选择评价办法、不算完整比较、不填写结论。通用 `quantile` 函数可选用或改写；标准库足够，不需要新增安装。

修改或自行写程序，在 `artifacts/` 保存支持报告的证据；完成后在 `submission.json`填实际路径、`complete`和能重建全部证据的 `run`。重跑最终程序，再用 `python3 scripts/course.py check 04` 检查状态和文件；它不评判统计结论。按[工作流](../docs/WORKFLOW.md)提交，不覆盖已有最终标签。最后完成当课[课堂选择题](https://hblu.top/stat-check/)并阅读反馈；LEARN线下题供自主学习。
