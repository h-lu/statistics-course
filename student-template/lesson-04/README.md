# 第4课：设计服务质量评价办法

本课使用教学合成数据。你可以使用 AI 帮助计算和写作，但必须自己核对指标、分母、单位、阈值和结论。

如果不知道从哪里开始，先读[支持路线](SUPPORT.md)，再读[知识准备](LEARN.md)。

## 先做一个小判断

一组工单平均等待较短，是否一定很少有长等待？“超过15分钟”和“不少于15分钟”在恰好15分钟时是否相同？先写下答案。

## 项目背景

服务委员会准备公布评价并安排改进。均值可能被长等待影响，中位数可能隐藏少数特别长的等待。你要为明确的使用者设计一套可计算、可解释、能支持行动的评价办法，不必发布单一排名。

## 可用数据

正式项目以第一期为范围，主要使用 `data/service/tickets.csv`、`windows.csv` 和 `business_types.csv`；可按问题补充满意度或排班，但必须限定相同日期或工单范围。常规业务15分钟、复杂业务30分钟是本情境的参考等待时间，不是统计学标准。其他门槛要说明是管理假设。

## 分析任务

1. 说明评价给谁看、用于什么决定；
2. 定义并计算能反映通常表现和长等待的指标，写清分子、分母、单位、好坏方向、缺失和阈值等号；
3. 实际比较另一套合理办法，并完成一项敏感性分析；
4. 提出发布、调查、改进或暂缓使用的建议，说明风险和防范措施。

已服务等待只用明确未放弃且等待有效的工单；放弃比例使用放弃状态已知的登记工单。不同分母不能混用。零分母表示不能计算，不是0%。按业务使用不同阈值不等于完成直接标准化，也不能把中心排序解释为工作人员造成的效果。

## 运行和提交

```bash
python scripts/course.py start 04
python scripts/course.py run 04
```

打开 `lesson-04/artifacts/starting_overview.json`，它只给出中心、已服务数、均值、中位数和最大值，未替你完成评价办法。保存结果到 `artifacts/`，填写报告和 `submission.json`，再运行：

```bash
python scripts/course.py run 04
python scripts/course.py check 04
```

按工作流提交并创建 `v2-l04-final` 标签，最后完成第4课知识自查。
