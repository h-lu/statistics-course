# 第4课支持路线：从几个数字设计一套评价办法

## 你要留下的最小成果

一页评价规则、按规则生成的结果、另一套方案的比较、风险和使用建议。建议必须能回答“何时调查、何时试运行、何时暂缓”。

## 先懂概念

- **集中趋势**：数据大致位于哪里，常用均值和中位数。
- **离散程度和右尾**：记录相差多大，以及少数特别长等待的一端。
- **指标**：为某个判断定义的可计算量，必须有分子、分母、单位和方向。
- **阈值**：触发行动的界限；“超过”不含等号，“不少于”含等号。
- **敏感性分析**：改变一个有理由的规则，观察评价和建议是否变化。

评价办法的原理是先明确决定，再选指标；数字变好不等于服务改善，指标也不自动证明因果。

## 入门跟做

### 1. 先写使用者和决定

在 `lesson-04/report.md` 写谁看报告、要决定调查/改进/试运行中的什么。选择两项指标，例如中位数与P90、超时比例与放弃比例，并写各自分母。

**反思**：只报均值会隐藏什么？放弃者不在已服务分母中时，放弃比例应怎样单列？

### 2. 运行起点

```bash
python3 scripts/course.py start 04
python3 scripts/course.py run 04
```

如果你的系统使用 `python` 作为 Python 3 命令，把上面两行中的 `python3` 换成 `python`。

查看 `artifacts/starting_overview.json`，指出哪个字段描述位置、哪个描述极端值、每个单位是什么。回到数据说明核对放弃状态和业务参考时间。

**做对信号**：你能解释最大值不是“大多数人的等待”，均值和中位数也不是同一个指标。**反思**：如果最大值改变，是否一定代表整体服务改变？

### 3. 手算阈值

三张已服务工单等待2、4、10分钟，均值5.33、中位数4。阈值为5时，“超过5”比例为1/3；“不少于5”比例为2/3。一个等号就可能改变行动数量。

**反思**：如果两项比例都是50%，分母也一定相同吗？读者能否按你的说明复算？

### 4. 设计并比较规则

先写主办法：指标、分母、方向、阈值、缺失处理、触发的行动。再实际比较一种替代办法：改变阈值、中心统计量、业务分层或权重。保留放弃数量和业务构成，不为了排名删除复杂业务。

把 `submission.json` 的 `status` 改为 `complete`，在 `artifacts` 列出实际生成的结果文件，再运行 `python3 scripts/course.py check 04`。如果你的系统使用 `python` 作为 Python 3 命令，将命令中的 `python3` 换成 `python`。报告列出两套结果、变化原因和建议。如果排名不变，也说明为什么；如果改变，说明是指标、分母、构成还是阈值造成的。

## 标准与提高

标准完成要同时报告通常等待和长等待，并完成替代方案和敏感性分析。提高可以研究综合指标的尺度与权重、分业务直接比较，或写一页面向管理者的发布条件；不以单一排名为目标。

## 卡住和提交前检查

先确认使用者和决定，再写指标；数字不一致查已服务条件、放弃状态、阈值等号和分母。提交前确认两套办法均有实际结果、原始数据未改写、`submission.json` 和 `check 04` 正确。
