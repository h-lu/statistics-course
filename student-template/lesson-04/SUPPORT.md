# 第4课支持路线：一步一步完成服务质量评价

这份文件适合不知道从哪里开始的同学。每一步都说明要做什么、为什么做，以及看到什么才算完成。

## 最少需要完成哪些成果

完成本课时，你应该留下：

1. `report.md`：说明评价对象、计算规则、两套办法的结果和使用建议；
2. `artifacts/` 中至少一个结果文件：保存支持报告数字的表格或JSON；
3. `submission.json`：状态为 `complete`，并列出结果文件路径。

报告不需要给中心强行排名，但必须回答：一般工单等待怎样、有没有较长等待、多少工单放弃，以及什么情况需要调查。

## 先认识五个术语

| 统计术语 | 通俗解释 | 本课中的例子 |
|---|---|---|
| 算术平均数（简称均值） | 把等待总分钟数平均分给每张工单 | 2、5、10分钟的均值是17÷3≈5.67分钟 |
| 中位数 | 把数值排序后位于中间的数 | 2、5、10分钟的中位数是5分钟 |
| 第90百分位数（P90） | 大约90%的记录不超过这个数，用来观察较长等待 | P90较大，说明等待较长的一部分工单值得关注 |
| 阈值 | 判断是否触发某项规则的界限 | 等待严格超过15分钟算超时 |
| 敏感性分析 | 改变一项有理由的规则，再看结果是否改变 | 比较统一15分钟与按业务采用15/30分钟 |

每个指标还要写清**分母**。分母就是“这次计算总共以哪些工单为对象”。例如，已服务工单的平均等待以已服务工单为对象；放弃比例以放弃状态已知的登记工单为对象。

## 三个层次怎么选

- **基础练习：**先完成三张工单的手算和一个中心的一条规则。你要能解释数字，不只是把程序跑出结果。
- **标准任务：**完成正式数据、两套评价办法、敏感性分析和有条件的建议。这是本课默认的完成标准。
- **扩展练习：**在标准任务后任选一个方向深入。可以研究不同调查门槛、不同业务构成、综合指标的权重，或评价规则可能造成的行为风险。

如果你刚开始学习，先做基础练习；做完后仍要继续标准任务。扩展练习不通过增加图表数量或代码长度来提高难度，而是要求你解释新的选择及其影响。

## 入门跟做

### 第1步：先看数据代表什么

打开 `data/service/README.md`，再查看 `tickets.csv`、`windows.csv` 和 `business_types.csv` 的表头与前几行。

你需要确认：`tickets.csv` 一行是一张登记工单；`abandoned=0` 表示没有放弃并获得服务，`abandoned=1` 表示在等待中离开；放弃工单的等待时间是离开前的等待，不能解释为获得服务所需时间。

**做对的信号：**你能用一句话解释 `wait_minutes` 和 `abandoned`，也知道窗口编号要通过 `windows.csv` 才能对应到中心。

**想一想：**为什么计算已服务等待时不能把放弃工单当成已经获得服务？

### 第2步：运行起始程序

回到学生仓库根目录，也就是能看到 `lesson-04/`、`data/` 和 `scripts/` 的目录，运行：

```bash
python3 scripts/course.py start 04
python3 scripts/course.py run 04
```

如果系统使用 `python` 作为 Python 3 命令，就把 `python3` 换成 `python`。

打开 `lesson-04/artifacts/starting_overview.json`。其中：

- `center` 是中心编号；
- `served_n` 是纳入等待统计的已服务工单数；
- `mean` 是等待时间的算术平均数，单位为分钟；
- `median` 是等待时间的中位数，单位为分钟；
- `maximum` 是这组记录中最长的等待，单位为分钟。

**做对的信号：**文件中出现A、B、C三个中心，而且你能解释每个字段。

**想一想：**最大值只来自一张工单。它能提醒你存在长等待，但为什么不能代表大多数工单？

### 第3步：用三张工单检查阈值

假设三张已服务工单分别等待2、5、10分钟：

- 均值为 `(2＋5＋10)÷3≈5.67` 分钟；
- 中位数为5分钟；
- 若“严格超过5分钟”算超时，只有10分钟这一张超时，比例是 `1÷3`；
- 若“不少于5分钟”算超时，5分钟和10分钟两张都超时，比例是 `2÷3`。

这说明阈值是否包含等号，会改变超时数量和比例。

**做对的信号：**你能分别写出两条规则的分子、分母和结果。

### 第4步：先把主要办法写成完整句子

可以使用下面的句式，但要换成自己的选择：

> 对每个中心，我用中位数描述一般等待，用第90百分位数和超时比例描述较长等待。超时定义为已服务工单等待严格超过业务参考时间。超时比例的分母是等待有效的已服务工单。若超时比例严格大于10%，建议先调查长等待原因。10%是本项目采用的管理假设。

这只是结构示例，不是唯一正确规则。你可以选择其他指标或门槛，但要说明它们支持什么决定。

**想一想：**未触发“调查长等待”是否等于所有服务都合格？还有哪些指标没有被这条规则覆盖？

### 第5步：让程序完成正式计算

起始程序只提供均值、中位数和最大值。你可以自己修改 `analysis.py`，也可以让AI帮助增加：

- 第90百分位数；
- 超时工单数和超时比例；
- 放弃数量和放弃比例；
- 常规业务与复杂业务的工单数量。

要求AI同时输出每个比例的分子和分母，而不是只给一个百分比。运行后随机挑一个中心，回到原始记录核对至少一项数量。

**做对的信号：**结果文件能够重新生成，且报告中的主要数字能在结果文件中找到。

### 第6步：比较另一套办法

改变一个有实际理由的条件，例如：

- 办法甲：所有业务都以严格超过15分钟算超时；
- 办法乙：常规业务严格超过15分钟、复杂业务严格超过30分钟算超时。

分别计算两套办法。说明哪些结果或调查建议改变了，变化来自阈值、分母还是业务构成。如果结果没有改变，也要说明你实际检查了什么。

这一步就是敏感性分析：它只能说明结论对已经检查的规则变化是否敏感，不能保证其他所有规则下都一样。

### 第7步：完成报告并检查提交

在 `report.md` 中写入实际结果和建议。然后编辑 `submission.json`：

- 把 `status` 改为 `complete`；
- 在 `artifacts` 中列出结果文件，例如 `lesson-04/artifacts/center_metrics.csv`。

运行：

```bash
python3 scripts/course.py run 04
python3 scripts/course.py check 04
```

## 想进一步完成得更好

完成上述步骤后，可以选择一个方向深入：

- 研究不同百分位数或调查门槛是否改变建议；
- 分别展示不同业务类别，避免总体结果掩盖业务构成差异；
- 讨论规则是否可能鼓励少接困难业务，并说明还需记录哪些申请、接单和拒单信息；
- 若设计综合得分，解释单位转换、权重，以及一项好结果是否允许抵消另一项严重问题。

提高不等于增加更多图或更复杂的模型，重点是让评价规则更容易复核、更适合实际决定。

## 卡住时依次检查

1. 当前目录是否为学生仓库根目录；
2. Python 3命令是 `python3` 还是 `python`；
3. `tickets.csv` 中是否只把 `abandoned=0` 的工单用于已服务等待；
4. 超时规则是否包含等号；
5. 百分比的分子和分母是否来自同一组工单；
6. 报告数字能否在 `artifacts/` 的结果文件中找到；
7. `submission.json` 是否已标记 `complete` 并列出真实文件路径。
