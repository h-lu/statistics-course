# 第04课支持路线：第4课 · 设计服务质量评价办法

这份文件给还不知道从哪里开始的同学使用。它不是另一份作业，也不替你决定统计结论；请按“入门跟做”完成一条最小路线，再根据时间选择标准或提高任务。所有数字都要从本课程序和数据重新运行得到，不能把示例数字当成自己的结果。

## 先知道今天要交出什么

完成后，你至少应有：

- 一个用一句话写出的统计问题（谁要用、看哪些记录、要作什么决定）；
- 一次成功运行和一份能重新生成结果的程序；
- 一张表、一个图或一组能支持结论的计算结果；
- 一段说明分母、单位、数据范围、局限和下一步行动的报告。

本课任务可以先按下面顺序拆开：

1. **说明评价目标。** 评价给谁看，用于什么决定？可以分别报告多个指标，也可以发布等级或有条件的排名，不必合成总分。
2. **定义指标并计算。** 同时描述日常表现与较长等待。说明指标含义、单位、好坏方向、分子与分母、缺失处理，以及阈值是否包含等号。保留放弃数量及比例、业务构成和记录数。统计对象是工单，不是去重后的人数。
3. **比较另一套合理办法。** 在说明清楚的数据范围内实际计算两套结果，解释哪些评价改变及原因。至少研究一项与长等待、业务构成或指标权重有关的敏感性问题。一次充分的比较可以同时用于评价办法比较和敏感性分析，不必重复做表，也不要求一定出现排名反转。
4. **提出使用建议与防范措施。** 选择办法并说明依据；分析可能出现的排除复杂业务、忽略放弃者等风险，提出可执行、可检查的防范措施，以及何时应调整或暂停使用。区分风险与已经观察到的行为。

## 先懂四个概念，再开始操作

- **集中趋势**：描述数据大致位于哪里，常用均值和中位数。均值使用全部数值，长等待可能对它影响较大；中位数更关注排序后的中间位置。
- **离散程度与尾部**：离散程度说明记录相差多大；右尾表示少数等待特别长的一端。只报一个中心数值，可能把长等待藏起来。
- **指标与分母**：指标是为某个判断定义的可计算量。每个比例要写分子、分母、单位和纳入条件；不同指标可以有不同分母。
- **阈值与敏感性**：阈值是作出提醒或行动判断的界限；改变阈值后重新计算，才能知道评价办法是否稳健。

本课的基本原理是“评价办法服务于决定”：先说谁要根据结果做什么，再选择能反映该问题的指标，不能因为某个数字看起来好看就删除长等待或强行合成总分。

## 入门跟做：先让第一个结果出现

### 1. 写下问题和预计

打开 `lesson-04/report.md`，先不要追求完整，写三句话：

1. “我的使用者是……，他/她需要决定……”；
2. “我把一行记录看作……，分析范围是……”；
3. “我预计……，因为……；最可能改变这个预计的信息是……”。

这里的“预计”是运行前的可检验想法，不是最后结论。不会选问题时，直接使用 README 项目背景中的第一个问题，把范围缩小到一个数据表、一个时期和一个指标。

### 2. 在仓库根目录运行示例

仓库根目录是能同时看到 `scripts` 和 `lesson-04` 的目录。不要在 Python 的 `>>>` 后输入下面命令。电脑只有 `python3` 时，把 `python` 换成 `python3`。

```bash
python scripts/course.py start 04
python scripts/course.py run 04
```

运行成功后，打开 `lesson-04/artifacts/starting_overview.json` 或终端提示的结果文件。JSON 是按字段名保存的文本，不必一开始读懂所有字段；先找到与自己问题对应的一个数字，记下它的记录数、单位和分母。

### 3. 手算并核对一条

从输出中挑一条记录或一个小组，写出“原始值 → 处理 → 结果”的三步。至少核对一个加总、平均、比例、排序或分组数量。若结果是比例，明确写出分子和分母；若结果是平均数，写出参与计算的记录数；若是时间或金额，写单位。核对不一致时先检查路径、字段名、筛选条件和小数显示，不要手改结果文件。

### 4. 完成一个最小可交版本

根据 README 的任务，把 `analysis.py` 扩展到能回答自己的问题，把表、图或 JSON 结果保存到 `lesson-04/artifacts/`，再在报告中引用文件名。报告先写“观察到的事实”，然后分别写“可能解释”和“还不能证明什么”。

```bash
python scripts/course.py run 04
python scripts/course.py check 04
```

只有在报告、结果文件和 `submission.json` 都准备好后，才把 `status` 改为 `complete`。


## 入门跟做时怎样反思

每完成一步，先停下来回答一句：

- 写评价目标后：这个指标要支持什么决定？如果只看均值，会漏掉什么？
- 运行后：每个数值的分子、分母、单位和时间范围是什么？阈值是否包含等号？
- 比较后：改变阈值或指标后，哪些中心或业务的评价改变？为什么？
- 写建议后：我是在报告服务表现，还是把统计差异写成工作人员造成的效果？证据能支持到哪一步？

## 标准完成：补上统计论证

在入门路线基础上，再完成三件事：

1. **替代口径。** 改变一个有理由的记录范围、阈值、分组或计算方法，实际运行两次，说明哪些结果变了、为什么变。
2. **证据链。** 让每个主要结论都能指向数据范围、程序步骤、结果文件和分母；把缺失、异常、未匹配或零分母单独说明。
3. **使用建议。** 写清楚可以采取什么行动、适用到哪些记录，什么情况应先补数据、限制使用或暂停发布。不要把相关关系直接写成因果关系。

## 提高与拓展：按自己的基础选择

不要为了“看起来复杂”堆方法。完成标准路线后任选一项：

- **方法拓展：** 比较两种统计方法或模型，说明目标量、假设、评价指标和适用条件；
- **稳健性拓展：** 改变一个关键假设、分母、阈值或时间范围，画出结果如何变化；
- **复现拓展：** 从原始数据重新生成全部主要表图，增加重复键、范围、单位或分母检查；
- **决策拓展：** 面向另一类使用者重写一页说明，明确哪些结论可以发布、哪些必须保留。

提高任务的评价依据是论证是否更可靠、边界是否写清楚，不是代码行数或图表数量。

## 卡住时按这个顺序排查

1. `不是 Git 仓库`：先 `cd` 到自己的仓库目录，再运行 `git status`。
2. `找不到文件`：确认当前目录能看到 `scripts`、`data` 和 `lesson-04`，不要在 `lesson-04` 内再重复拼路径。
3. 程序报错：保留完整命令和最后 20 行错误；先恢复最近一次能运行的版本，再一次只改一处。
4. 数字对不上：核对记录单位、筛选条件、缺失值、分母和输出目录；不要把旧目录结果当成新运行结果。
5. 不知道报告写什么：先填“问题—数据—方法—结果—限制—建议”六个小标题，每项写一两句，再补证据。

如果环境暂时不能运行，可以先按 README 和本支持文件完成手算与报告草稿，并明确标记“尚未运行”；修复环境后必须补跑并更新结果。
