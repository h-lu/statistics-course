# 第2课 · 分析结论对统计口径有多敏感

## 项目背景

管理者读完探索简报后问：“换一种同样合理的算法或数据范围，结论还成立吗？”本课要检查初步结论是否依赖某种分析选择。你可以延续上节课的发现，也可以从当前数据提出新的研究假设。

## 可用数据

沿用 `data/service/tickets.csv` 及窗口、业务字典。需要时参考调查、排班；所有表的时期与记录层次见[数据说明](../data/service/README.md)。不能用第二期变化来冒充同一期分析口径差异。

本课数据均为教学合成数据，不代表真实机构。先阅读[知识准备](LEARN.md)，再选择分析方法。你可以全程使用AI完成代码、分析和写作；报告需解释主要结论的统计依据、适用条件和局限性。

## 分析任务

撰写一份敏感性分析报告：先提出一项需要核实的初步结论或研究假设，再选择有实际依据的统计口径进行比较。说明哪些结论在这些口径下较为稳定，哪些依赖特定条件，哪些仍缺少依据；据此修改报告中的结论表述。

### 必须遵守的约束

- 选择变化必须针对问题：例如面向所有登记工单与面向获得服务者、关注总等待负担与典型体验、合并业务与分别描述。
- 不把没有业务理由的任意删数、遍历所有参数后挑最喜欢的结论，称为稳健性分析。
- 比较统计量时说明它们是否回答同一个问题；均值与中位数不同不自动意味着计算矛盾。
- 写清分位数算法。本课示例采用排序后位置 `(n−1)p` 的线性插值；使用其他常见算法也可以，但保持比较一致。

### 由你决定

你决定核实哪项初步结论、哪些合理口径最可能影响它、如何展示“稳定”和“不稳定”。不必枚举所有组合；可以选择有代表性的方案，并说明未考察的部分。

## 成果要求

- 给出初步结论、选择变化的理由、可追溯的方案比较表及最终修订表述。
- 同时展示方向与实际差异大小，不能只写“变化了”或“没变化”。
- 说明某项变化是换了估计口径、换了使用目标，还是揭示原分析结论不稳。
- 对重复探索保持透明：在同一批数据发现并检验的结论仍属探索性证据。

在本目录的 `report.md` 中撰写分析报告，篇幅与结构可按问题需要调整。关键表、图或分析数据保存到 `artifacts/`，并在报告中引用。可以修改或替换 `analysis.py`；提供的示例代码只生成数据概览，不是本课的完整分析。

## 建议时间安排

0—12分钟知识与微型例子；12—22分钟确定待核实的结论和需要比较的统计口径；22—53分钟运行比较；53—68分钟划分结论稳定范围；68—75分钟核对提交；75—90分钟知识自查。复用上一课代码，不重复搭建读表程序。

## 运行与提交

从仓库根目录运行：

```bash
python scripts/course.py start 02
python scripts/course.py run 02
```

完成报告和分析后，在 `submission.json` 填入支持报告结论的结果文件路径，将 `status` 改为 `complete`；如果更换运行入口，同步修改 `run`。运行 `python scripts/course.py check 02`，核对修改后提交并创建最终标签 `v2-l02-final`。完整步骤见[操作与提交步骤](../docs/WORKFLOW.md)。自动检查通过只说明文件、路径和运行命令符合提交要求，不代表统计结论正确。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面显示当日第2课，按当前场次作答。建议先自行判断，不会时请AI解释概念再作答；使用方式见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
