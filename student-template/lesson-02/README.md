# 第2课 · 分析结论对统计口径有多敏感

**以下数据全部为教学合成数据，不代表真实机构、个人或实际效果。** 可以全程使用AI提出候选问题、编程、分析、写作和协助提交；你需要确认最终采用的选择，核对结果、依据和适用范围。无需提交AI对话或证明代码由谁输入。先阅读[知识准备](LEARN.md)，再展开正式分析。

## 你要解决什么问题

上一课形成了初步发现，本课要判断：在有理由的分析选择下，结论的方向、大小或行动建议会怎样变化？交付一份结论稳定性报告，说明哪些表述可以保留、哪些必须附条件。**本课不计分，但须完成项目和自查**；入门成果在第二周开始前补齐。

## 可用数据与基准

沿用第一期 `data/service/tickets.csv`、窗口与业务字典，必要时选用调查或排班资料，先读[数据说明](../data/service/README.md)。不同分析口径应基于声明的同一期记录；第二期是另一时间段，不能把时期变化当作第一期口径变化的结果。

已服务工单的平均等待、全登记工单的队列经过时间、中位数和P90分别回答不同问题。示例程序的合并描述只是起点，不是指定答案。分位数算法须明确；本课讲解采用排序位置 `h=(n−1)p` 的线性插值，其他常见算法可用，但比较时保持一致。

## 分析任务

1. **写待核实的结论和基准。** 交代时间、单位、纳入规则、结果含义、统计量、比较对象与各组分母。可以延续上一课，也可以提出新问题。
2. **选两到三种有理由的替代口径。** 可改变已服务/全部登记范围、业务分层、统计量或有业务依据的时间窗口。一次改变一个主要选择，或明确同时改变了什么；不机械遍历全部组合，不任意删记录寻找满意结果。
3. **用一张比较表呈现实际后果。** 每行写选择理由、对象是否变化、纳入规则、每组 `n`、统计量、单位、差值或比值。方向与大小都要说明；空组或零分母记为未定义，不能填0后继续比较。
4. **判断变化的含义。** 区分同一目标下的分析选择、统计量更换和目标人群更换。分层方向变化可以提示构成问题，但不自动识别因果；均值与中位数不同不表示一个算错。
5. **修订结论。** 说明方向、量级、行动或措辞在什么范围内稳定，以及什么证据还需独立核实。没有反转也是有效发现；同一批数据反复尝试不构成独立验证。

## 成果与提交前自核

报告包含初步结论、基准规格、两到三种替代口径及理由、可追溯比较表、变化来源、修订表述与下一步。两到三种替代口径是完整任务的一部分，不是只供优秀作品增加的项目。

进一步完善应解释哪些变化真正影响决定、哪些只是换了问题，以及比较的局限；无需新采数据或把所有结论都证明成不稳定。报告可采用自己的结构，不以图表数或模型数评价。

## 90分钟建议安排

## 运行、核对与提交

以下“仓库根目录”指你自己的学生仓库中包含 `scripts/`、`data/` 的目录；在合并资料库中阅读时，对应 `student-template/`。先运行：

```bash
python scripts/course.py start 02
python scripts/course.py run 02
```

`analysis.py` 是可运行的数据概览，不是完整项目答案。按问题修改或替换它，将关键数值结果和图表写入本课 `artifacts/`，在 `report.md` 中引用。可以调整报告结构，不能只保留提示或粘贴默认输出。原始数据不改写；新增依赖写入 `requirements.txt`。

完成后，在本课 `submission.json` 中将 `status` 设为 `complete`，填写 `report`、支持结论的 `artifacts` 和非空命令参数列表 `run`。所有路径相对于学生仓库根目录。再执行：

```bash
python scripts/course.py run 02
python scripts/course.py check 02
git diff --check
git status
git diff
git add lesson-02 requirements.txt
git diff --cached
git commit -m "完成第02课项目"
git push
git tag v2-l02-final
git push origin v2-l02-final
```

**`run` 执行分析；`check` 只检查完成声明、路径和文件是否存在且非空，不会重新运行分析或判断结论。** 推送后查看 Actions 的重跑结果；配置了重现检查时，它会在临时副本移除所列结果文件、运行程序并比较内容。固定随机种子、排序和输出精度，避免将带生成时间的文件列入逐字节比较。程序运行成功和文件检查通过，都不等于统计解释正确。

新增共用程序也须核对后纳入提交。已有最终标签不要覆盖；修订保留原版本。网络、环境或检查故障时保存本地文件与提交，向教师说明，不把失败写成已通过。完整步骤见[项目工作流](../docs/WORKFLOW.md)和[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第2课。建议先作答A，再学习不熟悉的概念，完成B并阅读反馈；AI始终可用，无需提交对话记录。自查正确率用于反馈，不直接计分，详见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
