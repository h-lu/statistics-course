# 第2课：分析结论对统计口径有多敏感

## 你要解决什么问题

上一课你用一套方法得出了一个初步结论。本课要追问：**如果采用另一种同样合理的分析定义，结论的方向、大小或行动建议会不会改变？**

这叫作**敏感性分析（sensitivity analysis）**：有理由地改变分析中的一个关键选择，观察结果受到多大影响。它不是为了把结果“调到满意”，而是为了找出结论成立的条件，判断哪些发现比较稳定，哪些发现依赖特定选择。

例如，把所有业务合并后比较两个中心，可能得到一个方向；在相同业务类型内比较，方向可能不同。这可能是因为两中心的业务构成不同，合并比较混入了构成差异。若合并结果和各业务层内的结果出现反向，这种现象可能属于**辛普森悖论（Simpson's paradox）**。你要展示这种差异，而不是简单宣布某一种算法才是正确答案。

## 先理解几个常用词

| 统计术语 | 简单解释 | 本课中的用法 |
|---|---|---|
| 统计口径（分析规格） | 对分析对象、纳入规则、变量定义和统计量的完整约定 | 只看已服务工单，还是把放弃者也纳入等待负担 |
| 估计对象 | 你想用数据回答的具体数量或比较 | “已服务工单的平均等待差”与“所有登记工单的等待负担差”不是同一个问题 |
| 敏感性分析 | 有理由地改变关键选择，观察结果后果 | 比较合并数据与业务分层、均值与中位数、不同时间范围 |
| 稳健性 | 合理改变分析选择后，结论方向或行动判断仍大体不变 | 稳健不等于对所有目的都最合适 |
| 分层比较 | 在相同或相近的业务层内分别比较群体 | 可能减少业务构成差异的影响，但会改变结论适用的对象 |
| 混杂 | 一个未充分处理的变量同时与比较组和结果有关，使差异难以解释 | 业务复杂程度可能同时影响中心分布和等待时间 |
| 辛普森悖论 | 合并数据的方向与各分层内的方向相反 | 这是需要解释的构成差异现象，不是软件出错 |
| 探索性分析 | 从数据中寻找模式并形成假设 | 本课在同一批数据上比较方案，仍属于探索性证据 |
| 验证性分析 | 对预先提出的假设使用独立数据或预先规定的方法进行检验 | 不能把本课反复尝试后的结果称为独立验证 |

## 可用数据与基准口径

沿用 `data/service/tickets.csv`、`windows.csv` 和 `business_types.csv`，必要时查阅调查与排班数据。第一期和第二期是不同时间段，不能把第二期变化当成第一期不同分析口径的证据。

示例程序的**基准口径**是：第一期、已获得服务的工单、所有中心合并、比较等待时间的均值、中位数和分位数。它只是一个起点，不是本课规定的答案。

放弃者的 `wait_minutes` 是离开前等待。如果把他们纳入分析，必须说明这已经改变了结果变量的含义。**分位数**是排序后某个累计位置的数值，例如P90表示约90%的观测不超过该值；本课示例采用线性插值：将 `n` 个值排序后，以位置 `h=(n−1)p` 计算 `p` 分位数，在非整数位置的相邻值之间插值。你可以使用其他常见算法，但必须写明方法并保持比较一致。

## 分析任务：按步骤完成

### 1. 写出要核实的初步结论

可以延续上一课，例如“中心A的已服务工单平均等待更长”，也可以提出新的研究假设。结论必须包含对象、时间范围、结果变量、统计量和比较对象，不能只写“某中心更好”。

### 2. 固定基准分析规格

先记录基准方案：

- 分析单位是什么；
- 纳入和排除哪些记录；
- 等待时间或满意度如何定义；
- 使用均值、中位数、四分位距还是P90；
- 每组的 `n` 和分母是什么。

这些内容共同定义了你的**估计对象**，否则改变口径后无法判断究竟比较了什么。

### 3. 选择两到三种有理由的替代口径

一次只改变一个主要选择，或明确说明同时改变了哪些选择。可考虑：

- 所有已登记工单 vs 仅已获得服务的工单；
- 所有业务合并 vs 按业务复杂程度分层；
- 均值 vs 中位数、四分位距或P90；
- 全部日期 vs 有明确业务理由的时间范围。

不要因为结果不符合预期就任意删掉记录，也不要遍历很多参数后只报告最喜欢的一组结果。那不是有依据的稳健性分析。

### 4. 用同一张比较表呈现结果

每种方案至少列出：方案名称、分析单位、纳入规则、每组 `n`、统计量、差值或比值、单位和方向。除了“是否改变方向”，还要报告实际差异大小。例如差异从+2分钟变为−3分钟，比只写“结果变化了”更有信息。

### 5. 判断变化属于哪一类

- **统计量更换**：均值和中位数回答不同问题，不能只因数字不同就说原计算错误；
- **估计对象更换**：从已服务工单换成所有登记工单，结论适用范围发生了变化；
- **分层后方向变化**：可能反映业务构成差异或混杂，需要说明合并结果与分层结果分别回答什么问题；
- **合理选择下仍方向和行动一致**：可以说结论在这些方案下较稳定，但不能推广到没有考察的所有情况。

### 6. 修订你的结论

报告最后要明确写出：结论在哪些条件下成立，在哪些条件下不稳定，管理者现在可以采取什么行动，以及还需要收集什么数据。不要用“数据有限、无法判断”结束；请指出具体缺少哪个变量或哪种比较。

## 必须遵守的边界

- 每种方案都要有业务或统计理由；
- 不能把任意删数、挑选结果或大量试算称为稳健性分析；
- 比较统计量时说明它们是否回答同一个问题；
- 报告分位数算法和分母；
- 同一批数据上反复探索仍是探索性证据，不是独立验证；
- 不把分层结果自动解释为因果效果；
- 不要求所有合理方案都给出相同结果，差异本身就是分析发现。

## 报告应交付什么

在 `report.md` 中写一份敏感性分析报告，至少包括：

1. 初步结论或研究假设；
2. 基准分析规格和估计对象；
3. 替代口径的选择理由；
4. 可追溯的方案比较表，包含 `n`、统计量、差异大小和单位；
5. 哪些结论稳定、哪些结论敏感，以及原因；
6. 修订后的结论、适用范围、局限性和下一步行动。

把支持结论的表、图或分析数据保存到 `artifacts/`，并在报告中引用。`analysis.py` 只提供一个合并数据的基准示例；你需要根据自己的问题加入合理的对照方案。
