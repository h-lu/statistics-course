# 第02课支持路线：第2课 · 分析结论对统计口径有多敏感

这份文件给还不知道从哪里开始的同学使用。它不是另一份作业，也不替你决定统计结论；请按“入门跟做”完成一条最小路线，再根据时间选择标准或提高任务。所有数字都要从本课程序和数据重新运行得到，不能把示例数字当成自己的结果。

## 先知道今天要交出什么

完成后，你至少应有：

- 一个用一句话写出的统计问题（谁要用、看哪些记录、要作什么决定）；
- 一次成功运行和一份能重新生成结果的程序；
- 一张表、一个图或一组能支持结论的计算结果；
- 一段说明分母、单位、数据范围、局限和下一步行动的报告。

本课任务可以先按下面顺序拆开：

1. **确定原有结论和基准方法。** 基准方法就是用来与其他方法比较的原方案；可以延续第1课，也可以在本课数据中提出新的初步结论。写清时期、分析对象、纳入规则、指标含义、计算方法和比较对象。
2. **选择两到三种有理由的替代口径。** 可比较已服务与全部登记工单、合并与分层结果、不同统计量，或有业务依据的日期范围。一次改变一个主要选择；同时改变多项时说明各项是什么。
3. **列出比较结果。** 用一张表说明每种方法的理由、采用的记录、每组记录数、分母、结果和单位。报告差异的方向与大小，不能只写“有变化”。先固定差值顺序，例如“中心A减中心B”；负数表示A的该项指标较小，各方案不要交换顺序。某组没有记录或分母为0时，说明无法计算，不填0来制造差异。
4. **解释为什么不同。** 是在同一个问题下换了算法，还是换了统计量或研究对象？均值与中位数不同不表示计算错误；分层结果不同也不自动证明因果关系。
5. **修改结论。** 哪些表述仍可保留，哪些需要说明条件，哪些建议应调整？没有方向反转也是结果。同一批数据反复分析，不能称为已经完成独立验证。

## 入门跟做：先让第一个结果出现

### 1. 写下问题和预计

打开 `lesson-02/report.md`，先不要追求完整，写三句话：

1. “我的使用者是……，他/她需要决定……”；
2. “我把一行记录看作……，分析范围是……”；
3. “我预计……，因为……；最可能改变这个预计的信息是……”。

这里的“预计”是运行前的可检验想法，不是最后结论。不会选问题时，直接使用 README 项目背景中的第一个问题，把范围缩小到一个数据表、一个时期和一个指标。

### 2. 在仓库根目录运行示例

仓库根目录是能同时看到 `scripts` 和 `lesson-02` 的目录。不要在 Python 的 `>>>` 后输入下面命令。电脑只有 `python3` 时，把 `python` 换成 `python3`。

```bash
python scripts/course.py start 02
python scripts/course.py run 02
```

运行成功后，打开 `lesson-02/artifacts/starting_overview.json` 或终端提示的结果文件。JSON 是按字段名保存的文本，不必一开始读懂所有字段；先找到与自己问题对应的一个数字，记下它的记录数、单位和分母。

### 3. 手算并核对一条

从输出中挑一条记录或一个小组，写出“原始值 → 处理 → 结果”的三步。至少核对一个加总、平均、比例、排序或分组数量。若结果是比例，明确写出分子和分母；若结果是平均数，写出参与计算的记录数；若是时间或金额，写单位。核对不一致时先检查路径、字段名、筛选条件和小数显示，不要手改结果文件。

### 4. 完成一个最小可交版本

根据 README 的任务，把 `analysis.py` 扩展到能回答自己的问题，把表、图或 JSON 结果保存到 `lesson-02/artifacts/`，再在报告中引用文件名。报告先写“观察到的事实”，然后分别写“可能解释”和“还不能证明什么”。

```bash
python scripts/course.py run 02
python scripts/course.py check 02
```

只有在报告、结果文件和 `submission.json` 都准备好后，才把 `status` 改为 `complete`。

## 标准完成：补上统计论证

在入门路线基础上，再完成三件事：

1. **替代口径。** 改变一个有理由的记录范围、阈值、分组或计算方法，实际运行两次，说明哪些结果变了、为什么变。
2. **证据链。** 让每个主要结论都能指向数据范围、程序步骤、结果文件和分母；把缺失、异常、未匹配或零分母单独说明。
3. **使用建议。** 写清楚可以采取什么行动、适用到哪些记录，什么情况应先补数据、限制使用或暂停发布。不要把相关关系直接写成因果关系。

## 提高与拓展：按自己的基础选择

不要为了“看起来复杂”堆方法。完成标准路线后任选一项：

- **方法拓展：** 比较两种统计方法或模型，说明目标量、假设、评价指标和适用条件；
- **稳健性拓展：** 改变一个关键假设、分母、阈值或时间范围，画出结果如何变化；
- **复现拓展：** 从原始数据重新生成全部主要表图，增加重复键、范围、单位或分母检查；
- **决策拓展：** 面向另一类使用者重写一页说明，明确哪些结论可以发布、哪些必须保留。

提高任务的评价依据是论证是否更可靠、边界是否写清楚，不是代码行数或图表数量。

## 卡住时按这个顺序排查

1. `不是 Git 仓库`：先 `cd` 到自己的仓库目录，再运行 `git status`。
2. `找不到文件`：确认当前目录能看到 `scripts`、`data` 和 `lesson-02`，不要在 `lesson-02` 内再重复拼路径。
3. 程序报错：保留完整命令和最后 20 行错误；先恢复最近一次能运行的版本，再一次只改一处。
4. 数字对不上：核对记录单位、筛选条件、缺失值、分母和输出目录；不要把旧目录结果当成新运行结果。
5. 不知道报告写什么：先填“问题—数据—方法—结果—限制—建议”六个小标题，每项写一两句，再补证据。

如果环境暂时不能运行，可以先按 README 和本支持文件完成手算与报告草稿，并明确标记“尚未运行”；修复环境后必须补跑并更新结果。

## 提交前自检

- [ ] 报告没有保留模板提示语，问题和使用者具体可辨；
- [ ] 结果文件确实由当前程序生成，原始数据未被覆盖；
- [ ] 每个比例写了分子、分母和单位；
- [ ] 结论区分观察事实、解释和行动建议；
- [ ] `submission.json` 的路径、命令和状态正确；
- [ ] 已运行 `python scripts/course.py check 02`，并检查 `git diff --cached`。

完成核心路线后，再进入教师指定的统计学知识自查场次。自查用于发现概念混淆，不能替代项目报告；不会的题可以标记不确定，先记录问题再学习。
