# 第2课支持路线：改变一个选择，看看结论是否改变

## 你要留下的最小成果

一份写明基准方案和替代方案的报告、一张并列比较表、可重复运行程序，以及关于结论是否稳健的建议。

## 先懂概念

- **分位数**：排序后某个位置的数；第50百分位数是中位数，第90百分位数不是最大值。
- **离散程度**：记录彼此相差多大；四分位距看中间一半，标准差描述围绕均值的离散。
- **统计口径**：纳入哪些记录、指标怎样定义和怎样计算。
- **敏感性分析**：有理由地改变一个选择，观察结果如何变化；不等于挑选最好看的结果。
- **稳健性**：在实际检查过的变化范围内，结论是否大体保持。

## 入门跟做

### 1. 固定基准

在 `report.md` 写清上一课或本课的一个基准结论：数据时期、分析单位、记录范围、指标和分母。再写预计：你觉得改变哪个选择最可能改变结论。

**反思**：如果同时改变记录范围、指标和时间，结果变了时还能知道原因吗？

### 2. 运行并翻译起点

```bash
python scripts/course.py start 02
python scripts/course.py run 02
```

打开 `artifacts/starting_overview.json`，选择一个数字，用完整句子写出它描述谁、单位是什么、分母是什么。

**做对信号**：读者不用看代码也能理解数字。**反思**：这是中心位置、离散程度还是比例？有没有把第90百分位误写成最大值？

### 3. 手算位置和差异

把2、3、4、10、11排序，中位数为4；第90百分位要按 `LEARN.md` 约定计算。先手算，再核对程序。写出两方案的差值顺序，例如“方案A减方案B”，不要一会儿换顺序。

**反思**：算法改变和数据改变有什么不同？不同软件默认分位数方法不同，报告如何说明？

### 4. 只改变一个选择

实际比较两种有理由的方案，例如均值与中位数、已服务与全部登记、或两个时间范围。并列表格：方案、纳入记录、记录数、分母、结果、差值、建议。

运行 `check 02`，然后写“哪些结论保留、哪些需要加条件、哪些建议改变”。没有变化也是结果。

## 标准与提高

标准完成要实际计算替代方案并解释差异。提高可以做阈值或分组的敏感性图、复现检查，或面向管理者写一页“在什么条件下可以使用”的说明。不要为了找反转而无限调参数。

## 卡住和提交前检查

先固定基准，再一次改变一项；数字对不上查数据范围、筛选、分母和分位数算法。提交前确认两种方案都由程序生成，报告写出单位和差值方向，`submission.json` 和 `check 02` 正确。
