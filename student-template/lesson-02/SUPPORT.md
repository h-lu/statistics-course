# 第2课支持路线：改变一个选择，看看结论是否改变

## 先知道今天要交出什么

一份写明基准方案和替代方案的报告、一张并列比较表、可重复运行程序，以及关于结论是否稳健的建议。

基础练习只帮助你把比较问题定义清楚；标准任务要求实际计算至少一种替代方案；提高与拓展只在标准任务完成后进行。`check` 通过只说明文件齐全，不代表比较已经解释清楚。

## 核心概念与原理

- **分位数**：排序后某个位置的数；第50百分位数是中位数，第90百分位数不是最大值。
- **离散程度**：记录彼此相差多大；四分位距看中间一半，标准差描述围绕均值的离散。
- **统计口径**：纳入哪些记录、指标怎样定义和怎样计算。
- **敏感性分析**：有理由地改变一个选择，观察结果如何变化；不等于挑选最好看的结果。
- **稳健性**：在实际检查过的变化范围内，结论是否大体保持。

## 基础练习（可信起点）：入门跟做

### 1. 固定基准

在 `report.md` 写清上一课或本课的一个基准结论：数据时期、分析单位、记录范围、指标和分母。再写预计：你觉得改变哪个选择最可能改变结论。

**反思**：如果同时改变记录范围、指标和时间，结果变了时还能知道原因吗？

### 2. 运行并翻译起点

```bash
python scripts/course.py start 02
python scripts/course.py run 02
```

打开 `lesson-02/artifacts/starting_overview.json`，选择一个数字，用完整句子写出它描述谁、单位是什么、分母是什么。

**成功信号**：读者不用看代码也能理解数字。**反思**：这是中心位置、离散程度还是比例？有没有把第90百分位误写成最大值？

### 3. 手算位置和差异

把2、3、4、10、11排序，中位数为4；第90百分位要按 `LEARN.md` 约定计算。先手算，再核对程序。写出两方案的差值顺序，例如“方案A减方案B”，不要一会儿换顺序。

**反思**：算法改变和数据改变有什么不同？不同软件默认分位数方法不同，报告如何说明？

## 入门反思

在运行替代方案前，确认你能分别说清“保持了什么”和“改变了什么”。如果一次改变多项，结果变化将无法归因到某个分析选择。

## 标准任务（本课应完成）

### 4. 只改变一个选择

实际比较两种有理由的方案，例如均值与中位数、已服务与全部登记、或两个时间范围。并列表格：方案、纳入记录、记录数、分母、结果、差值、建议。

运行 `check 02`，然后写“哪些结论保留、哪些需要加条件、哪些建议改变”。没有变化也是结果。

### 完成标准任务的判断

固定一个基准方案，实际计算至少一种有理由的替代方案。比较表必须同时给出每种方案的记录范围、记录数、分母、单位、结果和统一方向的差值。报告还要解释：改变的是同一问题的计算选择，还是已经换了研究对象或评价目标；原结论最终应保留、增加条件还是改变。

## 提高与拓展（提前完成后）

完成标准任务后，从 README 的提高菜单任选一项。无论选哪项，都先写下合理范围和预计，再运行分析，避免看结果后挑选参数。

选择“二维敏感性分析”时，每次只改变一个选择。例如先固定记录范围比较三个阈值，再固定阈值比较两个记录范围。表格中标明每个格子的记录数、指标值和行动建议，这样才能判断变化来自哪一项。

选择“决策边界”时，寻找的是在预先说明的范围内何时会改变行动，而不是追求结论反转。报告边界两侧的结果和分母，并说明边界是否接近当前方案。

选择“时间或业务迁移”时，对各组使用完全相同的计算规则，并报告各组记录数。方向相同但大小不同，不应简单写成“结果完全一致”；同一期资料的分组比较也不是独立验证。

选择“独立复算”时，第二种实现要重新读取原始数据并进行筛选。若分位数不同，先核对算法；若记录数不同，先核对时间、缺失和纳入规则。

## 卡住时按顺序排查

先固定基准，再一次改变一项；数字对不上查数据范围、筛选、分母和分位数算法。

## 提交前自检

确认两种方案都由程序生成，报告写出单位和差值方向，`submission.json` 已按实际结果填写。然后在仓库根目录运行：

```bash
python scripts/course.py run 02
python scripts/course.py check 02
```

最后核对主要数字可以从所列结果文件复算。
