# 第2课支持路线：分析结论对统计口径有多敏感

这课不是让你找一个“最正确”的数字，而是让你看到：同一批数据换一个合理的统计口径，结论可能改变。你要学会说明改变了什么、为什么改变、结果是否足以改变建议。

## 这课到底在学什么

- **分位数**：把数据排序后，用位置描述等待。例如第50百分位数是中位数，第90百分位数表示约90%的记录不超过该值。
- **离散程度**：描述记录彼此相差多大。四分位距是中间一半数据的跨度，标准差描述数据围绕均值的离散程度。
- **统计口径**：明确纳入哪些记录、指标怎样定义和计算。例如“只看已服务工单”和“所有登记工单”是两种口径。
- **敏感性分析**：有理由地改变一个方法或假设，观察结果怎样变化。它不是为了挑一个好看的结果。

原理是“数字必须带着口径解释”。如果均值和中位数不同，不一定是程序错了；它们回答的是不同问题。

## 入门跟做

### 1. 固定一个基准结论

打开 `lesson-02/report.md`，先写清：时期、分析单位、纳入记录、指标、比较对象，以及你沿用第1课的哪一个结论。再写一个预计：哪一个选择最可能改变结果。

**反思**：你改变的是统计方法，还是连研究对象和时间范围也一起改变了？如果一起改变，如何分辨影响来自哪里？

### 2. 运行起点

```bash
python scripts/course.py start 02
python scripts/course.py run 02
```

打开 `lesson-02/artifacts/starting_overview.json`。先找一个分组的均值、中位数、分位数或离散程度，写下记录数和单位。

**为什么**：先固定同一批数据和基准方法，才能把后续差异归因到一个明确的选择。

**做对的信号**：你能把输出的一行翻译成完整句子，例如“在纳入的X张已服务工单中，第90百分位等待为Y分钟”。

**反思**：第90百分位不是最大值；如果只有很少记录，它能支持多稳定的判断？

### 3. 手算位置统计量

把 `2、3、4、10、11` 排序。中位数是4；第90百分位数的具体数值要按本课规定的软件/插值约定计算。先查 `LEARN.md` 的约定，再核对程序，不能把不同软件的默认算法混在一起。

**反思**：如果换一种分位数计算约定，差异属于数据变化还是方法变化？报告怎样写才不会让读者误以为是新数据？

### 4. 只改变一个选择

从起点复制程序或结果设置，实际比较一个替代口径：例如均值与中位数、全部记录与已服务记录、或另一种有业务理由的时间范围。把两种方案放在同一张表中，列出记录数、分母、指标和差值。

运行：

```bash
python scripts/course.py run 02
python scripts/course.py check 02
```

**做对的信号**：读者能看出你只改变了哪一个选择；没有变化也要报告，并解释为什么。

**反思**：结论在你实际检查的变化范围内是否稳健？“稳健”只表示在检查过的条件下变化不大，不表示任何情况下都不变。


## 标准完成

在入门路线基础上，完成 README 中全部必做任务：实际比较一个有理由的替代方案，列出每种方案的记录范围、指标、分子、分母和单位；说明结果变化的原因；最后给出适用范围、限制和下一步行动。不能只说“结果不同”，也不能把相关关系写成因果关系。

## 提高与拓展

完成标准路线后任选一项：

- **方法比较**：比较两个目标相同但假设不同的方法，说明为什么选择其中一个；
- **敏感性分析**：改变一个有实际依据的阈值、分母、时间范围或处理规则，画表说明结果如何变化；
- **复现检查**：从原始数据重新生成主要结果，增加重复键、范围、单位或分母检查；
- **决策说明**：面向另一类使用者写一页简报，说明哪些结论可以发布、哪些需要限制。

提高不是增加代码数量。好的提高任务会让读者更清楚结果在什么条件下可靠。

## 卡住时按顺序排查

1. 先确认在能看到 `scripts`、`data` 和本课目录的仓库根目录；
2. 确认命令中的课次编号、文件名和输出目录没有写错；
3. 保留完整命令和最后一段报错，不要删除旧结果来“清理”问题；
4. 数字对不上时，依次核对观测单位、筛选条件、缺失值、分母、单位和输出目录；
5. 报告无从下手时，先填写“问题—数据—方法—结果—限制—建议”六个小标题。

如果程序暂时不能运行，可以先完成手算和报告草稿，但必须标明“尚未运行”，修复后再补跑并更新数字。
