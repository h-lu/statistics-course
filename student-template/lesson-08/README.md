# 第8课 · 多表数据整合与统计指标核查

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

第一次使用这些资料时，可先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。

如果你不知道下一步做什么，打开本课的[支持路线](SUPPORT.md)，先完成“入门跟做”。

## 项目背景与数据

管理者需要合并两期的运营报告，同时了解工单办理、满意度、服务接触工作量和计划工时。直接把所有表连接起来，可能让工单重复计算，也可能遗漏没有匹配成功的记录。

使用 `data/service/` 中的工单、第二期原始工单、调查、接触、窗口、业务和排班七张表，详见[数据说明](../data/service/README.md)。第一期有3,600张工单，第二期有1,200个工单编号。可复用第3课的数据处理程序。先阅读[知识准备](LEARN.md)，理解主键、连接关系和不同分析单位。

## 分析任务

1. **说明每张表怎样组织。** 一行代表一张工单、一次接触，还是一个窗口的一天？哪个字段或字段组合能唯一识别记录？输入表、输出表及连接关系都应写清。
2. **整合两期并计算指标。** 按已说明的规则处理第二期重复、版本、单位和未知值，统一字段后与第一期按行追加；随后按对应编号连接调查、窗口等信息。追加完整两期时应有4,800张工单，并检查编号是否重叠。根据容量安排、流程改进或服务体验的用途，分别计算工单结果、接触工作量和窗口日排班指标。
3. **编写并运行检查。** 至少对一项重复计算或记录遗漏风险设置程序检查，报告实际结果。同时核对连接前后工单数、接触数、关键总量及未匹配数量。仅修正去重后的工单数，并不自动修复已经重复计算的均值。
4. **说明未匹配记录的影响。** 未知窗口工单的有效等待仍可用于相应总体描述，但不能直接归属某个窗口。窗口未知、已知窗口缺排班、缺调查登记和无回答应分开说明，不全部删除或填0。
5. **提交有明确范围的报告。** 每个指标写明单位、计算记录、分母和时期，说明哪些结果可以发布、哪些应暂缓，以及下一期出现什么异常时需要核查或更新。

## 日期与工时需要分别核对

每日接触工作量按 `contact_date` 理解，跨日接触不能自动计入工单登记日。没有实际办理窗口字段时，用工单窗口归属工作量需要说明假设，或补充资料。

报告整个计划期时，应保留有排班但没有工单的日期。确认没有业务才能记为0；没有取得数据不能当成零业务。计划工时按每个窗口的每天只累计一次。人时是人数与工作小时数的乘积，例如2人各工作4小时为8人时；接触记录的工作人员分钟除以60后才与人时单位一致。计划工时不等于实际劳动时间，不能据此声称测得了个人生产率。

## 需要提交什么

提交报告、整合程序、各表主键与连接关系说明、至少一项已执行检查、数量与总量核对，以及未匹配记录的影响。两期和工单、接触、窗口日三个层次都需要处理，不要求搭建数据库或网站。

还需在报告末从**第3—8课选择一件模块一代表作**，写明选择理由；若计划修订，再写明要修改的统计问题及依据。代表作不必是第8课，不要求当天重做六课，也不必为了填写修订计划而编造问题。选择修订时，截止下一次课开始前；保留原 `v2-lNN-final` 标签，修订版用 `v2-lNN-revision-1`，其中NN替换为课次。有修订时质量评价采用修订版，没有修订则采用原版，不改变原按时完成分，详见[成果与评分](../docs/ASSESSMENT.md)。

## 课堂安排

0—12分钟阅读例子；12—25分钟明确各表对象和主键；25—54分钟整合、检查和计算；54—68分钟写发布说明并选代表作；68—75分钟检查提交；75—90分钟知识自查。

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`inventory` 列出七张表的行数、准备核对的编号字段 `proposed_key`，以及不同编号或编号组合的数量 `unique_keys`。这些字段名不保证编号已经唯一；尤其第二期原始表仍有重复和修订。示例没有完成清洗、连接或指标核对。

先阅读输出中与你的问题有关的内容，再按上面的分析任务扩展程序。自己的计算结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。若使用完整课程资料库，先进入 `student-template/`。

```bash
python scripts/course.py start 08
python scripts/course.py run 08
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据本课问题修改或替换程序，将结果和图表保存到本课 `artifacts/` 文件夹，并在 `report.md` 中解释和引用。原始数据保持不变；程序使用的新软件包写入 `requirements.txt`。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起；更换程序时要相应更新命令。然后重新运行并检查：

```bash
python scripts/course.py run 08
python scripts/course.py check 08
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送到个人仓库，创建本课最终标签 `v2-l08-final`，再查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，但不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖，修改时保留原版本。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令、结果文件设置和修订办法见上述操作说明，评分见[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第8课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
