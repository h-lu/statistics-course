# 第8课 · 多表数据整合与统计指标核查

数据为**教学合成数据**，所有机构与编号虚构。AI可以全程帮助编程、分析和写作。评价关注分析问题是否明确、方法选择是否有依据、结果能否复核，以及结论适用于哪些对象和情境。你可以自主决定分析顺序、方法和报告结构。

## 问题情境

服务中心需要合并两个时期的记录，用于安排人员、改善流程或了解服务体验。一张工单记录一次登记的业务；一次接触记录工作人员与来访者的一次服务互动；一条排班记录对应某窗口的一天。这些表的一行代表不同对象。直接连接后计算均值，或不作说明就删掉无法匹配的记录，都可能改变结果所描述的对象。请确定报告用途，完成能够复核、适用范围清楚的分析。

第3课的数据质量、第4–6课的指标与比较、第7课调查覆盖可作为已有资源，无需重新完成旧作业。概念按需查 [LEARN.md](LEARN.md)，遇阻可选择 [SUPPORT.md](SUPPORT.md) 的对应提示；[EXERCISES.md](EXERCISES.md) 提供小例和可选挑战，[HINTS.md](HINTS.md) 是进一步帮助。先明确自己的问题，再选择需要的资源。

## 可用资料与工具

[七张表的数据说明](../data/service/README.md)：第一期工单表有3,600行；第二期原始导出有1,265行，对应1,200个不同工单编号。调查、接触、窗口、业务和排班表分别有4,800、8,921、6、2和240行。原始行数、不同对象数和指标分母要分别核对。两期工单编号不重叠；整理第二期、统一字段和单位后，两期共应保留4,800张工单的记录。

`analysis.py` 运行后列出七张表的行数和不同编号数。它还提供三个通用函数：`read` 读表，`unique_index` 检查指定键是否缺失或重复，`group_totals` 按指定字段分组求和。正式数据的清洗规则、连接和指标计算由你确定。可以改写程序、另写程序或请AI实现自己的方案；这些函数按需使用。

```bash
python3 scripts/course.py start 08
python3 scripts/course.py run 08
```

以上命令在学生仓库根目录运行，该目录中应有 `scripts/` 和 `data/`。如果打开的是完整课程资料库，先进入 `student-template/`。结果保存在 `lesson-08/artifacts/starting_overview.json`，它只说明资料已读入。资料可以离线使用，已有Python3标准库足够，无需安装新软件。

## 基础练习（可信起点）

如果还无法判断连接会怎样影响结果，可用两张工单的小例子核对分析单位和均值，也可以从七张表中选一组对应关系，检查用来匹配记录的字段（键）。可选提示见 [SUPPORT.md](SUPPORT.md)。熟悉这些概念的同学可以直接进入标准任务。基础结果不能替代正式分析。

## 标准任务（本课应完成）

**用途由你确定。** 可以关注容量安排、流程改善、体验评价或另一项能由资料支持的管理问题。至少作出并解释两个会影响结果的重要决定，例如选择哪些指标、针对什么对象分析、哪些记录可用于计算、怎样处理未匹配记录、比较哪些对象、按哪个日期汇总，或哪些结果足以支持建议。不要任意改参数后补理由。

成果需要满足这些证据要求：

- 说明每张输入表和结果表的一行代表什么，以及用哪些字段识别记录。整理两期工单的修订版本、重复记录、单位和未知值后，按行追加到同一张工单表。原始CSV保持不变。
- 同时在工单、接触和窗口日三个层次分析，并分别给出与报告用途有关的结果。“窗口日”指一个窗口在一天的记录；例如A1窗口周一和周二对应两个窗口日。指标由你选择，可以使用等待时间、办结率、满意比例或其他有依据的指标。说明每项指标的时期、单位、计算范围和分母。
- 核对记录数量和关键总量，并实际执行至少一项检查，判断是否发生重复计算或遗漏。工单数、接触数和计划人时都不能因连接增加的行而重复累计。人时按人员投入时间累计：两人各安排一小时，合计两人时。
- 实际计算并比较一种有依据的替代分析方案，或用计算检验另一种解释。说明它针对的对象、分母、结果，以及对建议的影响。可以改变连接方式、用于计算的记录、统计量或日期范围，也可以选择其他与问题有关的方法。两种方案得到相同结果也可以是有意义的发现。
- 分别说明窗口未知、排班记录缺失、调查登记缺失、未受邀和受邀后无回答对相关指标的影响。这些情况需要根据指标分别处理。说明哪些结果可用于报告，哪些需注明条件，哪些暂时不能使用，以及下一期需要核查什么。

计算时请留意日期和单位。工单的 `date` 是登记日期，接触的 `contact_date` 是接触发生日期。接触表没有记录实际办理窗口；若用工单的窗口分配接触工作量，需要说明这一假设。`staff_minutes` 是工作人员分钟数，除以60得到人时。排班人时按 `staff_count × open_hours − absence_hours` 计算，其中 `absence_hours` 已是当天所有人员合计的缺勤人时，不能再乘人数。排班量表示计划安排，不是实际劳动投入的测量。报告还需说明怎样处理有排班却没有活动记录的日期，以及有活动却缺少排班记录的日期。

## 提高与拓展（提前完成后）

可自行提出一个新问题，检验报告中的重要假设。例如，改变连接保留的对象、比较最新版本冲突的处理方法、分析按接触次数加权的影响，或从异常结果查回源记录。也可以提出其他有依据的方法比较。[EXERCISES.md](EXERCISES.md) 的反例可按需参考或改写。拓展应带来新的统计判断，而不只是重复运行或调整排版。

## 成果与提交

报告形式可以调整，`report.md` 提供写作提示。提交自己的可运行程序、支持结论的计算结果、重要选择及理由、实际执行的检查和替代方案比较。所列结果都应能从原始数据重新生成。在 `submission.json` 中，`run` 填写运行你实际分析程序的命令，`report` 填报告路径，`artifacts` 填结果文件路径。完成分析后，将 `status` 改为 `complete`。

```bash
python3 scripts/course.py run 08
python3 scripts/course.py check 08
```

`run` 执行你在提交配置中指定的程序；`check` 检查完成状态、路径和文件是否非空，不判断统计结论。按 [工作流](../docs/WORKFLOW.md) 提交，并保留原有 `final` 标签。

在报告末尾，从第3–8课中选择模块一代表作品并说明理由。若计划修订，说明要改进的统计问题和依据；若不修订，说明保留原版的理由。截止时间为下一次课前。保留 `v2-lNN-final`，修订版本使用 `v2-lNN-revision-1`，其中 `NN` 是两位课次编号。评分规则见 [成果与评分](../docs/ASSESSMENT.md)，不要求重做六课。
