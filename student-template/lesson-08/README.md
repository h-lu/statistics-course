# 第8课 · 多表数据整合与统计指标核查

## 项目背景

管理者要求一份合并两期的运营报告，同时展示工单办理、满意度、接触工作量与计划工时。直接把所有CSV连接起来可能让同一张工单重复出现，也可能在连接失败时悄悄丢掉记录。你需要建立一套可按期更新的统计分析流程，并依据核查结果判断报告是否适合发布。

## 可用数据

使用 `data/service/` 的工单、原始新一期、调查、接触、窗口、业务和排班七张表。第一期3,600张工单，新一期1,200个工单编号；一张工单可以对应多次服务接触；排班表每行对应一个窗口的一天。[数据说明](../data/service/README.md)。

本课数据均为教学合成数据，不代表真实机构。先阅读[知识准备](LEARN.md)，再选择分析方法。你可以全程使用AI完成代码、分析和写作；报告需解释主要结论的统计依据、适用条件和局限性。

## 分析任务

建立两期数据整合流程，选择对运营管理有用的指标，生成可发布报告。必须同时处理工单级结果、接触级工作量与窗口日排班，并用核对结果证明指标没有因连接基数而失真。指出哪些范围仍应暂缓发布。

### 必须遵守的约束

- 声明每张输入表及每个输出表的分析单位、主键和连接关系。
- 新一期重复、修订、单位和未知值沿用有理由的处理流程，可复用第3课成果。
- 接触工作量可按工单或窗口日汇总后连接；不能将连接后的行数直接称为工单数。
- 不用删除全部未匹配记录来掩盖问题；报告无法归属窗口或缺字段的记录数量及影响。
- 排班工时不等于实际劳动时间；每小时产出不能被表述为已测得的个人生产率。

### 由你决定

你决定报告服务于容量安排、流程改进或服务体验；可采用分层汇总表、图表或交互式图表。流程应清楚到其他人替换下一期数据后能重新运行，不强制搭建数据库或网站。

## 成果要求

- 提供连接前后工单数、接触数、关键总量和未匹配量的核对，并说明预期的一对多扩展。
- 至少针对一项可能造成重复计算或记录遗漏的问题编写检查，并报告检查结果，不能只列注意事项。
- 工作量、质量与满意度指标分别采用与其分析单位一致的数据和分母，最终报告有明确发布范围。
- 提交本课成果；同时在报告末尾选定模块一代表作品，记录计划修订的统计理由。选择代表作不要求当天重做全部六课。

在本目录的 `report.md` 中撰写分析报告，篇幅与结构可按问题需要调整。关键表、图或分析数据保存到 `artifacts/`，并在报告中引用。可以修改或替换 `analysis.py`；提供的示例代码只生成数据概览，不是本课的完整分析。

## 建议时间安排

0—12分钟知识与连接例子；12—25分钟明确各表每行代表的对象及连接字段；25—54分钟整合、核对与指标计算；54—68分钟形成发布决定并选择代表作；68—75分钟核对提交；75—90分钟知识自查。直接复用前面处理规则，避免重写业务代码。

## 运行与提交

从仓库根目录运行：

```bash
python scripts/course.py start 08
python scripts/course.py run 08
```

完成报告和分析后，在 `submission.json` 填入支持报告结论的结果文件路径，将 `status` 改为 `complete`；如果更换运行入口，同步修改 `run`。运行 `python scripts/course.py check 08`，核对修改后提交并创建最终标签 `v2-l08-final`。完整步骤见[操作与提交步骤](../docs/WORKFLOW.md)。自动检查通过只说明文件、路径和运行命令符合提交要求，不代表统计结论正确。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面显示当日第8课，按当前场次作答。建议先自行判断，不会时请AI解释概念再作答；使用方式见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
