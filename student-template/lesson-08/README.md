# 第8课 · 多表数据整合与统计指标核查

**以下数据全部为教学合成数据，不代表真实机构、个人或实际效果。** 可以全程使用AI提出候选问题、编程、分析、写作和协助提交；你需要确认最终采用的选择，核对结果、依据和适用范围。无需提交AI对话或证明代码由谁输入。先阅读[知识准备](LEARN.md)，再展开正式分析。

## 项目背景与数据

管理者需要合并两期的运营报告，展示工单办理、满意度、接触工作量与计划工时。直接连接全部CSV可能重复计算或遗漏记录；你要建立能按期更新的流程，并依据核对结果决定发布范围。

使用 `data/service/` 七张表：第一期工单、原始第二期工单、调查、接触、窗口、业务和排班，见[数据说明](../data/service/README.md)。第一期3,600张工单，第二期1,200个工单编号；接触是一工单多行，排班是一窗口每日一行。复用第3课处理规则，不维护另一套矛盾口径。

## 分析任务

1. **列清每张表的单位、键和关系。** 区分 `ticket_id`、`contact_id`、窗口与日期联合键，声明各输出表是工单、接触还是窗口日。核对字典与调查键，预期一对多扩展不等于新增工单。
2. **整合两期并计算三种层次指标。** 清理第二期重复、修订、单位和未知值后与第一期合并。选择对容量、流程或体验有用的指标，同时处理工单级结果、接触级工作量与窗口日排班。
3. **执行数据检查。** 至少针对一项重复计算或遗漏问题编写并运行检查，提交结果；同时核对连接前后工单数、接触数、关键总量和未匹配量。先按目标层次汇总再连接，不能只修复去重计数却继续使用被隐式加权的均值。
4. **说明未匹配及时间范围的影响。** 未知窗口工单可按字段有效性留在总体报告，具体窗口报告中单列；已知窗口缺排班、缺整条调查登记、无回答是不同问题，不能一律删除或填0。
5. **形成可发布报告。** 对每个指标说明单位、有效分母、范围和暂缓发布的部分，给出下一期异常处理或更新条件。程序能运行不是发布充分条件。

## 日期与计划工时

工作量按接触实际日期理解，不能把跨日接触自动算在工单登记日。实际办理窗口没有记录时，按工单窗口归属接触工作量需要说明假设或补充字段。

报告整个计划期容量时，要保留该期有排班但无工单的窗口日；只从工单出发连接可能遗漏它们。确认无业务才可将业务计数设0，数据缺失或接口失败不能当零业务。计划人时只在每个唯一窗口日累计一次；接触工作人员分钟先换算成人时才可作量纲一致的比较。计划工时不等于实际劳动时间，不能称为个人生产率。

## 成果与模块代表作

提交完整报告、整合程序、键与关系说明、至少一项已执行检查、数量/总量核对及未匹配影响。两期与三种记录层次均须处理，不要求数据库、网站或全部检查采用同一种实现。

在本课报告末，从**第3—8课中选一件模块一代表作**，写出计划修订的统计理由。代表作不必是第8课，也不要求今天重做六课。修订截止下一次课开始前，保留原 `v2-lNN-final`，修订使用 `v2-lNN-revision-1`；修订用于质量评价，不改变原按时完成分。详见[成果与评分](../docs/ASSESSMENT.md)。

进一步完善在于量化未匹配对不同指标的影响，明确新一期变化时何时停止发布；不能以零未匹配或漂亮界面代替统计依据。

## 90分钟建议安排

0—12分钟连接小例子；12—25分钟单位与键；25—54分钟整合、检查和指标；54—68分钟发布决定及代表作选择；68—75分钟核对提交；75—90分钟自查。复用已有处理和汇总工具，不削去关键检查。

## 运行、核对与提交

以下“仓库根目录”指你自己的学生仓库中包含 `scripts/`、`data/` 的目录；在合并资料库中阅读时，对应 `student-template/`。先运行：

```bash
python scripts/course.py start 08
python scripts/course.py run 08
```

`analysis.py` 是可运行的数据概览，不是完整项目答案。按问题修改或替换它，将关键数值结果和图表写入本课 `artifacts/`，在 `report.md` 中引用。可以调整报告结构，不能只保留提示或粘贴默认输出。原始数据不改写；新增依赖写入 `requirements.txt`。

完成后，在本课 `submission.json` 中将 `status` 设为 `complete`，填写 `report`、支持结论的 `artifacts` 和非空命令参数列表 `run`。所有路径相对于学生仓库根目录。再执行：

```bash
python scripts/course.py run 08
python scripts/course.py check 08
git diff --check
git status
git diff
git add lesson-08 requirements.txt
git diff --cached
git commit -m "完成第08课项目"
git push
git tag v2-l08-final
git push origin v2-l08-final
```

**`run` 执行分析；`check` 只检查完成声明、路径和文件是否存在且非空，不会重新运行分析或判断结论。** 推送后查看 Actions 的重跑结果；配置了重现检查时，它会在临时副本移除所列结果文件、运行程序并比较内容。固定随机种子、排序和输出精度，避免将带生成时间的文件列入逐字节比较。程序运行成功和文件检查通过，都不等于统计解释正确。

新增共用程序也须核对后纳入提交。已有最终标签不要覆盖；修订保留原版本。网络、环境或检查故障时保存本地文件与提交，向教师说明，不把失败写成已通过。完整步骤见[项目工作流](../docs/WORKFLOW.md)和[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第8课。建议先作答A，再学习不熟悉的概念，完成B并阅读反馈；AI始终可用，无需提交对话记录。自查正确率用于反馈，不直接计分，详见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
