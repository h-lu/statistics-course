# 第8课可选支持

本页提供遇到困难时可查阅的小例、检查方法和提示。先明确自己的分析问题，再选择需要的帮助，之后回到 [README.md](README.md) 完成自己的方案。工具、例子和分析顺序都可以调整。

## 先明确要提交什么

分析需要覆盖两个时期，并在工单、接触和窗口日三个层次给出与报告用途有关的结果。说明至少两个重要决定及理由，展示实际执行的核对和一种合理替代方案的比较，写清结论的适用范围。只运行数据概览还没有完成标准任务。

## 核心概念在哪里查

主键用来识别记录，分析单位说明统计结论针对谁。一张工单有多次接触时，连接后的多行会让这张工单被计算多次，从而改变等待均值的权重。排班量则按“日期＋窗口”累计，每个窗口日只计一次。左连接与内连接保留的对象可能不同；缺失信息对不同指标的影响也可能不同。概念解释与完整手算见 [LEARN.md](LEARN.md)，可按需要查阅。

## 基础练习（可信起点）

**不确定是否读到了数据时：** 在学生仓库根目录运行 `python3 scripts/course.py start 08` 和 `python3 scripts/course.py run 08`，再打开 `lesson-08/artifacts/starting_overview.json`。它列出七张表的行数和不同键值数。例如，第二期导出有1,265行、1,200个不同工单编号。这个差异说明编号重复，但还没有解释重复的原因，也没有证明其他表的键都有效。

**不理解分析单位时：** 可先核算 [LEARN.md](LEARN.md) 中等待2分钟和10分钟的两张工单，或运行 `python3 lesson-08/experiments.py duplication`。结果在 `lesson-08/artifacts/experiment_duplication.json`。核对等待均值6分钟、按接触行计算的4分钟、只改分母后错误得到的8分钟，以及接触耗时16工作人员分钟。前三项与后一项测量什么，为什么不能互相替代？如果不同工单的等待恰好相同，能按等待数值去重吗？

**不确定怎样处理原始记录时：** 可选一张第二期工单，查看数值最大的 `export_revision`（导出修订版本号）和原始等待单位。说明怎样识别缺失编码、把有效秒数换成分钟，并让处理后的值能查回源字段。某个字段缺失，是否必然使其他字段也无法使用？记录和核查方法由你选择。

## 标准任务（本课应完成）：可选问题提示

以下问题帮助检查自己的方案，不规定分析方法或执行顺序：

- 报告要描述哪类对象？所选指标怎样支持报告用途？哪些资料只用来说明背景？
- 哪两项决定会改变对象、权重、分母或日期范围？替代方案为什么也有依据？
- 如何检查连接是否重复计算工单或排班？是否可能只改了分母，分子仍然重复？
- 接触分钟怎样分为已归属窗口和未归属窗口两部分？汇总前后的差额能否解释？
- 调查登记缺失与受邀后无回答分别影响什么？窗口未知的工单还能用于哪些总体描述？
- 保留哪些日期、怎样处理未知排班量，会如何影响人员安排报告？排班计划能支持什么解释？
- 改用另一种合理方案后，建议是否改变？若不变，已检查的是哪些条件和数据范围？

`read`、`unique_index` 和 `group_totals` 是通用函数，可按需调用。清洗规则、指标和完整分析由你确定，可以请AI编程，也可以使用其他已有工具。成果文件可以按自己的分析组织，不要求得到某一套固定指标或数值。

## 提高与拓展（提前完成后）

[EXERCISES.md](EXERCISES.md) 提供未匹配记录（`unmatched`）、版本冲突（`revision`）和排班范围（`staffing`）的小例。这些命令只演示另设数据。可以改写例子或提出更适合自己报告的问题：先确定新的统计疑问，再寻找计算依据并解释结果。拓展案例数量由你决定。

## 技术问题与数字冲突怎样排查

命令出错时，先确认当前目录中有 `scripts/` 和 `data/`，再核对Python命令、文件路径、退出状态和本次输出。旧结果文件仍然存在，不表示本次程序已运行成功。

数字不一致时，可检查所用记录和单位，再检查键、连接关系、修订版本与分母。未知值需要标明；分母为0时，均值或比例未定义。保留错误信息，不手工改结果来掩盖问题。

## 提交前自检

原始CSV是否未改？结果是否完成了标准分析？至少两个重要决定能否说明理由？每个指标是否写清对象、分母、单位和时期？替代方案是否实际计算过？未匹配记录的处理能否解释？

`submission.json` 中的 `run` 应能从原始数据重新生成 `artifacts` 所列结果。修改命令后，再运行 `run` 和 `check`，提交前查看暂存内容。保留原有 `final` 标签。详细操作见 [工作流](../docs/WORKFLOW.md)。
