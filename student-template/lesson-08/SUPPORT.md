# 第8课支持路线：多表连接后怎样避免重复计算

## 先知道今天要交出什么

基础练习帮助你认清七张表的记录单位、主键和一对多风险；标准任务要求完成两期追加、三个分析层次、程序检查、未匹配影响和发布建议；提高与拓展只在标准任务完成后进行。

## 先做一个小判断

一张工单有三次接触，连接后出现三行，它还是一张工单还是三张？如果直接平均等待，哪张工单会被重复计权？

## 核心概念与原理

- **主键**唯一识别一条记录；窗口排班需要“窗口编号＋日期”的**联合主键**；
- **连接**按共同字段对应不同表；一对多连接会增加行数；
- **追加**把同类记录按行放在一起，与连接不同；两期工单应先清洗再追加；
- **左连接**保留左表记录，**内连接**只保留匹配记录；左连接也不能自动防止重复；
- 汇总前必须先回到合适的分析单位，否则工单会按接触次数重复计权。

## 基础练习（可信起点）：入门跟做

### 1. 画出表关系

运行：

```bash
python scripts/course.py start 08
python scripts/course.py run 08
```

打开 `lesson-08/artifacts/starting_overview.json` 中的 `inventory`，为七张表写“一行代表什么”和“预计主键是什么”。把工单、调查、接触、窗口和排班画成箭头，标出一对一或一对多。

**成功信号：**你能解释每张表的 `proposed_key` 和 `unique_keys`，并指出第二期原始工单表为什么还不能直接当作一行一张不同工单。

### 2. 手算重复平均

T1等待2分钟，有三次接触；T2等待10分钟，有一次接触。按工单平均是 `(2+10)/2=6` 分钟；直接连接后平均是 `(2+2+2+10)/4=4` 分钟，因为T1被算三次。把行数去重后再除也不能修复重复总和。

## 入门反思

指出手算例子中哪一步改变了分析单位，哪张工单因此获得更大权重。再说明一项能在程序中自动发现这种风险的数量核对。

## 标准任务（本课应完成）

### 3. 先汇总再连接

先把接触按工单汇总：T1三次、9工作人员分钟；T2一次、7分钟。再与工单一对一连接，保留2张工单的等待和16工作人员分钟。人时要把工作人员分钟除以60；排班每天只累计一次。

### 4. 报告未匹配记录

窗口未知、已知窗口缺排班、缺调查登记、无回答和接触找不到工单要分别统计。不能全部删除或填0。至少写一项程序检查：连接前后数量、总量或重复键检查，并报告实际结果。

完成后对照 README，确认已经处理两期追加、工单/接触/窗口日三个层次、至少一项实际执行的检查、未匹配影响和范围明确的报告，并完成模块代表作选择。`check` 通过不能证明连接关系和统计量正确。

## 提高与拓展（提前完成后）

先反思：一个均值没变能否证明没有记录丢失？如果有排班但没有工单，整个计划期的业务量能否直接删掉这一天？完成标准任务后，可任选一项：为每次连接建立自动检查表；比较左连接与内连接的覆盖影响；从一个发布数字反向追踪到输入记录；或独立复算三个层次各一个指标。新增检查要说明发现和建议变化，不能只连接更多表。

## 卡住时按顺序排查

先确认每张表的一行代表什么，再决定连接顺序；出现行数增加时不要马上删重复，先判断是否是一对多。
