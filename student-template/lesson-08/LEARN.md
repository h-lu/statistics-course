# 知识准备 · 连接正确才能汇总正确

## 数据表之间的关系也是统计问题

数据库连接不是纯粹技术准备。一次连接可能让同一工单重复三次，从而改变均值、比例和总量。如果没有先确定每张表的记录层次，程序即使不报错，也可能计算了另一个目标量。

## 必须理解

| 概念 | 含义 | 本课检查 |
|---|---|---|
| 主键与联合主键 | 唯一识别一行的字段或字段组合 | 工单编号；排班的窗口＋日期，单独窗口不唯一 |
| 连接基数 | 一对一、一对多或多对多的关系 | 工单到调查为一对一，工单到接触为一对多 |
| 分析单位与记录层次 | 每行代表的统计对象或汇总层次 | 工单指标、接触工作量和窗口日工时不能直接混算 |
| 连接造成的重复计算 | 一对多连接让原表中的同一观测值重复出现 | 连接后的工单均值会按接触次数隐式加权 |
| 核对与未匹配 | 检查连接前后数量、总量及未连上的对象 | 行数变化需解释，关键总量需守恒或说明范围变化 |

左连接保留左表记录，未匹配的右侧字段为空；内连接只保留两侧都匹配的记录。哪一种适合要看目标，不是“内连接更干净”。右表键不唯一时，两种连接都可能扩增左表行。

## 微型例子

工单T1等待2分钟、T2等待10分钟；T1有三次接触，工作人员分钟数为2、3、4，T2有一次接触为7。原工单平均等待＝(2＋10)/2＝6分钟。

直接连接得到四行，工单等待为2、2、2、10，其均值为4分钟。连接并未改变任何原值，却改变了工单权重。接触工作量2＋3＋4＋7＝16分钟仍应保留，但应先按工单汇总为T1的9和T2的7，再与工单指标连接。

若两张工单都属于同一窗口日，该日排班8工时不能在每张工单上重复相加成16工时。先在窗口日层次汇总工单和接触，再连接排班，才能比较相同记录层次的量。

## 回到项目

为输入表列出键、单位、预期关系。连接前验证唯一性，连接后检查未匹配与行数变化。每个指标要能解释其分母；使用去重计数只能修补部分计数，不能自动修复已被加权的均值或重复的工时总量。

## 借助AI分析与进一步学习

AI可以实现SQL、pandas或标准库连接，不要求搭建数据库。可运行检查应覆盖键的唯一性、原始工单的保留情况、接触总量守恒、排班不重复和未知窗口的保留情况。可以进一步学习多表结构设计以及如何追溯数据处理过程；本课更看重能否说明报告数字的来源与计算方法。

模块代表作修订时，优先改进数据单位、结论依据与适用范围，而非只换图表颜色。可以请AI用订单、订单明细、门店日营业时长举新例子，问你哪些量可以直接相加。
