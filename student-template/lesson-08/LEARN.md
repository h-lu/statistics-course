# 第8课知识准备 · 合并数据表后，怎样避免重复计算

一张工单可能对应多次服务接触。把两张表合并后，工单可能出现多行。即使每个原始值都没变，均值和总量也可能算错。本课学习先说明每行代表什么，再连接和汇总。

## 先做一个小判断

一张工单有三次接触，连接后出现三行，它还是一张工单还是三张？先写下你的答案。

## 1. 先认识主键和连接关系

**主键**是能唯一识别一条记录的字段，或字段组合。整理后的工单表可以用工单编号作主键；第二期原始导出还需先处理同编号的重复与修订记录，不能一看到编号重复就把全部重复编号的工单删掉。排班表需要“窗口编号＋日期”共同识别一行，称为**联合主键**。单独一个窗口会在不同日期重复。

用共同字段把表对应起来，称为**连接**。一张工单对应一条调查登记，是一对一关系；对应多次接触，是一对多关系。这类数量关系也称**连接基数**。一对多连接后行数增加，不表示增加了真实工单。

**左连接**保留左表记录，没有匹配到的右表信息为空；**内连接**只保留两表能够匹配的记录。右表对应多行时，两种连接都可能增加行数，因此左连接也不能自动防止重复计算。

### 两期工单先按行追加，其他信息再按编号连接

两期工单是不同时间发生的不同记录。先处理第二期的重复和修订，统一两期字段与单位，再把第二期记录接在第一期后面，称为按行追加。追加完整两期时，应有3,600＋1,200＝4,800张工单，还需检查两期编号是否重叠。后续某项指标排除记录时，再说明数量和原因。

这与按编号连接其他表不同：追加是把同类记录放在一起；连接是把同一对象在不同表中的信息对应起来。两期工单编号本来不重合，不能通过内连接寻找共同工单来整合两期。调查、窗口等信息则应按对应编号连接。

## 2. 两张工单为什么会得到两个均值

另设同一窗口同一天的两张工单：T1等待2分钟，T2等待10分钟。T1有三次接触，工作人员耗时分别为2、3、4分钟；T2有一次接触，耗时7分钟。

按工单计算，平均等待为(2＋10)÷2＝6分钟。

| 工单 | 接触耗时（工作人员分钟） | 连接后出现的等待时间（分钟） |
|---|---:|---:|
| T1 | 2 | 2 |
| T1 | 3 | 2 |
| T1 | 4 | 2 |
| T2 | 7 | 10 |

直接对连接后的等待求均值，得到(2＋2＋2＋10)÷4＝4分钟。T1被算了三次，T2只算一次，相当于按接触次数给工单加权，不再是每张工单权重相同的平均。

只把工单数改成去重后的2，也不能修复已经重复的等待总和：16÷2＝8分钟仍然错误。

## 3. 先汇总到合适的分析单位

先按工单汇总接触：T1为3次接触、9工作人员分钟；T2为1次接触、7工作人员分钟。再与工单表一对一连接，就能同时保留2张工单、4次接触、16工作人员分钟，以及6分钟的平均等待。

不同接触的耗时可能相同，不能仅按相同数值删除记录。是否重复要根据记录编号及含义判断。

假设该窗口当天计划安排 **8 人时**，例如2名工作人员各工作4小时，合计8人时；不是说这个窗口必须开放8小时。排班属于一个窗口的一天，只应计一次。在两张工单上各加8会得到16，在四次接触上各加8会得到32，都是重复累计。工作人员分钟除以60才与人时单位一致；计划工时也不等于实际劳动时间。排班表中，计划有效工时按“人数×每人开放小时−当天合计缺勤工时”计算；缺勤工时已经是合计数，不要再乘一次人数。

## 4. 未匹配记录不能悄悄消失

另加T3：等待6分钟、窗口未知，有一次5分钟接触。全体有3张工单、5次接触，工作量21分钟，平均等待仍为6分钟。

能够归属到已知窗口的部分只有2张工单、4次接触、16分钟；另有1张工单、1次接触、5分钟待核实。全体与已匹配部分的均值恰好相同，也不能证明没有遗漏，所以还要核对数量和总量。

如果再有一天安排8人时却没有工单，两天计划工时应为16人时。报告整个计划期时，应从该期排班记录出发连接业务汇总，保留没有工单的日期。只有确认没有业务时才能将数量记为0，数据缺失不等于零业务。

## 5. 日期和分母也要分别核对

工单登记日期 `date` 与接触发生日期 `contact_date` 含义不同。接触跨日时，每日工作量要按接触实际日期汇总。若没有实际接触窗口字段，还需说明用工单窗口归属工作量所作的假设。

满意比例应以有评价的有关工单为分母，不能用接触行数。窗口未知、已知窗口缺排班、缺整条调查登记、已有登记但无回答，是不同问题，应分别记录。

## 可选例子：把核对要求写成程序

可以先选择一项明确的检查，例如“整理后的每个工单编号只能出现一次”。下面代码对两张示例工单检查编号；如果把列表改成 `["T1", "T1"]`，就会报告问题。`set` 表示只保留不同编号的集合，`len` 表示数量。

<details>
<summary>展开编号检查代码</summary>

```python
# cold-read-check
ticket_ids = ["T1", "T2"]
if len(ticket_ids) != len(set(ticket_ids)):
    raise ValueError("整理后的工单编号重复，请检查重复记录或连接过程")
print(f"编号检查通过：{len(ticket_ids)}张工单没有重复编号")
```

</details>

这个检查只验证编号是否重复，不检查编号是否缺失，也不证明等待均值、接触耗时或排班工时都正确。输出数量由 `len(ticket_ids)` 计算，换成其他数量的记录后会随之改变。正式项目应把示例编号换成实际读取的编号，并记录检查结果；也可以选择与你的分析更有关的总量或未匹配记录检查。

## 用Python核对例子（可选）

先读懂上面的计算，再按需要运行代码。代码只使用学习例子，不读取项目数据；不要求逐行背诵。

<details>
<summary>展开核算代码</summary>

```python
# learning-example
import json
waits = {"T1": 2, "T2": 10}
contacts = [("T1", 2), ("T1", 3), ("T1", 4), ("T2", 7)]
expanded = [waits[ticket] for ticket, minutes in contacts]
result = {"ticket_mean": sum(waits.values())/len(waits),
          "expanded_mean": sum(expanded)/len(expanded),
          "wrong_sum_over_distinct": sum(expanded)/len(waits),
          "contact_minutes": sum(minutes for ticket,minutes in contacts),
          "planned_day_hours": 8, "wrong_ticket_hours": 8*len(waits),
          "wrong_contact_hours": 8*len(contacts),
          "all_mean_with_unknown": (sum(waits.values())+6)/(len(waits)+1),
          "all_minutes_with_unknown": sum(m for t,m in contacts)+5,
          "two_day_plan": sum([8,8])}
print(json.dumps(result, ensure_ascii=False, allow_nan=False))
```
