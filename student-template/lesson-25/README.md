# 第25课 · 预测性能与模型维护成本

## 项目背景

工单处理时长预测要长期运行。workload需要每日人工更新，单条更新成本设为0.5单位；仅用低维护字段的方案成本为0。你需要比较预测误差与维护成本，帮助负责人判断是否值得为更高的预测精度增加日常维护工作。

比较简单模型、复杂模型，以及关键输入缺失时可用的备用模型。分别报告预测误差和维护成本，并说明条件变化时如何调整选择。

可用资料为[预测分析数据集](../data/prediction/README.md)中的`requests.csv`。**资料全部为教学合成数据。** 数据字典说明记录单位、字段、时点和局限；同时阅读`feature_availability.csv`。你可以全程使用AI完成编程、分析、写作与提交，也可以复用前课代码。

## 任务分层

本课沿用[第24课的数据划分、无泄漏流程与评价记录](../lesson-24/README.md)。第一次做这一类项目时，按[陪做支持](SUPPORT.md)完成每一步；概念解释见[知识准备](LEARN.md)。

### 基础练习（可信起点）

1. 在同一月0—11开发、12—15验证范围内，比较一个简单基线和一个增加结构的模型。
2. 分别记录平均绝对误差（单位为分钟）与字段维护成本（单位为情境损失单位），不要直接相加。
3. 移除 `workload` 后重新运行一次，确认备用方案能够在该字段缺失时真正生成预测。

基础练习帮助你得到可信的第一份结果，**并不等于已经完成本课**。继续完成下面的标准任务，才能把计算变成可使用的统计结论。

### 标准任务（本课应完成）

1. 复用0—11开发、12—15验证；比较简单基线、具有实质改进的模型和去掉高维护字段的方案。不限具体算法，但需说明增加结构解决了什么统计问题。

2. 检查正则化强弱、训练范围变化或相关变量取舍如何影响验证误差及关键特征稳定性。重复试验只用开发资料，不能把重复使用的16—19月当新的独立确认。

3. 模拟workload不能提供、输入范围变化或部分字段缺失的使用情境；实现一个可运行的备用分析程序，并比较它与正常方案的后果。

4. 形成性能—维护成本报告：给出采纳条件、可接受误差和降级触发规则；不要把分钟误差与成本单位直接相加，除非明确给出转换依据。

以上均为本课需要完成的任务，分析方法和报告形式可以自行选择。评价不以图表或模型数量为依据。使用外部资料时注明来源，补充的业务假设应明确标注，不得当作已知事实。

### 提高与拓展（提前完成后）

完成标准任务后，从下面选择一项深入；重点是改善证据或决策，不按代码、图表或模型数量评价。

- 改变正则化强度或训练窗口，检查关键特征和验证误差的稳定性。
- 为“误差改善多少才值得0.5单位维护成本”建立情境表，而不是假定唯一换算。
- 模拟输入范围超出开发资料的情况，制定降级、人工复核或暂停规则。

## 示例代码与运行方法

从仓库根目录运行：

```bash
python scripts/course.py start 25
python scripts/course.py run 25
```

本课`analysis.py`读取数据并生成`artifacts/starting_summary.json`，用于熟悉数据结构。**请在此基础上完成本课分析任务，形成自己的分析方案和结论。** 可使用Python标准库、numpy/scipy、pandas、statsmodels、scikit-learn或其他合适工具；说明新增依赖与运行命令。

## 成果要求与提交

- `report.md`：面向报告使用者，写清分析问题、方法依据、主要结果、适用范围和建议。
- 可复现的分析程序或研究设计文件，以及报告引用的计算结果和图表；不要手工修改原始数据。
- `submission.json`：将`status`设为`complete`，`report`指向分析报告，`artifacts`列出支持报告结论的结果文件路径，`run`填写可复现分析的命令。

仅运行示例代码或粘贴模型输出，还没有完成本课分析任务。合格报告应分别列出预测误差与维护成本，并提供可运行的备用方案；更好的报告还会说明何时值得增加维护成本，并实际检验输入缺失时的预测表现。

完成后执行`python scripts/course.py check 25`，按[项目工作流](../docs/WORKFLOW.md)提交并创建`v2-l25-final`标签；有修订时保留原标签。自查按[知识自查说明](../docs/KNOWLEDGE_CHECK.md)进行。项目分析允许全程使用AI，不要求提交AI对话记录。
