# 第30课陪做支持 · 时间序列预测与容量规划

这份材料帮助你在不知道下一步时建立可信起点。它不提供本课正式数据的答案，也不能代替 [README 主任务](README.md)；概念的完整解释见 [LEARN.md](LEARN.md)。

## 先知道今天要交出什么

- `report.md`：排班团队可执行的四周容量与复核规则。
- 逐个历史预测时点保存的点预测、实际值、误差和预测区间。
- `submission.json`：列出回测结果和排班简报。

最低出口是：别人能够按你的命令重新生成报告引用的数字，并知道这些数字可以和不可以用于什么决定。

## 核心概念与原理

| 规范术语 | 通俗解释 | 怎样在自己的结果中检查 |
|---|---|---|
| 趋势 | 需求随较长时间持续上升或下降。 | 决定基线能否只沿用近期水平。 |
| 季节性 | 按较固定周期重复的需求模式。 | 比较上一周期同周等季节基线。 |
| 滚动回测 | 在多个历史时点，只使用当时可见资料预测之后的周。 | 模拟真实四周排班。 |
| 平均绝对误差（MAE） | 预测误差绝对值的平均，单位是需求件数。 | 比较点预测准确度。 |
| 预测区间 | 给未来单周需求可能范围；比平均需求估计区间包含更多个体波动。 | 设置容量余量并检查覆盖率。 |

### 先用一个小例子想清楚

站在第100周，只能使用第0—100周已经知道的资料预测101—104周。四周后再把预测起点移到第104周，预测105—108周。若预测104周时先读取104周真实需求，就发生时间泄漏。

这个例子只用于核对概念，不是正式数据的结论。正式项目必须使用自己的运行结果。

## 基础练习（可信起点）：入门跟做

以下命令都从仓库根目录运行，也就是同时能看到 `scripts/`、`data/` 和 `lesson-30/` 的目录。

```bash
python scripts/course.py start 30
python scripts/course.py run 30
```

第二条命令成功后，应看到终端提示结果已经生成，并能打开 `lesson-30/artifacts/starting_summary.json`。这个文件只是数据起点，不是本课完整答案。

若终端明确提示 `python: command not found`，按仓库首页说明，把上面两行开头的 `python` 换成 `python3`，其余内容不变。

### 第1步：画出时间线

- **动作：** 运行起点程序，按 `week` 排序；把80—115、116—131、132—155标成开发、区间校准和独立评价的**目标周**。
- **目的：** 时间资料不能随机拆分，预测时点与目标周也不能混为一谈。
- **成功信号：** 周次无重复乱序；标准路线从第79周末开始，每四周移动一次预测时点，三段用途写入报告。
- **想一想：** 节假日标记在预测时点是否已经知道？

### 第2步：做一次手工历史预测

- **动作：** 任选开发期预测时点，用简单朴素法预测随后四周，记录预测时点、目标周、跨度、预测和实际值。
- **目的：** 先理解一条回测记录怎样产生。
- **成功信号：** 四个目标周都晚于预测时点，且输入只来自当时以前；下一个标准预测时点比当前晚四周。
- **想一想：** 第1周与第4周预测的误差应否分开查看？

### 第3步：滚动比较两种方法

- **动作：** 按每四周一次的相同预测时点，比较简单基线与趋势/季节方法，并按预测跨度汇总MAE。
- **目的：** 方法比较必须面对相同的真实预测任务。
- **成功信号：** 结果表保留每条历史预测，不只有一个平均分。
- **想一想：** 复杂模型在哪个跨度有实际改善？

### 第4步：校准并独立评价区间

- **动作：** 只用116—131周误差确定区间宽度，在132—155周计算覆盖率和平均宽度。
- **目的：** 区间校准和评价需要分开。
- **成功信号：** 评价期区间未被事后改宽，覆盖率分母清楚。
- **想一想：** 覆盖不足时应调整容量、复核规则，还是事后修改历史结论？

完成这四步后，你已经有可信起点，但还没有完成整项主任务。

## 标准任务（本课应完成）

回到 [README](README.md) 完成全部标准任务，特别核对：

- 固定每四周一次的预测时点、随后四周的跨度和输入可得时点。
- 用滚动回测比较有意义的基线与候选方法。
- 分开区间校准和独立评价，报告覆盖率与宽度。
- 将预测与容量规则相连，区分异常、输入错误和结构变化。

把程序输出翻译成完整统计句子：对象是谁，比较什么，数值和单位是什么，哪些假设成立时可以怎样使用，哪些结论仍不能作出。

## 提高与拓展（提前完成后）

先完成标准任务，再选一项。提高的标准是让证据、适用范围或行动更可靠，而不是增加代码或图表数量。

- 按预测跨度分别设置容量余量。
- 建立连续低估后的结构变化复核规则。
- 引入不对称成本比较预测最优和决策最优。

## 卡住时按顺序排查

- **回测分数异常好：** 检查是否在每个预测时点重新拟合，以及特征、平滑参数或标准化是否使用了未来周。
- **覆盖率很低：** 先核对校准期和评价期是否分开、跨度是否混合，再讨论漂移或区间方法。
- **命令提示找不到文件：** 先运行 `pwd`，确认当前位置是仓库根目录；这里应同时看见 `scripts/` 和本课目录。
- **程序能运行但结果还是旧的：** 检查结果文件的修改时间，确认修改并运行的是本课 `analysis.py`；必要时删除自己生成的旧结果后重跑，但不要删除原始数据。
- **报告数字和程序输出不一致：** 从报告中的一个关键数字反向找到结果文件、筛选范围、分子和分母；不要手工把报告改成“看起来合理”的数字。
- **不知道怎样开始写报告：** 先写五句：谁使用、要决定什么、数据覆盖谁、一个主要结果、一个不能支持的结论，再补方法和证据。
