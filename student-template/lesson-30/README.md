# 第30课 · 时间序列预测与容量规划

## 项目背景

排班团队要每四周更新未来四周的容量计划。节假日安排已知，但未来真实需求未知；漏配与闲置均有代价。负责人需要一套能按历史时点检验表现的预测和预警方案。

哪种方法在真实预测时点表现可接受？预测区间如何影响容量和异常判断？

可用资料为[政策与决策数据集](../data/policy/README.md)中的`weekly_demand.csv`。**资料全部为教学合成数据。** 数据字典说明记录单位、字段、时点和局限；你可以全程使用AI完成编程、分析、写作与提交，也可以复用前课代码。

## 分析任务

1. 固定预测时点、四周预测跨度与所需输入，比较有业务意义的简单基线和趋势/季节方法。所有参数只能由预测时点之前的数据学习。

2. 用滚动回测选择方法：建议80—115周用于模型开发与评价，116—131周用于预测区间校准，132—155周用于按时间顺序独立评估；保留每次的预测时点、目标周和实际误差。不能随机打乱周次。

3. 构造预测区间并说明计算方法，评价覆盖率与区间宽度，并对后期误差变化解释可能的漂移。给出容量上下界或复核规则，不把一个点预测包装成确定需求。

4. 提交排班简报和可复现的历史预测评估程序，区分正常波动、输入错误和可能的结构变化。若认为政策改变需求，要说明那是另一项因果问题，不能只凭预测残差归因。

以上均为本课需要完成的任务，分析方法和报告形式可以自行选择。评价不以图表或模型数量为依据。使用外部资料时注明来源，补充的业务假设应明确标注，不得当作已知事实。

## 课堂安排（90分钟）

- 0—12分钟：阅读[知识准备](LEARN.md)和项目背景，明确分析问题；需要时可延长到17分钟，相应减少重复操作和排版时间。
- 12—55分钟：选择方法、开展分析或研究设计，并比较不同方案；遇到不熟悉的概念可随时查阅知识准备或询问AI。
- 55—68分钟：核对一项主要结论的计算结果、假设与替代解释，完成分析报告。
- 68—75分钟：重新运行程序，检查结果并提交；提前完成时，可进一步检验报告中的重要结论。
- 75—90分钟：[知识自查](https://hblu.top/stat-check/)，确认页面为当日V2课次，建议先完成A版基础题，再向AI学习不熟悉的概念，随后完成B版变式题。

## 示例代码与运行方法

从仓库根目录运行：

```bash
python scripts/course.py start 30
python scripts/course.py run 30
```

本课`analysis.py`读取数据并生成`artifacts/starting_summary.json`，用于熟悉数据结构。**请在此基础上完成本课分析任务，形成自己的分析方案和结论。** 可使用Python标准库、numpy/scipy、pandas、statsmodels、scikit-learn或其他合适工具；说明新增依赖与运行命令。

## 成果要求与提交

- `report.md`：面向报告使用者，写清分析问题、方法依据、主要结果、适用范围和建议。
- 可复现的分析程序或研究设计文件，以及报告引用的计算结果和图表；不要手工修改原始数据。
- `submission.json`：将`status`设为`complete`，`report`指向分析报告，`artifacts`列出支持报告结论的结果文件路径，`run`填写可复现分析的命令。

仅运行示例代码或粘贴模型输出，还没有完成本课分析任务。合格的历史评估应保持时间顺序，并报告预测区间覆盖率；更好的分析会根据覆盖不足的情况调整容量余量或复核规则，同时考虑实际资源约束，而不是只增加模型复杂度。

完成后执行`python scripts/course.py check 30`，按[项目工作流](../docs/WORKFLOW.md)提交并创建`v2-l30-final`标签；有修订时保留原标签。自查按[知识自查说明](../docs/KNOWLEDGE_CHECK.md)进行。项目分析允许全程使用AI，不要求提交AI对话记录。
