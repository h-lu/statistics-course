# 第29课陪做支持 · 政策效果的双重差分评估

这份材料帮助你在不知道下一步时建立可信起点。它不提供本课正式数据的答案，也不能代替 [README 主任务](README.md)；概念的完整解释见 [LEARN.md](LEARN.md)。

## 先知道今天要交出什么

- `report.md`：区分观察变化与依赖假设的政策效果解释。
- 政策前轨迹、双重差分、聚类推断和替代对照/窗口结果。
- `submission.json`：列出主要和敏感性结果。

最低出口是：别人能够按你的命令重新生成报告引用的数字，并知道这些数字可以和不可以用于什么决定。

## 核心概念与原理

| 规范术语 | 通俗解释 | 怎样在自己的结果中检查 |
|---|---|---|
| 双重差分 | 处理组前后变化减去对照组前后变化。 | 扣除两组共同的时间变化。 |
| 平行趋势 | 若没有政策，两组结果趋势应保持项目所需的可比性；这是反事实假设。 | 决定双重差分能否解释为政策效应。 |
| 事件时间 | 每个月相对政策开始月的距离。 | 查看政策前后动态。 |
| 聚类推断 | 允许同一地区各月结果相关。 | 不把864行误当864个独立地区。 |
| 干扰 | 一个地区的政策影响其他地区。 | 判断附近地区能否作为未受影响对照。 |

### 先用一个小例子想清楚

处理组从50降到44，前后变化为−6；对照组从40降到38，变化为−2。双重差分为−6−(−2)=−4，单位仍是结果指数。若对照地区也受到政策传播，−4不能直接解释为与“未实施政策”相比的效果。

这个例子只用于核对概念，不是正式数据的结论。正式项目必须使用自己的运行结果。

若终端明确提示 `python: command not found`，按仓库首页说明，把上面两行开头的 `python` 换成 `python3`，其余内容不变。

### 第1步：确认设计和权重

- **动作：** 运行起点程序，确认月18开始政策、三类地区和每地区36个月；选择等地区或按人口加权。
- **目的：** 目标权重决定估计回答“典型地区”还是“典型居民”。
- **成功信号：** 报告写明处理组、对照候选、时点和权重。
- **想一想：** 中途改变权重会把目标问题变成什么？

### 第2步：先看政策前轨迹

- **动作：** 画月0—17三组趋势，记录明显水平差和趋势差。
- **目的：** 平行趋势关心的是无政策反事实下的趋势可比性。
- **成功信号：** 图上标有政策时点，各组采用一致权重。
- **想一想：** 事前检验不显著能证明平行趋势吗？

### 第3步：复算双重差分

- **动作：** 选定前后窗口，手工复算组均值变化，再用面板模型或等价方法估计。
- **目的：** 确保模型系数与基本差分定义一致。
- **成功信号：** 手算与程序估计在相同权重和窗口下相符。
- **想一想：** 地区月度行之间为何不是全部独立？

### 第4步：更换合理对照或窗口

- **动作：** 比较附近/远处对照或另一窗口，加入事前安慰剂或事件时间检查。
- **目的：** 检验结论对干扰和背景差异的依赖。
- **成功信号：** 替代结果与主要结果并列，并解释变化。
- **想一想：** 哪一种变化会让政策效应表述降为观察性证据？

完成这四步后，你已经有可信起点，但还没有完成整项主任务。

## 卡住时按顺序排查

- **程序估计和手算差异很大：** 先核对前后窗口、对照组、权重以及模型中的固定效应；不要先调整到数值相同。
- **命令提示找不到文件：** 先运行 `pwd`，确认当前位置是仓库根目录；这里应同时看见 `scripts/` 和本课目录。
- **程序能运行但结果还是旧的：** 检查结果文件的修改时间，确认修改并运行的是本课 `analysis.py`；必要时删除自己生成的旧结果后重跑，但不要删除原始数据。
- **报告数字和程序输出不一致：** 从报告中的一个关键数字反向找到结果文件、筛选范围、分子和分母；不要手工把报告改成“看起来合理”的数字。
- **不知道怎样开始写报告：** 先写五句：谁使用、要决定什么、数据覆盖谁、一个主要结果、一个不能支持的结论，再补方法和证据。
