# 设备告警数据：教学合成数据

本目录由固定种子 `26090505` 生成，不包含真实设备或真实损失。脚本：`scripts/generate_alerts.py`。这组数据用于比较不同复核方案的成本与损失，金额和复核效果属于情境假设。

## 项目背景

维护团队每天收到90台设备的风险分数，工作日最多复核20台，周末最多15台。不同设备故障损失不同，复核也有成本。希望给出可以按日期执行的名单，不能把“分数高”直接等同于“最值得复核”。

| 文件 | 行数与观测单位 | 字段 |
|---|---|---|
| development.csv | 3,780条，42天×90台；每设备每日一行 | record_id唯一编号，date日期，device_id设备，risk_score 0—100分，failure_within_24h次日24小时内是否故障（0/1） |
| evaluation.csv | 1,260条，之后14天×90台，字段同上 | 时间顺序晚于方案制定期；用于方案确定后的历史数据评估 |
| devices.csv | 90台，每设备一行 | device_id主键，campus校区，device_class设备类别，miss_loss一次故障损失，inspection_cost一次复核成本，prevention_fraction复核能避免的故障损失比例 |
| daily_capacity.csv | 56天，每天一行 | date主键，batch所属时期，max_reviews当日最多复核数 |

损失与成本统一以“教学成本单位”计量，不是真实人民币报价。分数只是排序信号，`risk_score=70`不表示70%故障概率。

## 复核后果的计算约定

为了比较规则，本模拟假设每台被复核设备都支付复核成本；如它原本会故障，可避免85%的故障损失，其余15%仍发生。未复核的故障承担全部损失。不复核且不故障不产生损失。可少用名额，不能超过当日容量。

因而一条记录的情境损失为：

- 未复核：故障标记×故障损失；
- 已复核：复核成本＋故障标记×故障损失×(1−可避免比例)。

这些是给定决策假设，不能从历史数据评估结果中声称“已经证实复核具有85%的因果效果”。可分析不同效果假设如何影响决定。

## 时间与标签

所有历史记录都经过统一追踪，故障标签均可见；不存在“只有被复核者才有标签”的缺失。当前实现名单时，只能使用行动当时可知的分数、设备信息与既往数据，不能用该日未来故障标签排序。先用方案制定期提出并选择策略，再保留规则评估后一期；如看后一期后改规则，应把它标明为探索修订，不能继续称独立验证。

两期设备相同但日期不同，包含时期变化；设备日之间不保证统计独立。14天评估结果只能支持有限条件的试运行建议，不保证未来损失相同。
