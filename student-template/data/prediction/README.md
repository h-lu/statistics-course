# 预测分析数据集：工单登记信息、服务时长与升级风险

**全部为教学合成数据，不对应真实人员、设备或企业。** 由`scripts/generate_prediction.py`以固定种子2026090521生成；运行`python scripts/generate_prediction.py`可重建。

## 文件与观测单位

- `requests.csv`：5280条设备—月份记录，涉及240台设备，月份为0—23。每行是一台设备在某月的服务记录，`record_id`唯一。同一设备在不同月份重复出现，因此5280行不能视为5280台相互独立的设备。
- `feature_availability.csv`：说明各字段的含义和可得时点。预测工单升级风险时，只能使用登记工单时已经获得的信息。表中保留了事后采集的字段，供你判断信息的可用时间，不能将这些字段用于工单登记时的预测。

| 字段组 | 含义与单位 |
|---|---|
| record_id / entity_id | 记录/设备标识；E000—E199从月0起，E200—E239从月12起出现 |
| month / region | 顺序月份0—23；east/west/north三地区，不是真实地理数据 |
| backlog | 当前积压件数的平均化指标，允许小数 |
| workload / staffing_index | 当日每人预计负荷；相关的排班指数，二者不随机分配 |
| complexity | 工单登记时已知standard/complex |
| prior_failures / age_years | 已发生故障次数/设备年限 |
| sensor_quality | 0—1质量评分；空字符串表示未取得，后期可用性变化 |
| resolution_minutes | 工单办结后得到的实际时长，分钟，连续目标 |
| escalated | 工单办结后得到的是否升级处理，0/1目标 |
| after_close_minutes / satisfaction_after | 工单办结后时长与满意度；预测时不可得 |

## 连续课程的数据使用约定

月0—11有2400行；12—15、16—19、20—23各960行。L21—23只使用前16个月，保留16—19供L24首次测试、20—23供L26后续评估。L25仍用开发资料讨论复杂度；L26可以把已使用的16—19明确改作历史校准资料，但不能再称为未用测试集。文件本地可见不意味着可以用测试结果反复选模型。

## 生成背景与局限

合成数据包含工作负荷、工单复杂度和地区差异，以及非线性关系、同一设备的重复观测相关性和后期环境变化。样本不是从真实总体随机抽取，没有真实服务质量结论。生成机制用于模拟复现，不是现实因果识别证据。结果标签并不提供“复核能减少多少升级”的干预效应；成本与容量上限由各课项目背景给定。若生成机制与分析模型不同，模型诊断和泛化比较仍需用当前项目可观察到的证据解释。
