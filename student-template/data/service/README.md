# 服务中心数据：教学合成数据

本目录由固定随机种子 `26090501` 生成，不来自真实学校、企业或个人。A、B、C中心与人员编号均为虚构。生成脚本是 `scripts/generate_service.py`；生成假设只说明这个模拟情境，不证明现实中同类机制成立。

## 情境与范围

三个中心承接常规材料办理和复杂个案处理。中心业务构成、预约比例和不同时间的来访情况不同。管理者希望改善体验、安排资源并发布有依据的服务报告。办结、等待、满意度和工作量是不同目标，没有预置综合得分。

- `tickets.csv`：2026-03-02至04-10的3,600张工单，每工单一行；用于开始分析。这是已整理的基础登记，不能代表未取号者、全校人口或其他月份。
- `tickets_raw.csv`：04-13至04-24的新一期导出，1,265行、1,200个工单编号；保留重复、修订和编码问题。它与前表没有相同工单，不能用前表找“原答案”。
- `satisfaction.csv`：两期全部4,800张工单的调查登记，每工单一行；未邀请、未回答的评分为空。只分析第一期时必须限定相同工单集合。
- `visits.csv`：8,921次服务接触，每次接触一行，一张工单可能对应多次接触。
- `windows.csv`：6个窗口的字典，每窗口一行。
- `business_types.csv`：2类业务的字典，每业务代码一行。
- `staffing.csv`：240条窗口—日期排班，每窗口每日一行。

记录涵盖模拟期间全部已登记工单，不是随机抽取的全校人群样本。第一期与第二期处在不同时间，不能把时期变化直接归因于中心或个人。

## 字段与单位

| 表 | 字段 | 含义 |
|---|---|---|
| tickets / tickets_raw | ticket_id；person_id | 工单编号；来访者编号。一个人可能有多张工单。整理后的工单表中，ticket_id可作主键；原始导出允许同一工单出现重复行或修订版本，须先处理 |
| 同上 | date；arrival_period | 登记日期；上午或下午 |
| 同上 | window_id；business_code | 窗口与业务代码，用字典连接；不从字符顺序推测高低 |
| 同上 | appointment | 是否预约，1是、0否 |
| 同上 | wait_minutes | 进入队列到开始服务或放弃离开的分钟数。放弃者记录的是离开前等待，不能当成已经获得服务的等待 |
| 同上 | service_minutes | 本次面对面服务分钟数；放弃者为空，不是0分钟已完成服务 |
| 同上 | abandoned | 是否放弃排队，1是、0否 |
| 同上 | completed_same_day | 工单是否当日办结，1是、0否；这是登记结果，不直接衡量工作努力 |
| tickets_raw | wait_unit | minute表示分钟，second表示秒。原字段名不保证原值都已经统一单位 |
| 同上 | export_revision | 同工单的导出修订版本，数值较大者为更新记录；同版本完全相同的行是重复导出 |
| satisfaction | survey_id；ticket_id | 调查登记主键；关联工单 |
| 同上 | invited | 是否发出调查邀请，1是、0否 |
| 同上 | score | 对本次办理体验的1—5级评价，1非常不满意，5非常满意；空白表示没有取得评价，不是中立或0分；须结合invited区分未受邀与受邀后无回答 |
| 同上 | response_days | 回答距邀请的天数；未回答为空 |
| visits | contact_id；ticket_id；contact_sequence | 接触主键；所属工单；工单内第几次接触 |
| 同上 | contact_type；contact_date；staff_minutes | 接触类型、日期、该次接触耗用的工作人员分钟数 |
| windows | window_id；center；specialty；opened | 窗口主键、所属中心、业务范围、启用日期 |
| business_types | business_code；name；complexity | 业务主键、名称、复杂程度类别 |
| 同上 | reference_wait_minutes | 情境中的参考等待线：常规15分钟、复杂30分钟；不是统计学规定的唯一合理阈值 |
| staffing | date；window_id | 联合主键 |
| 同上 | staff_count；open_hours；absence_hours | 排班人数、每人开放小时、该窗口当天合计缺勤工时；计划有效工时为人数×开放小时−缺勤工时 |

评分空白时，先查看 `invited`：0表示未受邀；1表示受邀后无回答。整条调查登记未匹配、邀请字段缺失或字段取值互相矛盾时，应单列待核实，不能只凭评分空白猜测类别。

## 第二期导出说明

`wait_minutes`中的999与−1均是“未取得测量值”的编码，先识别编码，再做单位换算。窗口UNKNOWN、空业务代码不能自行猜测类别；空白办结状态表示结果未记录。合理的长等待不能仅因极端而删除。修订行按版本处理，不能随文件顺序取最后一行。不同指标可以使用不同有效记录集合，但必须报告分母、保留数和排除原因。

## 适用范围

是否被邀请、受邀后是否回答，都可能与办理经历有关。受邀后没有提供评价称为无回答；未受邀与无回答均会造成评分缺失，但两者含义不同。有评价工单的满意度不能自动代表全部工单。字典没有中心资源、业务难度的全部细节；分层后差异仍不是因果效果。排班是计划量，并非工作人员实际可用分钟的完整测量。多次接触既可能反映复杂程度，也可能反映返工，不能直接判定质量差。
