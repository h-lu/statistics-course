# 第24课陪做支持 · 模型比较与泛化能力评价

这份材料帮助你在不知道下一步时建立可信起点。它不提供本课正式数据的答案，也不能代替 [README 主任务](README.md)；概念的完整解释见 [LEARN.md](LEARN.md)。

## 先知道今天要交出什么

- `report.md`：分别回答“已知设备未来记录”和“全新设备”的表现。
- 固定的数据用途时间线、完整预处理流程、候选模型比较与一次独立测试结果。
- `submission.json`：记录可重跑命令和实际引用的结果。

最低出口是：别人能够按你的命令重新生成报告引用的数字，并知道这些数字可以和不可以用于什么决定。

## 核心概念与原理

| 规范术语 | 通俗解释 | 怎样在自己的结果中检查 |
|---|---|---|
| 训练资料 | 用于拟合模型和预处理参数的数据。 | 月0—11。 |
| 验证资料 | 用于比较候选方案、阈值和超参数的数据。 | 月12—15。 |
| 测试资料 | 方案冻结后只评价一次的数据。 | 月16—19首次用于本轮测试；看过后不能再称从未使用。 |
| 数据泄漏 | 预测时不可得的信息或评价资料的信息进入拟合、预处理或选择。 | 检查字段时点、插补、尺度变换和特征选择。 |
| 泛化场景 | 已知设备的未来记录与全新设备是两个不同目标。 | 决定时间切分和按设备分组方式，并记录设备结果是否参与过模型选择。 |

### 先用一个小例子想清楚

设备甲有10个月记录。若把前8个月放训练、后2个月放测试，可以评价已知设备未来记录；若随机按行拆分后声称评价“新设备”，训练中已经见过设备甲，结论就不成立。评价新设备时应把一台设备的所有记录放在同一侧。

这个例子只用于核对概念，不是正式数据的结论。正式项目必须使用自己的运行结果。

## 基础练习（可信起点）：入门跟做

以下命令都从仓库根目录运行，也就是同时能看到 `scripts/`、`data/` 和 `lesson-24/` 的目录。

```bash
python scripts/course.py start 24
python scripts/course.py run 24
```

第二条命令成功后，应看到终端提示结果已经生成，并能打开 `lesson-24/artifacts/starting_summary.json`。这个文件只是数据起点，不是本课完整答案。

若终端明确提示 `python: command not found`，按仓库首页说明，把上面两行开头的 `python` 换成 `python3`，其余内容不变。

### 第1步：先登记数据用途

- **动作：** 在打开月16—19结果前，写下月0—11训练、12—15验证、16—19测试、20—23保留。
- **目的：** 每批资料只能承担已声明的作用，才能保留独立评价。
- **成功信号：** 报告或结果中有一张数据用途表。
- **想一想：** 哪一次选择若看了测试结果，就会让测试参与开发？

### 第2步：核对字段与流程

- **动作：** 阅读字段可用时点，把插补、变量尺度标准化、特征选择和拟合放进同一训练流程。
- **目的：** 每个参数都只能从当前训练资料学习。
- **成功信号：** 能指出插补值和尺度参数来自哪一批记录。
- **想一想：** 先用全表算均值再拆分为什么仍是泄漏？

### 第3步：用验证资料选方案

- **动作：** 比较至少两个有实质差别的候选方案，并在看测试前写下评价目标和最低可接受标准。
- **目的：** 把模型选择与最终评价分开。
- **成功信号：** 候选方案使用相同目标、验证资料和指标；冻结版本有记录。
- **想一想：** 如果两模型指标接近，哪项使用约束决定选择？

### 第4步：分别评价两个场景

- **动作：** 只在冻结后读取月16—19，报告已知设备未来表现；另按 `entity_id` 做不共享设备的评价，并注明这些设备是否曾在验证阶段影响模型选择。
- **目的：** 同一个总分不能回答两种泛化问题；未进入拟合也不自动等于完全未用于开发。
- **成功信号：** 两种场景有独立小节，能够复现设备与拟合、验证资料是否共享。
- **想一想：** 新设备结果已参与模型选择或样本很少时，结论应怎样变得更谨慎？

完成这四步后，你已经有可信起点，但还没有完成整项主任务。

## 标准任务（本课应完成）

回到 [README](README.md) 完成全部标准任务，特别核对：

- 保持训练、验证、测试和保留资料的用途分离。
- 预处理与模型放入无泄漏流程。
- 冻结评价标准和模型后才看测试。
- 分别报告已知设备与新设备的样本量、基础率、性能、资料共享情况和适用范围。

把程序输出翻译成完整统计句子：对象是谁，比较什么，数值和单位是什么，哪些假设成立时可以怎样使用，哪些结论仍不能作出。

## 提高与拓展（提前完成后）

先完成标准任务，再选一项。提高的标准是让证据、适用范围或行动更可靠，而不是增加代码或图表数量。

- 同时限制时间和设备共享的验证。
- 量化不同流程在两种泛化场景中的后果。
- 形成数据使用登记和版本冻结记录。

## 卡住时按顺序排查

- **新设备测试结果为空或很少：** 检查 `entity_id` 首次出现月份与分组逻辑；不要用随机按行拆分替代新设备评价。
- **“新设备”已经出现在验证资料：** 如实称为“未进入拟合但参与过验证选择的设备”；若要评价完全未用于开发的设备，需要重新设计按设备分组的开发与评价。
- **测试结果比验证明显更好：** 先排查字段时点、预处理拟合范围和设备共享，再讨论真实差异。
- **命令提示找不到文件：** 先运行 `pwd`，确认当前位置是仓库根目录；这里应同时看见 `scripts/` 和本课目录。
- **程序能运行但结果还是旧的：** 检查结果文件的修改时间，确认修改并运行的是本课 `analysis.py`；必要时删除自己生成的旧结果后重跑，但不要删除原始数据。
- **报告数字和程序输出不一致：** 从报告中的一个关键数字反向找到结果文件、筛选范围、分子和分母；不要手工把报告改成“看起来合理”的数字。
- **不知道怎样开始写报告：** 先写五句：谁使用、要决定什么、数据覆盖谁、一个主要结果、一个不能支持的结论，再补方法和证据。
