# 第24课 · 模型比较与泛化能力评价

## 项目背景

平台正在选择一个模型，用于在工单登记时预测后续升级风险。近期新增了以前没有服务记录的设备，负责人需要知道模型对“已有设备未来记录”和“全新设备”分别表现怎样。

模型将用于预测已有设备的后续工单，还是全新设备的工单？应如何划分数据，分别完成预处理、模型与阈值选择，以及独立评价？

可用资料为[预测分析数据集](../data/prediction/README.md)中的`requests.csv`。**资料全部为教学合成数据。** 数据字典说明记录单位、字段、时点和局限；同时阅读`feature_availability.csv`。你可以全程使用AI完成编程、分析、写作与提交，也可以复用前课代码。

## 任务分层

本课直接使用[第23课建立的风险预测与行动目标](../lesson-23/README.md)。第一次做这一类项目时，按[陪做支持](SUPPORT.md)完成每一步；概念解释见[知识准备](LEARN.md)。

### 基础练习（可信起点）

1. 先画数据用途时间线：月0—11训练、12—15验证、16—19测试、20—23保留。
2. 核对一个预处理步骤的参数只由训练数据得到，并确认没有使用结单后字段。
3. 固定一个候选模型和评价指标，在查看月16—19结果前写下选择标准；再分别列出拟合阶段见过和未见过的设备样本量与基础率，并注明这些设备的结果是否已经在验证阶段用于模型选择。

基础练习帮助你得到可信的第一份结果，**并不等于已经完成本课**。继续完成下面的标准任务，才能把计算变成可使用的统计结论。

### 标准任务（本课应完成）

1. 先画出或列出数据使用时间线与字段可用时间。月0—11训练，12—15选择模型，16—19首次作为本轮测试；20—23留给L26。对新设备另设不共享`entity_id`的评价，并记录这些设备的结果是否参与过模型选择，说明它与同一设备的未来工单预测不同。

2. 将缺失值插补、变量尺度标准化、特征选择与模型拟合纳入同一训练流程；每一步只用训练数据确定参数。比较针对同一预测目标、方法上有实质差别的候选方案，记录选择依据，并保存不再据测试结果调整的版本。

3. 在看测试结果前确定评价目标与可接受的性能标准，再独立运行测试，报告已知设备、新设备的样本量、基础率及性能。若所谓“新设备”已经在验证资料中出现，须明确这不是完全未使用的新设备独立评价；测试可否代表未来时段也必须说明。

4. 提交模型评价报告：哪些结果受时间泄漏或训练、测试共享设备信息的影响，不能用于说明目标场景的预测能力？其余结果支持在哪些设备和时段使用模型？本课以后16—19月不再称为从未用过的测试资料。

以上均为本课需要完成的任务，分析方法和报告形式可以自行选择。评价不以图表或模型数量为依据。使用外部资料时注明来源，补充的业务假设应明确标注，不得当作已知事实。

### 提高与拓展（提前完成后）

完成标准任务后，从下面选择一项深入；重点是改善证据或决策，不按代码、图表或模型数量评价。

- 设计同时限制时间和设备共享的验证方案，说明它对应什么真实使用场景。
- 比较两个实质不同的预处理或模型方案，并量化选择在两种设备场景中的后果。
- 写一份可审查的数据使用登记表，说明每批资料影响了哪些选择、以后还能怎样使用。

## 课堂安排（90分钟）

- 0—12分钟：阅读[知识准备](LEARN.md)和项目背景；需要分步引导时打开[陪做支持](SUPPORT.md)，明确分析问题；需要时可延长到17分钟，相应减少重复操作和排版时间。
- 12—55分钟：选择方法、开展分析或研究设计，并比较不同方案；遇到不熟悉的概念可随时查阅知识准备或询问AI。
- 55—68分钟：核对一项主要结论的计算结果、假设与替代解释，完成分析报告。
- 68—75分钟：重新运行程序，检查结果并提交；提前完成时，可进一步检验报告中的重要结论。
- 75—90分钟：[知识自查](https://hblu.top/stat-check/)，确认页面为当日V2课次，建议先完成A版基础题，再向AI学习不熟悉的概念，随后完成B版变式题。

## 示例代码与运行方法

从仓库根目录运行：

```bash
python scripts/course.py start 24
python scripts/course.py run 24
```

本课`analysis.py`读取数据并生成`artifacts/starting_summary.json`，用于熟悉数据结构。**请在此基础上完成本课分析任务，形成自己的分析方案和结论。** 可使用Python标准库、numpy/scipy、pandas、statsmodels、scikit-learn或其他合适工具；说明新增依赖与运行命令。

## 成果要求与提交

- `report.md`：面向报告使用者，写清分析问题、方法依据、主要结果、适用范围和建议。
- 可复现的分析程序或研究设计文件，以及报告引用的计算结果和图表；不要手工修改原始数据。
- `submission.json`：将`status`设为`complete`，`report`指向分析报告，`artifacts`列出支持报告结论的结果文件路径，`run`填写可复现分析的命令。

仅运行示例代码或粘贴模型输出，还没有完成本课分析任务。合格分析应能复现同一数据划分，且不使用预测时尚不可得的事后变量；更好的分析会分别评价两种使用场景，不因某批新设备的分数较高就断言新设备普遍更易预测。

完成后执行`python scripts/course.py check 24`，按[项目工作流](../docs/WORKFLOW.md)提交并创建`v2-l24-final`标签；有修订时保留原标签。自查按[知识自查说明](../docs/KNOWLEDGE_CHECK.md)进行。项目分析允许全程使用AI，不要求提交AI对话记录。
