# 第7课知识准备 · 没有取得的评价会怎样影响满意度

“回答者中大多数满意”可以由已有评价计算出来。“全部办事经历是否满意”还取决于没有取得的评价。本课先分清这些对象，再研究不同假设下的结果。

## 1. 先区分未受邀与无回答

**目标总体**是希望报告描述的全体对象，本课通常为第一期全部登记工单。有的工单没有收到调查邀请，有的收到邀请却没有提供评价。后一种情况称为**无回答（也称无应答）**。两者都造成评分缺失，但原因不同。

空白表示评分未知，不是0分，也不表示满意或不满意。先按第一期工单编号找到调查登记，再看 `invited`：0表示未受邀，1且评分空白表示受邀后无回答。若连调查登记都没有匹配到，还应单独核实邀请情况，不能直接归入未受邀。邀请字段缺失或与评分矛盾时也应单列待核实。

## 2. 同一调查中的四个比例

另设100张目标工单，其中50张受邀，40张回答，回答者中32张满意。满意定义在本例中为评分不低于4。

三类工单分别为未受邀50张、受邀后无回答10张、已回答40张，合计100张。

| 指标 | 计算 | 分母包括谁 |
|---|---|---|
| 邀请率 | 50÷100＝50% | 全部目标工单 |
| 受邀者回答率 | 40÷50＝80% | 收到邀请的工单 |
| 全部工单中有评价的比例 | 40÷100＝40% | 全部目标工单 |
| 回答者满意比例 | 32÷40＝80% | 已取得评价的工单 |

两个80%虽然相同，却不是同一个指标。只用所需字段完整的记录进行分析，称为**完整案例分析**；这里可以描述回答者，但不能不加说明就推广到全部工单。

## 3. 没有评价时，能够给出什么范围

其余60张工单的满意情况未知。若它们全部不满意，全体满意比例为32÷100＝32%；若它们全部满意，则为(32＋60)÷100＝92%。因此上下界为32%—92%。

这不是95%置信区间，而是在目标对象和已有答案不变的情况下，考虑未知评价可能取值所得到的范围。它仍以目标范围清楚、满意定义明确、已记录答案有效为前提。

可以进一步作**敏感性分析**：假设无评价工单中的满意比例为q，q在0到1之间，则：

`全体满意比例＝(32＋60q)÷100`。

q表示无评价工单中假设的满意比例，不是这些人会回答的概率。例如q＝0.5表示假设60张未知评价中有30张满意，并不是给每张工单补一个0.5分。q为0.25、0.5、0.75时，结果分别为47%、62%、77%。这些是不同假设下的结果，不是三份实际调查结果。

## 4. 什么情况下建议会改变

另设一项教学要求：全体满意比例达到70%才采用某项发布建议。需要未知的60张工单中至少有38张满意，即q至少为38÷60，约63.33%。70%是这个例子的业务要求，不是统计学规定的标准。

未受邀与受邀无回答也可以采用不同假设。若前者40%满意、后者80%满意，全体比例为(32＋50×0.4＋10×0.8)÷100＝60%；交换两种比例，结果为76%。因此补充调查时要说明优先了解哪个群体、为什么，以及成本和再次无回答的可能影响。

## 5. 用已有信息调整，需要哪些假设

可以先按业务类型、等待情况等分组，再假设每组回答者能够代表该组没有评价的工单。计算全体结果时，用各组目标工单数确定权重，而不是再次用回答人数加权。

用已有信息给缺失评分补入估计值，称为**插补**。插补和分组调整都不能恢复已经证实的个人答案。完全没有回答的组无法直接计算组内满意比例；用其他组预测，需要额外假设。回答很少的组也应说明结果可能不稳定。

统计学按缺失与信息的关系区分以下情况：

| 术语 | 本课中怎样理解 |
|---|---|
| 完全随机缺失（MCAR） | 是否缺失与有关的已观察信息、未取得的评分都无关。 |
| 随机缺失（MAR） | 在给定用于分析的已观察信息后，是否缺失不再依赖未取得的评分。 |
| 非随机缺失（MNAR） | 即使考虑已有信息，是否缺失仍与未取得的评分有关。 |

例如，同类业务、相近等待时间下，越不满意者仍越不愿回答，就可能属于非随机缺失。这里“随机”不是指随机抽样。只看已知特征相近，不能证明缺失机制成立。分组调整的代表性假设还要涵盖未受邀者，不能只讨论受邀后无回答的人。

本课不要求先确定真实的缺失机制，才能继续分析。先说明采用什么假设，再比较不同假设下的结果，并指出哪些未知信息会影响建议；无法验证的假设要保留为使用条件。

## 在项目中使用

先说明满意定义和第一期范围，报告邀请、回答和满意比例。比较有评价与无评价工单的已知经历，再给出至少两种有实际差别的缺失评价假设及计算结果。

说明什么情况下建议会改变，或回答同样有实际意义的问题。补充调查要具体到对象、希望了解的信息和何时更新建议。范围很宽也可以是诚实的结论，不必为了得到一个精确数字而强行插补。

## 按需阅读：分组调整怎样算

另设100张目标工单，分成两类业务。以下数字与前面的调查例子无关。

| 业务组 | 目标工单数 | 有评价数 | 其中满意数 | 回答者满意比例 |
|---|---:|---:|---:|---:|
| 甲 | 20 | 10 | 8 | 8÷10＝80% |
| 乙 | 80 | 20 | 12 | 12÷20＝60% |

全部回答者的满意比例为(8＋12)÷(10＋20)，约66.67%。若假设每组回答者能够代表该组全部工单，则目标工单中甲占20%、乙占80%，调整结果为0.2×0.8＋0.8×0.6＝0.64，即64%。

如果仍按回答人数加权，计算的依然是回答者满意比例，并没有调整到目标工单构成。64%依赖组内代表性假设，不是新观察到的事实；甲或乙完全没有评价时，就不能直接计算该组比例。

```python
# learning-example
import json
n, invited, responded, happy = 100, 50, 40, 32
missing = n - responded
def scenario(q):
    return (happy+missing*q)/n
def two_process(q_u, q_n):
    return (happy+(n-invited)*q_u+(invited-responded)*q_n)/n
result = {"invitation": invited/n, "response_invited": responded/invited,
          "response_all": responded/n, "happy_respondents": happy/responded,
          "bounds": [scenario(0), scenario(1)],
          "scenarios": [scenario(q) for q in (.25, .5, .75)],
          "q_for70": (.7*n-happy)/missing,
          "two_process": [two_process(.4,.8), two_process(.8,.4)]}
print(json.dumps(result, ensure_ascii=False, allow_nan=False))
```
