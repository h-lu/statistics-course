# 第7课 · 满意度调查的覆盖与无回答问题

**以下数据全部为教学合成数据，不代表真实机构、个人或实际效果。** 可以全程使用AI提出候选问题、编程、分析、写作和协助提交；你需要确认最终采用的选择，核对结果、依据和适用范围。无需提交AI对话或证明代码由谁输入。先阅读[知识准备](LEARN.md)，再展开正式分析。

## 项目背景与数据

服务中心已有评价大多满意，但部分工单未受邀，另一些受邀后无回答。你要说明这些结果描述谁、全体满意程度还依赖哪些未知信息，以及应优先补充调查谁。

使用 `data/service/tickets.csv` 与 `satisfaction.csv` 按 `ticket_id` 连接，限定第一期3,600张工单。调查表含两期4,800条，不能全部进入第一期分母。见[服务数据说明](../data/service/README.md)。评分1—5为有序评价；空白不是0分。满意可定义为评分≥4，也可选择有理由的其他定义并保持一致。

## 分析任务

1. **先界定目标与覆盖。** 核对未受邀、受邀无回答、已回答三类数量。分别报告邀请率、受邀者回答率、全体有评价比例和回答者满意比例，给出各自分子分母。若整条调查登记未匹配，单列信息缺口，不能直接归为未受邀。
2. **比较已观测经历。** 检查业务、等待、放弃等可见特征与取得评价的关系。可见相近或检验不显著，不能证明评价缺失完全随机。
3. **计算至少两种实质不同的假设结果。** 可用未知评价极端上下界、有理由的情景值或分组调整。说明假设适用于未受邀、受邀无回答，还是全部无评价工单；估计量所针对的人群和满意定义不能暗中更换。
4. **让分析影响发布建议。** 判断未知者满意比例低到何种程度会改变建议，或回答同样有实际意义的问题。门槛依据要说明；比较方案数量不能替代假设区别。
5. **提出具体补采计划。** 写清目标人群、希望消除的不确定性、可行的联系方式和成本考虑，以及何时更新结论或停止补采。不只选择容易联系的人，也不只写“扩大样本”。

## 解释边界

只用回答者可以描述已回答工单；推广到全部工单需要额外依据。组内调整通常还外推到未受邀者，不能只论证受邀后的无回答。完全无回答的组没有观测满意率，不能将0或软件预测称为真实调查结果；少量回答即使经过平滑仍信息有限。

未知评价上下界是固定目标人群中可能结果的范围，**不是置信区间**；仍以目标覆盖、满意定义和已记录答案有效为前提。插补与调整不恢复已证实的个体真值。诚实的宽范围加有针对性的补采建议可以构成完整成果。

## 成果与提交前自核

提交覆盖与分母表、可见特征比较、假设—结果对照、发布文案及补采计划，关键范围或情景可重新计算。至少两种假设、建议会改变的条件或等价问题，以及具体补采均为主任务。

进一步完善可区分两个缺失过程、稀疏群体和补采代价，并据此修改优先级；不要求多重插补，也不因区间更窄自动评价更好。

## 90分钟建议安排

0—13分钟分母和缺失小例子；13—27分钟范围、邀请、回答和经历核对；27—55分钟假设与结果比较；55—68分钟发布与补采建议；68—75分钟核对提交；75—90分钟自查。

## 运行、核对与提交

以下“仓库根目录”指你自己的学生仓库中包含 `scripts/`、`data/` 的目录；在合并资料库中阅读时，对应 `student-template/`。先运行：

```bash
python scripts/course.py start 07
python scripts/course.py run 07
```

`analysis.py` 是可运行的数据概览，不是完整项目答案。按问题修改或替换它，将关键数值结果和图表写入本课 `artifacts/`，在 `report.md` 中引用。可以调整报告结构，不能只保留提示或粘贴默认输出。原始数据不改写；新增依赖写入 `requirements.txt`。

完成后，在本课 `submission.json` 中将 `status` 设为 `complete`，填写 `report`、支持结论的 `artifacts` 和非空命令参数列表 `run`。所有路径相对于学生仓库根目录。再执行：

```bash
python scripts/course.py run 07
python scripts/course.py check 07
git diff --check
git status
git diff
git add lesson-07 requirements.txt
git diff --cached
git commit -m "完成第07课项目"
git push
git tag v2-l07-final
git push origin v2-l07-final
```

**`run` 执行分析；`check` 只检查完成声明、路径和文件是否存在且非空，不会重新运行分析或判断结论。** 推送后查看 Actions 的重跑结果；配置了重现检查时，它会在临时副本移除所列结果文件、运行程序并比较内容。固定随机种子、排序和输出精度，避免将带生成时间的文件列入逐字节比较。程序运行成功和文件检查通过，都不等于统计解释正确。

新增共用程序也须核对后纳入提交。已有最终标签不要覆盖；修订保留原版本。网络、环境或检查故障时保存本地文件与提交，向教师说明，不把失败写成已通过。完整步骤见[项目工作流](../docs/WORKFLOW.md)和[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第7课。建议先作答A，再学习不熟悉的概念，完成B并阅读反馈；AI始终可用，无需提交对话记录。自查正确率用于反馈，不直接计分，详见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
