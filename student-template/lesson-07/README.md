# 第7课 · 满意度调查的覆盖与无回答问题

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

第一次使用这些资料时，可先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。

## 项目背景与数据

服务中心已有的评价大多满意，但一些工单没有收到邀请，另一些受邀后没有回答。你需要说明已有结果描述谁、全体满意比例还不能确定什么，以及应优先向谁补充调查。

用 `data/service/tickets.csv` 与 `satisfaction.csv` 按 `ticket_id` 对应，限定第一期3,600张工单。调查表有两期4,800条登记，不能全部用作第一期分母。字段见[数据说明](../data/service/README.md)，概念和计算见[知识准备](LEARN.md)。

1—5级评分有顺序，空白表示未知，不是0分。可以定义评分不低于4为满意，也可采用有理由的其他定义，但全文应保持一致。

## 分析任务

1. **说明对象与调查情况。** 列出未受邀、受邀无回答、已回答的数量。分别报告邀请率、受邀者回答率、全部工单中有评价的比例和回答者满意比例，写清分子、分母。没有匹配到调查登记的工单要单列，不能直接归为未受邀。
2. **比较已经知道的办理经历。** 检查业务类型、等待和放弃情况是否与取得评价有关。已知特征相近，不能证明未知评分也相近或缺失完全随机。
3. **比较至少两种不同的缺失评价假设。** 可计算极端上下界、设定不同满意比例，或作有依据的分组调整。说明假设针对未受邀者、受邀无回答者，还是全部无评价工单。用实际数值说明结论怎样变化，不暗中更换满意定义或目标对象。
4. **说明建议在何种条件下改变。** 例如，没有评价的工单满意比例低到多少时，发布建议会改变？也可以提出同样有实际意义的问题。采用业务门槛时应解释依据。
5. **制定补充调查计划。** 写清优先联系的人群、希望了解的未知情况、拟采用的联系方式和成本，以及何时更新结论或停止补充调查。这是调查方案，不要求实际联系任何人。合成数据没有真实联系方式；未给出的联系条件和费用须注明为方案假设，不能当成已有事实。不只写“增加样本量”，也不只选最容易联系的人。

## 结果怎样解释

回答者满意比例直接描述已经回答的工单；推广到全部工单需要额外依据。分组调整的假设应同时考虑未受邀者与受邀无回答者。没有回答的组不能直接估计组内满意比例，少量回答的组也应说明结果可能不稳定。

全体满意比例的上下界不是置信区间；它以目标范围、满意定义和已记录答案有效为前提。插补给出的是假设下的估计，不是查实了每个人的评分。范围较宽但解释清楚，并有针对性的补充调查建议，同样可以形成完整报告。

## 需要提交什么

提交邀请与回答情况表、各比例的分母、已知特征比较、至少两种假设下的计算结果、发布建议和补充调查计划。写清何时建议会改变，或回答同样有价值的问题。

重点是未知信息怎样影响决定，不要求先判定真实的缺失机制，也不要求一定使用多重插补。说明假设、实际比较结果，再判断建议是否依赖这些假设；不因估计范围更窄就认为方法更好。

## 课堂安排

0—13分钟阅读例子；13—27分钟核对范围、邀请、回答与办理经历；27—55分钟比较假设和结果；55—68分钟写发布与调查建议；68—75分钟检查提交；75—90分钟知识自查。

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`target_tickets` 是第一期工单数，`matched_surveys` 是与它们对应的调查登记数，`invited`、`responded` 分别是受邀数和有评价数。`observed_score_counts` 按评分列出已有评价的数量，不包含空白评分；示例尚未对未知评价作假设或计算全体满意比例的范围。

先阅读输出中与你的问题有关的内容，再按上面的分析任务扩展程序。自己的计算结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。若使用完整课程资料库，先进入 `student-template/`。

```bash
python scripts/course.py start 07
python scripts/course.py run 07
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据本课问题修改或替换程序，将结果和图表保存到本课 `artifacts/` 文件夹，并在 `report.md` 中解释和引用。原始数据保持不变；程序使用的新软件包写入 `requirements.txt`。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起；更换程序时要相应更新命令。然后重新运行并检查：

```bash
python scripts/course.py run 07
python scripts/course.py check 07
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送到个人仓库，创建本课最终标签 `v2-l07-final`，再查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，但不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖，修改时保留原版本。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令、结果文件设置和修订办法见上述操作说明，评分见[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第7课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
