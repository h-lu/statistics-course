# 第7课 · 满意度调查的覆盖与无回答问题

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

## 项目背景与数据

服务中心收到的评价大多是满意的，但有些工单没有收到调查邀请，有些受邀后没有留下评分。如果只报告回答者的满意比例，读者可能误以为它代表全部工单。你需要说明现有数据能描述谁、全部工单的满意比例还有哪些未知部分，以及应优先向谁补充调查。

**目标总体**是结论希望描述的全部对象；本课通常指第一期已登记的3,600张工单，不是3,600名不同来访者。用 `data/service/tickets.csv` 与 `data/service/satisfaction.csv` 按工单编号 `ticket_id` 对应。调查表还包括第二期，共4,800条登记，不能把全部调查登记都用作第一期的分母。字段见[数据说明](../data/service/README.md)。先按[支持路线](SUPPORT.md)得到可核对的结果，遇到概念时读[知识准备](LEARN.md)，再回到本页完成任务。

评分从1级到5级，级别越高表示评价越好；空白表示没有取得评分，不是0分。可以把评分不低于4级定义为“满意”，也可采用有理由的其他定义，但计算和报告须始终使用同一标准。

## 分析任务

1. **说明对象与调查情况。** 把已匹配调查登记的第一期工单分为未受邀、受邀后没有评分、已有评分三类，列出数量。分别计算邀请率（受邀数÷全部目标工单数）、受邀者回答率（有评分数÷受邀数）、全部工单中有评价的比例（有评分数÷全部目标工单数）和回答者满意比例（满意数÷有评分数）。没有匹配到调查登记或邀请状态不明的工单要单列，不能猜成未受邀；如果存在这类工单，还应说明真实邀请率可能无法由现有记录精确确定。
2. **比较已知的办理经历。** 比较有评价与无评价工单的业务类型、等待时间和放弃排队情况，并列出各组工单数。放弃者的等待时间是离开前的等待，不是接受服务后的等待。即使这些已知特征相近，也不能证明没有取得的评分相近。
3. **比较至少两种不同的缺失评价假设。** 未取得的评分称为**缺失评价**。可以计算未知者全不满意、全满意时的**上下界**（可能的最低和最高比例），或假设未知者有不同的满意比例，也可以按已知特征分组后作有条件的调整。说明假设针对未受邀者、受邀后无回答者，还是全部无评价工单；用实际数值说明结论怎样变化，不暗中更换满意定义或目标总体。
4. **说明建议在何种条件下改变。** 这也是一种**敏感性分析**：改变未知者的满意比例，看发布建议何时不同。例如，如果发布部门规定“全部工单满意比例至少达到某值才发布单一结论”，未知者需要有多高比例满意？说明这一门槛的用途和依据；也可以提出同样有实际意义的问题。
5. **制定补充调查计划。** 写清优先调查哪类工单、希望了解什么、拟采用的联系渠道与成本，以及何时更新结论或停止调查。这是调查方案，不要求实际联系任何人。合成数据没有真实联系方式；未给出的联系条件和费用须注明为方案假设，不能当成已有事实。工单数也不等于不同来访者人数，实际联系前还需核对重复来访。不能只写“增加样本量”，也不能只选最容易联系的人。

## 难度分层

下面三层按顺序使用。基础练习帮助你分清目标工单、邀请、回答与满意四类数量，不能代替标准任务；标准任务保留上面的五项要求；提高与拓展供提前完成者继续检验未知评价对决定的影响。

### 基础练习（可信起点）

运行起始程序，写出邀请率、受邀者回答率、全部工单中有评价的比例和回答者满意比例各自的分子与分母；再用知识准备的小例子手算全体满意比例的上下界。这一层还没有比较正式数据中的缺失假设，也没有完成补充调查计划。

### 标准任务（本课应完成）

完成上面的五项任务：核对调查范围和比例，比较回答与取得评价有关的已知经历，实际计算至少两种缺失评价假设，找出建议改变的条件，并制定有对象、方式、成本假设和停止条件的补充调查计划。

### 提高与拓展（提前完成后）

标准任务完成后任选一项：按业务类型、等待或放弃状态分层做缺失评价敏感性分析；分别改变未受邀与受邀无回答两组的假设，找出哪组最可能使发布建议改变；比较两种补充调查优先顺序对取得评价的范围和决定的影响；或用独立实现复算邀请、回答、上下界和一个假设情景。提高部分要说明新增检查让发布或补充调查建议怎样变化，不把更窄的估计范围自动当作更可信。

## 结果怎样解释

回答者满意比例直接描述已经留下评分的工单；要将它推广到全部工单，需要额外依据。**分组调整**是按业务类型等已知特征分组，假设每组回答者能代表该组全部工单，再按各组目标工单数合并结果。这项假设要同时考虑未受邀者与受邀后无回答者。完全没有回答的组不能直接算出组内满意比例；回答很少的组也应说明结果可能不稳定。

全体满意比例的上下界来自未知评分的极端可能值，**不是置信区间**。统计抽样中的置信区间用于表达估计量随抽样而变的不确定性，不能代替本课对未取得评分的分析。上下界仍以目标范围、满意定义和已记录答案有效为前提。**插补**是按模型或假设为缺失评分填入估计值，不是查实了每张工单的评分。即使上下界较宽，只要解释清楚并提出有针对性的补充调查建议，也能形成完整报告。

## 需要提交什么

提交邀请与回答情况表、各比例的分母、已知特征比较、至少两种假设下的计算结果、发布建议和补充调查计划。写清何时建议会改变，或回答同样有价值的问题。

重点是未知信息怎样影响决定，不要求先判定评分为什么缺失，也不要求为每张缺失工单预测评分。说明假设和实际比较结果，再判断建议是否依赖这些假设；不能仅因某种方法给出较窄的范围，就认为它更可信。

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`target_tickets` 是第一期工单数，`matched_surveys` 是与它们对应的调查登记数；`unmatched_tickets` 是没有对应调查登记的工单数。`invited`、`responded` 分别是受邀数和有评分数；`observed_score_counts` 按评分列出已有评价的数量，不包含空白评分。示例尚未对未知评价作假设或计算全部工单满意比例的范围。

先阅读输出中与你的问题有关的内容，再按上面的分析任务扩展程序。自己的计算结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。若使用完整课程资料库，先进入 `student-template/`。

```bash
python scripts/course.py start 07
python scripts/course.py run 07
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据本课问题修改或替换程序，将结果和图表保存到本课 `artifacts/` 文件夹，并在 `report.md` 中解释和引用。原始数据保持不变；程序使用的新软件包写入 `requirements.txt`。

若终端提示找不到 `python`，将本页命令中的 `python` 改为 `python3`，并在 `submission.json` 的 `run` 中使用可用的命令。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起；更换程序时要相应更新命令。然后重新运行并检查：

```bash
python scripts/course.py run 07
python scripts/course.py check 07
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送到个人仓库，创建本课最终标签 `v2-l07-final`，再查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，但不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖，修改时保留原版本。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令、结果文件设置和修订办法见上述操作说明，评分见[成果与评分](../docs/ASSESSMENT.md)。

完成项目后进入[知识自查](https://hblu.top/stat-check/)，确认页面为第7课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
