# 第7课 · 满意度调查的覆盖与无回答问题

发布部门看见收到的评价大多满意，准备描述全部登记工单。问题是有些工单没被邀请，有些受邀后没回答。你要区分已经观察到的结果、依赖假设的结果与尚未确定的范围，并给出有对象和成本的补充调查方案。

本课使用**教学合成数据**，没有真实联系方式，不实际联系任何人。可以全程使用 AI，仍须核对目标、分母、假设与发布条件。

先用本页理解任务；按需要查 [SUPPORT](SUPPORT.md) 或 [LEARN](LEARN.md)，再按自己的路线完成标准任务。初次使用可读[阅读指南](../docs/READING_GUIDE.md)。

## 数据与目标

**目标总体**是结论希望描述的全部对象，本课通常为第一期 3,600 张已登记工单。工单不等于不同来访者；这份登记表也不覆盖未取号的人，无法据此评价全部潜在使用者。

按 `ticket_id` 连接第一期 `tickets.csv` 与 `satisfaction.csv`，见[数据说明](../data/service/README.md)。调查表含两期共 4,800 条，不能用全表作第一期分母。评分 1—5 级，空白表示未取得评分。可把评分≥4定义为满意，也可作有理由的其他定义，整个分析保持一致。

**未受邀**是确认未发邀请；**无回答**是受邀后未提供所需回答。缺调查登记或邀请状态未知另列，不能猜成未受邀。已有评分直接描述回答者；推广到全部目标需要额外依据。

## 基础练习（可信起点）

运行覆盖支架，列邀请率、受邀者回答率、全部工单有评价的比例和回答者满意比例各自的分子分母；手算 LEARN 小例子的未知评分上下界。起点尚未完成正式数据中的假设比较、翻转条件和补采方案。

## 标准任务（本课应完成）：用途与证据要求

1. **核对调查过程。** 保留全部目标工单，检查编号唯一及调查匹配。列未受邀、受邀无回答、已回答和待核实状态，计算四个比例。邀请状态有未知时，说明真实邀请率是否还能精确计算；零分母标未定义。评分空白不填零。
2. **比较可见经历。** 按状态比较工单数、业务构成、等待和放弃情况。放弃者的等待是离开前等待。解释这些差异如何帮助提出缺失假设，以及为什么不能据此证明尚未取得的评分是什么。
3. **保留界限，比较至少两种合理假设。** 计算无评分者全部不满意与全部满意时的全体上下界。再提出至少两种有实质差别的情景，或分组调整方案，解释为什么不同；至少一种区分未受邀与受邀无回答。保持满意定义和目标一致，以目标工单数为分母。分组调整按目标组数量加权，说明回答者代表同组全部工单的假设与零/少回答组限制。
4. **找到建议改变的条件。** 为发布用途选一个有依据的门槛或同样有意义的问题，算出哪一未知组需要怎样的满意比例，建议才会变化。也检查所需比例是否在 0—1 内。门槛是情境要求，不是统计学统一标准；满足某情景的门槛不表示数据已证实它。
5. **比较补采次序并写计划。** 至少比较两种有理由的优先次序，结合未知组大小、对结论的影响、预计联系成功和成本作取舍。写对象、需要的信息、联系渠道假设、预算或人时、再度无回答怎样处理、何时更新或停止。数据未给联系方式和费用，这些要标明为方案假设；实际联系前还需按来访者去重，不能用工单数冒称人数。

报告分别写回答者观察结果、全体上下界、各假设下结果与建议，不用单一精确数遮住未知信息。界限来自固定目标中缺失评分的可能值，**不是置信区间**；置信区间表达抽样变动，不能替代对未回答者的假设分析。

路线、实现和呈现方式由你决定。至少自主作出两个会影响结果含义或使用建议的重要决定，说明依据并实际比较合理备选。上面的例子和下面的深入方向不是方法菜单，也不限定唯一结论。

## 提高与拓展（提前完成后）

可自行提出深入问题，把新增证据对应到建议变化。以下仅是例子，也可以采用其它有依据的方法或问题：

- **分别改变两种未知过程。** 找出未受邀与受邀无回答假设组合的发布分界。比较同样提高 10 个百分点对总体的影响，再结合成本说明先调查谁，不能只按人数机械决策。
- **调整更细，假设未必更弱。** 比较按业务调整与按业务、等待、放弃分组的调整结果；找稀疏组，解释新分组为何改变点值、会增加什么不稳定性。再对组内无评分者设满意比例偏差，检查调整结论是否仍成立。
- **补采真正减少了什么未知。** 在明确的假设成本、联系成功率和所得评分下比较两种补采方案的剩余界限，判断预算是否足以改变发布决定。补采后的新回答者仍可能有选择差异，不能因回答更多自动声称偏差消失。

课后可以为登记框外人群提出独立调查设计，说明为何本课表格无法替代它。

## 运行与提交

从学生仓库根目录（含 `scripts/` 和 `data/`）运行：

```bash
python3 scripts/course.py run 07
```

生成 `lesson-07/artifacts/starting_overview.json`：包含目标数量、状态、四个比例、已知评分界限与可见经历。可选通用计算帮助见 SUPPORT，使用 Python 3 标准库可离线运行。程序不会替你选择满意定义、未知评分假设或发布决定。

更新 `submission.json` 的完成状态、报告、结果路径与统一复算命令；路径从学生仓库根目录写起。用你自己的统一入口复算所列结果。原始数据保留。

```bash
python3 scripts/course.py run 07
python3 scripts/course.py check 07
```

文件检查不证明假设合理。版本与提交见[WORKFLOW](../docs/WORKFLOW.md)，评分见[ASSESSMENT](../docs/ASSESSMENT.md)。原标签不覆盖。进入[知识自查](https://hblu.top/stat-check/)确认第 7 课，完成 A、学习、B 与反馈；离线可先用 LEARN 的本地变式自检，线上记录仍由自查系统保存。
