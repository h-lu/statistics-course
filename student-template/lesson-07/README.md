# 第7课 · 满意度调查的覆盖与无回答问题

已完成前七次作业的同学无需重交。

负责发布服务情况的部门看见收到的评价大多满意，准备据此描述全部登记工单。问题是有些工单没被邀请，有些受邀后没回答。你要区分已经观察到的结果、依赖假设的结果与尚未确定的范围，并提出补充调查方案，说明向谁调查及预计成本。

本课使用**教学合成数据**，没有真实联系方式，不实际联系任何人。可以全程使用 AI，仍须核对目标、分母、假设与发布条件。

先用本页理解任务；按需要查 [SUPPORT](SUPPORT.md) 或 [LEARN](LEARN.md)，再按自己的路线完成标准任务。初次使用可读[阅读指南](../docs/READING_GUIDE.md)。

## 数据与目标

**目标总体**是结论希望描述的全部对象，本课通常为第一期 3,600 张已登记工单。工单不等于不同来访者；这份登记表也不覆盖未取号的人，无法据此评价全部潜在使用者。

用工单编号 `ticket_id`，为第一期 `tickets.csv` 中的每张工单找到 `satisfaction.csv` 中对应的调查登记，见[数据说明](../data/service/README.md)。调查表含两期共 4,800 条，不能用全表作第一期分母。`invited` 记录是否发出邀请：0表示未受邀，1表示受邀；`score` 是1—5级评分，空白表示未取得评分。可把评分≥4定义为满意，也可作有理由的其他定义，整个分析保持一致。

**未受邀**是确认未发邀请；**无回答**是受邀后未提供所需回答。缺调查登记或邀请状态未知另列，不能猜成未受邀。已有评分直接描述回答者；推广到全部目标需要额外依据。

本课要区分四个比例：

| 比例 | 分子 | 分母 |
|---|---|---|
| 邀请率 | 受邀工单数 | 全部目标工单数 |
| 受邀者回答率 | 受邀且有评分的工单数 | 受邀工单数 |
| 全部工单中有评价的比例 | 全部有评分的工单数 | 全部目标工单数 |
| 回答者满意比例 | 有评分且满意的工单数 | 全部有评分的工单数 |

邀请状态未知时，不能直接得到精确的邀请率；可以单独报告确认受邀者中的回答率，并写明它描述的范围。

## 基础练习（可信起点）

可运行示例程序，核对调查登记与目标工单是否匹配，并列出四个比例各自的分子和分母；也可手算 LEARN 小例子中未知评分造成的上下界。这些练习帮助你开始，标准任务仍须完成正式数据中的假设比较、建议改变的条件和补充调查方案。

## 标准任务（本课应完成）：用途与证据要求

1. **核对调查过程。** 保留全部目标工单，检查每张工单编号是否唯一、是否匹配到调查登记。分别列出未受邀、受邀后无回答、已回答和待核实的工单数，计算四个比例。邀请状态有未知时，说明真实邀请率是否还能精确计算；分母为零时标为“未定义（不能计算）”。评分空白不填零。
2. **比较可见经历。** 按状态比较工单数、业务构成、等待和放弃情况。放弃者的等待是离开前等待。解释这些差异如何帮助提出缺失假设，以及为什么不能据此证明尚未取得的评分是什么。
3. **保留界限，比较至少两种合理假设。** 假设无评分的工单全部不满意或全部满意，计算全体满意比例的上下界。再比较至少两种有实质差别的假设方案：可以设定不同情景，也可以采用有不同依据的分组调整。解释各方案为什么不同；至少一种区分未受邀与受邀后无回答。**分组调整**是先按已知特征分组，再假设各组回答者的满意比例适用于该组全部工单。保持满意定义和目标一致，以目标工单数为分母。分组调整时，按各组目标工单数所占比例加权，并说明组内代表性假设；没有回答或回答很少的组会怎样限制结果，也要说明。共同权重的含义可回看[第6课](../lesson-06/LEARN.md)。
4. **找到建议改变的条件。** 为发布用途选一个有依据的门槛或同样有意义的问题，算出哪一未知组需要怎样的满意比例，建议才会变化。也检查所需比例是否在 0—1 内。门槛是情境要求，不是统计学统一标准；满足某情景的门槛不表示数据已证实它。
5. **比较补充调查的优先次序并写计划。** 至少比较两种有理由的优先次序，结合各未知组的工单数、对结论的影响、预计联系成功率和成本作取舍。写清调查对象、需要的信息、假设可用的联系渠道、预算或所需人时，以及再次无回答怎样处理、何时更新或停止调查。人时是所有人的工作小时数合计，例如2人各工作3小时，共6人时。数据未给联系方式和费用，这些要标明为方案假设；实际联系前还需按来访者去重，不能把工单数当作人数。

报告分别写回答者的观察结果、全体满意比例的上下界、各假设下的结果与建议，保留尚未取得评分带来的不确定性。这里的界限来自固定目标中缺失评分的可能值，**不是置信区间**。置信区间用于描述由抽样变动带来的估计不确定性，不能替代对未回答者的假设分析。

路线、实现和呈现方式由你决定。至少自主作出两个会影响结果含义或使用建议的重要决定，说明依据并实际比较合理备选。上面的例子和下面的深入方向不是方法菜单，也不限定唯一结论。

## 提高与拓展（提前完成后）

可自行提出深入问题，把新增证据对应到建议变化。以下仅是例子，也可以采用其它有依据的方法或问题：

- **分别改变两种未知过程。** 分别改变未受邀与受邀后无回答工单的假设满意比例，找出哪些组合会改变发布建议。比较两组各自提高10个百分点时，对全体满意比例的影响，再结合成本说明先调查谁，不能只按工单数决定。
- **调整更细，假设未必更弱。** 比较只按业务分组调整，与同时按业务、等待、放弃分组调整的结果。找出回答很少或没有回答的组，解释新分组为何改变估计值、会增加什么不稳定性。再允许组内无评分者的满意比例高于或低于回答者，检查调整结论是否仍成立。
- **补充调查真正减少了什么未知。** 在明确的成本、联系成功率和所得评分假设下，比较两种补充调查方案实施后的上下界，判断预算是否足以改变发布决定。新回答者仍可能与尚未回答者不同，不能因回答更多自动声称偏差消失。

课后可以为没有进入工单登记的人群提出独立调查设计，说明为何本课表格无法替代它。

## 运行与提交

从学生仓库根目录（含 `scripts/` 和 `data/`）运行：

```bash
python3 scripts/course.py run 07
```

生成 `lesson-07/artifacts/starting_overview.json`，包含目标工单数、调查状态、四个比例、未知评分造成的上下界，以及各状态组已记录的业务、等待和放弃情况。起始概览暂按 `score≥4` 定义满意；你可以修改定义，但须统一重新计算有关结果。可选通用计算帮助见 SUPPORT，使用 Python 3 标准库可离线运行。起始定义不替代你的选择依据，程序也不会替你选择未知评分假设或发布决定。

更新 `submission.json` 的完成状态、报告、结果路径与统一复算命令；路径从学生仓库根目录写起。用你自己的统一入口复算所列结果。原始数据保留。

```bash
python3 scripts/course.py run 07
python3 scripts/course.py check 07
```

文件检查不证明假设合理。版本与提交见[WORKFLOW](../docs/WORKFLOW.md)，评分见[ASSESSMENT](../docs/ASSESSMENT.md)。原标签不覆盖。进入[知识自查](https://hblu.top/stat-check/)确认第 7 课，完成 A、学习、B 与反馈；离线可先用 LEARN 的本地变式自检，线上记录仍由自查系统保存。
