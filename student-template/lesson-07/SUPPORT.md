# 第7课可选支持 · 区分观察、假设与未知范围

本页按困难提供帮助，不要求全班采用同一条分析路线。可以自行定义满意、选择缺失假设和比较方法、设计补充调查；只需明确目标、证据与使用条件。小例子不代替正式分析。

## 先知道今天要交出什么

发布者需要一份报告和可复算结果，说明结论描述哪些对象、哪些评分仍未知、假设怎样影响结果，以及补充调查的取舍。文件结构自定；即使结果范围很宽，也应完成 README 要求的计算与比较。

## 核心概念与原理

未受邀与受邀后无回答是不同过程；缺少调查登记或邀请状态未知的工单要另列。完整案例分析直接描述所需信息完整的工单。上下界来自固定目标中未知评分的可能值，不是抽样置信区间。分组调整需要假设每组回答者可以代表该组全部工单；已知特征相近不能证明未知评分也相近。

## 基础练习（可信起点）：需要时选一项

**调查范围不清楚。** 先预测一期工单应怎样对应两期调查表，再从学生仓库根目录运行：

```bash
python3 scripts/course.py run 07
```

打开 `lesson-07/artifacts/starting_overview.json`。这一步只核对调查起点；可核对的结果是目标3,600张工单、本期缺少调查登记和邀请状态未知的工单均为0，各状态工单数合计等于目标工单数。反思：若缺少调查登记，为什么不能称为未受邀？

输出中的 `target_tickets` 是目标工单数，`states` 列出各状态的工单数。状态名 `uninvited` 表示未受邀，`invited_nonresponse` 表示受邀后无回答，`responded` 表示已回答，`unmatched` 表示没有匹配到调查登记，`unknown_invitation` 表示邀请状态未知。

输出中的数量字段 `invited` 是确认受邀数，`responded` 是全部有评分数，`invited_responded` 是其中确认受邀的有评分数。`satisfied_at_least` 是满意评分下限，起始值为4；`satisfied` 是按该定义计得的满意数。

**四个比例分母混淆。** 用输出的邀请、回答、满意数分别写四个算式，再与程序核对。每个算式应标明对象、分子和分母。`observed_score_counts` 按评分分别计数；若定义4—5级为满意，就要合计这两个等级，不能只用5级的数量。反思：回答者满意比例是否观察到了未知工单的评分？

**不会保留未知。** 用 LEARN 小例子100张目标、40份评分、32张满意，先预测极端结果，再手算。成功信号是回答者80%，目标界限32%—92%。反思：空白填零是在恢复事实，还是采用极端假设？

## 入门反思

给报告每项结果标“观察”“假设下计算”或“未知范围”。分类是帮助解释，不要求额外表格；若一句混合三者，拆开说清。

## 标准任务（本课应完成）：可用资源，不指定假设

默认程序核对调查登记是否覆盖目标工单，并汇总已知评分。它暂按评分≥4定义满意，不自动生成情景、调整估计或发布结论。你可以复用以下通用帮助，也可以自行实现：

- `records()`：保留第一期目标工单，区分缺调查登记、邀请状态未知、未受邀与受邀后无回答。
- `overview(rows, happy_cutoff)`：核对目标、状态、比例和已知经历；`happy_cutoff` 是你指定的满意评分下限，上下界也按这一定义计算。
- `unknown_score_bounds(happy, responded, target)`：根据满意数 `happy`、有评分数 `responded` 和目标数 `target`，计算未知评分造成的上下界。
- `weighted_rate(rates, weights)`：按你选择的分层比例 `rates` 和权重 `weights` 计算加权比例；某层权重大于0而比例未知时，返回 `None`。

Python 中的 `None` 在 JSON 结果文件中显示为 `null`，表示没有可直接使用的数值，不是零。

重要的决定由你作出，至少两项须有理由与备选结果，例如满意定义、对哪些未知过程分别作假设、用哪些已知特征分组调整、什么证据足以发布、哪类对象优先补充调查。无需使用全部帮助，也无需为每张未知工单填值。

若情景不会算，可查 LEARN 中“各组工单数×假设满意比例”的例子；要写清比例用于哪一组，并保持目标和满意定义一致。若分组调整受阻，先核对目标工单数怎样决定权重、回答数怎样用于计算组内比例，再说明组内代表性假设，以及没有回答或回答很少的组带来的限制。发布时应同时说明估计值所依赖的假设和未知范围。

## 提高与拓展（提前完成后）

从自己的报告中选一个会影响建议的未知问题，自行调整方法或提出资料需求。README 中分别改变两组假设、细分调整与评价补充调查效果只是示例；可做其它有理由的研究。分组更细、数值更精确或范围更窄，都不自动表示结果更可信。

## 卡住时按顺序排查

先检查运行目录与结果是否最新，再核对第一期目标及工单编号、调查匹配和状态分类、各比例的分子与分母。随后检查假设针对哪一组，最后核对报告希望描述的对象。看到 `None` 或 `null` 时，先查是否分母为零、邀请状态未知，或某组没有回答，保留未确定的结果。写不下去时，先区分已知与未知，再问什么新资料能改变决定。

## 提交前自检

核对目标与满意定义是否一致，状态工单数合计是否正确，缺少调查登记的工单是否保留为待核实。上下界不称置信区间，假设结果不称已知事实；重要决定应比较备选，补充调查方案应考虑再次无回答。用自己的运行入口更新 `submission.json`，运行 `python3 scripts/course.py run 07`、`python3 scripts/course.py check 07`，再手算一个正式情景。保留原始数据与旧版本；本课只交方案，不联系个人。
