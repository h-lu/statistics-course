# 第7课支持路线：调查没有回答时，能说到什么程度

先读[本课任务](README.md)，再按这里的步骤得到第一份可核对的结果；遇到概念时读[知识准备](LEARN.md)，最后回到 README 完成标准任务。

## 先知道今天要交出什么

报告写在 `lesson-07/report.md`，计算结果存入 `lesson-07/artifacts/`。报告应说明第一期工单的邀请与回答情况、四种比例各以谁为分母、未知评分怎样影响结论，以及怎样补充调查。基础练习只帮你得到第一份可信结果；标准任务还要比较已知经历、至少两种缺失评价假设，并提出有条件的建议。

## 先做一个小判断

100张登记工单中，只有40张留下评分。如果其中32张满意，`32÷40` 能直接描述哪40张？先写一句判断，再看下面的计算。

## 核心概念与原理

- **目标总体**是报告希望描述的全部对象；本课通常是第一期登记工单，不是来访者人数。
- **未受邀**表示调查登记中确认没有收到邀请。**无回答**表示已经受邀，却没有留下评分。没有匹配到调查登记的工单，邀请情况待核实，不能猜成未受邀。
- **邀请率**以全部目标工单为分母；**受邀者回答率**以受邀工单为分母；**回答者满意比例**只以有评分工单为分母。即使两个比例数值相同，也可能描述不同的人群。
- **缺失评价**是尚未取得的评分。比较已有业务、等待等信息可以了解哪些工单没有评分，却不能直接知道它们是否满意。改变未知者满意比例的假设、观察结论变化，称为**敏感性分析**。

已回答工单的满意比例是观察到的结果，不自动等于全部工单的满意比例。先用最宽的上下界表示未知评分可能造成的范围，再比较有实际用途的假设；[知识准备](LEARN.md)有完整的小例子。

## 基础练习（可信起点）：入门跟做

### 1. 先预测，再运行起始程序

**动作：**在自己的学生仓库根目录运行下面的命令；根目录是同时包含 `scripts/` 和 `data/` 的文件夹。

```bash
python scripts/course.py start 07
python scripts/course.py run 07
```

若终端提示找不到 `python`，改用 `python3`；若使用完整课程资料库，先进入 `student-template/`。**目的：**先取得第一期工单与调查登记的实际数量，再检验你的预测。

**成功信号：**终端显示 `lesson-07/artifacts/starting_overview.json`；它只是起始概览，不是完整报告。**反思：**调查表包含两期，为什么第一期的分母不能用全部调查登记数？

### 2. 从一项评分走到四种比例

**动作：**打开输出文件。`target_tickets` 是第一期工单数，`matched_surveys` 是匹配到的调查登记数；`unmatched_tickets` 和 `unknown_invitation` 分别记录未匹配及邀请状态不明的工单。本期两项都是0。`invited` 是受邀数，`responded` 是有评分数。`observed_score_counts` 中，评分4级和5级的数量相加，就是采用“评分不低于4级”为满意时的已知满意数；你可以先找到5级这一项，本期为1,291张。

**目的：**分清“受邀”“有评分”“满意”是不同状态。**成功信号：**你能从输出算出邀请率、受邀者回答率、全部工单中有评价的比例、回答者满意比例，并在每个比例旁写出分子和分母。本期没有未匹配或邀请状态不明的工单，因此未受邀数可用 `matched_surveys－invited` 核对；受邀无回答数可用 `invited－responded` 核对。**反思：**如果 `unmatched_tickets` 不为0，还能直接把 `target_tickets－invited` 称为未受邀数吗？

### 3. 手算未知评分的上下界

**动作：**先用另设的小例子练手：100张目标工单中40张有评分，32张满意。算回答者满意比例；再假设其余60张全部不满意、全部满意，分别算全部100张的满意比例。必要时读[知识准备](LEARN.md)的分步计算。

**目的：**认识回答者结果与全部目标工单结果的区别。**成功信号：**回答者比例为 `32÷40=80%`；两种极端情况下，全部工单比例分别为32%和92%。这不是由抽样误差得到的置信区间。**反思：**为什么32%和92%的分母都是100，而80%的分母是40？

## 入门反思

回到本期数据：哪些数量是已经观察到的？哪些满意比例需要对没有评分的工单另作假设？不要把小例子的32、40、100写成本期结果。

## 标准任务（本课应完成）

### 4. 比较谁留下了评分

**动作：**按 `ticket_id` 把第一期 `data/service/tickets.csv` 与对应的 `data/service/satisfaction.csv` 连接，也就是让每张工单找到同编号的调查登记。先检查同一编号是否出现多条调查记录；连接后仍应一张工单只算一次。调查表的 `invited=0` 表示未受邀，`invited=1` 且 `score` 空白表示受邀无回答，有1—5级 `score` 表示已回答；未匹配或邀请状态不明者另列。比较各组的业务类型、等待时间和放弃排队情况，同时报告每组工单数。`business_code` 的 `basic` 和 `case` 分别是常规、复杂业务，可在 `data/service/business_types.csv` 核对。

**目的：**查看已知办理经历是否与取得评分有关，为后续假设和补充调查确定重点。**成功信号：**每个比较都写明组别、分母和指标；三组人数与单列的待核实人数相加，等于第一期目标工单数。放弃者的等待时间是离开前的等待，不能说成接受服务后的等待。**反思：**即使两组的等待或业务构成相近，你是否已经知道未回答者的真实评分？

### 5. 比较至少两种缺失评价假设

**动作：**用本期已知满意数、无评分工单数和目标工单数计算全不满意与全满意的上下界。再比较至少两种有实际差别的假设；可以分别设定未受邀组与受邀无回答组的满意比例，也可以按已知特征分组，但要说明为什么选这些假设。计算方法是：把已知满意数与各无评分组“工单数×假设满意比例”相加，再除以全部目标工单数。假设某组满意比例为 `q`，这里的 `q` 是该组未知评分中假设的满意份额，不是实际观察值。

**目的：**检查全体满意比例和发布建议对未知评分有多敏感。**成功信号：**报告中每个情景都写明适用哪组、使用什么比例、算出的全部目标工单满意比例；情景结果应位于你算出的上下界内。若用分组调整，权重来自各组目标工单数，而不是回答人数。**反思：**哪组人数或假设变化对你的建议影响最大？这能否直接告诉你该组真实满意程度？

### 6. 写发布建议和补充调查计划

**动作：**选择与发布用途有关的问题，例如“如果发布部门要求全部工单至少达到某满意比例，未知评分需满足什么条件？”若所有无评分工单暂用同一假设满意比例，可以用“门槛比例×全部目标工单数－已知满意数”，得到还需要多少张满意，再除以无评分工单数。门槛是你提出并解释用途的假设，不是统计学统一标准。写出你建议报告哪些现有结果、先调查哪组、打算通过什么渠道联系、估计需要多少人时或费用，以及何时重算或停止。数据没有真实联系方式和费用，须把这些写成方案假设；本课不实际联系任何人。

**目的：**把尚未观察到的信息转化为清楚的发布条件和可执行的调查方案。**成功信号：**读者能分辨“已回答工单的观察结果”“全部工单的上下界”“某一假设下的结果”和“建议改变所需条件”。**反思：**只调查最容易联系的人，是否一定能缩小对全部工单满意比例的不确定性？

完成后对照 README 的五项分析任务。`check` 通过只说明提交文件齐全，不能证明缺失假设或发布建议合理。

## 提高与拓展（提前完成后）

完成标准任务后，可任选一项：按业务、等待或放弃状态分层分析未知评分；找出最接近发布条件的未知组；比较两种补充调查优先顺序可能获得的信息与成本；或独立复算邀请、回答、上下界和情景结果。各组工单数、回答数与分母都要报告，并说明新增结果是否改变建议。回答率提高，也不一定消除无回答带来的偏差。

## 卡住时按顺序排查

1. 找不到 `scripts/course.py`：确认当前目录同时含 `scripts/` 和 `data/`；找不到 `python` 时试 `python3`。
2. 找不到输出：确认 `run 07` 成功，再打开 `lesson-07/artifacts/starting_overview.json`；改过程序后重新运行，避免看旧文件。
3. 数字对不上：先限定第一期，再检查 `ticket_id` 是否唯一、是否有未匹配调查登记、邀请状态和空白评分，最后检查分子与分母。空白评分不是0分。
4. 情景算不对：分别记录已知满意数、未受邀数、受邀无回答数和全部目标工单数，检查假设比例是否用于正确的组；情景结果应在上下界内。
5. 报告无从下手：按“目标与四个比例→已知经历→未知评分假设→建议改变条件→补充调查”逐段写，每段注明观察结果还是假设。
