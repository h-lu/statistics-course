# 第22课 · 多元回归的模型比较与解释

## 项目背景

服务负责人需要了解：在不同地区、工单复杂度和工作负荷下，完成工单预计需要多长时间。你的分析应解释为什么相同的积压量可能对应不同的预计时长，但不能将地区系数解释为员工能力排名。

围绕一项具体使用需求，在明确的地区和负荷条件下进行比较，判断是否需要交互项、非线性项，或采用较简单的描述方法。

可用资料为[预测分析数据集](../data/prediction/README.md)中的`requests.csv`。**资料全部为教学合成数据。** 数据字典说明记录单位、字段、时点和局限；同时阅读`feature_availability.csv`。你可以全程使用AI完成编程、分析、写作与提交，也可以复用前课代码。

## 任务分层

本课直接接续[第21课的相关与单变量回归](../lesson-21/README.md)。第一次做这一类项目时，按[陪做支持](SUPPORT.md)完成每一步；概念解释见[知识准备](LEARN.md)。

### 基础练习（可信起点）

1. 沿用月0—11开发、12—15验证，选定一个目标地区和一个实际出现过的负荷范围。
2. 拟合一个包含地区、复杂度和负荷的多元回归，明确分类变量参照组和连续变量单位。
3. 为同一组实际输入条件计算两个地区的预计时长；检查这些条件在数据中是否有记录支持。

基础练习帮助你得到可信的第一份结果，**并不等于已经完成本课**。继续完成下面的标准任务，才能把计算变成可使用的统计结论。

### 标准任务（本课应完成）

1. 沿用月0—11开发、12—15验证，先声明目标地区和负荷范围。写清分类变量的参照组、连续变量的单位和需要比较的条件；不能用全表结果倒推目标人群。

2. 比较统计含义不同的多元回归模型，例如各地区采用共同斜率或不同斜率，以及采用线性或非线性关系。说明比较时哪些变量保持相同。

3. 检查workload与staffing_index的共同变化及系数稳定性。报告相关变量取舍对条件对比和预测误差的影响，不能仅按p值删除变量。

4. 给出至少一个典型情境和一个边缘情境的预计时长对比，并说明其适用范围；由证据决定采用更简单模型、复杂模型或分场景说明。

以上均为本课需要完成的任务，分析方法和报告形式可以自行选择。评价不以图表或模型数量为依据。使用外部资料时注明来源，补充的业务假设应明确标注，不得当作已知事实。

### 提高与拓展（提前完成后）

完成标准任务后，从下面选择一项深入；重点是改善证据或决策，不按代码、图表或模型数量评价。

- 用条件预测图比较共同斜率与地区交互模型，判断复杂模型是否带来可解释的改善。
- 更换参照组或相关变量组合，检查预测是否稳定、单个系数为何变化。
- 为边缘输入组合标记外推程度，提出比直接给出单点预测更稳妥的使用规则。

## 示例代码与运行方法

从仓库根目录运行：

```bash
python scripts/course.py start 22
python scripts/course.py run 22
```

本课`analysis.py`读取数据并生成`artifacts/starting_summary.json`，用于熟悉数据结构。**请在此基础上完成本课分析任务，形成自己的分析方案和结论。** 可使用Python标准库、numpy/scipy、pandas、statsmodels、scikit-learn或其他合适工具；说明新增依赖与运行命令。

## 成果要求与提交

- `report.md`：面向报告使用者，写清分析问题、方法依据、主要结果、适用范围和建议。
- 可复现的分析程序或研究设计文件，以及报告引用的计算结果和图表；不要手工修改原始数据。
- `submission.json`：将`status`设为`complete`，`report`指向分析报告，`artifacts`列出支持报告结论的结果文件路径，`run`填写可复现分析的命令。

仅运行示例代码或粘贴模型输出，还没有完成本课分析任务。合格报告应说明变量编码、比较条件和结果含义；更好的报告还会根据共线性或数据覆盖不足调整解释，不将每个回归系数都当作可以通过管理措施改变结果的依据。

完成后执行`python scripts/course.py check 22`，按[项目工作流](../docs/WORKFLOW.md)提交并创建`v2-l22-final`标签；有修订时保留原标签。自查按[知识自查说明](../docs/KNOWLEDGE_CHECK.md)进行。项目分析允许全程使用AI，不要求提交AI对话记录。
