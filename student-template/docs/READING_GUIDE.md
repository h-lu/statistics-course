# 第一次阅读课程材料与运行程序

这份指南帮助你找到学习、计算和写报告的位置，不增加作业要求。已经熟悉这些操作时可以跳过。第一次配置个人仓库，按[操作与提交步骤](WORKFLOW.md)进行。

## 一节课先读什么

先读本课 `README.md` 的项目背景，弄清要回答的问题、需要提交的内容和三层任务边界。然后按 `SUPPORT.md` 的入门跟做获得一份可核对的起点结果，再读 `LEARN.md` 的概念与例子。遇到不熟悉的词，可以回看前课或请AI解释，不必等到全部读完才提问。

`SUPPORT.md` 中的基础练习是可信起点，不是整课作业的简化替代。完成起点后，回到 README 继续完成标准任务；提前完成后，再做提高与拓展中的一项实质分析。

接着运行 `analysis.py`，查看示例读到了哪些记录、输出了什么。它只是开始分析的示例，不是完整答案。按任务修改程序、计算结果，再将 `report.md` 中的写作问题替换为你的分析。报告结构可以调整；没有使用的资料不需要为了填栏目而强行分析，但本课规定的主要任务仍要完成。

`LEARN.md` 中的短例子使用另设数据，是为了看清计算过程。展开的Python代码只核算这些例子，不能用例子的结果代替正式项目分析。

## 文件名各表示什么

| 名称 | 用途 |
|---|---|
| `.md` | Markdown文本文件，用普通文字和简单标记写标题、表格、链接。网页上看到的排版来自这些标记。 |
| `.csv` | 数据表的文本格式，通常一行是一条记录、第一行是字段名。字段就是一列，例如等待时间。每行描述谁，要看数据说明。 |
| `.py` | Python程序文件。运行它才会执行计算，打开文件只是阅读代码。 |
| `.json` | 按字段名保存信息的文本格式。例如 `"mean": 5` 表示字段mean的值为5；`[]` 表示列表。 |
| `artifacts/` | 本课保存计算结果和图表的文件夹，名称本身不是一种统计方法。 |
| `submission.json` | 说明报告在哪里、哪些结果需核对、用什么命令运行的文件，不是分析报告。 |

文件夹用来组织文件；`lesson-01/report.md` 表示第1课文件夹中的报告。文件名前后的英文符号、大小写和扩展名应保留，不把中文说明当作路径的一部分。

## 命令在哪里输入

在电脑或编辑器的**终端**中输入命令，不是在Markdown文件里，也不是在显示 `>>>` 的Python交互窗口里。如果当前显示 `>>>`，可输入 `exit()` 返回终端。

先进入自己的学生仓库文件夹，确认能看到 `scripts` 和 `data`。完整课程资料库中应先进入 `student-template`。教程中的 `bash` 和三个反引号是代码块的排版标记，不需要输入。

以第1课为例，依次输入下面两行；如果电脑用 `python3` 启动Python，就把 `python` 换成 `python3`。

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

`start` 把本课状态记为正在进行，不是创建答案；`run` 按提交配置中的命令运行分析。终端若显示 `lesson-01/artifacts/starting_overview.json`，这是结果文件的位置。用编辑器打开文件，就能看见字段名和数值；同一文件可能已随模板提供，重新运行后应查看本次生成的内容。

输出中的小数位可能很多。报告可以按问题需要保留合理精度，例如分钟保留两位小数；后续计算仍使用未四舍五入的数值，并保持表格和文字一致。不要为了使显示结果相同而手工改写原始数据。

终端报告错误时，保存错误信息，请AI或教师帮助核对当前文件夹、文件名和软件包；不要把“程序未运行”写成“结果已验证”。不必把理解每行代码作为学习统计概念的前提。

## 怎样把结果放进报告

先让程序把用于论证的数值写入结果文件。例如你生成了 `lesson-01/artifacts/wait_summary.csv`，报告中可以这样引用：

```markdown
各组等待时间的计算结果见[等待时间汇总](artifacts/wait_summary.csv)。
```

这里的文件名只是例子，必须换成你实际生成的文件。文字还要说明这些数字支持什么结论，不能只贴一个文件链接。写图片链接时也应先确认图片文件已经生成。

同一个结果文件在两处写法不同：报告位于 `lesson-01` 中，所以链接从该文件夹写起；`submission.json` 的结果路径则从学生仓库根目录写起，应写为 `lesson-01/artifacts/wait_summary.csv`。其他课把 `01` 换成相应两位课次。

完成分析后，保留提交配置原有的课次字段；将 `status` 改为 `complete`，在 `artifacts` 列表中填写实际结果路径。`run` 是命令各部分组成的列表，例如 `["python", "lesson-01/analysis.py"]`，不是一个整句字符串。JSON使用英文双引号，不写注释；完整示例见[操作与提交步骤](WORKFLOW.md)。尚未完成分析时，不要只改状态来表示完成。

## 检查、提交和知识自查有什么区别

`run` 执行计算，`check` 检查完成状态、路径和文件存在性；后者不重新计算，也不判断统计解释。推送后的自动检查还可能重跑程序。检查失败或排队时保留本地成果并向教师说明，不因看到一个文件就认为全部通过。

**提交**是用Git保存一个版本，**推送**是把本地版本上传到个人仓库；只有本地提交还没有上传。**标签**是给某个版本起固定名称，例如 `v2-l01-final`，用于记录本课提交的版本。保留原标签，修改后使用规定的修订标签；具体命令见操作说明。

课末的A题、概念学习和B题是知识自查，不能代替项目报告，也不要求提交AI对话。学习例子的可选测试只核算例子，不评价你的正式项目；参与方式和评分见[知识自查说明](KNOWLEDGE_CHECK.md)与[成果与评分](ASSESSMENT.md)。
