# 第10课 · 为随机需求设计容量方案

告警部门每天要提前预订复核名额。当天阳性请求数会变化，闲置名额不能退款，短缺需要转送并付出额外代价。你为部门比较容量方案，给出适用于不同需求情境的预订建议。

**本课问题：平均需求相同，为什么可能需要不同的复核容量？**

所有数据均为教学合成。AI可以完成方案、代码、分析、写作和提交，不要求编程先修、提示词日志或额外答辩。先用本页明确目标，再自行选择工作方式；[LEARN](LEARN.md)解释概念，[SUPPORT](SUPPORT.md)按卡点提供帮助，不要求按统一操作顺序完成。

## 数据、条件与选择

正式数据demand.csv给每种日需求及其发生概率；base是基准设定，stress是大需求日更突出的压力设定。每预订一名额花2，没用也不退；一台请求超出容量，主设定另付8。预算240只限制预订支出。

[数据字段、抽人和回答规则](../data/inference-09-14/README.md)写明字段、预算和方法边界；最小程序为[analysis.py](analysis.py)，Python 3.10+标准库即可。共同数据是默认可运行路线，可替换计算工具，比较时应说明是否改变了目标人群、抽人或回答规则。

你决定预订多少容量，以及按平均总成本还是短缺风险优先评价。你还可决定在基准和压力情境之间怎样作稳健取舍，但必须给出业务理由；不能为了让某方案胜出再改评价口径。

## 基础练习（可信起点）

需求0、1、2的概率0.2、0.5、0.3，均值1.1，方差0.49；容量1的短缺概率0.3。程序重复模拟10000天供核对，结果接近精确值而不必相等。 可以手算、读代码或请AI换一个例子解释。基础例子的运行不代表完成标准任务。

## 标准任务（本课应完成）

主情境按当日转送的短缺代价8评价。在每日预订预算240内比较至少两个容量，使用相同需求情境和相同模拟日序列。在看结果前说明更重视平均成本还是短缺严重度，给出业务依据；分别报告平均总成本、短缺概率、绝大多数天短缺不超过多少台（用高分位数表示，算法见LEARN并在报告中注明）和最大可能短缺；用离散状态精确加权核对模拟均值或短缺概率。比较base与stress，针对平均需求相同、大需求日的频率和大小却不同的情况修订建议。

最低证据是：**追踪一个例子、做一个公平比较、说明限制**。这里公平比较指清楚写出保持什么相同、只改变什么；不是各方案必须得出同样结论。至少两项有后果的决定由你选择并解释，结论不同、有证据的保留意见或暂缓建议均可。

## 提高与拓展（提前完成后）

给出短缺代价从8到20变化时方案切换的范围；或者设计连续高需求日的压力情境，明确为什么独立抽日不能回答连续积压。
