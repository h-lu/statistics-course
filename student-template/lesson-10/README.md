# 第10课 · 为随机需求设计容量方案

服务中心需要购买每日处理容量。容量不足会产生未服务损失，买得过多又浪费。未来日需求随机，活动日与平常日不同；经理需要常态方案、活动预案和对预测失准的准备。

**数据均为教学合成，不代表真实机构或真实效果。** 本课可以全程使用AI完成编程、分析、写作与提交；报告需要说明主要结论的统计依据和适用条件。

## 从问题开始

按平均需求购买容量，是否意味着大多数天都不会缺额？先预测哪些天最容易使这个规则失效。

先阅读[知识准备](LEARN.md)。必要概念用于解释你的成果，计算和复杂实现可以交给工具。

## 可用材料

- [demand_history.csv](../data/inference/demand_history.csv)
- [capacity_options.csv](../data/inference/capacity_options.csv)

先阅读[数据字典与任务要求](../data/inference/README.md)，了解观测单位、字段含义、分组、时间范围和数据局限性。示例代码只读取数据并生成概览；请根据分析问题扩展它，或另写分析程序。

## 分析任务

1. 区分历史期和留出期，检查工作日、活动、天气下需求的均值、离散和尾部。建立至少一种与数据机制相容的随机需求模型，说明为什么不直接假定方差等于均值。

2. 在相同模拟需求下比较容量方案的期望成本、未服务量和尾部风险。保留一个目标不同的可行对照，说明常态与已知活动日是否使用不同容量。

3. 先依据历史期数据确定规则，并在后续评估中保持不变，再用42天留出期数据评价。改变损失设定、活动频率或整体需求水平进行敏感性分析，给出采购建议，并说明什么情况下应重新评估。

## 需要你作出的选择

可以用经验重抽样、分层模型或合适的计数分布；决定优化期望成本还是对未服务风险加约束。方案必须来自可购买容量，不能创造没有报价的无限弹性资源。

记录随机种子、情境参数和各项成本的单位；检查模拟均值、方差或分位数是否符合所设需求模型。用留出期结果说明建议能否保持，而不是看完留出期再选最优并称其为验证。 方法和结论可以不同，但需要解释选择依据，并用计算结果说明不同方案在成本、风险或服务目标上的取舍。

## 成果要求

容量模拟工具或可运行分析、采购建议报告、历史选择与留出数据评估对照表，清楚区分预测、模拟和已经发生的实际需求。

- [report.md](report.md)应能被使用者直接阅读；关键数字指向计算结果或图表文件，而不是仅写“分析表明”。
- 保存可重复运行的代码和必要分析结果到本课`artifacts/`；保留数据原貌，说明处理口径、随机性和方法条件。
- 区分观察结果、模型/情境假设与行动建议。重抽样只覆盖历史支持的情境；留出期短，未包含不代表不会发生。这里没有跨日积压、排队时长或班次人员差异，不能把件数容量结论扩大成全部服务体验。
- 实际计算备选方案或不同假设下的结果，检查这些结果是否支持报告中的结论。

## 90分钟建议安排

| 时间 | 工作 |
|---|---|
| 0—5分钟 | 阅读项目背景，记录初步判断和关心的结果 |
| 5—15分钟 | 阅读知识准备，核对小例子与必要概念 |
| 15—55分钟 | 完成主要分析或方案设计，比较备选方法；尽早形成可读草稿 |
| 55—68分钟 | 检查不确定性、假设和适用范围，修订建议 |
| 68—75分钟 | 本地重新运行、整理成果并提交 |
| 75—90分钟 | 知识自查、概念学习与变式反馈 |

时间可根据课堂进展调整。尽量在课堂完成；不以写代码行数、模型数量或耗满时间衡量成果。

## 运行与提交

从仓库根开始：

```bash
python scripts/course.py start 10
python scripts/course.py run 10
```

完成报告和分析后，在`submission.json`填写支持报告结论的结果文件路径、运行入口，并将状态改为`complete`，再运行：

```bash
python scripts/course.py check 10
```

按[操作与提交步骤](../docs/WORKFLOW.md)提交代码、报告与分析结果，本课最终标签为`v2-l10-final`。自动检查核对文件路径和运行命令；统计分析的质量还需要结合方法、计算结果和结论解释判断。

课末打开[知识自查](https://hblu.top/stat-check/)，确认页面为当日V2课次；可以先自己判断，再向AI询问概念并完成变式。参见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
