# 第10课 · 为随机需求安排复核名额

上一课，我们比较了怎样把名额分给不同设备组。本课把目光放到每天的工作量上：请求有时少、有时多，可是名额必须提前订。

你要给复核部门一个建议：预订多少复核容量（capacity）比较合适？如果大需求日比原来设想的更突出，建议要不要改变？

先读[学习材料](LEARN.md)中的小例，再选择自己的分析方式。AI可以帮助理解、写代码和检查，不要求提交对话记录。

## 已知条件

[需求表](data/demand.csv)是教学模型，不是实际采集的业务记录。base与stress分别给出基准、压力两种日需求的概率分布（probability distribution），两者平均需求都是88台。

- 每订一个名额花2元，即使空着也不退钱。
- 每台超出容量的设备当天转送，另付8元。
- 提前预订的预算是240元，因此容量是0至120之间的整数。
- 转送费不含在240元预订预算里，总成本可能超过240元。
- 请求当天处理或转送，不积压到第二天。

字段说明见[data/README.md](data/README.md)。

## 你需要作出的选择

首先说明自己更重视平均花费，还是繁忙日的短缺风险。再选择至少两个有理由的容量作比较。

你可以把“达到某项服务要求后尽量省钱”作为目标，也可以解释自己愿意为降低短缺承担多少额外花费。目标应在看最终比较结果前说明，不能只挑一个让喜欢的方案胜出的指标。

## 本课的一件作品

写一份给部门负责人看的简短建议，附上能核对的比较表和计算文件。标准完成应包含：

1. 比较至少两个容量，检查它们都符合预订预算。
2. 对每个容量，分别在base和stress下计算平均总成本、短缺概率、95%短缺分位数（quantile，定义见下文）。
3. 选其中一个“情境＋容量”，用概率加权手算或精确枚举，再用随机模拟核对平均成本或短缺概率。模拟结果接近即可，不要求相等。
4. 说明选择、代价及适用条件。若压力情境改变了建议，要说清原因；若没有改变，也要给出依据。

精确枚举可以承担主要比较，不必为了代码量把所有事情模拟一遍。若用模拟比较容量，请让不同容量面对同一批模拟需求。

本课95%分位数统一用“累计概率第一次达到95%对应的短缺台数”，不要直接套用默认插值算法。

## 不同完成程度怎样安排？

- **基础练习：**先算懂LEARN中的0、1、2台小例，检查容量1的平均成本5.6元与短缺概率0.3。它是理解起点，还不是正式任务的完整成果。
- **标准完成：**完成上面的一件作品。可以使用提供的计算辅助程序，也可以请AI协助构建自己的计算。
- **扩展练习：**完成标准任务后，再从[EXERCISES](EXERCISES.md)选一项：研究短缺代价变化，或研究连续忙碌日与积压。无需全部完成。
