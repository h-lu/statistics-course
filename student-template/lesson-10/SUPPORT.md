# 第10课支持路线 · 为随机需求选择容量

## 先知道今天要交出什么

你要为服务中心交出常态容量方案、活动日预案和需求失准时的调整条件。最终至少包括：

- `report.md`中的采购建议和适用范围；
- `artifacts/`中的候选容量对照表，含期望成本、未服务量和尾部风险；
- 历史期选规则、42天留出期评价及敏感性分析的可运行程序。

入门跟做只建立需求分组和一次成本核算。完成它并不等于完成本课标准任务。

## 核心概念与原理

**随机变量**表示未来一天的需求量可能取不同值；它的**分布**说明这些值出现的可能性。均值只说明长期中心，方差和尾部决定容量不足的风险。即使平均需求等于容量，也不表示大多数天都没有缺额。

容量为`c`、当天需求为`D`时，闲置量是`max(c−D,0)`，未服务量是`max(D−c,0)`。成本应包含固定成本、闲置成本和未服务损失。所有候选方案必须在同一批模拟需求上比较，这样差异来自容量规则，而不是不同的随机样本。

**留出数据**是选定规则时没有使用的较晚数据。先用`history`选择规则，再保持规则不变，在`holdout`上评价，才能减少“看过答案再选”的乐观偏差。

## 基础练习（可信起点）：入门跟做

先在**仓库根目录**打开终端，完整运行：

```bash
python scripts/course.py start 10
python scripts/course.py run 10
```

第二条命令成功时，终端会提示概览已经写入`lesson-10/artifacts/starting_inventory.json`。打开这个文件；它只是数据起点，不是本课答案。若文件没有生成，先按后面的排错顺序处理，再继续。

### 第一步：认识历史期与留出期

- **动作**：运行`python scripts/course.py run 10`，打开`lesson-10/artifacts/starting_inventory.json`和`data/inference/README.md`。
- **目的**：确认一行代表一天，并找到`requests`、`event`、`rain`、`weekday`和`split`。
- **成功信号**：你能分别数出`history`与`holdout`天数，并且没有用留出期选择容量。
- **反思**：若先查看留出期再改变规则，这次评价还能称为留出评价吗？

### 第二步：比较中心与波动

- **动作**：只用`history`，按普通日和活动日分别计算需求均值、方差和一个高分位数。
- **目的**：判断需求是否存在活动冲击和过度离散，避免只按总均值建模。
- **成功信号**：结果明确写出每天“件数”单位；每组都同时有中心和尾部信息。
- **反思**：哪一种统计量最直接反映“少数特别忙的日子”？

### 第三步：手算一天的方案损失

- **动作**：从`capacity_options.csv`任选一条方案，再任选一个简单需求值，手算固定成本、闲置成本或未服务损失；让程序算同一例核对。
- **目的**：确认损失函数中的方向和单位。
- **成功信号**：同一天不会同时出现正的闲置量和正的未服务量；各项成本相加等于总损失。
- **反思**：未服务单位损失变大时，较高容量为什么可能更有吸引力？

### 第四步：建立共同情境比较

- **动作**：选择一种与数据相容的需求生成方法，用固定随机种子生成一批未来需求，并让所有容量方案使用这同一批需求。
- **目的**：公平比较候选方案并检查模拟机制。
- **成功信号**：模拟需求的均值、方差或分位数与设定相符；每个方案得到期望成本与未服务风险。
- **反思**：增加模拟次数解决的是模拟误差，还是未来机制选错的问题？

### 入门反思

先写下你的主要目标是期望成本最小，还是限制缺额风险；再写出活动日是否需要单独规则。目标不同，合理方案可以不同。

## 标准任务（本课应完成）

1. 用历史期检查工作日、活动和天气条件下的需求中心、离散及尾部，说明需求模型依据。
2. 在相同模拟需求上比较所有可购买方案，至少报告期望成本、未服务量和尾部风险。
3. 保留一个目标不同但可行的对照方案，分别给出常态与已知活动日安排。
4. 冻结选择规则后，用42天留出期评价，不因留出结果重新挑选并称为验证。
5. 改变损失、活动频率或整体需求水平进行敏感性分析，写出重新评估条件。

## 提高与拓展（提前完成后）

- 比较经验重抽样与一个考虑过度离散的计数模型，说明差异来自哪些分布假设。
- 在期望成本之外增加“缺额超过某一水平的概率”约束，展示成本与服务风险取舍。
- 对未来整体需求上移或活动频率改变建立压力情境，检查原方案何时不再可行。
- 量化留出期评价的不确定性，避免把短期没有极端日解释为风险不存在。

## 卡住时按顺序排查

1. 用`pwd`确认仓库根目录，再运行`python scripts/course.py run 10`。
2. 分期错误时，直接检查`split`字段，不要按行号自行猜测。
3. 成本异常时，先对一个需求值和一个容量方案手算，再扩展到全部数据。
4. 模拟每次结果不同且难复核时，设置并记录随机种子。
5. 所有方案结果一模一样时，检查循环中是否真正使用了各自的`capacity`和报价。
6. 报告无从下手时，先写“常态选什么、活动日选什么、什么变化会撤回建议”。
