# 第27课陪做支持 · 从观察关联到因果研究设计

这份材料帮助你在不知道下一步时建立可信起点。它不提供本课正式数据的答案，也不能代替 [README 主任务](README.md)；概念的完整解释见 [LEARN.md](LEARN.md)。

## 先知道今天要交出什么

- `report.md`：现有观察结果与未来研究方案分开的设计报告。
- 目标研究要素、因果关系图或变量关系表，以及数据补采建议。
- `submission.json`：列出描述结果和研究设计文件。

最低出口是：别人能够按你的命令重新生成报告引用的数字，并知道这些数字可以和不可以用于什么决定。

## 核心概念与原理

| 规范术语 | 通俗解释 | 怎样在自己的结果中检查 |
|---|---|---|
| 潜在结果 | 同一个人在接受与不接受支持两种策略下可能出现的结果；现实通常只能观察其中一个。 | 定义要比较的两种处理策略。 |
| 平均处理效应（ATE） | 在明确目标人群中，两种潜在结果之差的平均。 | 写清人群、时间零点、处理和随访结果。 |
| 混杂 | 某个处理前因素同时影响支持选择与随访结果。 | 解释未经调整差异为何不是直接效果。 |
| 中介变量 | 位于支持影响结果的路径上的处理后变量。 | 估计总效应时不能无条件控制。 |
| 碰撞变量 | 同时受两个变量影响的共同结果；按其筛选或调整可能引入新关联。 | 检查回访参与等处理后选择。 |

### 先用一个小例子想清楚

严重程度S影响是否接受支持A，也影响随访负担Y，写作 A←S→Y。支持后的联系次数M可能在 A→M→Y 路径上。若目标是支持的总效应，控制M会改变问题；这和控制处理前严重程度不是同一件事。

这个例子只用于核对概念，不是正式数据的结论。正式项目必须使用自己的运行结果。

## 基础练习（可信起点）：入门跟做

以下命令都从仓库根目录运行，也就是同时能看到 `scripts/`、`data/` 和 `lesson-27/` 的目录。

```bash
python scripts/course.py start 27
python scripts/course.py run 27
```

第二条命令成功后，应看到终端提示结果已经生成，并能打开 `lesson-27/artifacts/starting_summary.json`。这个文件只是数据起点，不是本课完整答案。

若终端明确提示 `python: command not found`，按仓库首页说明，把上面两行开头的 `python` 换成 `python3`，其余内容不变。

### 第1步：先描述观察差异

- **动作：** 运行起点程序，比较支持组与未支持组的严重程度、基线负担和随访负担。
- **目的：** 先看人群为何不可直接相比。
- **成功信号：** 结果表同时显示组别人数、基线和随访指标。
- **想一想：** 哪一项基线差异可能同时影响支持选择与结果？

### 第2步：写清目标研究

- **动作：** 填写入组资格、时间零点、处理策略、比较策略、随访终点和目标人群。
- **目的：** 不先定义问题，就无法判断需要什么设计。
- **成功信号：** 读者能判断某个人何时进入研究、接受哪种策略。
- **想一想：** “接受过支持”是否足够精确，支持从何时算起？

### 第3步：画出假设关系

- **动作：** 用文字箭头、图或变量表区分处理前共同原因、处理后中介和可能的碰撞变量。
- **目的：** 变量调整由因果问题和时点决定。
- **成功信号：** 每个变量都有测量时点和角色说明。
- **想一想：** 如果只分析参与回访者，会打开什么选择问题？

### 第4步：比较可行设计

- **动作：** 比较随机名额、准实验或观察研究需要的资源、伦理条件和识别假设。
- **目的：** 把“最好做实验”转成能执行的方案。
- **成功信号：** 至少一个方案写明分配、测量、分析和失败风险。
- **想一想：** 当前最值得补采的信息会减少哪一种不确定性？

完成这四步后，你已经有可信起点，但还没有完成整项主任务。

## 标准任务（本课应完成）

回到 [README](README.md) 完成全部标准任务，特别核对：

- 报告未经调整差异但不把它当效果。
- 完整定义目标研究与平均处理效应。
- 表达因果假设并区分处理前、处理后变量。
- 提出可执行研究设计、限制和优先补采信息。

把程序输出翻译成完整统计句子：对象是谁，比较什么，数值和单位是什么，哪些假设成立时可以怎样使用，哪些结论仍不能作出。

## 提高与拓展（提前完成后）

先完成标准任务，再选一项。提高的标准是让证据、适用范围或行动更可靠，而不是增加代码或图表数量。

- 把未测量共同原因转成具体补采。
- 比较三类设计的可行性和识别条件。
- 补充干扰、失访或执行不一致的处理。

## 卡住时按顺序排查

- **图中箭头越画越多：** 只保留与处理选择、随访结果和选择进入分析有关的变量，并为每条箭头写一句情境依据。
- **命令提示找不到文件：** 先运行 `pwd`，确认当前位置是仓库根目录；这里应同时看见 `scripts/` 和本课目录。
- **程序能运行但结果还是旧的：** 检查结果文件的修改时间，确认修改并运行的是本课 `analysis.py`；必要时删除自己生成的旧结果后重跑，但不要删除原始数据。
- **报告数字和程序输出不一致：** 从报告中的一个关键数字反向找到结果文件、筛选范围、分子和分母；不要手工把报告改成“看起来合理”的数字。
- **不知道怎样开始写报告：** 先写五句：谁使用、要决定什么、数据覆盖谁、一个主要结果、一个不能支持的结论，再补方法和证据。
