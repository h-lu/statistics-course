# 第19课支持路线 · 在多项指标中控制错误发现

## 先知道今天要交出什么

你要交出全部12项指标的分析结果表和发布规则。表中至少有指标用途、改善方向、效应、区间、原始p值、校正结果和实际重要门槛；报告还要区分可验证结论、可能伤害、不确定结果与待验证发现。

入门跟做只建立指标计划与完整结果表的骨架，不能代替保留团队结构的效应估计和多重比较分析。

## 核心概念与原理

同时检验多个假设，会增加偶然出现显著结果的机会。需要共同控制错误率的一组假设称为**检验族**，应按发布用途事先界定，而不是看到结果后把不显著项移走。

**族错误率（family-wise error rate，FWER）**是一个检验族中至少错误拒绝一个真实原假设的概率，常用于验证性结论。**错误发现率（false discovery rate，FDR）**是错误拒绝数占全部拒绝数比例的期望，常用于探索性清单。FDR不是每条被选中结论为假的概率，也不保证本次清单恰有固定比例错误。

多重比较校正只处理特定的错误率问题，不能替代效应大小、置信区间、方向、安全性或实际门槛。未显著也不等于安全或相等。

## 基础练习（可信起点）：入门跟做

先在**仓库根目录**打开终端，完整运行：

```bash
python scripts/course.py start 19
python scripts/course.py run 19
```

第二条命令成功时，终端会提示概览已经写入`lesson-19/artifacts/starting_inventory.json`。打开这个文件；它只是数据起点，不是本课答案。若文件没有生成，先按后面的排错顺序处理，再继续。

### 第一步：连接指标数据与预先计划

- **动作**：从仓库根运行`python scripts/course.py run 19`，读取`experiment_metrics.csv`和`metric_plan.csv`，按`metric`核对一一匹配。
- **目的**：在查看组间结果前固定每项指标的用途、改善方向和实际门槛。
- **成功信号**：12项指标都能匹配`family`、`desirable_direction`和`practical_threshold`，没有重复或缺失计划。
- **反思**：为什么不能看见哪些指标显著后再把它们定义为主要指标？

### 第二步：确认独立单位与指标单位

- **动作**：统计人员数、团队数、每人指标数，按数据说明为分钟、比例、计数或量表分标注单位。
- **目的**：保留团队随机结构并避免跨单位直接比较差值大小。
- **成功信号**：每个效应都带方向与单位，团队数没有被指标长表行数替代。
- **反思**：12个指标的5760行是否等于5760个独立随机化单位？

### 第三步：建立完整结果表

- **动作**：按预先方向计算每项工具组与常规组差异、区间和原始p值；结果中保留所有指标。
- **目的**：避免只展示好看的发现，并检查实际重要性与不利方向。
- **成功信号**：12项全部出现，效应符号能按`desirable_direction`解释，区间与门槛并列。
- **反思**：统计显著但未达到实际门槛时，发布措辞应怎样限制？

### 第四步：先定义检验族，再做校正

- **动作**：根据`family`和发布目的写出哪些假设共同控制FWER、哪些作为探索控制FDR，再计算相应校正。
- **目的**：让错误率控制对应真实发布承诺。
- **成功信号**：每次校正包含哪些指标有清单；原始与校正结果并列；方法没有按保留亮点多少切换。
- **反思**：如果把一个不显著指标从检验族删掉，原先声明的错误率控制还代表同一程序吗？

### 入门反思

用三句话区分：统计证据、实际重要性和安全性。再说明验证性结论与探索性发现分别需要什么后续行动。

## 标准任务（本课应完成）

1. 按预先计划定义主要、安全和探索问题及相应检验族。
2. 保留团队随机结构估计全部指标的效应与不确定性，核对单位、方向和门槛。
3. 并列原始p值与合适的FWER或FDR校正，解释各自控制的量。
4. 把全部指标分类为改善、可能伤害、不确定或待验证，不隐藏无显著和不利结果。
5. 形成发布措辞与后续独立验证计划，不在同一数据上反复调整规则。

## 提高与拓展（提前完成后）

- 比较Holm与Bonferroni在验证族中的结果和假设，不按显著数选择方法。
- 对探索指标比较适合的FDR方法，并讨论指标相关性对条件的影响。
- 构建同时显示效应区间、实际门槛和校正结论的结果图或表。
- 为安全指标预先定义可接受伤害界值，说明为何`p>0.05`不能证明安全。

## 卡住时按顺序排查

1. 指标行数异常时，检查每人每指标是否唯一。
2. 方向混乱时，先用`desirable_direction`定义“改善”为正或明确原始差值顺序。
3. p值校正数量不对时，列出当前检验族的指标名再运行。
4. 结果只剩显著项时，回到完整12项表，禁止过滤后发布。
5. 推断过于乐观时，检查是否忽略团队层级。
6. 写报告时按“预先计划—完整结果—错误控制—实际意义—后续验证”组织。
