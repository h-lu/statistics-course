# 第3课知识准备：哪些记录可以用于这次分析

本课要解决的不是“怎样把表格变得没有空白”，而是“这批记录能不能支持一个明确的问题”。读完后，你应该能先判断记录和字段，再决定怎样处理。

## 先记住三个问题

看到一列数据，先问：

1. 这一行描述的对象是谁？
2. 这个值的含义、单位和有效范围是什么？
3. 我准备计算的指标，分母到底包括哪些记录？

代码可以帮助计算，但不能替你回答这三个问题。

## 1. 记录单位、主键和版本

**分析单位**是结论针对的对象。本课按工单分析：一位来访者有两张不同工单，应算两张，不能按来访者自动合成一张。

**主键**是能够唯一识别一条记录的字段或字段组合。整理后的工单表可以用 `ticket_id` 作主键，但原始导出中同一个编号可能出现多行，所以必须先检查它们为什么重复。

- **完全重复记录**：字段内容完全相同，常见原因是同一行被重复导出；
- **修订记录**：同一工单的信息后来更新，`export_revision` 数值更大的版本更新；
- **冲突记录**：同一最新版本出现不同内容，不能静默选择其中一行。

文件排在后面不代表版本更新。先按版本号判断，再处理重复和冲突。

## 2. 缺失、无效和离群值不是一回事

**缺失值**表示所需信息没有取得。本课等待值 `999` 和 `-1` 是未测量编码；`0` 是已测得的零等待，不是缺失。真实秒数要先按单位换算，例如180秒是3分钟；999秒不能换算成有效等待。

**无效取值**不符合字段定义。例如状态代码不在数据说明允许的范围内，或者单位名称无法识别。它应被标记为问题，不要猜成某个合法类别。

**离群值**是与多数记录明显不同的值。60分钟可能很长，但仍可能是真实等待。只有“数值很大”不能成为删除理由；应核对来源，并报告它对结果的影响。

有些空白是因为字段不适用。放弃排队的工单没有面对面服务时长，不代表服务时长为0。先理解字段，再判断空白。

## 3. 先判断，再计算五行例子

下面是另设的学习例子，不是正式项目数据。办结状态1表示当日办结，0表示未当日办结；`UNKNOWN`表示窗口未知。

| 工单 | 版本 | 原等待值 | 单位 | 当日办结 | 窗口 |
|---|---:|---:|---|---:|---|
| R1 | 1 | 120 | 秒 | 1 | A1 |
| R1 | 1 | 120 | 秒 | 1 | A1 |
| R1 | 2 | 180 | 秒 | 1 | A1 |
| R2 | 1 | 999 | 秒 | 1 | UNKNOWN |
| R3 | 1 | 60 | 分钟 | 0 | A1 |

先不要看答案，写下：应保留几张工单？R2能不能参加办结比例？等待均值的分母是3还是2？

再按顺序核对：

1. R1的两行版本1完全相同，一行是重复导出；版本2是更新版本；
2. 最终保留R1、R2、R3，共3张工单；
3. R1等待为180÷60=3分钟；R2等待未知；R3等待为60分钟；
4. R2的办结状态已知，可以参加办结比例，但不能参加等待均值。

于是：

| 指标 | 参加的工单 | 计算 | 结果 |
|---|---|---|---:|
| 有效等待的平均值 | R1、R3 | (3+60)/2 | 31.5分钟 |
| 办结状态已知时的办结比例 | R1、R2、R3 | 2/3 | 约66.7% |
| 已确认属于A1的工单数 | R1、R3 | 计数 | 2张 |

31.5分钟只描述两张有有效等待的工单，不是三张工单的完整平均值。A1的“已确认2张”也不等于A1全部只有2张，因为R2的窗口未知。

下面的小程序只复算这三张工单，并且只检查每个指标声明需要的字段。给记录增加一个与本次分析无关的空白备注，不应改变结果。

```python
# learning-example
import json


rows = [
    {"ticket_id": "R1", "wait": 3, "completed": 1, "window": "A1"},
    {"ticket_id": "R2", "wait": None, "completed": 1, "window": None},
    {"ticket_id": "R3", "wait": 60, "completed": 0, "window": "A1"},
]

waits = [row["wait"] for row in rows if row["wait"] is not None]
completion_rows = [row for row in rows if row["completed"] is not None]
complete_case_rows = [
    row for row in rows
    if all(row[field] is not None for field in ("wait", "completed", "window"))
]

result = {
    "target_n": len(rows),
    "wait_n": len(waits),
    "wait_mean": sum(waits) / len(waits),
    "completion_rate": sum(row["completed"] for row in completion_rows) / len(completion_rows),
    "complete_case_rate": sum(row["completed"] for row in complete_case_rows) / len(complete_case_rows),
    "known_window_n": sum(row["window"] is not None for row in rows),
}
print(json.dumps(result, ensure_ascii=False, sort_keys=True))
```

## 4. 为什么同一批数据会有不同分母

**完整案例分析**指**本次分析所需字段**都有效的记录，不是所有字段都必须有值。分析问题不同，所需字段也可能不同，因此“完整”必须跟具体用途一起说明。

只计算办结比例时，三张工单的办结状态都已知，结果是2/3。若另一个报告要求等待、办结和窗口三项都有效，那么R2会被排除，办结比例变为1/2=50%。

50%和66.7%的差别来自纳入记录不同，并不表示真实办结情况被清洗程序改变。这里的**另一组字段要求**改变了记录范围。可以分别按每项指标所需字段选择完整记录，也可以统一使用等待、办结和窗口都完整的记录；前者保留更多可用信息，后者便于多个指标在同一批工单上比较，但会排除本来能参加单项计算的记录。报告应说明采用哪种方案及其取舍。

**插补**是利用已有资料和假设，为缺失值补入估计值。插补值不是查实的原值。本课不要求插补；如果选择插补，必须保留原值和插补标记，并比较插补与不插补的结果。

## 5. 两个自测问题

**问题一：** 10张不同工单中，3张缺等待，2张窗口未知，其中1张同时缺等待且窗口未知。有问题的不同工单有几张？

**问题二：** 一张工单等待12分钟，但是否放弃未知。它能否进入“已服务工单平均等待”？如果所有工单都没有有效等待，平均值应写0吗？

<details>
<summary>先回答，再展开核对</summary>

问题一是3+2-1=4张，因为同时有两个问题的工单只能数一次。问题二不能据等待值认定已服务；没有有效等待时分母为0，平均值不能计算，不是0分钟。

## 回到项目

为至少两个用途填写：分析单位、所需字段、纳入条件、指标、分子、分母和建议。至少一个指标要实际比较两种有理由的记录选择。排除某项计算不等于删除原文件；原始数据保留，处理结果和原因另存。

已给定的版本优先、缺失编码和单位换算规则不能随意修改。没有外部核实来源时，写“按约定处理”或“仍未知”，不要写“已经找到真实值”。两期日期不同，两期均值之差也不能直接解释为清洗或管理改善。

## 按需了解：遇到最新版本冲突

如果同一工单的最新版本内容不同，应保留冲突并停止自动选值，或把该工单单列后继续不受影响且范围明确的分析。不能自行平均、猜选或用文件最后一行代替版本规则。
