# 第03课｜先确定用途，再整理数据

一张工单缺少等待时间，却已记录办结状态。它不能用于等待均值，但仍可能用于办结比例。因此，数据整理应从指标所需的信息出发，而不是看到空白就删整行。

## 1. 区分工单与导出行

**观测单位**（observational unit）是记录描述的对象；**分析单位**（unit of analysis）是统计结论针对的对象。本课按工单分析，但原始导出中，同一工单可能占多行。

**主键**（primary key）是唯一识别记录的字段或字段组合。整理后的工单表应由 `ticket_id` 唯一识别。处理重复编号时，区分：

- **完全重复记录**（exact duplicate）：字段内容相同的重复导出；
- **修订记录**（revised record）：同一工单后来更新，数值更大的 `export_revision` 更新；
- **冲突记录**（conflicting record）：同一最新版本有不同内容，需要保留并核实。

同一人办两张工单与同一工单导出两次不同。前者保留两张，后者先判断重复或修订。版本按数值比较，文件的行顺序不能代替版本号。

## 2. 先识别含义，再转换单位

等待是数值变量，窗口和业务是分类变量；0/1状态码表示两个类别。对每个字段先核对定义与有效范围。

**缺失值**（missing value）表示信息没有取得。本课999和−1是等待的未测量编码，0是已测得的零等待。先识别这些编码，再转换单位；180秒等于3分钟，999不能被换算成16.65分钟。

**无效取值**（invalid value）违反字段定义，例如无法识别的单位；**离群值**（outlier）与多数记录差异较大，却可能是真实数值。60分钟等待可以先核对来源，再分析它对结果的影响。放弃者没有服务时长，则属于该字段不适用，不应解释成完成了0分钟服务。

## 3. 将五行导出整理为三张工单

下面是人工例子，办结状态1为当日办结，0为未当日办结。

|工单|版本|等待原值|单位|办结|窗口|
|---|---:|---:|---|---:|---|
|R1|1|120|秒|1|A1|
|R1|1|120|秒|1|A1|
|R1|2|180|秒|1|A1|
|R2|1|999|秒|1|UNKNOWN|
|R3|1|60|分钟|0|A1|

R1选版本2，等待为3分钟；R2等待与窗口未知，办结状态已知；R3等待60分钟。最终保留三张工单。

|指标|参加的工单|结果|
|---|---|---|
|有效等待的均值|R1、R3| $(3+60)/2=31.5$ 分钟|
|办结状态已知者的办结比例|R1、R2、R3| $2/3\approx66.7\%$ |
|已确认属于A1的工单数|R1、R3|2张|

31.5分钟描述两张有有效等待的工单；A1“已确认2张”也没有确定R2的归属。

## 4. 分母由分析所需字段决定

**完整案例分析**（complete-case analysis）使用本次分析所需字段都有效的记录。所需字段由问题决定，不是整张表的所有列。

只计算办结比例时，三张工单均可参加，得到 $2/3$ 。若要求等待、办结和窗口都有效，R2被排除，只剩R1与R3，办结比例为 $1/2=50\%$ 。

两者的差别来自纳入对象不同。逐指标选择记录能保留更多信息；统一使用多个字段都完整的记录，便于在同一批对象上比较，但会少用一些信息。

本页核算代码使用整理后的三张工单，`None`表示未知。`completion_rate`只要求办结状态有效；`complete_case_rate`要求三个字段都有效。增加无关的空备注不应改变这两项的分母。

**插补**（imputation）根据资料与假设为缺失值补入估计。若采用，应保留原值、插补标记，并比较插补前后的结果；本课的标准任务不要求插补。

## 5. 未知状态形成的范围

另设5张工单：3张已办结、1张未办结、1张未知。状态已知者的办结比例为 $3/4=75\%$ 。全体5张的比例则在 $3/5=60\%$ 与 $4/5=80\%$ 之间。

若已知办结数为 $s$ ，未知数为 $u$ ，总数为 $N$ ，全体办结比例 $p$ 满足：

$$
\frac{s}{N}\le p\le\frac{s+u}{N}.
$$

这里的范围来自同一观察时点的未知状态；第13课将讨论来源不同的抽样置信区间（confidence interval）。报告前先确定是描述状态已知者，还是希望描述全部登记工单。

## 6. 回到项目与自检

按[任务页](README.md)选择至少两个用途，为每项写清分析单位、字段要求、纳入条件与分母，并实际比较一种合理的记录选择。保存原始值、选用版本、处理结果和原因。

1. 同一工单有版本2、10，应选哪版？若版本10有两个冲突值，哪些信息仍能保留？
2. 0秒、120秒、999秒、−1分钟，哪些是有效等待？
3. 10张工单中3张缺等待、2张窗口未知，其中1张同时如此，涉及多少张不同工单？
4. 等待12分钟但放弃状态未知，能否进入“已服务工单等待均值”？
5. 2、3、55分钟与2、3、−55分钟分别需要怎样核对？理由有什么不同？

<details>
<summary>自检做完后，展开答案与理由</summary>

1. 按数值选版本10，而不是按文本排序选2。若最新版本某字段冲突，应保留冲突证据、核实该字段；其他一致且有效的字段仍可能用于不依赖冲突字段的分析。
2. 本课编码约定下，0秒是有效零等待，120秒为2分钟；999和−1是未测量编码，先记未知，不能先换算成正常等待。
3. 不同工单数为 $3+2-1=4$ ，同时缺两项的那张只计一次。
4. 不能确定它属于已服务工单，因此不能直接纳入该范围的均值；不能从12分钟等待推断未放弃。
5. 55分钟可能是需要核实的真实长等待；−55分钟违反等待非负的定义，应查录入或单位错误。两者不能都按“看起来极端”自动删除。

## 可选代码核对

先完成手算，再运行下面的人工例子，对照前面的数值。正式项目按任务页另行完成。

<details>
<summary>展开核算代码</summary>

```python
# learning-example
import json


rows = [
    {"ticket_id": "R1", "wait": 3, "completed": 1, "window": "A1"},
    {"ticket_id": "R2", "wait": None, "completed": 1, "window": None},
    {"ticket_id": "R3", "wait": 60, "completed": 0, "window": "A1"},
]

waits = [row["wait"] for row in rows if row["wait"] is not None]
completion_rows = [row for row in rows if row["completed"] is not None]
complete_case_rows = [
    row for row in rows
    if all(row[field] is not None for field in ("wait", "completed", "window"))
]

result = {
    "target_n": len(rows),
    "wait_n": len(waits),
    "wait_mean": sum(waits) / len(waits),
    "completion_rate": sum(row["completed"] for row in completion_rows) / len(completion_rows),
    "complete_case_rate": sum(row["completed"] for row in complete_case_rows) / len(complete_case_rows),
    "known_window_n": sum(row["window"] is not None for row in rows),
}
print(json.dumps(result, ensure_ascii=False, sort_keys=True))
```
