# 第3课知识准备 · 哪些记录可以用于这次分析

等待时间报告需要等待记录，窗口工单数量报告需要窗口信息，办结比例需要办结结果。一个字段缺失，不一定让整张工单对所有问题都没有用。

读完本页，应能解释：5行导出为什么不等于5张工单；哪些值需要核实；为什么同一批工单可以有不同的有效分母。代码是选读，先用下面的小表判断和计算。

## 1. 先确定正在数什么

前两课的**分析单位**是结论针对的对象。本课按工单分析：一位来访者有两张不同工单，应算两张，而不是按来访者合成一张。

**主键**是能唯一识别表中一条记录的字段或字段组合。整理后的工单表可用 `ticket_id`（工单编号）作主键。但原始导出中，同一工单可能重复出现，也可能有更新版本，因此先不能把它当作已经满足唯一性要求的表。

**重复记录**是同一条记录重复出现。**修订记录**是同一工单的信息更新。本课按 `export_revision`（修订版本号）的数值选最新版本；文件中排在最后，不等于版本最新。同版本内容不同是待核实的冲突，不是可以直接去掉的完全重复行。

## 2. 区分缺失、无效取值和很大的真实值

**缺失值**表示所需信息没有取得。本课等待值999和−1是未测量编码；0则是已测得的零等待，不是缺失。先识别编码，再将真实的秒数除以60换成分钟。例如999秒不能换算为有效等待16.65分钟。

**有效取值**是符合字段定义的值。办结状态只允许0、1或表示未知的空白；2不是“办结两次”。没有特殊编码约定的负等待、不合法单位等，应保留原值并标明问题，不猜成0。

**离群值**是与多数观测值明显不同的值。60分钟可能是很长但真实的等待；仅凭它很大，不能认定录入错误。可以核对来源并查看它对结果的影响，不能只展示删去它后更好看的结果。

有些空白来自字段本身不适用。例如放弃排队的工单没有面对面服务时长，不能把这项空白补成“已服务0分钟”。判断空白前，先看字段描述的是什么。

## 3. 先判断，再整理这五行

这是另设的学习例子，不是项目数据。三张工单都没有放弃排队。办结状态1表示当日办结，0表示未当日办结；UNKNOWN表示窗口未知。

| 工单 | 版本 | 原等待值 | 单位 | 当日办结 | 窗口 |
|---|---:|---:|---|---:|---|
| R1 | 1 | 120 | 秒 | 1 | A1 |
| R1 | 1 | 120 | 秒 | 1 | A1 |
| R1 | 2 | 180 | 秒 | 1 | A1 |
| R2 | 1 | 999 | 秒 | 1 | UNKNOWN |
| R3 | 1 | 60 | 分钟 | 0 | A1 |

先试着回答三个问题：应保留几张工单？R2的办结状态能否使用？计算等待均值时分母是3还是2？然后核对下面的过程。

5行对应3张工单，另有1行完全重复和1行旧版本。先去除完全重复的行，再数被新版本替代的行，避免重复计数。“有修订的工单数”不一定等于旧版本行数，一张工单可能有多个旧版本。

R1保留第2版，等待180÷60＝3分钟。R2的999表示未测量，等待保留为未知；其办结状态1仍可使用。R3保留60分钟。

| 要计算什么 | 可以使用哪些工单 | 结果 |
|---|---|---|
| 已服务且有测量工单的平均等待 | R1、R3 | (3＋60)÷2＝31.5分钟 |
| 办结状态已知工单中的当日办结比例 | R1、R2、R3 | 2÷3，约66.7% |
| 已确认属于A1窗口的工单数 | R1、R3 | 2张；另1张窗口待核实 |

平均等待31.5分钟只描述两张有测量的已服务工单，不是三张工单的完整平均情况。R2也可能属于A1，所以只能说“已确认2张”，不能说“A1全部只有2张”。工单数量也不是工作人员投入的小时数。

## 4. “完整”是相对于哪些字段

**完整案例分析**使用本次分析所需字段没有缺失的记录。判断之前要先处理999等特殊编码，并核查取值、单位和代码；单看单元格是否有文字或数字，不足以判断数据有效。

只计算办结比例时，三张工单的办结字段都有效，结果为2÷3。另一份报告希望多个指标使用同一批工单，提出另一组字段要求：同时要求等待、办结和窗口三项信息有效。R2被排除，办结比例变为1÷2＝50%。

50%与约66.7%的区别来自纳入记录不同，不是数据处理改变了真实办结情况。采用共同的记录集合便于并列报告，却可能丢掉某个指标本来能用的信息。应说明这种取舍，不把字段越全等同于结论越可靠，也不必为了比较而制造结果反转。

“窗口信息有效”在这里表示窗口代码能在窗口表中查到，不是只检查它非空。给程序增加一列备注，不应自动改变上述三项信息的选择条件。

**插补**是利用已有资料和假设，为缺失值补入估计值。它不是查实原值。本课不要求一定使用插补；已经完成有依据的记录选择比较，就不必为了增加方法而再做插补。选用插补时，保留原值及标记，并比较不插补的结果。

## 5. 再做两道判断

这些问题用来检查刚才的理解，不增加项目提交要求。

**问题一：** 原有10张不同工单，其中3张缺等待、2张窗口未知，有1张同时存在这两个问题。共有多少张工单至少有一个问题？

**问题二：** 一张工单测得等待12分钟，但是否放弃未知。能否用于“已服务工单的平均等待”？若所有工单都没有有效等待测量，平均等待应写成0分钟吗？

<details>
<summary>完成判断后，展开核对</summary>

问题一为3＋2−1＝4张，而不是5张。分别报告问题数量时可以重复计入同一张工单，报告“有问题的不同工单数”时只能数一次。

问题二中，12分钟可以按其定义描述从开始排队到开始服务或放弃离开的时间，但不能据此认定已经获得服务。它不能进入“已服务”均值。没有有效等待测量时，分母为0，均值不能计算；程序中的 `None` 或JSON的 `null` 表示没有可用结果，不是0分钟。

## 回到项目

为至少两个用途列出分析单位、所需信息、参与计算的记录、指标与使用建议。可以比较分别按每项指标所需字段选择完整记录，与多个指标统一使用等待、办结和窗口都完整的记录；这里仍要先核查单位、取值和窗口归属。至少一个指标要有两种有理由方案的实际结果，并写清分母和适用范围；不要求所有用途都换方法。

这里“排除”只指不让一条记录参与某项计算，不是删除原文件或整张工单。保留原始数据，另存处理结果及原因。同一工单可能有多个问题，问题数量不能直接相加当作不同工单数。

版本优先、缺失编码和单位换算是已经给定的约定，不能随意改变。没有另外核实来源时，应写“按约定处理”，不能写“已找到真实值”。两期日期不同，两期均值之差也不能直接当作清洗或管理改善的效果。

## 按需了解：新数据出现冲突时

若同一最新版本有不同内容，保留冲突并停止自动选值。可以停止整个计算并提示核实，也可以把该工单单列、只继续不受影响且范围明确的分析；不要自行平均或猜选。空白、不能解析的文字及无穷大不能当正常等待值。这些是检查程序的例子，不表示本课文件含有所有这些情况。

## 用Python核对五行例子的计算（可选）

先读懂前面的整理过程；下面从已整理的三张工单开始，核对各用途的计算，不负责处理原始五行。代码不读取正式项目数据。

<details>
<summary>展开核算代码</summary>

```python
# learning-example
import json
rows = [{"wait": 3, "completed": 1, "window": "A1"},
        {"wait": None, "completed": 1, "window": None},
        {"wait": 60, "completed": 0, "window": "A1"}]
waits = [r["wait"] for r in rows if r["wait"] is not None]
# 只检查本次明确要求的三项信息，不检查新增备注等无关字段。
required_fields = ("wait", "completed", "window")
complete = [r for r in rows if all(r[field] is not None for field in required_fields)]
result = {"target_n": len(rows), "wait_n": len(waits), "wait_mean": sum(waits) / len(waits),
          "completion_rate": sum(r["completed"] for r in rows) / len(rows),
          "complete_case_rate": sum(r["completed"] for r in complete) / len(complete),
          "known_window_n": sum(r["window"] is not None for r in rows)}
print(json.dumps(result, ensure_ascii=False, allow_nan=False))
```

</details>
