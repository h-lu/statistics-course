# 第3课 · 业务数据质量与适用性评估

## 项目背景

服务中心新一期数据导出包含重复行、修订版本、混合单位和未测量编码。管理者需要知道：这批数据能否用于等待体验报告、当日办结比较和窗口工作量统计？数据不是“清洗完成”就自动适合所有用途。

## 可用数据

使用 `data/service/tickets_raw.csv` 的1,265行导出与窗口、业务字典。本期有1,200个工单编号，与第一期没有重合。导出约定在[数据说明](../data/service/README.md)：999、−1为未测量；版本较大者更新；秒与分钟需统一。

本课数据均为教学合成数据，不代表真实机构。先阅读[知识准备](LEARN.md)，再选择分析方法。你可以全程使用AI完成代码、分析和写作；报告需解释主要结论的统计依据、适用条件和局限性。

## 分析任务

建立可重复执行的数据处理流程，并为至少两个不同使用目的作出采用、限用或暂不采用决定。追踪原始行到最终分析记录的变化，比较一种合理替代处理方式，量化它如何改变分母、关键统计量或发布范围。

### 必须遵守的约束

- 保留原始文件；处理后的表与质量记录写入本课 `artifacts/`。
- 先明确每个目的的分析单位，处理同工单重复与修订；不能随文件顺序去重。
- 先识别缺失编码再换单位，未知窗口不能靠编号相似强行归类。
- 极端长等待不自动删除。无法证明错误时，可以报告敏感性或单列说明。
- 不要求所有指标共用同一份完整案例：例如缺少窗口不一定阻止全体有效等待分布的描述。

### 由你决定

采用哪些字段和记录、哪些指标可发布、哪些需要限制范围，以及对未知值是否采用带假设的估计，由你说明依据。处理流程必须能区分“已核实修正”“依据约定处理”和“尚未解决”。

## 成果要求

- 提供用途—所需字段—处理规则—有效分母—使用决定的清晰对应。
- 给出行数、唯一工单数、重复/修订、缺失与无法匹配记录的核对。
- 主报告展示处理选择对实际结论的影响，而不只是列数据质量百分比。
- 程序重复运行结果一致；保留被排除记录及原因，不能静默丢弃。

在本目录的 `report.md` 中撰写分析报告，篇幅与结构可按问题需要调整。关键表、图或分析数据保存到 `artifacts/`，并在报告中引用。可以修改或替换 `analysis.py`；提供的示例代码只生成数据概览，不是本课的完整分析。

## 建议时间安排

0—13分钟知识与导出约定；13—25分钟确定两个使用目的；25—55分钟处理、核对和比较；55—68分钟写适用性决定；68—75分钟核对提交；75—90分钟知识自查。可以复用AI提供的通用质量工具，把时间用在规则与用途的对应。

## 运行与提交

从仓库根目录运行：

```bash
python scripts/course.py start 03
python scripts/course.py run 03
```

完成报告和分析后，在 `submission.json` 填入支持报告结论的结果文件路径，将 `status` 改为 `complete`；如果更换运行入口，同步修改 `run`。运行 `python scripts/course.py check 03`，核对修改后提交并创建最终标签 `v2-l03-final`。完整步骤见[操作与提交步骤](../docs/WORKFLOW.md)。自动检查通过只说明文件、路径和运行命令符合提交要求，不代表统计结论正确。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面显示当日第3课，按当前场次作答。建议先自行判断，不会时请AI解释概念再作答；使用方式见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
