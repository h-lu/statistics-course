# 第3课 · 业务数据质量与适用性评估

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

第一次使用这些资料时，可先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。

## 项目背景

新一期工单导出时出现了重复行、不同修订版本、秒与分钟混用，以及表示未测量的特殊编码。管理者需要判断：这些数据能否用于等待时间、当日办结和窗口工作量报告？

本课不是把所有空白填满，而是判断哪些记录适合回答哪种问题。

## 可用数据与处理约定

`data/service/tickets_raw.csv` 是2026年4月13日至24日的导出资料，共1,265行、1,200个工单编号，与第一期工单不重合。另有窗口和业务类型表。先读[数据说明](../data/service/README.md)和[知识准备](LEARN.md)。

同一工单的 `export_revision` 越大，表示版本越新；同版本完全相同的行是重复导出。等待字段999与−1表示未测量，应先识别，再按 `wait_unit` 统一秒和分钟。未知窗口、空业务和空办结结果需要保留为待核实信息，不能猜填。

## 分析任务

1. **选择至少两个用途。** 对每个用途说明按什么对象分析、需要哪些字段、采用哪些记录、比例以什么为分母。缺窗口不一定妨碍计算全体有测量工单的等待；缺等待也不一定妨碍计算办结比例。
2. **编写可重复运行的处理程序。** 核对原始行数、不同工单数、重复行、旧版本、单位换算和缺失数量。保留原文件和原字段，将处理后的表及处理原因另存到 `artifacts/`。
3. **比较一种合理的替代处理。** 例如计算办结比例时，方案一只要求办结状态已知；方案二为了同时报告多个指标，要求等待、办结和窗口信息都完整，再计算办结比例。两种方案采用的字段要求不同。完整案例分析总是相对于所需字段而言，并不是一律删除所有带缺失值的工单。也可比较有依据的插补与不插补。实际计算分母、指标或可用范围怎样改变。版本和缺失编码等已知约定不能随意改成另一种假设。
4. **分别提出使用建议。** 对每个用途说明可以采用、只能用于部分范围，还是应暂不采用。区分按数据约定处理、已查实改正和仍未解决的问题，并指出应继续核实的记录或字段。

## 分析时需要注意

长等待不自动等于录入错误。保留被排除记录和原因；同一工单可能同时缺多个字段，各类问题数量不能直接相加当作不同工单数。新旧两期的差异，也不能直接归因于清洗或管理改善。

处理其他数据时，若遇到最新版本互相冲突，应停止对该记录自动选值并保留问题。未知放弃状态不能当成已服务；不能解析的等待值也不能当正常测量。这些是检查程序时的例子，不要求另建复杂系统。

## 需要提交什么

提交分析报告、处理程序、处理后的数据和核对结果。报告应清楚对应“用途、所需字段、处理规则、参与计算的记录、使用建议”，包含至少两个用途和一项有实际数值的替代处理比较。

较完整的报告会说明哪些进一步核实能改变使用建议，而不只是报告删除了多少行。

## 课堂安排

0—13分钟阅读知识与数据约定；13—25分钟确定用途；25—55分钟处理、核对和比较；55—68分钟写使用建议；68—75分钟检查提交；75—90分钟知识自查。

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`raw_rows` 是导出行数，`unique_ticket_ids` 是不同工单编号数；`wait_units`、`revision_counts` 和 `missing_wait_code_rows` 仍按原始行统计。先处理重复和修订后，才能计算每项指标可用的工单数，不能把这些原始行数直接当作工单质量统计。

先阅读输出中与你的问题有关的内容，再按上面的分析任务扩展程序。自己的计算结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。若使用完整课程资料库，先进入 `student-template/`。

```bash
python scripts/course.py start 03
python scripts/course.py run 03
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据本课问题修改或替换程序，将结果和图表保存到本课 `artifacts/` 文件夹，并在 `report.md` 中解释和引用。原始数据保持不变；程序使用的新软件包写入 `requirements.txt`。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起；更换程序时要相应更新命令。然后重新运行并检查：

```bash
python scripts/course.py run 03
python scripts/course.py check 03
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送到个人仓库，创建本课最终标签 `v2-l03-final`，再查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，但不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖，修改时保留原版本。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令、结果文件设置和修订办法见上述操作说明，评分见[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第3课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
