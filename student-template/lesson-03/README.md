# 第3课：业务数据质量与适用性评估

服务管理者拿到新一期工单导出，想知道哪些信息足以支持报告，哪些需要先核实。你的任务是为**至少两个自行选择的用途**评估数据适用性，并说明处理和记录选择怎样影响结论。

本课数据是**教学合成数据**，不是真实机构或个人记录。可以全程使用AI；你负责核对单位、分母、依据和适用范围。分析路线和最终建议由你决定：可以建议发布结果、只在明确的记录范围内使用结果，或暂缓使用。

## 情境和资源

| 数据 | 记录范围与用途 |
|---|---|
| `data/service/tickets_raw.csv` | 第二期2026-04-13至24日的1265行原始导出、1200个工单编号；同一工单可能有重复或修订行 |
| `data/service/windows.csv` | 窗口与中心的对应说明 |
| `data/service/business_types.csv` | 业务代码的含义 |

[数据说明](../data/service/README.md)给出字段和来源范围。[LEARN](LEARN.md)解释分析单位、版本、缺失与用途，并有另设小例子；[SUPPORT](SUPPORT.md)提供遇到具体困难时可选择的提示，不规定统一操作顺序。可以复用前两课的描述方法和统计口径比较；统计口径包括纳入哪些记录，以及怎样定义和计算指标。

第一期与第二期没有相同工单，第一期不能提供第二期未知字段的真值。`tickets_raw.csv` 一行是导出记录；同一人有不同工单也不应按人自动合并。

## 目标产物

形成一份管理者能读懂、另一位分析者能复核的数据适用性报告，以及从原始表重新生成计算结果的程序。成果需要保留原始值、选用的版本、处理后的值和问题原因。这些信息可以放在一张处理表中，也可以放在能相互对应的结果文件中；文件数量、图形和算法由你选择。

你的成果应回答：

- 两个用途分别需要什么信息？结论针对的对象（分析单位）是什么，哪些记录参与计算？比例的分子和分母各包含哪些工单？
- 重复、修订、单位和未知信息怎样处理，关键数量能否核对到原始导出？
- 至少一个指标在**另一种有理由的记录选择**下结果怎样变化？两者各覆盖谁、失去什么信息，哪种更适合你的用途？
- 对每个用途，这批数据可以直接采用、只能描述部分记录，还是需要先核实？判断依据是什么，哪些对象尚未被结果覆盖？

## 重要决策由你作出

至少保留并解释以下两类决策：

1. **报告的用途与目标。**例如，描述已服务工单的等待时间、计算办结状态已知工单的当日办结比例，或统计窗口已确认工单的登记量。也可以提出其他用途，说明谁使用结果、需要什么信息。至少完成两个用途，不能只交“清洗成功”的表。
2. **指标所需记录与比较方案。**可以分别使用每个指标所需信息都有效的记录，也可以让多个指标使用同一批记录，要求这些指标所需的字段全部有效。还可提出另一种有实际依据的方案。写清字段要求并实际比较，不因某个比例较高就认定更正确。

你也决定如何处理仍未知的信息、安排核实的先后顺序和提出发布建议。**插补**是根据已有资料和假设，为缺失值补入估计值。本课不要求插补；如采用，应保留插补标记并比较插补与不插补的结果，因为估计值不等于查实的原值。比较后结论没有改变，同样有价值。

## 需要遵守的约定

- `export_revision` 数值越大版本越新；相同版本内容完全相同是重复导出。最高版本内容冲突应明确保留与核实，可停止或说明范围后隔离，不静默任选一行。
- 等待999、−1表示未测量，不能先换算成有效时间；真实秒数按单位换为分钟。零等待可有效，长等待不自动是错误。
- 未知窗口、空业务、空办结状态不能猜填。某字段无效不意味着该工单对所有用途都无效。
- 计算已服务工单的等待时间，只纳入明确未放弃（`abandoned=0`）且等待值有效的工单。放弃状态未知的工单不能当作已服务。分母为零时写“不能计算”。
- 原始数据不覆盖；区分按约定处理、有来源证据的修正和仍待核实。不把不同日期的差异直接解释为管理改善。

## 三层选择

**基础练习（可信起点）：**需要概念帮助时使用LEARN的五行例子，或从原表自行追踪一张工单，区分导出行、工单和可用于某指标的记录。它不能代替标准任务。

**标准任务（本课应完成）：**完成至少两个用途的分析，提供可重新运行的处理程序并核对数量，实际比较一项有理由的替代方案，再分别给出每个用途的使用建议。计算与表达方式由你决定，所有主要数字应能追溯到原始数据和计算过程。

**提高与拓展（提前完成后）：**选择一个可能改变建议的问题深入。例如，多个指标共用同一批记录会怎样影响第二个用途，未知信息会使目标指标处在哪个可能范围，单列冲突工单会排除哪些对象，或应优先核实哪些极端记录。也可以研究补充核实的成本与先后顺序，或自行提出问题。说明为什么研究它、实际发现什么、建议是否需要改变，避免只重复运行或增加图数。

## 怎样核对计算结果和适用范围

报告原始行数、不同工单数、完全重复行数、被新版本替代的非重复旧版本行数、实际单位转换数和各类问题数量。同一工单可能有多个问题，因此问题标记次数不等于有问题的工单数。说明每条原始导出行最终是被保留、作为重复导出排除，还是被新版本替代；如遇冲突后单列待核实，也应说明这些行的去向。

比较替代方案时，给出各自的纳入条件、分母与结果，说明它们是否回答同一个问题。缺失值减少、比例变高或程序运行成功，都不足以证明数据真实正确或偏差消失。窗口的工单数量也不能直接表示工作人员投入的时间。

## 工具和提交

在能看到 `scripts/`、`data/`、`lesson-03/` 的学生仓库根目录，可运行：

```bash
python3 scripts/course.py start 03
python3 scripts/course.py run 03
```

默认 `analysis.py` 仅生成 `lesson-03/artifacts/starting_overview.json`，用于认识原始字段；它不选择版本、不处理完整项目，也不预填结论。代码中的单值等待解析函数可选用或改写。使用标准库即可，不需要安装新包；也可让AI协助自行实现方法。

完成后，在 `submission.json` 中把 `status` 改为 `complete`，在 `report` 和 `artifacts` 中填写实际报告与结果文件的路径，在 `run` 中填写能从原始表重新生成报告证据的命令。再次运行自己的分析，再用 `python3 scripts/course.py check 03` 检查状态和文件；`check` 不判断统计结论。按[工作流](../docs/WORKFLOW.md)提交，不覆盖已有最终标签。完成当课[知识自查](https://hblu.top/stat-check/)并阅读反馈；LEARN 的线下题供自主学习。
