# 第3课：业务数据质量与适用性评估

服务管理者拿到新一期工单导出，想知道哪些信息足以支持报告，哪些需要先核实。你的任务是为**至少两个自行选择的用途**评估数据适用性，并说明处理和记录选择怎样影响结论。

本课数据是**教学合成数据**，不是真实机构或个人记录。可以全程使用AI；你负责核对单位、分母、依据和适用范围。分析路线和最终建议由你决定，结果可以支持发布、限范围使用或暂缓。

## 情境和资源

| 数据 | 记录范围与用途 |
|---|---|
| `data/service/tickets_raw.csv` | 第二期2026-04-13至24日的1265行原始导出、1200个工单编号；同一工单可能有重复或修订行 |
| `data/service/windows.csv` | 窗口与中心的对应说明 |
| `data/service/business_types.csv` | 业务代码的含义 |

[数据说明](../data/service/README.md)给出字段和来源范围。[LEARN](LEARN.md)解释分析单位、版本、缺失与用途，并有另设小例子；[SUPPORT](SUPPORT.md)提供遇到具体阻塞时可选择的提示，不规定统一操作顺序。前两课的描述和口径比较可以复用。

第一期与第二期没有相同工单，第一期不能提供第二期未知字段的真值。`tickets_raw.csv` 一行是导出记录；同一人有不同工单也不应按人自动合并。

## 目标产物

形成一份管理者能读、另一位分析者能复核的数据适用性报告，以及从原表重建证据的程序。成果需要保留原始值、采用版本、处理值和问题原因，可以放在一张处理表或相互关联的结果文件中；不统一规定文件数量、图形或算法。

你的成果应回答：

- 两个用途分别需要什么信息，分析单位和纳入记录是什么，比例的分子分母是什么？
- 重复、修订、单位和未知信息怎样处理，关键数量能否核对到原始导出？
- 至少一个指标在**另一种有理由的记录选择**下结果怎样变化？两者各覆盖谁、失去什么信息，哪种更适合你的用途？
- 每个用途可以采用、应限范围描述还是先核实？依据和未覆盖范围是什么？

## 重要决策由你作出

至少保留并解释以下两类决策：

1. **报告的用途与目标。**可以关注已服务等待、状态已知者办结、可确认窗口登记量，或其他能说明所需信息与使用者的用途；至少两个用途，不能只交“清洗成功”的表。
2. **指标所需记录与比较方案。**可以每个指标采用自身有效信息，也可以让多个指标共用共同所需字段的记录；还可提出另一种有实际依据的方案。写清字段要求并实际比较，不因某个比例较高就认定更正确。

你也决定如何处理仍未知的信息、安排核实优先级和提出发布建议。插补不是必做；如采用，它是基于假设的估计而非查实原值，应保留标记并比较结果。结果未反转同样有价值。

## 需要遵守的约定

- `export_revision` 数值越大版本越新；相同版本内容完全相同是重复导出。最高版本内容冲突应明确保留与核实，可停止或说明范围后隔离，不静默任选一行。
- 等待999、−1表示未测量，不能先换算成有效时间；真实秒数按单位换为分钟。零等待可有效，长等待不自动是错误。
- 未知窗口、空业务、空办结状态不能猜填。某字段无效不意味着该工单对所有用途都无效。
- 已服务等待需要明确未放弃且等待有效；未知放弃不能当已服务。分母为零时写不能计算。
- 原始数据不覆盖；区分按约定处理、有来源证据的修正和仍待核实。不把不同日期的差异直接解释为管理改善。

## 三层选择

**基础练习（可信起点）：**需要概念帮助时使用LEARN的五行例子，或从原表自行追踪一张工单，区分导出行、工单和可用于某指标的记录。它不能代替标准任务。

**标准任务（本课应完成）：**完成两个用途、可重跑处理和数量核对、一项合理替代的实际比较、逐用途使用建议。自主决定计算与表达方式，所有主要数字应有可追溯证据。

**提高与拓展（提前完成后）：**选择一个可能改变建议的问题深入。可以研究共同字段在第二用途中的影响、未知信息对目标量的可能范围、冲突处置的覆盖损失、极端记录的来源核对，或补核成本与优先级；也可以自行提出。说明为什么研究它、实际发现什么、建议是否需要改变，避免只重复运行或增加图数。

## 证据自检边界

报告原始行数、不同工单数、完全重复与非重复旧版本行数、实际单位转换数、各类问题数量。问题会重叠，标记次数不等于问题工单数。行数应能解释为最终工单、重复导出和旧版本的去向；如遇冲突隔离，应另外说明其去向。

替代比较应给各自纳入条件、分母与结果，说明它们是否回答同一目标。少了缺失、比例变高或程序运行成功，都不足以证明数据真实正确或偏差消失。窗口工单数也不是工作人员投入。

## 工具和提交

在能看到 `scripts/`、`data/`、`lesson-03/` 的学生仓库根目录，可运行：

```bash
python3 scripts/course.py start 03
python3 scripts/course.py run 03
```

默认 `analysis.py` 仅生成 `lesson-03/artifacts/starting_overview.json`，用于认识原始字段；它不选择版本、不处理完整项目，也不预填结论。代码中的单值等待解析函数可选用或改写。使用标准库即可，不需要安装新包；也可让AI协助自行实现方法。

完成后在 `submission.json` 填 `complete`、实际报告和结果路径，以及能从原表重建报告证据的 `run` 命令。再次运行自己的分析，再用 `python3 scripts/course.py check 03` 检查状态和文件；`check`不判断统计结论。按[工作流](../docs/WORKFLOW.md)提交，既有最终标签不覆盖。完成当课[知识自查](https://hblu.top/stat-check/)并阅读反馈；LEARN的线下题供自主学习。
