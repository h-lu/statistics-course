# 第3课 · 业务数据质量与适用性评估

**以下数据全部为教学合成数据，不代表真实机构、个人或实际效果。** 可以全程使用AI提出候选问题、编程、分析、写作和协助提交；你需要确认最终采用的选择，核对结果、依据和适用范围。无需提交AI对话或证明代码由谁输入。先阅读[知识准备](LEARN.md)，再展开正式分析。

## 项目背景

新一期导出含重复行、修订版本、混合单位和未测量编码。管理者想知道它能否用于等待体验、当日办结或窗口工作量报告。你要判断“对哪种用途可用”，而不是只交一张没有空值的表。

## 可用数据与已知约定

`data/service/tickets_raw.csv` 有1,265行、1,200个工单编号，时间为4月13日至24日，与第一期工单不重合；另有窗口和业务字典。见[服务数据说明](../data/service/README.md)。

同工单取较大 `export_revision` 的更新记录；同版本完全相同行是重复导出。先识别等待字段999、−1为未测量，再按 `wait_unit` 换算秒/分钟。未知窗口、空业务、空办结不能猜填。上述是数据约定，不是可以任意改变以获得好结果的“敏感性参数”。

## 分析任务

1. **选至少两个用途。** 对每个用途列出分析单位、必需字段、纳入规则与有效分母。缺窗口不一定妨碍全体有效等待描述，缺等待也不一定妨碍办结比例。
2. **建立可复现处理流程。** 保留原文件和原字段，把处理后的表与质量记录存到 `artifacts/`。核对原行数、唯一工单、完全重复、被替代版本和各项缺失；记录排除及限用原因，不能按文件最后一行随意去重。
3. **比较一种合理替代处理。** 例如按用途保留有效记录与完整案例分析，或带假设插补与不插补。实际计算它对分母、指标或可发布范围的影响；不能只列方案名称。
4. **给出采用、限用或暂不采用建议。** 分开说明依据约定处理、已核实修正和仍待解决的问题；指出需要补核的记录或字段及其影响。不能把新旧时期差异归因于清洗或管理改善。

## 处理时的边界

极端长等待不等于错误，没有证据时不自动删除。若未来输入出现空白、非数值或非有限等待，应标明问题；未知放弃状态不能视作已服务。若同一最新版本相互矛盾，应保留冲突并停止该记录的自动取值，不能按行顺序任选。这些是检查程序的例子，不表示现有CSV包含所有情况，也不要求为了覆盖它们扩建系统。

## 成果与提交前自核

报告应有“用途—所需字段—处理规则—有效分母—使用决定”的对应；提交处理程序、核对记录、替代处理结果及未解决记录和原因。至少两个用途和一项有实际结果的比较均须完成。

进一步完善应说明哪些补核能改变发布范围，而不是只追求删除后零缺失。字段有效集合可能重叠，各类质量标记数量不能不加说明地相加成唯一问题工单数。成绩按[成果与评分](../docs/ASSESSMENT.md)，不增加额外考核。

## 90分钟建议安排

0—13分钟知识与导出约定；13—25分钟确定用途；25—55分钟处理、核对和比较；55—68分钟写适用性决定；68—75分钟核对提交；75—90分钟自查。可复用AI提供的通用工具，把时间用于规则与用途的对应；处理流程以后可复用。

## 运行、核对与提交

以下“仓库根目录”指你自己的学生仓库中包含 `scripts/`、`data/` 的目录；在合并资料库中阅读时，对应 `student-template/`。先运行：

```bash
python scripts/course.py start 03
python scripts/course.py run 03
```

`analysis.py` 是可运行的数据概览，不是完整项目答案。按问题修改或替换它，将关键数值结果和图表写入本课 `artifacts/`，在 `report.md` 中引用。可以调整报告结构，不能只保留提示或粘贴默认输出。原始数据不改写；新增依赖写入 `requirements.txt`。

完成后，在本课 `submission.json` 中将 `status` 设为 `complete`，填写 `report`、支持结论的 `artifacts` 和非空命令参数列表 `run`。所有路径相对于学生仓库根目录。再执行：

```bash
python scripts/course.py run 03
python scripts/course.py check 03
git diff --check
git status
git diff
git add lesson-03 requirements.txt
git diff --cached
git commit -m "完成第03课项目"
git push
git tag v2-l03-final
git push origin v2-l03-final
```

**`run` 执行分析；`check` 只检查完成声明、路径和文件是否存在且非空，不会重新运行分析或判断结论。** 推送后查看 Actions 的重跑结果；配置了重现检查时，它会在临时副本移除所列结果文件、运行程序并比较内容。固定随机种子、排序和输出精度，避免将带生成时间的文件列入逐字节比较。程序运行成功和文件检查通过，都不等于统计解释正确。

新增共用程序也须核对后纳入提交。已有最终标签不要覆盖；修订保留原版本。网络、环境或检查故障时保存本地文件与提交，向教师说明，不把失败写成已通过。完整步骤见[项目工作流](../docs/WORKFLOW.md)和[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第3课。建议先作答A，再学习不熟悉的概念，完成B并阅读反馈；AI始终可用，无需提交对话记录。自查正确率用于反馈，不直接计分，详见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
