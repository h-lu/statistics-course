# 第3课：业务数据质量与适用性评估

本课使用教学合成数据，也就是为了学习而生成的数据，不是真实机构或个人的记录。你可以使用 AI 帮助读代码、写程序、计算和修改报告，但提交前要自己核对记录、单位、分母和结论。

如果你第一次做这类分析，先打开[支持路线](SUPPORT.md)，完成“入门跟做”；如果想理解术语和小例子，再读[知识准备](LEARN.md)。

## 先用一句话理解任务

新一期工单导出里有重复行、同一工单的不同版本、秒和分钟混用，还有代表“没有测量”的特殊编码。你的任务不是把所有空白填满，而是回答：

> 这批数据能不能用于某个明确的报告？哪些记录可以用，哪些记录只能保留为待核实？

同一张工单可能适合一个用途，却不适合另一个用途。例如它没有等待时间，但有明确的办结状态；它可以参加办结比例，却不能参加等待均值。

## 第一步：先做一个小判断

在继续读文件前，先回答：

1. 如果同一个 `ticket_id` 出现三行，这三行一定是三张工单吗？
2. 如果等待值是 `999`，能不能直接除以60变成分钟？
3. 如果窗口编号为空，能不能把它归到某个中心？

把你的答案写在 `report.md` 开头的“运行前判断”小节。读完本课后回来修改，并说明哪一条答案发生了变化。

## 数据和文件

本课正式项目主要使用下面三个文件。路径都从学生仓库根目录开始：

| 文件 | 用途 |
|---|---|
| `data/service/tickets_raw.csv` | 2026年4月13日至24日的第二期工单导出，共1,265行、1,200个工单编号；一行不一定是一张不同工单 |
| `data/service/windows.csv` | 根据 `window_id` 查窗口及所属中心，是代码说明表，不是新的工单 |
| `data/service/business_types.csv` | 根据 `business_code` 核对业务类型，是代码说明表 |

第一期 `tickets.csv` 与第二期没有相同工单。不能用第一期记录替第二期补出未知真值，也不要把本课提前做成第8课的多表整合。

已给定的数据约定是：`export_revision` 数值越大表示版本越新；同版本完全相同的行属于重复导出；等待值 `999` 和 `-1` 表示未测量；真实秒数按 `wait_unit` 换算为分钟。未知窗口、空业务和空办结结果保留为待核实信息，不能猜填。

## 按这个顺序完成项目

### 1. 选择至少两个用途

先看完数据字段，再从下面选择至少两个用途：

- 描述已服务工单的等待时间；
- 计算办结状态已知工单中的当日办结比例；
- 统计可以确认窗口归属的工单数量；
- README 中另一个你能说明依据的用途。

对每个用途写清：分析单位是什么、需要哪些字段、哪些记录纳入、分子和分母是什么、结果将支持什么决定。

### 2. 写可重复运行的处理程序

处理顺序建议固定为：

1. 识别完全重复行；
2. 按 `export_revision` 选择每个工单的最新版本；
3. 识别 `999`、`-1` 等缺失编码；
4. 核对等待单位、状态代码和窗口/业务代码；
5. 另存处理后的数据、问题标记和核对结果。

核对并报告原始行数、不同工单数、完全重复行、被替代的旧版本行、真正换算的记录数和各类问题数量。不要只导出一张删掉所有缺失的表。

### 3. 比较一种合理的替代处理

至少选择一个指标，实际比较两种有理由的记录选择。例如：办结比例只要求办结状态有效；另一种方案要求等待、办结和窗口信息全部有效，以便多个指标使用同一批工单。

报告两种方案的分母、结果和适用范围。结果没有反转也要报告；不要为了制造差异而任意改变版本规则、缺失编码或单位换算。

### 4. 对每个用途提出建议

把建议分成三类：

- 按现有约定可以使用；
- 只能描述部分范围，仍需说明排除记录；
- 需要先核实，暂不适合发布。

区分“按约定处理”“有来源证据支持的修正”和“仍未知”。没有核实来源时，不要把程序成功运行写成数据已经真实正确。

## 报告至少要让别人看懂什么

报告和结果文件应能追溯：某张工单采用了哪一版、原值是什么、处理后值是什么、还存在哪些问题，以及它参与了哪些指标。可以在处理后的表增加列，也可以单独保存核对表。

行数核对可以写成：

> 原始行数 = 最终不同工单数 + 完全重复行数 + 被替代的非重复旧版本行数。

一张工单可能同时有多个问题，所以问题次数之和不等于有问题的不同工单数。长等待不自动等于错误；未知放弃状态不等于已服务。

## 运行与提交

在能同时看到 `scripts`、`data` 和 `lesson-03` 的仓库根目录运行：

```bash
python scripts/course.py start 03
python scripts/course.py run 03
```

`start` 只把本课标记为进行中；`run` 才运行示例程序并生成 `artifacts/starting_overview.json`。这个概览只帮助你认识字段和原始数据，不能代替完整项目。

根据任务修改或替换 `lesson-03/analysis.py`，将处理后的数据和核对结果保存到 `lesson-03/artifacts/`，原始数据保持不变。使用新软件包时写入 `requirements.txt`。

完成后填写 `lesson-03/submission.json`：把 `status` 改为 `complete`，填写报告路径、结果文件列表和运行命令。再运行：

```bash
python scripts/course.py run 03
python scripts/course.py check 03
```

`check` 只检查完成状态、路径和文件是否存在且非空，不判断统计结论。按[操作与提交步骤](../docs/WORKFLOW.md)提交并创建 `v2-l03-final` 标签；已有标签不要覆盖。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认教师已开放第3课场次。先完成A题，再学习不熟悉的概念，最后完成B题并阅读反馈。自查用于发现概念混淆，不替代项目报告。
