# 第3课可选提示：遇到具体问题再查

本页不是全班操作流程。你可以先独立设计分析，卡在哪一类问题就看对应提示；每类从少提示到较具体的帮助逐层展开。完整任务与约束见[README](README.md)，概念解释见[LEARN](LEARN.md)。这些帮助不替你决定用途、比较方案或结论。

## 不知道怎样选择用途

**先问自己：**报告给谁看，他们要作什么决定？哪一个结果真的会影响这个决定？

**进一步提示：**同一张工单可能有办结状态却没有有效等待，因而能参加一种计算，但不能参加另一种计算。为每个用途分别说明结论针对什么对象、需要哪些信息、纳入哪些记录、计算什么指标，以及结果能支持什么决定。可以选择 README 的示例，也可以自拟有数据支持的用途。

**检查依据：**每个比例有明确的分子和分母，等待的单位明确，两个用途均有实际结果。窗口未知会妨碍把工单归入某个中心，但工单仍可能用于描述办结状态已知者的当日办结情况。

## 分不清重复、版本和单位

**先问自己：**同一个编号的内容完全一致，还是信息更新？哪一个字段给出版本新旧？

**进一步提示：**LEARN的五行例子可以帮助区分5个导出行与3张工单。数值10比2更新；999先按缺失识别，180秒才换算为3分钟。不要用行在文件中的先后代替版本。

**可选操作：**在原始CSV找一个重复编号，查看它的所有行；用自己程序保存采用版本与来源。源行号或完整原值都可以用于追溯，不强制统一格式。

**检查依据：**每条原始导出行都有可解释的去向，同一张工单不会因重复或修订被多次计数；同一工单的最新版本有内容冲突时，处理结果应明确显示这个问题。

## 不知道比较什么

**先问自己：**哪项合理选择会改变你报告描述的对象或用途？不能只比较任意两组参数。

**进一步提示：**若多个指标要放在同一张表，你可能想使用同一批记录；若各指标目的独立，分别检查各自需要的字段，可能保留更多信息。比较两者时，说明共用记录需要哪些字段有效，不要求无关备注也完整。

**按需深入：**找出只在一种方案中被纳入的工单。被排除的工单是否集中在某类业务或窗口？排除了哪些原本可用的信息，怎样影响结果？也可比较有依据的其他规则；替代方案仍须遵守版本、单位和999含义的数据约定。

**检查依据：**至少完成一项实际比较，给出两种方案各自的记录范围、分母、结果和取舍。结果不变也需解释比较了什么，不要求结论必须改变。

## 未知信息怎样影响发布

**先问自己：**你描述的是已知记录，还是试图代表全部登记工单？

**进一步提示：**不插补时，可以只描述信息已知的记录，并说明范围；插补时，需要说明假设。若目标是全部登记工单的办结比例，可分别假设状态未知的工单全部已办结、全部未办结，得到现有信息允许的可能范围，手算例子见 LEARN。这是可选的分析方向，由报告用途决定是否采用。

**检查依据：**建议针对的对象与结果覆盖的对象一致。未知值不直接填0；上述范围描述未知工单在两种极端情况下的结果，不是置信区间。窗口的工单数量也不能写成人员工时。

## 工具、排错与提交

从学生仓库根目录运行 `python3 scripts/course.py run 03`，默认程序会生成 `lesson-03/artifacts/starting_overview.json`。这份概览显示原始表的结构和行数，还不是项目分析结果。函数 `parse_wait_value` 每次识别一个等待值的编码与单位；选择版本、分析范围和方法仍需在你的程序中实现。

提示找不到文件时，先确认当前目录能看到 `data/`、`scripts/`、`lesson-03/`；字段不匹配时核对[数据说明](../data/service/README.md)。计算数字不一致时，依次核对版本选择、缺失编码、单位换算、纳入条件与分母。修正程序后重新生成结果，不手工改结果文件。报告可按[提示](report.md)自由组织。

提交前确认原表未改、至少两个用途的分析与替代方案比较已完成、主要数字可复核，且 `submission.json` 的状态和路径与实际文件相符，`run` 能重新生成计算证据。运行自己的最终分析，再执行 `python3 scripts/course.py check 03`。检查通过说明状态和文件符合提交要求；统计依据与结论仍需自己核对。
