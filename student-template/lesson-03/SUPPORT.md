# 第3课支持路线：业务数据质量与适用性评估

本课面对的是“数据看起来很多，但能不能用于某个报告？”的问题。重点不是把所有异常删掉，而是保留处理痕迹，针对不同用途判断哪些记录可以用。

## 这课到底在学什么

- **分析单位**：结论针对的对象，例如一张工单或一个窗口。它决定去重方式和分母。
- **缺失值**：本来需要但没有取得的信息。空白、999、−1等特殊编码要按数据说明判断，缺失不等于0。
- **重复记录与修订记录**：完全相同的行可能是重复导出；同一工单的不同版本是修订，不能看到编号重复就全部删除。
- **数据适用性**：数据能否支持某个用途。能计算办结比例，不代表也能说明等待时间或个人效率。

原理是“清洗服务于用途”。先保留原始值和问题原因，再为每个指标定义纳入条件，才能知道谁被排除、排除会造成什么影响。

## 入门跟做

### 1. 先选两个用途

打开 `lesson-03/report.md`，从下面选择至少两个用途并写清需要的信息：已服务工单等待、办结比例、各窗口工单数，或 README 中的其他用途。每个用途写分析单位、所需字段、纳入条件和分子分母。

**反思**：同一张工单能参与两个用途吗？如果等待缺失但办结状态已知，它应该被两个指标同时排除吗？

### 2. 运行起点并认识原始行

```bash
python scripts/course.py start 03
python scripts/course.py run 03
```

打开 `lesson-03/artifacts/starting_overview.json`，再查看 `data/service/tickets_raw.csv` 的字段说明。记录原始行数、不同工单编号、修订版本、单位和缺失编码数量。

**为什么**：原始行数不一定等于工单数；一张工单可能有重复导出或多个版本。先认识原始结构，才能解释清洗后数量。

**做对的信号**：你能区分“原始行数”“不同工单数”“最终选用记录数”。

### 3. 手算版本与单位转换

假设同一工单有两个版本：版本1等待120秒，版本2等待3分钟。若版本2是最新，应先选版本2，再把它作为3分钟使用；不能把两行相加，也不能把120当作120分钟。

**反思**：如果最新版本的等待值是999（缺失编码），你会直接用旧版本补上吗？答案必须依据课程规则和证据，而不是为了让表格完整。

### 4. 写处理记录并比较用途

在程序中保留原字段，新增处理后的值和处理原因，结果保存到 `lesson-03/artifacts/`。至少做一次比较：一个指标只要求自己的字段有效，另一个指标要求多个字段都有效。报告列出两种分母和结果。

运行并检查：

```bash
python scripts/course.py run 03
python scripts/course.py check 03
```

**做对的信号**：任何一条被排除的记录都能说明原因；处理后的表没有悄悄覆盖原始CSV。

**反思**：你提出的是“按现有规则处理”“需要外部核实”，还是“仍然未知”？不要把程序成功运行写成数据已经真实正确。


## 标准完成

在入门路线基础上，完成 README 中全部必做任务：实际比较一个有理由的替代方案，列出每种方案的记录范围、指标、分子、分母和单位；说明结果变化的原因；最后给出适用范围、限制和下一步行动。不能只说“结果不同”，也不能把相关关系写成因果关系。

## 提高与拓展

完成标准路线后任选一项：

- **方法比较**：比较两个目标相同但假设不同的方法，说明为什么选择其中一个；
- **敏感性分析**：改变一个有实际依据的阈值、分母、时间范围或处理规则，画表说明结果如何变化；
- **复现检查**：从原始数据重新生成主要结果，增加重复键、范围、单位或分母检查；
- **决策说明**：面向另一类使用者写一页简报，说明哪些结论可以发布、哪些需要限制。

提高不是增加代码数量。好的提高任务会让读者更清楚结果在什么条件下可靠。

## 卡住时按顺序排查

1. 先确认在能看到 `scripts`、`data` 和本课目录的仓库根目录；
2. 确认命令中的课次编号、文件名和输出目录没有写错；
3. 保留完整命令和最后一段报错，不要删除旧结果来“清理”问题；
4. 数字对不上时，依次核对观测单位、筛选条件、缺失值、分母、单位和输出目录；
5. 报告无从下手时，先填写“问题—数据—方法—结果—限制—建议”六个小标题。

如果程序暂时不能运行，可以先完成手算和报告草稿，但必须标明“尚未运行”，修复后再补跑并更新数字。
