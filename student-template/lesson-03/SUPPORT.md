# 第3课可选提示：遇到具体问题再查

本页不是全班操作流程。你可以先独立设计分析，卡在哪一类问题就看对应提示；每类从少提示到较具体的帮助逐层展开。完整任务与约束见[README](README.md)，概念解释见[LEARN](LEARN.md)。这些帮助不替你决定用途、比较方案或结论。

## 不知道怎样选择用途

**先问自己：**报告给谁看，他们要作什么决定？哪一个结果真的会影响这个决定？

**进一步提示：**同一张工单可能有办结状态却没有有效等待，因而能参加一个用途但不能参加另一个。为每个用途分别列“分析单位—所需信息—纳入条件—指标—能支持的决定”。可以选择README示例，也可以自拟有数据支持的用途。

**检查依据：**每个比例有分子分母，等待的单位明确，两个用途均有实际结果。未知窗口影响中心归属，不自动影响全体已知办结描述。

## 分不清重复、版本和单位

**先问自己：**同一个编号的内容完全一致，还是信息更新？哪一个字段给出版本新旧？

**进一步提示：**LEARN的五行例子可以帮助区分5个导出行与3张工单。数值10比2更新；999先按缺失识别，180秒才换算为3分钟。不要用行在文件中的先后代替版本。

**可选操作：**在原始CSV找一个重复编号，查看它的所有行；用自己程序保存采用版本与来源。源行号或完整原值都可以用于追溯，不强制统一格式。

**检查依据：**原始每条导出有可解释去向，选定工单仍代表分析单位；同一最新版本冲突不能被静默处理。

## 不知道比较什么

**先问自己：**哪项合理选择会改变你报告描述的对象或用途？不能只比较任意两组参数。

**进一步提示：**若多个指标要放在同一张表，你可能想共用记录；若各指标目的独立，分别使用必要字段可能保留更多信息。比较两者时明确共同集合需要哪些字段，别要求无关备注也完整。

**按需深入：**检查两集合的差集。被排除者是否集中在某类业务或窗口？结果变动来自哪些可用信息丢失？也可比较有依据的其他规则；数据约定中的版本、单位和999含义不应任意改成“替代”。

**检查依据：**至少一个实际比较给出两种范围、分母、结果和取舍。结果不变也需解释所检查的范围，不强求反转。

## 未知信息怎样影响发布

**先问自己：**你描述的是已知记录，还是试图代表全部登记工单？

**进一步提示：**不插补可以限范围报告；插补需要说明假设。若目标是全部办结比例，可把未知状态分别当全部已办结与全部未办结，得到逻辑可能范围，手算例子见LEARN。这个分析方向可选，不是每个人必须采用的模板。

**检查依据：**结果所覆盖的对象与建议一致。未知值不填0，范围不是置信区间，窗口数量不冒称人员工时。

## 工具、排错与提交

默认概览可从学生仓库根运行 `python3 scripts/course.py run 03`，结果在 `lesson-03/artifacts/starting_overview.json`。它只认识原始结构，不完成你的项目。单值函数 `parse_wait_value` 识别一个等待值的编码与单位；选择版本、分析范围和方法仍由你实现。

目录错时确认能看到 `data/`、`scripts/`、`lesson-03/`；字段错时核对[数据说明](../data/service/README.md)；数字不同时先核版本、缺失识别、单位、条件与分母，不手改结果文件。旧输出应由最终程序重建。报告可按[提示](report.md)自由组织。

提交前确认原表未改、两个用途与比较完成、主要数字可复核、`submission.json`的状态与真实路径相符、`run`可重建证据。运行自己的最终分析再做 `python3 scripts/course.py check 03`；检查通过不是统计论证通过。
