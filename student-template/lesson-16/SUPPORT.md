# 第16课支持路线 · 根据实验结果作推广决策

## 先知道今天要交出什么

你要提交实验决策报告：核对实际分配和实施，估计“提供工具”这一措施的效应与不确定性，并把3分钟改善门槛、每人8单位成本和缺失情境放进推广、有限试用或停止的比较中。

入门跟做只完成数据连接、人数核对和效应方向检查，不能代替保留团队结构的正式分析与敏感性分析。

## 核心概念与原理

**意向性分析（intention-to-treat，ITT）原则**要求按最初随机分配组分析，不按实际是否使用工具重新分组。这样保留随机分配所建立的可比性，估计的是“提供工具”这一措施的效应。

随机化单位是团队。480行个人结果不是480次独立分配；效应区间或检验应保留团队和区组结构。

失访、未依从和组间污染是不同问题。失访使结局缺失；未依从是未按分配接受处理；污染是对照组接触到工具。ITT原则不会自动补出失访者的结果，因此仍要说明缺失假设和敏感性分析。

## 基础练习（可信起点）：入门跟做

先在**仓库根目录**打开终端，完整运行：

```bash
python scripts/course.py start 16
python scripts/course.py run 16
```

第二条命令成功时，终端会提示概览已经写入`lesson-16/artifacts/starting_inventory.json`。打开这个文件；它只是数据起点，不是本课答案。若文件没有生成，先按后面的排错顺序处理，再继续。

### 第一步：连接名单和结果

- **动作**：从仓库根运行`python scripts/course.py run 16`，按`person_id`连接`experiment_roster.csv`与`experiment_outcomes.csv`。
- **目的**：保留团队、区组、基线、初始分配和随访信息。
- **成功信号**：连接后仍是每人一行，能报告未匹配与重复数；没有用`received_tool`替换`assigned_arm`。
- **反思**：若按实际使用重新分组，哪些分配后的选择会进入组间差异？

### 第二步：核对随机化与实施

- **动作**：按`block`和`team`汇总初始分配，按组统计全部分配人数、实际使用人数、随访人数和独立团队数。
- **目的**：确认实际实施与L15方案的差异，并区分三种分母。
- **成功信号**：每个团队只有一个`assigned_arm`；人数、团队数和随访率都可复算。
- **反思**：随访率不同会使完整案例比较依赖什么额外假设？

### 第三步：确认效应符号

- **动作**：计算按初始分配的随访均值差`tool−usual`，保留分钟单位；用一个小例子核对负值表示处理时间下降。
- **目的**：避免把改善方向写反，并为区间与成本解释建立目标量。
- **成功信号**：结果标题和报告都明确差值顺序；没有只报告p值。
- **反思**：均值差达到3分钟与置信区间排除0分别回答什么问题？

### 第四步：选择保留设计的主要分析

- **动作**：选择团队汇总、保留区组的随机化分析、基线调整或适当的聚类方法之一，写清为何与实际分配相符。
- **目的**：用正确独立单位估计不确定性。
- **成功信号**：结果包含效应量、区间和方法条件；团队与区组没有在推断中被忽略。
- **反思**：增加同一团队内人数为什么不能等价替代更多独立团队？

### 入门反思

用四行记录：随机化单位；主要目标效应；完整案例分析依赖的缺失假设；哪种缺失或污染情境会改变行动建议。

## 标准任务（本课应完成）

1. 对照L15设计核对实际分配、使用、失访、基线和团队结构。
2. 按初始随机分配完成主要分析，报告效应量、区间及与原分配机制一致的检验或随机化分析。
3. 对缺失结果设置明确处理和至少一项敏感性分析，不把完整案例自动称为所有人的ITT效应。
4. 把效应、3分钟实际门槛、每人8单位成本和每分钟2单位价值放入同一决策表。
5. 比较推广、有限试用和停止，并说明缺失、污染或外推条件改变时如何更新。

## 提高与拓展（提前完成后）

- 比较团队汇总、基线调整和保留区组的随机化检验，解释差异来自目标或方法的哪一部分。
- 对失访者设置与已观察者不同的组别特定偏移，寻找建议发生改变的界点。
- 分别估计提供工具效应与实际使用者关联，明确后者为何需要更强因果假设。
- 对有限团队数采用适当的小样本校正并检查结果稳定性。

## 卡住时按顺序排查

1. 连接膨胀时先检查`person_id`唯一性。
2. 分组结果怪异时确认使用`assigned_arm`做主要分析，不是`received_tool`。
3. 团队数变成480时，检查是否误把个人行当随机化单位。
4. 效应方向混乱时固定写成`tool−usual`并在所有表中保持一致。
5. 缺失值导致程序错误时，先按`followup_observed`核对空值规则，再写处理方案。
6. 报告先按“实施核对、主要效应、敏感性、成本决策”组织。
