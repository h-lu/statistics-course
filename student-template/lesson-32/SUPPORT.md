# 第32课陪做支持 · 面向新问题的统计分析综合报告

这份材料帮助你在不知道下一步时建立可信起点。它不提供本课正式数据的答案，也不能代替 [README 主任务](README.md)；概念的完整解释见 [LEARN.md](LEARN.md)。

## 先知道今天要交出什么

- `lesson-31/LESSON_32_PLAN.md`：课前确定的新使用者、决定、目标量、数据和实质修订。
- `report.md`：面向新用途的完整综合报告和修订说明。
- 可重跑程序、主要结果与敏感性证据，并在 `submission.json` 正确登记。

最低出口是：别人能够按你的命令重新生成报告引用的数字，并知道这些数字可以和不可以用于什么决定。

## 核心概念与原理

| 规范术语 | 通俗解释 | 怎样在自己的结果中检查 |
|---|---|---|
| 目标量 | 针对明确人群、时间和比较所要估计或预测的量。 | 判断旧分析是否真正回答新问题。 |
| 证据可追溯 | 报告数字能回到原始数据、程序、筛选规则和结果版本。 | 让他人复核一条主要结论。 |
| 不确定性 | 由抽样、未来波动、模型或设计带来的未知程度。 | 决定表述强度和行动余量。 |
| 敏感性分析 | 改变一个有理由的分析选择，检查结论是否随之改变。 | 说明建议依赖哪些假设。 |
| 适用范围 | 结果可以用于哪些人群、时段、输入范围和行动。 | 写出限用、暂停或重做条件。 |

### 先用一个小例子想清楚

旧报告回答“历史平均等待多久”，新使用者却要决定“明天需要安排多少容量”。平均描述不能直接变成未来容量保证。实质修订可以是建立有时间顺序的预测与预测区间，并说明仍无法保证每个人都不超时。

这个例子只用于核对概念，不是正式数据的结论。正式项目必须使用自己的运行结果。

## 基础练习（可信起点）：入门跟做

以下命令都从仓库根目录运行，也就是同时能看到 `scripts/`、`data/` 和 `lesson-32/` 的目录。

```bash
python scripts/course.py start 32
python scripts/course.py run 32
```

第二条命令成功后，应看到终端提示结果已经生成，并能打开 `lesson-32/artifacts/starting_summary.json`。这个文件只是数据起点，不是本课完整答案。

若终端明确提示 `python: command not found`，按仓库首页说明，把上面两行开头的 `python` 换成 `python3`，其余内容不变。

### 第1步：确认课前计划或立即采用默认路线

- **动作：** 打开并完成 `lesson-31/LESSON_32_PLAN.md`。若没有计划，使用L31资料和README给出的教学情境报价（费用4、延迟3，高需求下阳性概率0.70，低需求下0.25），为调查费用上限6单位、延迟成本另计3单位的负责人重新评价追加调查。
- **目的：** 先锁定问题，避免把课堂时间耗在无限选题。
- **成功信号：** 计划含新使用者、决定、目标量、数据、原课次和一项实质修订；默认路线还能区分“费用4”、“延迟3”和“费用上限6”。
- **想一想：** 新问题相较旧报告具体改变了什么？

### 第2步：重跑旧流程并追踪数字

- **动作：** 运行旧项目或默认路线，选择报告中最重要的一条数字，记录原始文件、筛选范围、程序和结果路径。
- **目的：** 先证明旧证据可以复现，再修改。
- **成功信号：** 从空的生成结果目录重跑后能得到该数字。
- **想一想：** 手工改过的中间表会破坏哪一段追溯？

### 第3步：完成实质修订

- **动作：** 改变目标量、分析方法、适用范围或行动规则中至少一项，并重新分析。
- **目的：** 综合报告要回答新用途，而不是只换标题。
- **成功信号：** 修订前后问题和结果可并列说明，修订确实影响解释或决定。
- **想一想：** 新增模型或图若不改变证据或行动，是否算实质修订？

### 第4步：加入不确定性并写使用规则

- **动作：** 完成区间、预测评价或有理由的敏感性分析，写建议、限用和暂停条件。
- **目的：** 把统计证据转换成可执行且不过度承诺的规则。
- **成功信号：** 报告区分支持的结论与不能支持的结论，并有触发重做的条件。
- **想一想：** 哪项新证据最可能改变当前建议？

完成这四步后，你已经有可信起点，但还没有完成整项主任务。

## 标准任务（本课应完成）

回到 [README](README.md) 完成全部标准任务，特别核对：

- 明确新使用者、决定、目标量、数据与适用范围。
- 从原始数据重跑完整流程并形成实质修订。
- 让主要结论可追溯，并报告不确定性或敏感性。
- 提交完整报告、程序、结果和修订说明。

把程序输出翻译成完整统计句子：对象是谁，比较什么，数值和单位是什么，哪些假设成立时可以怎样使用，哪些结论仍不能作出。

## 提高与拓展（提前完成后）

先完成标准任务，再选一项。提高的标准是让证据、适用范围或行动更可靠，而不是增加代码或图表数量。

- 请不熟悉旧项目的人按命令复核关键数字。
- 比较两个合理目标量或行动规则。
- 增加能改变行动的稳健性检查和暂停条件。

## 卡住时按顺序排查

- **课堂开始仍未选题：** 不要继续浏览所有课次；立即采用README规定的L31默认路线（调查费用上限6单位，延迟成本另计3单位）。
- **旧程序无法复现：** 先固定依赖、路径和数据版本；不能用手工复制的旧数字代替重跑。
- **命令提示找不到文件：** 先运行 `pwd`，确认当前位置是仓库根目录；这里应同时看见 `scripts/` 和本课目录。
- **程序能运行但结果还是旧的：** 检查结果文件的修改时间，确认修改并运行的是本课 `analysis.py`；必要时删除自己生成的旧结果后重跑，但不要删除原始数据。
- **报告数字和程序输出不一致：** 从报告中的一个关键数字反向找到结果文件、筛选范围、分子和分母；不要手工把报告改成“看起来合理”的数字。
- **不知道怎样开始写报告：** 先写五句：谁使用、要决定什么、数据覆盖谁、一个主要结果、一个不能支持的结论，再补方法和证据。
