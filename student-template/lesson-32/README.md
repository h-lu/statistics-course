# 第32课 · 面向新问题的统计分析综合报告

## 项目背景

从前31课的项目中选择一个主题，面向更具体的使用者和分析问题，完成一份综合统计分析报告。可以是值班人员所需的模型使用说明、管理者所需的政策评估简报、调查团队所需的抽样方案，或业务部门所需的决策分析。

新报告面向谁，要回答什么具体问题，结果适用于哪些条件？相较原报告，目标量、分析方法、适用范围或行动规则至少有一项需要实质修改。

可从[本学期的数据集](../data/README.md)选择与新用途相符的资料。**随课资料全部为教学合成数据。** 数据字典说明记录单位、字段、时点和局限。示例代码默认读取[政策与决策数据集](../data/policy/README.md)中的`decision_options.csv`与`pilot_test.csv`，但这不是选题限制。你可以全程使用AI完成编程、分析、写作与提交，也可以复用前课代码。

## 课前准备与默认路线

先完成已随第31课发布的[分析计划](../lesson-31/LESSON_32_PLAN.md)：确定新使用者、具体决定、目标量、数据、原课次和一项实质修订。计划是在第31课后填写的短记录，不是提前写完报告。

如果课堂开始时还没有选题，直接采用默认路线：使用L31决策数据，为“可支付的调查费用上限为6个损失单位，延迟成本另计3个损失单位”的负责人重新评价是否追加调查。默认路线与自选路线执行相同的标准任务和提交要求，不降低评分核心。

为了让默认路线可以进行实质分析，题目另外给出一个**教学情境报价**：调查费用4个损失单位，延迟成本3个损失单位；高需求状态下收到阳性信号的概率为0.70，低需求状态下为0.25。这些是为练习决策而给定的情境假设，不是从数据估计得到的性能。你需要用它们重算信号后的行动、样本信息价值与扣除调查费用和延迟成本后的净信息价值。

## 任务分层

本课综合以前的工作；先阅读[第31课的决策分析](../lesson-31/README.md)，并回看与你选题相同的原课次。第一次做这一类项目时，按[陪做支持](SUPPORT.md)完成每一步；概念解释见[知识准备](LEARN.md)。

### 基础练习（可信起点）

1. 打开课前填写的 [LESSON_32_PLAN.md](../lesson-31/LESSON_32_PLAN.md)，核对新使用者、具体决定、目标量、数据和一项实质修订。
2. 重新运行旧项目，找到一条主要结论对应的原始数据、计算程序和结果文件。
3. 若没有课前计划，立即采用默认路线：使用L31决策资料和上述教学情境报价，为“调查费用上限6个损失单位，延迟成本另计3个损失单位”的负责人重新评价是否调查。

基础练习帮助你得到可信的第一份结果，**并不等于已经完成本课**。继续完成下面的标准任务，才能把计算变成可使用的统计结论。

### 标准任务（本课应完成）

1. 选择已有数据集和项目，写清新使用者、具体决定、目标量、时间范围和不能使用的情境。可复用旧代码和AI成果，不要求新建平台。

2. 重新运行从原始数据到分析结果的完整流程；检查旧稿的关键假设，完成一项会影响新用途的实质分析或设计修订，而不是只换标题与版式。

3. 为主要结论提供可追溯的计算结果，并报告不确定性或敏感性分析。根据结果判断是否建议使用、是否需要限制适用范围，或是否暂不建议采用。在使用说明中明确现有资料不能支持哪些结论。

4. 提交分析报告、可复现程序、计算结果和图表，以及简短的修订说明。若尚未确定主题，可使用本课示例代码读取L31决策数据，为“调查费用上限6单位，延迟成本另计3单位的采购负责人”重新评价追加调查方案。默认敏感性分析在“信号性能保持给定设定”的前提下，把调查费用从0到6逐步改变，延迟成本始终另计3单位；说明在什么调查费用下不再追加调查。

以上均为本课需要完成的任务，分析方法和报告形式可以自行选择。评价不以图表或模型数量为依据。使用外部资料时注明来源，补充的业务假设应明确标注，不得当作已知事实。

### 提高与拓展（提前完成后）

完成标准任务后，从下面选择一项深入；重点是改善证据或决策，不按代码、图表或模型数量评价。

- 邀请一个不了解旧项目的读者按复现命令检查关键数字，再根据其问题修改使用说明。
- 比较两个合理目标量或行动规则，说明为什么新使用者应采用其中一个。
- 增加一项能真正改变行动的稳健性检查，并写出触发暂停使用或重新分析的条件。

## 示例代码与运行方法

从仓库根目录运行：

```bash
python scripts/course.py start 32
python scripts/course.py run 32
```

本课`analysis.py`读取数据并生成`artifacts/starting_summary.json`，用于熟悉数据结构。**请在此基础上完成本课分析任务，形成自己的分析方案和结论。** 可使用Python标准库、numpy/scipy、pandas、statsmodels、scikit-learn或其他合适工具；说明新增依赖与运行命令。若自选另一数据集，修改分析程序，并同步更新`submission.json`中的`run`命令和结果文件路径。

## 成果要求与提交

- `lesson-31/LESSON_32_PLAN.md`：保留课前确定的使用者、决定、目标量、数据和实质修订；若采用默认路线也要填写。
- `report.md`：面向报告使用者，写清分析问题、方法依据、主要结果、适用范围和建议。
- 可复现的分析程序或研究设计文件，以及报告引用的计算结果和图表；不要手工修改原始数据。
- `submission.json`：将`status`设为`complete`，`report`指向分析报告，`artifacts`列出支持报告结论的结果文件路径，`run`填写可复现分析的命令。

`LESSON_32_PLAN.md`已随第31课发布，在第32课提交时一并保留你填写的内容。它不是最终报告，也不是分析结果，因此不需要写进`submission.json`的`report`或`artifacts`。`submission.json`仍用于登记最终报告、可重跑命令和报告实际引用的结果文件。

如果本课修改了计划，提交时不要只暂存 `lesson-32/`，而要同时保存计划：

```bash
git add lesson-31/LESSON_32_PLAN.md lesson-32
git diff --cached
```

然后再按[项目工作流](../docs/WORKFLOW.md)提交、推送和创建本课标签。

仅运行示例代码或粘贴模型输出，还没有完成本课分析任务。合格报告应明确新的使用者，能够复现分析结果，并有实质修订；更好的报告还会根据不确定性和局限性，给出具体的使用条件及暂停使用或重新分析的规则。

完成后执行`python scripts/course.py check 32`，按[项目工作流](../docs/WORKFLOW.md)提交并创建`v2-l32-final`标签；有修订时保留原标签。自查按[知识自查说明](../docs/KNOWLEDGE_CHECK.md)进行。项目分析允许全程使用AI，不要求提交AI对话记录。
