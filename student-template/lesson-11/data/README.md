# 第11课数据与调查规则

本课使用固定的4000人教学合成总体：A组3200人，B组800人。`need_weekend=1` 表示下个周末至少有一次需求，0表示没有需求。A/B是联系条件不同的虚构分组。

## 数据文件

|文件|内容|用途|
|---|---|---|
|`frame.csv`|编号、组别、网上名单状态|制定邀请方案|
|`strata.csv`|各组人数、网上名单人数、邀请费用和普通回答率|计算构成与预算|
|`provenance.json`|来源、固定种子和文件散列|核对版本与复现|
|`simulator/weekend_population.csv`|每个人的完整需求|模拟器生成回答；估计完成后作总体审计|

`frame.csv` 的三列是 `person_id`、`group`、`online_frame`。网上名单共3305人，`online_frame=1` 表示在名单中。总体和名单在各次模拟中保持不变。

先用公开名册保存比较方案，再取得回答、形成估计，最后查看完整总体。审计之后提出的新方案标为“事后修订”，与第一次方案分开记录。

## 三种机制

|名称|邀请规则|受邀后的回答概率|
|---|---|---|
|`register_ordinary`|完整名册内等概率、无放回邀请n人|A组0.8，B组0.6；同组内回答与需求独立|
|`web_voluntary`|网上名单内等概率、无放回邀请n人|有需求者0.85，无需求者0.25|
|`register_complete`|完整名册内等概率、无放回邀请n人|全部回答，作为理想对照|

完整名册中的邀请概率为 n/4000；网上名单内为 n/3305，名单外为0。每次发出邀请的费用是A组1单位、B组3单位，各机制使用同一费用规则。费用不含追访，因此相同邀请数可能有不同费用和回答人数。

## 一次调查生成什么

`run_request` 使用新目录保存三个文件：

|文件|内容|
|---|---|
|`request.json`|机制、n、选择种子、回答种子、名册散列和邀请编号|
|`observations.csv`|4000人的名单、邀请、回答状态及已观察的需求|
|`receipt.json`|实际邀请数、回答数、邀请费用与文件散列|

观测字段：

- `in_frame`：是否属于本机制的抽样框。
- `invited`：本次是否受邀。
- `answered`：本次是否回答。
- `invite_probability`：设计的邀请概率。
- `observed_need`：回答者为0或1，其他人为空；`read_observations` 将空值读为 `None`。
- `invitation_cost_units`：本次邀请费用，只有受邀者计费。

观测不导出个人回答概率，因为网上机制的该概率会透露尚未观察的需求。

## 重跑与审计

人口种子20261011用于生成固定总体。每份请求另有选择和回答种子；相同输入与种子可复现一次运行。不同机制即使用同种子，也可能邀请和收到不同人的回答。

每次重跑使用新目录。`audit_population(request, output_dir)` 核对请求与观测后返回总体真值，用于解释本次估计误差。它对应正式4000人总体，与LEARN中的100人小例分开。

原始CSV保持不变。许可见 [LICENSE.md](LICENSE.md)，生成依据和散列见 [provenance.json](provenance.json)。
