# 第11课数据：先看名册，再取得回答

本课的4000人是固定的教学合成总体，A组3200人、B组800人。每行对应一个虚构的人，编号是唯一标识。我们要估计这4000人中，下个周末至少需要一次服务的比例。

## 先打开这两个文件

`lesson-11/data/frame.csv` 是规划调查时使用的公开名册。前五条实际记录如下：

|person_id|group|online_frame|
|---|---|---:|
|A0001|A|1|
|A0002|A|0|
|A0003|A|1|
|A0004|A|1|
|A0005|A|1|

`person_id` 是编号，`group` 是A/B组别，`online_frame=1` 表示在网上联系名单中，0表示不在。A0002可以通过完整名册被邀请，却没有机会被网上方式邀请。这三列没有告诉我们谁有需求；名单中的4000行也不是4000份回答。

`lesson-11/data/strata.csv` 给出规划时已知的分组资料：

|group|population_count|online_count|invitation_cost_units|ordinary_response_probability|
|---|---:|---:|---:|---:|
|A|3200|2861|1|0.8|
|B|800|444|3|0.6|

这五列依次表示组别、全组人数、网上名单人数、每次邀请费用、普通联系下受邀者的回答概率。例如B组每邀请一人花3单位，并非每收到一份回答才花3单位。网上名单共2861+444=3305人；全体A/B构成权重为3200/4000=0.8和800/4000=0.2。

## 两种方式怎样生成一次调查

|程序中的机制名称|邀请规则|受邀后的回答概率|
|---|---|---|
|`register_ordinary`|完整名册内等概率、无放回邀请n人|A组0.8，B组0.6；同组内回答与需求独立|
|`web_voluntary`|网上名单内等概率、无放回邀请n人|有需求者0.85，无需求者0.25|
|`register_complete`（选做对照）|完整名册内等概率、无放回邀请n人|全部回答|

完整名册中的邀请概率为n/4000；网上名单内为n/3305，名单外为0。邀请之后是否回答另作一次随机决定，所以邀请人数与回答人数不同。同一组种子用于两种方式，也不表示邀请到同一批人。

## 取得回答后，看哪些列

一次调查生成 `request.json`（方案）、`observations.csv`（观测）和 `receipt.json`（运行核对记录）。观测CSV仍有4000行，用来保留每个人经历到哪一步；只有 `answered=1` 的行才是收到的回答。

|观测列|怎样读|
|---|---|
|`person_id`|与公开名册对应的编号|
|`group`|A或B|
|`in_frame`|是否属于本机制可邀请的名单；1是、0否|
|`invited`|本次是否受邀；1是、0否|
|`answered`|本次是否回答；1是、0否|
|`invite_probability`|本机制中该人的设计邀请概率，取值0至1|
|`observed_need`|回答者为0或1；未观察者留空|
|`invitation_cost_units`|本次对该人的邀请费用；未受邀为0|

空白表示“这次没有观察到需求”，明确的0表示“已回答且没有需求”。`read_observations` 将空白读为Python的 `None`；示范汇总把它显示为“未知”。不要把未知者加入“没有需求”的人数。五条可逐行核对的实际观测见[SUPPORT](../SUPPORT.md)。

## 估计之后，再核对完整总体

先保存两份方案，取得回答并形成比较表，再进行总体审计。`simulator/weekend_population.csv` 是模拟器使用的完整需求表，列为编号、组别、`need_weekend` 和网上名单状态。`need_weekend=1` 表示有需求，0表示没有需求。它用于生成合成回答，估计后才用来检查误差；现实调查通常拿不到这样的完整真值。

`audit_population(request, output_dir)` 核对已存方案与观测后返回总体人数、需求人数、总体比例及组内比例。它提供的是这份教学总体的事后真值，并非新收集的一份样本。100人手算小例与这里的4000人总体是两套数据，各自的比例不必相同。

每份方案保存邀请人数、邀请种子、回答种子和实际邀请编号。种子相同且输入不变，可以复现一次运行。新方案使用新目录，保留第一次方案；审计后提出的改进另记为“事后修订”。

人口种子20261011用于生成固定总体；原始CSV保持不变。许可见[LICENSE.md](LICENSE.md)，生成依据和SHA-256散列见[provenance.json](provenance.json)。散列用于核对文件版本及方案与观测的对应关系，不能判断样本是否具有代表性。观测不导出个人回答概率，以免由此透露尚未观察的需求。
