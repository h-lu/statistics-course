# 第11课数据与取得规则

这些文件全部是**教学合成数据**，没有真实个人或机构调查记录。固定研究对象是同一份4000人名册，A组3200人、B组800人；`need_weekend=1`表示指定的下一个周末有至少一次需求。组别表示联络方式不同的教学分组，不是受保护属性，也不表示因果关系。本课使用同一个固定总体，不在每次模拟时重新生成人群。

## 先看哪些文件

| 文件 | 一行表示什么 | 何时使用 |
|---|---|---|
| `frame.csv` | 一名虚构对象的编号、组别和是否在网上联系名单中 | 制定邀请方案时 |
| `strata.csv` | 一个组的已知人数、网上名单人数、邀请费用及普通联系回答率 | 制定方案、核对构成与资源时 |
| `provenance.json` | 数据来源、固定种子、字段用途、规则和文件散列 | 复现与输入核对时 |
| `simulator/weekend_population.csv` | 每个人的固定完整需求结果 | 模拟器产生回答，以及方案确定后的教学审计；不用来挑人或挑方案 |

`frame.csv`只含三列：`person_id`是唯一虚构编号；`group`为A/B；`online_frame`为1表示在网上联系名单内，为0表示不在。网上名单共3305人，成员在整个练习中固定。邀请规则只能使用这些公开信息，不使用未观察的需求结果。

完整结果文件就在本地，能够被打开。这里约定“先用公开名册写定比较方案，再取得回答，最后审计”，不是声称技术上无法绕过。AI也遵守同一分析约定；不以读取文件本身作为惩罚依据。若已看过审计结果，再提出的方案应明确标为事后修订，不能冒称尚未看结果时的选择。

## 三种明确的取得机制

- `register_ordinary`：从完整4000人名册等概率、无放回抽取你指定的n人邀请。受邀A组每人以0.8概率回答、B组以0.6概率回答；在每组内，回答与需求独立。这是本教学模型的假设，现实调查须另外论证。
- `web_voluntary`：只从网上名单内等概率、无放回抽取n人邀请。框外人的邀请概率为0。受邀且有需求者以0.85概率回答，无需求者以0.25概率回答。邀请随机不等于最后回答者具有代表性。
- `register_complete`：从完整名册随机邀请，理想化约定所有受邀者均回答。它可作为补充比较，不能当作现实中免费、必然能实现的完成联系。

完整名册每人的邀请概率是n/4000；网上框内是n/3305，框外为0。`strata.csv`另设**每发出一次邀请**的费用：A为1、B为3个教学成本单位，任何机制均按实际邀请的组别计。这是本课新增的邀请假设，并非历史“完成联系”价格或真实业务收费；它不包含追访、确保回答或实际实施费用。因此相同邀请数只固定了n，不固定成本、回答数或每个人的机会；比较同成本方案时须重新说明约束，不能直接宣称同n就是同预算。

## 取得文件的字段

`run_request`为一个已写定的请求创建新目录，其中保存：

- `request.json`：机制、n、选择与回答种子、公开名册散列和实际邀请编号；
- `observations.csv`：完整4000人逐人的框、邀请及回答状态；
- `receipt.json`：请求与观测散列、实际邀请和回答数、邀请费用。这里没有总体需求真值。

`observations.csv`中，`in_frame`表示本机制的名单是否包括这个人；`invited`表示实际受邀；`answered`表示实际回答。`invite_probability`是设计的邀请概率，**不是回答概率**。`observed_need`只有回答者为0或1，未回答者为空；`read_observations`把这个空值读为Python的`None`。未知不能填为0。`invitation_cost_units`只有受邀者计费。

可以追踪同一编号经历了什么，但不要把“框外”“框内未抽中”和“受邀未回答”混为同一种缺失。模拟器不导出个人的回答概率，因为网上机制的该数值会反过来泄漏其未观察需求。

## 重跑与审计

人口种子20261011只用于固定总体。每个请求分别保存选择种子和回答种子；相同文件、参数与种子可复现。同种子不会使不同联系名单变成相同机会或相同回答者。先写定所有比较方案，重跑使用新的输出目录，不覆盖原始请求和观测。

独立的`audit_population(request, output_dir)`核对已取得的请求及观测散列后，返回固定总体的事后核对值。这不是第二份随机样本，不是现实中能够免费取得的全面调查，也不是用来反向选择“最好看”方案的输入。两组需求率与总体比例属于这个正式4000人模型，不能与LEARN中另设100人小例的58%混用。
