# 遇到困难时可选的支持

先按自己的问题选择提示，不必依次完成每一节。基础小例只帮助开始，不代替正式调查比较。

## 基础练习：先把分母写出来

运行本课起点程序，核对另设100人小例的三件事：回答者直接合并为70%；按80%/20%的总体构成为58%；若A组中有需求者更容易进入回答，构成调整仍可得到82%，却不因此恢复总体。缺少B组回答时，调整结果是未知，不能把B组比例填成0。

成功信号是能解释每个数字的分母，以及为什么已知两组人数仍不足以判断同组回答者能否代表未回答者。起点程序的`formal_acquisition_run`为false，尚未完成正式方案。

## 标准任务：从公开名册开始

公开的`data/frame.csv`没有需求结果。`sampling_tools.py`提供几个独立工具：

| 工具 | 输入与输出 | 你仍须决定什么 |
|---|---|---|
| `load_frame()` | 读取公开联系名册 | 在完整总体主目标之外，是否增加辅助分组问题 |
| `choose_invites(frame, n, seed, mechanism)` | 在规定名单内等概率无放回选编号 | n、机制、比较约束及理由 |
| `make_request(frame, mechanism, n, selection_seed, response_seed)` | 生成含实际邀请编号的方案 | 方案依据、种子与保持相同的条件 |
| `write_request(request, path)` | 保存方案并返回散列，不覆盖旧文件 | 在第一次取得前保存哪些比较方案 |
| `run_request(request, output_dir)` | 取得一份观测及凭据，目录须尚不存在 | 如何公平比较和解释观测 |
| `read_observations(path)` | 读回观测，未知值保持`None` | 分母、构成、未知与适用范围 |
| `response_mean(rows, group=None)` | 描述回答者比例，无回答则为`None` | 这个比例能否用于目标人群 |
| `composition_estimate(rows, population_counts)` | 按已知组人数调整；缺组返回`None` | 是否有组内可代表的依据 |
| `audit_population(request, output_dir)` | 取得后核对记录并给固定总体真值 | 误差来自哪些取得环节，建议如何修订 |

可以先让AI说明函数接口，再自行组织程序或使用其他工具。所有比较方案应先保存，之后才调用取得函数；不要先批量试看结果再把选中的种子冒称为最初方案。输出文件的结构见[data说明](data/README.md)。本课没有自动挑出最优调查方案或替你写建议的函数。

若要用另设小例练习如何创建一份方案，可以在交互环境中先查看函数帮助和公开名册列名；正式n及比较方案由你选择。机制名称为`register_ordinary`、`web_voluntary`，可选补充为理想的`register_complete`。相同n并不意味着相同回答数或费用。

## 追踪一个编号时卡住

先分清四种状态：不在本次名单内；在名单内但没抽中；受邀但没回答；已回答。`observed_need=None`只说明本次未观察到需求，不说明此人没有需求。选择一个编号逐项写出`in_frame`、`invited`、`answered`与可观察结果；再说明哪个环节可能造成不同。

## 结果核对与排错

1. 框记录应为4000条、编号唯一，组人数为3200/800；网上名单3305人。若不符，先核对输入文件及来源，不手改CSV凑数。
2. 受邀人数应恰为请求n，每人最多一次；网上机制框外人的邀请概率必须为0。
3. 回答人数不能超过邀请人数；未回答结果应为空/`None`，不是0。组内没有回答时，不支持组别调整。
4. 如果报“output directory exists”，保留旧结果并换新目录，不删旧记录后重跑。
5. 如果报方案、名册或观测已改变，先对照请求和凭据。无法确认来源时，保留问题并在报告说明，不把不同方案的文件混在一起。

## 提高与拓展

完成标准任务后，可以研究“更大网上样本”是否仍稳定偏离，或者设计有资源依据的追访建议。重复抽样用于检查某个已写定机制，不是寻找一个更好看的种子。若改变回答规则、目标人群或取得费用，请明确这是新情境，不能把它与原比较混为同一模型。

最后检查报告、实际运行命令与结果文件是否一致。只运行100人小例、只把状态改为complete，或只抄函数输出，都不等于完成正式比较。
