# 第11课 · 回答的人很多，就能代表所有人吗？

服务部门想知道：名册中的4000人，下个周末有多少人至少需要一次服务？本课比较两种调查方式，判断回答者的比例能否代表这4000人，并向服务部门提出建议。全部数据为教学合成数据。

## 从哪里开始

[LEARN](LEARN.md)用100人小例解释回答者为什么可能与全体不同，以及构成加权能改正什么。想先动手，可查看[数据说明](data/README.md)，再按[SUPPORT](SUPPORT.md)完成一组能核对数字的示范。熟悉后自行组织正式比较；可以全程使用AI，无需提交对话记录。

- **基础练习：**100人手算小例与固定种子的4000人操作示范，帮助理解数据和计算。
- **标准任务：**自行确定调查规模、保存方案，完成下面的调查比较及建议。
- **提高与拓展：**完成标准任务后，按需选做[EXERCISES](EXERCISES.md)。

## 两种调查方式

目标总体为4000人：A组3200人，B组800人。每个人下个周末至少需要一次服务记为1，没有需求记为0。A/B是联系条件不同的虚构分组。

|调查方式|从哪里邀请|受邀后怎样回答|
|---|---|---|
|完整名册普通联系|从4000人中等概率、无放回抽取|A组回答概率0.8，B组0.6；同组内回答与需求独立|
|网上邀请、自愿回答|只从3305人的网上联系名单中等概率、无放回抽取|有需求者回答概率0.85，无需求者0.25|

两种方式的每次邀请费用均为A组1单位、B组3单位，只计算发出邀请，不包括追访。同样邀请200人，并不一定收到200份回答；邀请的组别不同，费用也可能不同。

规划时打开不含需求结果的 `lesson-11/data/frame.csv` 和分组资料 `strata.csv`。取得回答后，计算来自 `observations.csv` 的已回答记录。完整总体的需求只用于估计之后的审计核对。

## 标准任务：给服务部门的调查建议

为同一4000人总体比较上述两种方式，**保持邀请人数相同**。先确定邀请人数及种子，说明规模选择与资源的关系，再保存两份方案、取得回答。网上名单只有3305人，因此共同邀请人数应在1至3305之间。种子用于复现一次随机结果，不代表方案好坏。

报告完成四件事：

1. **追踪一个人。** 选一个正式模拟编号，说明他是否在本次调查的抽样框内、是否受邀、是否回答，以及观察到的需求。未观察到的需求保留未知，不能记为0。
2. **比较两套结果。** 保存第一次方案和可复跑输出，按报告模板列出人数、组内比例、直接比例、0.8/0.2构成比例及邀请费用。缺组时保留无法计算的比例，并解释原因。
3. **解释差异。** 先形成估计，再与完整总体核对。区分名单覆盖、受邀后无回答、同组内回答选择和一次随机波动。判断构成加权是否适合本次结果；一次运行不能证明某方法总是更好。
4. **提出建议。** 在现有资源下，建议采用哪种调查或补采方式？为什么，尚缺哪些信息？证据不足时也可建议暂缓推广到全体。

邀请规模、是否采用构成加权、如何补采及建议的适用范围由你依据结果决定。可以另加相同预算等比较。正式作品使用自己事先确定的方案；保留第一次结果，审计后改方案时另存为“事后修订”，不反复换种子挑选漂亮结果。

## 运行与提交

在学生仓库根目录开始；材料不全时查看[首次使用指引](../docs/LESSON11_UPDATE.md)：

```sh
python3 scripts/course_l11.py start 11
python3 scripts/course_l11.py run 11
```

默认程序只运行100人小例，输出 `lesson-11/artifacts/example.json`。接着可用[SUPPORT中的完整命令](SUPPORT.md)生成正式数据。那里先展示一组固定示范，再说明怎样改为自己的方案和提交命令。

用[report.md](report.md)组织报告，在 `submission.json` 登记自己的运行命令和结果文件，完成后才将状态改为 `complete`，再运行：

```sh
python3 scripts/course_l11.py check 11
```

按[提交流程](../docs/WORKFLOW.md)提交，最终标签为 `v2-l11-final`。文件检查与复现通过后，仍须在报告中说明统计依据。课末按教师开放场次完成A题、AI辅助学习和B题。
