# 第1课支持路线：先描述清楚，再提出问题

## 先知道今天要交出什么

一份报告、一段可运行程序、一张表或一幅图，以及能说明记录数、单位、分母和局限的文字。你不需要一开始就决定哪个中心最好。

本课分为三个层次：

- **基础练习（可信起点）**帮助你读懂字段、起始结果和分母，不能代替正式项目；
- **标准任务（本课应完成）**是 README 的五项分析任务，也是本课默认完成要求；
- **提高与拓展（提前完成后）**是在标准任务已经完成并通过检查后，对关键结论再做一次有统计意义的核对。

## 核心概念与原理

- **观测单位**：一行记录描述的对象。本课通常是一张工单；同一个人有多张工单不能自动合并。
- **变量**：对象的属性，如等待分钟数、业务类型、是否放弃，必须连同含义和单位理解。
- **均值**：数值总和除以记录数，容易受很长等待影响。
- **中位数**：排序后中间位置的数，不是大多数记录都等于它。
- **比例**：某类记录数除以指定范围内的全部记录数；分母不同，回答的问题不同。

探索性分析的原理是先描述证据，再提出问题。看到一个中心均值较低，只能描述这批纳入工单，不能直接证明工作人员造成了差异。

## 基础练习（可信起点）：入门跟做

### 1. 写问题和预计

在 `lesson-01/report.md` 写：使用者和决定；一行记录和时间范围；你预计哪组等待更长及理由。

**成功信号**：读者能知道比较对象、时期和分析单位。**反思**：如果改成按来访者分析，哪些工单会合并，分母会怎样改变？

### 2. 运行起点

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

打开 `lesson-01/artifacts/starting_overview.json` 的 `centers`。为一个中心写完整句子，包含登记数、已服务数、等待单位和分母。

**为什么**：输出是认识字段的起点，不是完整报告。**反思**：等待均值的分母是全部登记工单，还是已服务且等待有效的工单？放弃者为什么不能当作服务等待？

### 3. 手算小例子

三张已服务工单等待2、4、10分钟：均值为5.33，中位数为4；超过5分钟比例为1/3。把10改成30，均值变化明显而中位数不变，说明两者描述不同方面。

### 4. 做最小分析

围绕自己的问题增加一张分组表或图，保存到 `artifacts/`；报告按“观察事实—可能解释—限制”写三段。运行 `run` 和 `check`，确认数字能在结果文件中找到，原始数据没有被改写。

**反思**：图表是否写了记录数和单位？样本较少的组是否被过度解释？

## 入门反思

回看起始判断：你的统计量描述的是哪些工单，哪一种记录没有进入分母？把一条观察事实和一种可能解释分别写成两句话，确认两者没有混在一起。

## 标准任务（本课应完成）

在入门结果上完成 README 的五项任务。至少要有一个明确使用者和分析问题、数据检查记录、与问题相配的统计结果、一项实际计算过的替代统计口径或解释，以及能由程序重新生成的报告依据。

提交前用一句话回答：“替代方案改变了哪些记录或计算，结果变化是否足以修改建议？”只写“做了对比”还没有完成统计解释。

## 提高与拓展（提前完成后）

完成标准任务后，从 README 的提高菜单任选一项。可以按下面的顺序做：

1. 先写下要核对的原结论和预计；
2. 只增加一项有理由的分析，例如按业务类别分层、检查长尾或独立复算；
3. 列出新增分析的记录范围、每组记录数、单位和结果；
4. 明确写出原建议是保留、加条件还是改变。

例如选择“分层核对”时，应在相同业务类别内比较相同指标，而不是把一个中心的均值和另一个中心的比例放在一起。总体差异与分层差异不一致时，先报告业务构成可能影响比较；不要直接下因果结论。

选择“独立复算”时，第二种实现应重新从原始数据读取和汇总，不能只是复制第一段程序的输出。两个结果一致也有价值，因为它说明关键数字经过了独立核对；结果不一致时要保留查错记录。

## 卡住时按顺序排查

先回到仓库根目录，确认文件名和输出目录；数字不一致时查筛选条件、缺失和分母，不手改结果。

## 提交前自检

确认报告、结果文件和 `submission.json` 已按实际情况填写，再在仓库根目录运行：

```bash
python scripts/course.py run 01
python scripts/course.py check 01
```

`check` 通过后，再核对主要结论能在所列结果文件中找到。
