# 第1课支持路线：先描述清楚，再提出问题

## 你要留下的最小成果

一份报告、一段可运行程序、一张表或一幅图，以及能说明记录数、单位、分母和局限的文字。你不需要一开始就决定哪个中心最好。

## 先懂概念

- **观测单位**：一行记录描述的对象。本课通常是一张工单；同一个人有多张工单不能自动合并。
- **变量**：对象的属性，如等待分钟数、业务类型、是否放弃，必须连同含义和单位理解。
- **均值**：数值总和除以记录数，容易受很长等待影响。
- **中位数**：排序后中间位置的数，不是大多数记录都等于它。
- **比例**：某类记录数除以指定范围内的全部记录数；分母不同，回答的问题不同。

探索性分析的原理是先描述证据，再提出问题。看到一个中心均值较低，只能描述这批纳入工单，不能直接证明工作人员造成了差异。

## 入门跟做

### 1. 写问题和预计

在 `lesson-01/report.md` 写：使用者和决定；一行记录和时间范围；你预计哪组等待更长及理由。

**做对信号**：读者能知道比较对象、时期和分析单位。**反思**：如果改成按来访者分析，哪些工单会合并，分母会怎样改变？

### 2. 运行起点

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

打开 `artifacts/starting_overview.json` 的 `centers`。为一个中心写完整句子，包含登记数、已服务数、等待单位和分母。

**为什么**：输出是认识字段的起点，不是完整报告。**反思**：等待均值的分母是全部登记工单，还是已服务且等待有效的工单？放弃者为什么不能当作服务等待？

### 3. 手算小例子

三张已服务工单等待2、4、10分钟：均值为5.33，中位数为4；超过5分钟比例为1/3。把10改成30，均值变化明显而中位数不变，说明两者描述不同方面。

### 4. 做最小分析

围绕自己的问题增加一张分组表或图，保存到 `artifacts/`；报告按“观察事实—可能解释—限制”写三段。运行 `run` 和 `check`，确认数字能在结果文件中找到，原始数据没有被改写。

**反思**：图表是否写了记录数和单位？样本较少的组是否被过度解释？

## 标准与提高

标准完成要比较一个合理的替代口径，列出两种方案的记录范围、分母和结果。提高可以做分布图、稳健性比较、复现检查或面向另一类使用者重写建议；不以图和代码数量评价。

## 卡住和提交前检查

先回到仓库根目录，确认文件名和输出目录；数字不一致时查筛选条件、缺失和分母，不手改结果。提交前确认报告、结果文件、`submission.json` 和 `python scripts/course.py check 01` 都正确。
