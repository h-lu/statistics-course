# 第1课支持路线：服务数据的探索性分析

这份支持材料适合第一次做统计分析、还不知道从哪里开始的同学。它带你完成一个最小但完整的探索性分析：先确定问题，再认识数据，最后用一张表或一幅图支持结论。它不会替你选择“哪个中心最好”。

## 这课到底在学什么

- **观测单位**：一行记录描述的对象。本课通常把一张工单作为一个观测单位；同一个人有多张工单时，不能自动合并。
- **变量**：记录对象的属性，例如等待分钟数、业务类型、是否放弃。变量必须连同含义和单位理解。
- **算术平均数（均值）**：纳入记录的数值总和除以记录数。少数很长的等待会拉高均值。
- **中位数**：排序后处于中间位置的数。它描述位置，不是“大多数人恰好等于它”。
- **比例**：某类记录数除以指定范围内的全部记录数。分母不同，问题就不同。

探索性分析的原理是先描述已经观察到的记录，再提出值得验证的问题。看到中心A的均值较低，只能说这批纳入的工单平均等待较短；还不能直接说工作人员效率更高。

## 入门跟做

### 1. 先写问题，不要先画图

打开 `lesson-01/report.md`，写三句话：

1. 报告给谁看，他/她要决定什么；
2. 一行记录代表什么，时间范围是什么；
3. 你预计哪个业务、中心或群体的等待更长，理由是什么。

**为什么**：如果不先确定分析单位和用途，后面很容易把不同分母的数字放在一起比较。

**做对的信号**：别人读完三句话，能知道你要比较什么、比较谁、使用哪段数据。

**反思**：如果把“按工单”改成“按来访者”，哪些记录需要合并？结论会不会回答另一个问题？

### 2. 运行示例并认识输出

在仓库根目录运行：

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

打开 `lesson-01/artifacts/starting_overview.json`。找到 `centers`，查看每个中心的 `registered_tickets`、`served_n`、等待均值和中位数。

**为什么**：示例程序先给出一个起点，让你把字段名和统计含义对应起来。它不是完整报告，也没有替你检查另一种解释。

**做对的信号**：你能说出每个数字的记录数、单位和分母，并能区分登记工单数与已服务工单数。

**反思**：等待均值的分母是所有登记工单，还是已服务且等待有效的工单？放弃者为什么不能当成服务等待？

### 3. 手算一个小例子

假设三张已服务工单的等待时间是 2、4、10 分钟：

- 均值 = `(2+4+10)/3 = 5.33` 分钟；
- 中位数 = 排序后第二个数，即 4 分钟；
- 等待超过5分钟的比例 = `1/3 = 33.3%`。

先自己算，再在程序输出中找相同含义的结果。不要把中位数4解释成“多数人等了4分钟”。

**反思**：如果把10改成30，哪个统计量变化更明显？这说明为什么报告中不能只放一个中心数值？

### 4. 做一个最小分析

在 `analysis.py` 中围绕你的问题增加一张分组表或一幅图，保存到 `lesson-01/artifacts/`。报告中按“事实—解释—限制”写三段：事实引用结果文件，解释使用谨慎语言，限制说明数据没有记录什么。

运行并检查：

```bash
python scripts/course.py run 01
python scripts/course.py check 01
```

**做对的信号**：程序可重复运行，报告引用的数字能在结果文件中找到，原始CSV没有被改写。

**反思**：你的图表是否让读者看见记录数和单位？有没有因为某个中心样本较少就过度解读差异？


## 标准完成

在入门路线基础上，完成 README 中全部必做任务：实际比较一个有理由的替代方案，列出每种方案的记录范围、指标、分子、分母和单位；说明结果变化的原因；最后给出适用范围、限制和下一步行动。不能只说“结果不同”，也不能把相关关系写成因果关系。

## 提高与拓展

完成标准路线后任选一项：

- **方法比较**：比较两个目标相同但假设不同的方法，说明为什么选择其中一个；
- **敏感性分析**：改变一个有实际依据的阈值、分母、时间范围或处理规则，画表说明结果如何变化；
- **复现检查**：从原始数据重新生成主要结果，增加重复键、范围、单位或分母检查；
- **决策说明**：面向另一类使用者写一页简报，说明哪些结论可以发布、哪些需要限制。

提高不是增加代码数量。好的提高任务会让读者更清楚结果在什么条件下可靠。

## 卡住时按顺序排查

1. 先确认在能看到 `scripts`、`data` 和本课目录的仓库根目录；
2. 确认命令中的课次编号、文件名和输出目录没有写错；
3. 保留完整命令和最后一段报错，不要删除旧结果来“清理”问题；
4. 数字对不上时，依次核对观测单位、筛选条件、缺失值、分母、单位和输出目录；
5. 报告无从下手时，先填写“问题—数据—方法—结果—限制—建议”六个小标题。

如果程序暂时不能运行，可以先完成手算和报告草稿，但必须标明“尚未运行”，修复后再补跑并更新数字。
