# 第01课支持路线：第1课 · 服务数据的探索性分析

这份文件给还不知道从哪里开始的同学使用。它不是另一份作业，也不替你决定统计结论；请按“入门跟做”完成一条最小路线，再根据时间选择标准或提高任务。所有数字都要从本课程序和数据重新运行得到，不能把示例数字当成自己的结果。

## 先知道今天要交出什么

完成后，你至少应有：

- 一个用一句话写出的统计问题（谁要用、看哪些记录、要作什么决定）；
- 一次成功运行和一份能重新生成结果的程序；
- 一张表、一个图或一组能支持结论的计算结果；
- 一段说明分母、单位、数据范围、局限和下一步行动的报告。

本课任务可以先按下面顺序拆开：

1. **写出要回答的问题。** 说明报告给谁看、采用哪个时期的记录、按工单还是按人分析、比较什么。例如比较不同业务的等待时间，而不是笼统问“哪个中心最好”。
2. **检查数据。** 核对重复记录、缺失值、分类代码和时间单位。记录保留、排除的数量及理由，不因等待很长就自动删除。
3. **描述并比较。** 采用与问题相配的记录数、比例、均值、中位数、四分位数或其他分位数，并制作合适的图表或分组表。均值等概括数据的数值称为统计量；不适合所选变量的统计量不必硬算，但要说明原因。每组写清记录数、单位和比例分母。
4. **检查另一种合理解释或统计口径。** 统计口径指采用哪些记录、怎样定义和计算指标。 例如只报告已服务工单会遗漏谁，业务类型不同是否影响比较。能用现有数据核对的，应给出结果；不能核对的，说明还缺什么信息。
5. **写出结论和建议。** 区分已观察到的结果、可能的解释和需要继续验证的行动。不要把中心之间的差异直接写成工作人员造成的效果。

## 先懂四个概念，再开始操作

- **观测单位**：一行记录究竟描述谁或什么。本课通常把一张工单作为一个观测单位；同一个人有多张工单时，不能把几张工单自动合并成人。
- **变量**：记录对象的一个属性，例如等待分钟数、业务类型或是否放弃。变量要同时看取值、单位和含义，不能只看列名。
- **算术平均数（简称均值）**：把纳入记录的数值相加，再除以记录数。少数特别长的等待会把均值拉高。
- **中位数**：把数值从小到大排列后处在中间的位置。它描述“中间的一条记录”，不是大多数记录恰好等于这个数。
- **比例**：某类记录数除以声明范围内的全部记录数。分母决定比例回答的是谁的问题；已服务工单的放弃比例不能用全部登记工单的任意数量替代。

本课的基本原理是“先确定记录和问题，再计算数字”：同一份数据换一个观测单位、分母或时间范围，得到的数字可能都算对，但回答的是不同问题。

## 入门跟做：先让第一个结果出现

### 1. 写下问题和预计

打开 `lesson-01/report.md`，先不要追求完整，写三句话：

1. “我的使用者是……，他/她需要决定……”；
2. “我把一行记录看作……，分析范围是……”；
3. “我预计……，因为……；最可能改变这个预计的信息是……”。

这里的“预计”是运行前的可检验想法，不是最后结论。不会选问题时，直接使用 README 项目背景中的第一个问题，把范围缩小到一个数据表、一个时期和一个指标。

### 2. 在仓库根目录运行示例

仓库根目录是能同时看到 `scripts` 和 `lesson-01` 的目录。不要在 Python 的 `>>>` 后输入下面命令。电脑只有 `python3` 时，把 `python` 换成 `python3`。

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

运行成功后，打开 `lesson-01/artifacts/starting_overview.json` 或终端提示的结果文件。JSON 是按字段名保存的文本，不必一开始读懂所有字段；先找到与自己问题对应的一个数字，记下它的记录数、单位和分母。

### 3. 手算并核对一条

从输出中挑一条记录或一个小组，写出“原始值 → 处理 → 结果”的三步。至少核对一个加总、平均、比例、排序或分组数量。若结果是比例，明确写出分子和分母；若结果是平均数，写出参与计算的记录数；若是时间或金额，写单位。核对不一致时先检查路径、字段名、筛选条件和小数显示，不要手改结果文件。

### 4. 完成一个最小可交版本

根据 README 的任务，把 `analysis.py` 扩展到能回答自己的问题，把表、图或 JSON 结果保存到 `lesson-01/artifacts/`，再在报告中引用文件名。报告先写“观察到的事实”，然后分别写“可能解释”和“还不能证明什么”。

```bash
python scripts/course.py run 01
python scripts/course.py check 01
```

只有在报告、结果文件和 `submission.json` 都准备好后，才把 `status` 改为 `complete`。


## 入门跟做时怎样反思

每完成一步，先停下来回答一句：

- 写问题后：我的一行记录是谁？如果改成按人分析，分母和结论会怎样变化？
- 运行后：这个数字描述的是全部登记工单、已服务工单，还是某个中心？它的单位是什么？
- 手算后：我的计算分母与程序使用的记录数相同吗？缺失或放弃者是否被悄悄排除了？
- 写结论后：我观察到的是差异，还是已经证明某个中心或工作人员造成差异？还需要什么信息才能作因果解释？

## 标准完成：补上统计论证

在入门路线基础上，再完成三件事：

1. **替代口径。** 改变一个有理由的记录范围、阈值、分组或计算方法，实际运行两次，说明哪些结果变了、为什么变。
2. **证据链。** 让每个主要结论都能指向数据范围、程序步骤、结果文件和分母；把缺失、异常、未匹配或零分母单独说明。
3. **使用建议。** 写清楚可以采取什么行动、适用到哪些记录，什么情况应先补数据、限制使用或暂停发布。不要把相关关系直接写成因果关系。

## 提高与拓展：按自己的基础选择

不要为了“看起来复杂”堆方法。完成标准路线后任选一项：

- **方法拓展：** 比较两种统计方法或模型，说明目标量、假设、评价指标和适用条件；
- **稳健性拓展：** 改变一个关键假设、分母、阈值或时间范围，画出结果如何变化；
- **复现拓展：** 从原始数据重新生成全部主要表图，增加重复键、范围、单位或分母检查；
- **决策拓展：** 面向另一类使用者重写一页说明，明确哪些结论可以发布、哪些必须保留。

提高任务的评价依据是论证是否更可靠、边界是否写清楚，不是代码行数或图表数量。

## 卡住时按这个顺序排查

1. `不是 Git 仓库`：先 `cd` 到自己的仓库目录，再运行 `git status`。
2. `找不到文件`：确认当前目录能看到 `scripts`、`data` 和 `lesson-01`，不要在 `lesson-01` 内再重复拼路径。
3. 程序报错：保留完整命令和最后 20 行错误；先恢复最近一次能运行的版本，再一次只改一处。
4. 数字对不上：核对记录单位、筛选条件、缺失值、分母和输出目录；不要把旧目录结果当成新运行结果。
5. 不知道报告写什么：先填“问题—数据—方法—结果—限制—建议”六个小标题，每项写一两句，再补证据。

如果环境暂时不能运行，可以先按 README 和本支持文件完成手算与报告草稿，并明确标记“尚未运行”；修复环境后必须补跑并更新结果。

## 提交前自检

- [ ] 报告没有保留模板提示语，问题和使用者具体可辨；
- [ ] 结果文件确实由当前程序生成，原始数据未被覆盖；
- [ ] 每个比例写了分子、分母和单位；
- [ ] 结论区分观察事实、解释和行动建议；
- [ ] `submission.json` 的路径、命令和状态正确；
- [ ] 已运行 `python scripts/course.py check 01`，并检查 `git diff --cached`。

完成核心路线后，再进入教师指定的统计学知识自查场次。自查用于发现概念混淆，不能替代项目报告；不会的题可以标记不确定，先记录问题再学习。
