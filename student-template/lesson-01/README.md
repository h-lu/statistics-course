# 第1课 · 服务数据的探索性分析

**以下数据全部为教学合成数据，不代表真实机构、个人或实际效果。** 可以全程使用AI提出候选问题、编程、分析、写作和协助提交；你需要确认最终采用的选择，核对结果、依据和适用范围。无需提交AI对话或证明代码由谁输入。先阅读[知识准备](LEARN.md)，再展开正式分析。

## 你要解决什么问题

三个虚构服务中心准备召开改进会议，需要一份可复核的探索简报：这批已登记工单显示了什么，哪些现象值得关注，下一步需要核实什么。你可以研究等待、放弃排队、预约差异、业务办理，或提出其他有数据支持的问题；不预设必须给中心排名。

本课建立完整分析流程，**不计分，但须完成项目和自查**，不是只配置环境。入门成果在第二周开始前补齐，环境故障不扣分。

## 可用数据与统计对象

主表为 `data/service/tickets.csv`，含2026年3月2日至4月10日的3,600张已登记工单。`windows.csv` 提供窗口—中心对应，`business_types.csv` 提供业务含义；满意度、服务接触、排班可按问题选用。字段与限制见[服务数据说明](../data/service/README.md)，不要求使用全部表。

一张工单不一定是一个人。同一人可有多张工单；改按人分析时，应说明如何汇总个人经历。`wait_minutes` 止于开始服务或放弃离开；放弃者的等待不是获得服务所需的等待，`service_minutes` 空白也不是已完成0分钟服务。满意度表包含两期，选用时先限定第一期工单。

## 分析任务

1. **提出可回答的问题。** 写清报告使用者、时间范围、分析单位、结果变量和比较对象。例如比较本期已登记工单的等待分布，以决定优先核查哪类业务，而不是笼统评价“哪个中心最好”。
2. **检查数据与分母。** 核对重复、缺失、分类代码和单位，记录保留与排除的数量；不要把有效等待数、工单数和人数混写，不因等待很长就自动删除。
3. **描述分布并作有理由的比较。** 报告与问题相配的样本量和比例、均值、中位数、四分位数或其他分位数，以及合适的图表或分组表。说明各组 `n`、单位、筛选条件和缺失处理；统计量不适用于所选变量时解释原因，不为凑数计算无意义的均值。
4. **检查一种替代口径或解释。** 说明它是否改变主要发现及建议。例如仅报已服务等待会遗漏谁，业务构成是否限制中心比较。能用现有数据核对的就给结果；尚不能检验的，明确所缺信息，不伪称已经排除。
5. **形成三层结论。** 分开写观察事实、可能解释和待验证行动。指出下一步调查的对象或字段，不把关联当作中心或人员造成的效果。

## 成果与提交前自核

交付面向管理者的简报、支持结论的结果文件和可重跑程序。简报应包含问题与范围、筛选与分母、描述统计与图表、主要发现、替代口径或解释、局限性和具体下一步。

完成的简报能说清“哪些记录显示了什么”；进一步完善应解释聚合结果遗漏了谁，并据此改变核查建议，而不是增加图表数量。证据不足以排名时可暂不排名，但要给出具体依据。

## 90分钟建议安排

0—10分钟读背景与知识；10—20分钟确定问题、单位和比较；20—55分钟检查、描述和比较；55—68分钟核对替代解释并写简报；68—75分钟重跑、核对并提交；75—90分钟自查。复用通用工具，技术受阻时先形成问题和分析草稿，再按课堂故障安排补齐程序。

## 运行、核对与提交

以下“仓库根目录”指你自己的学生仓库中包含 `scripts/`、`data/` 的目录；在合并资料库中阅读时，对应 `student-template/`。先运行：

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

`analysis.py` 是可运行的数据概览，不是完整项目答案。按问题修改或替换它，将关键数值结果和图表写入本课 `artifacts/`，在 `report.md` 中引用。可以调整报告结构，不能只保留提示或粘贴默认输出。原始数据不改写；新增依赖写入 `requirements.txt`。

完成后，在本课 `submission.json` 中将 `status` 设为 `complete`，填写 `report`、支持结论的 `artifacts` 和非空命令参数列表 `run`。所有路径相对于学生仓库根目录。再执行：

```bash
python scripts/course.py run 01
python scripts/course.py check 01
git diff --check
git status
git diff
git add lesson-01 requirements.txt
git diff --cached
git commit -m "完成第01课项目"
git push
git tag v2-l01-final
git push origin v2-l01-final
```

**`run` 执行分析；`check` 只检查完成声明、路径和文件是否存在且非空，不会重新运行分析或判断结论。** 推送后查看 Actions 的重跑结果；配置了重现检查时，它会在临时副本移除所列结果文件、运行程序并比较内容。固定随机种子、排序和输出精度，避免将带生成时间的文件列入逐字节比较。程序运行成功和文件检查通过，都不等于统计解释正确。

新增共用程序也须核对后纳入提交。已有最终标签不要覆盖；修订保留原版本。网络、环境或检查故障时保存本地文件与提交，向教师说明，不把失败写成已通过。完整步骤见[项目工作流](../docs/WORKFLOW.md)和[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第1课。建议先作答A，再学习不熟悉的概念，完成B并阅读反馈；AI始终可用，无需提交对话记录。自查正确率用于反馈，不直接计分，详见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
