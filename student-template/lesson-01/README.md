# 第1课 · 服务数据的探索性分析

## 项目背景

三个虚构服务中心准备召开服务改进会议。负责人希望了解：现有数据反映了哪些值得关注的问题，分析依据是什么，还需要收集哪些信息。你获得了一期工单及相关登记，需要自行选择值得研究的问题；本课不预设结论。

## 可用数据

首先分析 `data/service/tickets.csv` 中的3,600张工单，并查阅 `windows.csv`、`business_types.csv`。可按问题需要连接调查或排班，但本课不要求用完所有表。字段含义与数据局限性见[数据说明](../data/service/README.md)。

本课数据均为教学合成数据，不代表真实机构。先阅读[知识准备](LEARN.md)，再选择分析方法。你可以全程使用AI完成代码、分析和写作；报告需解释主要结论的统计依据、适用条件和局限性。

## 分析任务

为改进会议撰写一份探索性分析报告，自主选择一个与服务改进有关的问题。你可以关注长等待集中在哪里、预约与非预约的体验差异、不同办理经历、办结与满意度是否一致，或提出其他有数据支持的问题。说明分析结果可以为哪项改进提供参考；至少比较一种可能改变结论解释的合理分析口径或替代解释。

### 必须遵守的约束

- 结论对象必须明确：工单、来访者、窗口还是日期；同一人可能多次出现。
- 放弃者的等待是离开前等待，不能默认为成功获得服务的等待；采用哪类记录要说清楚。
- 不根据中心名称、单张漂亮图或单一平均值直接评价工作人员。
- 描述性差异可以成为调查线索，不能直接证明增员、预约或某个中心造成效果。

### 由你决定

问题与使用者、分析单位、比较群体、图表及指标由你决定。可报告“尚不足以排序，但值得补采某类信息”；需要证据和明确的下一步，而不是泛泛地说数据有限。

## 成果要求

- 开头让使用者看懂：要回答什么、主要发现、建议下一步做什么。
- 关键数字能由程序重新计算，报告记录数据范围、分母和等待时间含义。
- 展示能支持分析结论的图或表，并解释一项合理替代口径或解释如何影响分析结论。
- 区分当前观察、可能解释和有待验证的行动效果。代码自动生成的表不等于完成简报。

在本目录的 `report.md` 中撰写分析报告，篇幅与结构可按问题需要调整。关键表、图或分析数据保存到 `artifacts/`，并在报告中引用。可以修改或替换 `analysis.py`；提供的示例代码只生成数据概览，不是本课的完整分析。

## 建议时间安排

0—10分钟阅读项目背景与知识准备；10—20分钟完成仓库和运行预检，同时选定问题；20—55分钟探索数据并分析结果；55—68分钟比较替代解释、撰写简报；68—75分钟核对并提交；75—90分钟知识自查。环境受阻时可先用浏览器中的CSV和AI生成报告草稿，再补齐可运行分析。

## 运行与提交

从仓库根目录运行：

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

完成报告和分析后，在 `submission.json` 填入支持报告结论的结果文件路径，将 `status` 改为 `complete`；如果更换运行入口，同步修改 `run`。运行 `python scripts/course.py check 01`，核对修改后提交并创建最终标签 `v2-l01-final`。完整步骤见[操作与提交步骤](../docs/WORKFLOW.md)。自动检查通过只说明文件、路径和运行命令符合提交要求，不代表统计结论正确。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面显示当日第1课，按当前场次作答。建议先自行判断，不会时请AI解释概念再作答；使用方式见[自查说明](../docs/KNOWLEDGE_CHECK.md)。
