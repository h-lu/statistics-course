# 第1课 · 服务数据的探索性分析

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

第一次使用这些资料时，可先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。

## 项目背景

三个虚构服务中心准备召开改进会议。管理者想知道：已经登记的办理记录反映了哪些问题，下一步应调查什么？你需要提交一份探索性分析报告，也就是先用数据描述现象，再提出值得进一步研究的问题。

本课不计分，但须完成项目和知识自查；入门成果在第二周开始前补齐，环境故障不扣分。第一课不仅是配置工具，也要完成一次有明确问题的分析。

## 可用数据

主要文件为 `data/service/tickets.csv`，包含2026年3月2日至4月10日的3,600张工单。一张工单是一笔服务办理记录；同一个人可能有多张工单。

`windows.csv` 说明窗口属于哪个中心，`business_types.csv` 说明业务类型。工单表没有直接给出中心名称：用工单的 `window_id` 在窗口表中找到相同编号，再读取 `center`；示例程序已经演示这一步。满意度、服务接触和排班资料可按问题选用，不必使用全部表。先查看[数据说明](../data/service/README.md)，再阅读[知识准备](LEARN.md)。

`wait_minutes` 是从开始排队到开始服务或放弃离开的时间。放弃者并未获得服务，不能把其等待解释为获得服务所需的时间；`service_minutes` 为空也不是服务了0分钟。使用满意度表时，要限定到第一期工单。

## 分析任务

1. **写出要回答的问题。** 说明报告给谁看、采用哪个时期的记录、按工单还是按人分析、比较什么。例如比较不同业务的等待时间，而不是笼统问“哪个中心最好”。
2. **检查数据。** 核对重复记录、缺失值、分类代码和时间单位。记录保留、排除的数量及理由，不因等待很长就自动删除。
3. **描述并比较。** 采用与问题相配的记录数、比例、均值、中位数、四分位数或其他分位数，并制作合适的图表或分组表。均值等概括数据的数值称为统计量；不适合所选变量的统计量不必硬算，但要说明原因。每组写清记录数、单位和比例分母。
4. **检查另一种合理解释或统计口径。** 统计口径指采用哪些记录、怎样定义和计算指标。 例如只报告已服务工单会遗漏谁，业务类型不同是否影响比较。能用现有数据核对的，应给出结果；不能核对的，说明还缺什么信息。
5. **写出结论和建议。** 区分已观察到的结果、可能的解释和需要继续验证的行动。不要把中心之间的差异直接写成工作人员造成的效果。

## 需要提交什么

提交分析报告、支持结论的图表或数值结果，以及能够重新运行的程序。报告应说明问题、范围、处理方法、主要发现、替代解释和下一步调查建议。

重点是说明“哪些记录显示了什么”。证据不足时可以不排名，但应说明理由。图表多不等于分析更好。

## 课堂安排

0—10分钟阅读背景与知识准备；10—20分钟确定问题；20—55分钟检查数据、描述和比较；55—68分钟核对解释并写报告；68—75分钟检查并提交；75—90分钟知识自查。技术受阻时先保留分析草稿，再按课堂安排补齐程序。

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`centers` 按中心列出登记工单数 `registered_tickets`、已服务工单数 `served_n`，以及已服务等待的均值和中位数。它还没有替你选择研究问题、分析等待分布或检查另一种解释。

先阅读输出中与你的问题有关的内容，再按上面的分析任务扩展程序。自己的计算结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。若使用完整课程资料库，先进入 `student-template/`。

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据本课问题修改或替换程序，将结果和图表保存到本课 `artifacts/` 文件夹，并在 `report.md` 中解释和引用。原始数据保持不变；程序使用的新软件包写入 `requirements.txt`。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起；更换程序时要相应更新命令。然后重新运行并检查：

```bash
python scripts/course.py run 01
python scripts/course.py check 01
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送到个人仓库，创建本课最终标签 `v2-l01-final`，再查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，但不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖，修改时保留原版本。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令、结果文件设置和修订办法见上述操作说明，评分见[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第1课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
