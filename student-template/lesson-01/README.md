# 第1课：服务数据的探索性分析

本课使用**教学合成数据**，不是真实机构或个人的记录。可以全程使用 AI 帮助学习、编程、分析和写作；问题、分析选择、结论与建议由你确定。先读本页，明确需要完成什么；遇到不熟悉的概念时查 [LEARN](LEARN.md)，操作或分析遇到困难时选择 [SUPPORT](SUPPORT.md) 中相关的提示。分析顺序和方法可自行安排。初次使用工具可查[阅读与运行指南](../docs/READING_GUIDE.md)。

## 情境与目标

三个虚构服务中心准备召开改进会议。你要写一份有实际用途的探索简报，帮助管理者决定优先核查哪些问题。**探索性分析**通过概括和展示已有数据，了解数值通常多大、怎样分布、各组有什么差异，并提出可继续核实的问题。例如，可以先描述上午和下午的等待差异，再考虑还需哪些资料来解释差异。你可以研究等待、时段、业务、预约、办结或其他有依据的问题，不要求宣布哪个中心最好。

## 可用资源

`data/service/tickets.csv` 包含 2026-03-02 至 2026-04-10 的 3,600 张登记工单。一张工单是一笔办理记录，同一个人可能有多张。`windows.csv` 对应窗口与中心，`business_types.csv` 解释业务类别；它们不是新的工单。满意度、接触和排班资料按问题选用，不要求全部使用。范围和字段见[数据说明](../data/service/README.md)。

`wait_minutes` 记录从开始排队到开始服务或放弃离开的时间，单位是分钟。对放弃者，这个值表示离开前等了多久；其 `service_minutes` 空白表示没有服务时长，不能填成服务了 0 分钟。使用其他表时，要将记录限定到与分析问题一致的工单或日期范围。

`analysis.py` 是可运行的示例程序，会生成 `lesson-01/artifacts/starting_overview.json`。这份概览列出各中心的登记工单数，以及已服务工单等待时间的均值和中位数。你可复用程序中的读表和统计函数，也可自写程序或使用其他软件。具体问题、合理备选方案和建议仍需自行分析。

## 三层任务

### 基础练习（可信起点）

任选一个关心的问题，从概览或自己的一项计算开始。至少核对一条原始记录或一项分组结果，把一项数字写成说明对象、时期和单位的句子；若是比例，还要说明分子和分母。区分观察事实、可能解释和待补充的信息。需要帮助时再查 SUPPORT。基础练习帮助你开始分析，不能替代标准任务。

### 标准任务（本课应完成）

提交有用途的探索简报、可运行程序和支持结论的表或图。成果需覆盖以下五项要求，可自行安排分析顺序：

- 说明报告给谁看、支持什么决定，采用哪个时期、比较什么。明确**分析单位**，即汇总结果针对工单还是来访者；同一个人有多张工单时，两种单位的结果可能不同。
- 检查重复记录、缺失值、分类代码和时间单位。缺失值是本应有却没有记录的信息；报告原始、保留、排除的记录数与理由，不为展示清洗而删记录。
- 选择适合问题的记录数、比例、均值、中位数、分位数或图表进行描述和比较。这些统计量的含义与小例子见 [LEARN](LEARN.md#必须理解的概念)。写清单位、分母与方法依据。
- 实际计算至少一种合理替代统计口径，或用数据检查另一种可能的解释。统计口径指纳入哪些记录、指标怎样定义和计算；例如，按工单和按来访者汇总可能回答不同问题。并列说明原分析和替代分析或检查的结果，以及它们对结论或建议的影响。备选须与问题有关，不要求得到反转。
- 分开写观察事实、可能解释和下一步调查；说明适用范围，中心差异不直接解释为工作人员造成的效果。

**至少两项重要决定由你作出：**第一，什么问题值得报告，以及采用什么单位和范围；第二，选择什么指标、怎样分组、用什么备选方案检验原结论。最终结论与行动建议也由你确定。问题、方法和排名没有预定的唯一答案；不同判断只要依据合理、可复核，同样可以成立。

### 提高与拓展（提前完成后）

在标准任务基础上，选择一项可能影响建议的新检查，也可自拟。可比较所有业务合并后的差异与同一业务内的差异，或比较通常的等待与少数特别长的等待；也可考察按工单和按个人汇总的不同权重、独立复算，或设计能区分两种可能解释的调查。这些是可选方向。说明为什么检查、增加了什么证据，以及结论应保留、补充条件还是改变。没有变化也报告检查范围；增加图表或重复运行本身不算深入分析。

## 证据自检与提交

报告中的主要数字能追溯到原始记录或程序生成的结果；每个计算的对象、单位和时期清楚，比例的分子分母明确；备选分析或解释检查已实际完成；原始 CSV 保持不变；结论没有超出资料取得范围。

在能看到 `scripts/`、`data/` 和 `lesson-01/` 的学生仓库根运行：

```bash
python3 scripts/course.py start 01
python3 scripts/course.py run 01
```

以上命令使用 `python3`；如果你的电脑用 `python` 运行 Python 3，可将命令中的 `python3` 换成 `python`。成功运行后应看到 `lesson-01/artifacts/starting_overview.json` 的路径，并能打开该文件。**仅提交这份概览还没有完成作业**，它不含你选定的问题、完整备选比较与结论。

将结果存到 `lesson-01/artifacts/`。在 `submission.json` 中，`report` 填实际报告路径，`artifacts` 填结果文件路径列表，`run` 填能重新生成这些结果的命令参数列表。路径从学生仓库根目录写起；完成标准任务后才把 `status` 设为 `complete`。

```bash
python3 scripts/course.py run 01
python3 scripts/course.py check 01
```

本地 `check` 只检查状态、路径和文件是否存在且非空，**不会重新运行分析**或判断统计质量。按[工作流](../docs/WORKFLOW.md)核对暂存内容并提交，使用 `v2-l01-final` 标签；修订保留旧标签。

[LEARN 的五组独立自检](LEARN.md#独立自检与迁移)供你检查理解，并在新情境中运用概念。课堂选择题按[知识自查说明](../docs/KNOWLEDGE_CHECK.md)进入 <https://hblu.top/stat-check/>，确认教师已开放当天第 1 课的场次；页面不可用时按课堂约定补做。
