# 第1课：服务数据的探索性分析

本课使用教学合成数据，即为了学习而生成的数据，不是真实机构或个人的记录。你可以使用 AI 帮助读代码、计算和写作，但提交前要自己核对记录、分母、单位和结论。

第一次使用这个仓库时，可以先看[阅读与运行指南](../docs/READING_GUIDE.md)。第一次做统计分析时，先读本课的[支持路线](SUPPORT.md)，再读[知识准备](LEARN.md)。支持路线会告诉你每一步做什么，知识准备解释为什么这样做。

## 先做一个小判断

在打开程序前，写下三句话：一行工单描述谁或什么？等待时间的单位是什么？“已服务工单平均等待”与“全部登记工单放弃比例”的分母相同吗？读完本课后回来检查答案。

## 项目背景与数据

三个虚构服务中心准备召开改进会议。管理者想知道已登记记录反映了哪些现象，下一步应调查什么。本课的**探索性分析**是先描述已经观察到的数据，再提出值得进一步核实的问题；它不是直接宣布哪个中心最好。

`data/service/tickets.csv` 包含2026年3月2日至4月10日的3,600张工单，一张工单是一笔服务办理记录，同一个人可能有多张工单。`windows.csv` 用 `window_id` 查中心，`business_types.csv` 用 `business_code` 查业务类型；它们是说明表，不是新的工单。满意度、接触和排班资料按问题选用，不要求全部使用。

`wait_minutes` 是从开始排队到开始服务或放弃离开的时间。放弃者没有获得服务，不能把等待解释成获得服务所需时间；`service_minutes` 为空也不是服务了0分钟。使用满意度时要限定到第一期工单。

## 分析任务

1. 写出报告给谁看、要决定什么、按工单还是按人分析、采用哪个时期、比较什么；
2. 检查重复记录、缺失值、分类代码和时间单位，记录保留和排除数量及理由；
3. 用与问题相配的记录数、比例、均值、中位数、分位数或图表描述并比较，写清单位和分母；
4. 实际比较一种合理的替代统计口径或解释，例如已服务记录与全部登记记录、不同业务构成或不同分组；
5. 区分观察事实、可能解释和下一步调查，不把中心差异直接写成工作人员造成的效果。

## 难度分层

下面三层按顺序使用。基础练习帮助你得到可信的分析起点，不能代替标准任务；标准任务是本课应完成的内容；提高与拓展供提前完成标准任务的同学继续研究。

### 基础练习（可信起点）

1. 运行起始程序，任选一个中心，把登记工单数、已服务工单数、等待均值和中位数改写成包含对象、单位和分母的完整句子；
2. 从原始数据中核对一个分组的记录数或一个统计量，记录你采用的筛选条件；
3. 写出一条观察事实、一种可能解释和一项需要补充调查的信息，三者不要混写。

完成这三项说明你已经读懂起始结果，可以继续正式分析；它们本身不等于完成本课。

### 标准任务（本课应完成）

完成上面的五项分析任务：明确使用者和分析问题，检查数据，选择合适的统计量或图表，实际比较一种合理的替代统计口径或解释，并形成可复现的报告和分析程序。这一层保留本课原有的课堂要求。

### 提高与拓展（提前完成后）

标准任务完成后任选一项，并把新增结果和它对建议的影响写进报告：

- **分层核对：**挑选报告中最重要的一项中心差异，按至少两个有业务意义的类别分别计算记录数和同一指标。判断总体差异在各类别内是否仍出现，并说明业务构成可能怎样影响总体结果；
- **长尾核对：**在均值和中位数之外，预先选定一个分位数或一个等待阈值，检查少数长等待是否会改变原建议。说明选择依据，不在看到结果后反复挑阈值；
- **独立复算：**使用另一段程序、另一种软件工具或从原始记录手工汇总，独立复算一个关键结果。若有差异，查明是筛选、缺失、分母还是算法造成的；
- **后续调查设计：**针对一种可能解释，写出要补记的变量、观测单位、目标人群、时间范围，以及不同调查结果会怎样改变行动。

提高不以图表、代码或文件数量评价。重点是新的检查是否真的检验了原结论，以及你是否据此修订了建议。

## 运行、修改和提交

在能看到 `scripts`、`data` 和 `lesson-01` 的仓库根目录运行：

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

`start` 只标记课程开始；`run` 生成 `lesson-01/artifacts/starting_overview.json`。其中 `centers` 给出登记数、已服务数、等待均值和中位数，但不是完整答案。修改 `analysis.py`，把支持结论的表、图或数据保存到 `lesson-01/artifacts/`，原始CSV保持不变。

仅提交这个概览还没有完成作业；你仍要完成数据检查、正式分析、替代统计口径或解释，以及报告中的结论边界。

填写 `submission.json` 的报告路径、结果列表和运行命令，真正完成后才把 `status` 改为 `complete`：

```bash
python scripts/course.py run 01
python scripts/course.py check 01
```

`check` 只检查文件和路径，不判断统计结论。按[操作与提交步骤](../docs/WORKFLOW.md)提交并创建 `v2-l01-final` 标签。最后完成教师指定的第1课知识自查。
