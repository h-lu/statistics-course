# 第1课：服务数据的探索性分析

## 你要解决什么问题

三个虚构的服务中心准备召开服务改进会议。管理者想知道：已有记录显示了什么，哪些现象值得进一步调查，下一步应该收集什么信息。

你的任务不是给三个中心简单排名，也不是找一个最“好看”的数字。你要像统计分析师一样，提出一个明确的问题，用数字和图表描述已经观察到的记录，并说明结论适用于哪些对象、时间和记录。

本课的核心问题是：**在这批已经登记的工单中，什么现象值得服务管理者关注？**你可以研究等待时间、放弃排队、预约与非预约的差异、不同业务的办理情况，或提出另一个有数据支持的问题。

## 先理解几个常用词

下面的词会在统计报告中反复出现。第一次遇到时，先把它理解成旁边的通俗解释。

| 统计术语 | 简单解释 | 本课中的例子 |
|---|---|---|
| 观测单位 | 数据表一行记录的对象 | `tickets.csv` 一行是一张工单，不一定是一个人 |
| 分析单位 | 你的结论真正针对的对象 | 可以是工单、来访者、窗口或日期 |
| 目标总体 | 你希望结论适用的全部对象 | 本期已登记工单、所有来访者或某类业务工单 |
| 变量 | 对象被记录的属性 | 等待分钟、中心、业务、预约状态、满意度 |
| 分类变量 | 用类别表示的变量 | 中心A/B/C、上午/下午、是否预约 |
| 数值变量 | 可以进行数值运算的变量 | 等待分钟、服务分钟；单位仍然是分钟 |
| 有序分类变量 | 类别有顺序，但相邻差距不一定相等 | 1—5级满意度；5不应自动当成1的五倍满意 |
| 描述性统计 | 用数字概括已经观察到的数据 | 样本量、比例、均值、中位数、分位数 |
| 分布 | 数据在不同取值上的集中、分散和尾部情况 | 等待时间是否右偏，是否有少数特别长的等待 |
| 关联 | 两个变量在记录中一起变化 | 下午记录的等待可能与上午不同 |
| 因果关系 | 改变一个因素会造成结果改变 | 改到下午是否会缩短同一类工单的等待；观察数据不能直接证明这一点 |

特别注意：同一个人可能有多张工单。按工单计算的平均等待，回答的是“每张工单平均等待多久”；它不是“每位来访者平均等待多久”。如果改用来访者作为分析单位，必须说明如何汇总同一人的多张工单。

## 可用数据

主要数据是 `data/service/tickets.csv`：2026年3月2日至4月10日的3,600张已登记工单。请同时查阅：

- `windows.csv`：窗口与服务中心的对应关系；
- `business_types.csv`：业务代码、业务名称和复杂程度；
- `satisfaction.csv`：调查邀请和1—5级体验评价；
- `visits.csv`：同一工单可能对应的多次服务接触；
- `staffing.csv`：窗口的计划排班。

字段定义、时间范围和数据局限性见[服务中心数据说明](../data/service/README.md)。本课数据是固定随机种子生成的教学合成数据，不代表真实学校、企业或个人，也不包含未取号的来访者。

`wait_minutes`表示进入队列到开始服务或放弃离开的分钟数。放弃者记录的是离开前等待，不能当成“已经获得服务的等待”；`service_minutes`为空也不是完成了0分钟服务。你采用哪些记录，必须在报告中写清楚。

## 分析任务：按步骤完成

### 1. 把问题写成可分析的句子

说明四件事：使用者是谁、分析单位是什么、结果变量是什么、比较范围是什么。

例如：“对第一期已登记工单，比较三个中心的等待时间分布，判断是否值得进一步核查排班和业务构成。”这比“分析哪个中心最好”更容易核对统计依据。

### 2. 先检查数据和分母

记录每一步保留了多少行（`n`，也就是有效观测数）、排除了什么，以及分母是什么。检查缺失值、重复记录、分类代码和等待时间单位；不要因为一个数很大就自动删除它。

### 3. 描述分布，而不只报一个平均数

至少报告与问题相配的几项指标：

- 样本量和比例；
- 均值（把总等待时间平均分摊到每张工单的结果）；
- 中位数（把等待时间从小到大排列后位于中间的值）；
- 四分位数或其他分位数，用来描述中部和尾部；
- 合适的图表，例如直方图、箱线图或分组表。

均值和中位数回答的问题不同。若少数工单等待特别久，均值可能明显高于中位数；这不是计算矛盾，而是数据分布有长尾的信号。

### 4. 做有理由的分组比较

比较两个或多个群体时，说明群体如何定义、每组的 `n`、指标和单位。不要只比较一张图，也不要把观察到的差异直接写成工作人员或中心造成的效果。业务复杂程度、预约比例、日期和重复来访都可能解释差异。

### 5. 把结论分成三层

- **观察到的事实**：在这批记录中，某组的中位数或放弃比例是多少；
- **可能的解释**：业务构成、时间安排或排班可能与差异有关；
- **需要验证的行动**：下一步应收集哪些变量，或做什么比较，才能判断改进措施是否有效。

## 必须遵守的边界

- 不把工单数量当作来访者人数；
- 不把放弃者的等待当作已完成服务的等待；
- 不根据中心名称、单张图或单一均值评价工作人员；
- 不把关联写成因果结论；
- 不要求所有数据表都必须使用，使用的表要说明用途；
- 如果证据不足以排序，可以建议暂不排名，并提出具体的数据收集计划。

## 报告应交付什么

在 `report.md` 中写一份面向管理者的探索性分析简报，至少包括：

1. 要回答的问题、分析单位、目标总体和时间范围；
2. 数据筛选规则、变量定义和各项分母；
3. 关键描述性统计和图表；
4. 主要发现及其统计依据；
5. 至少一个合理的替代口径或替代解释，以及它是否改变结论；
6. 结论的适用范围、局限性和下一步行动。

把支持结论的表、图或数据文件保存到 `artifacts/`，并在报告中引用。`analysis.py` 只提供数据读取和概览示例；你需要根据自己的问题修改或扩展它。

## 建议时间安排

0—10分钟阅读背景、数据说明和知识准备；10—20分钟确定问题与分析单位；20—55分钟检查数据、描述分布并完成比较；55—68分钟检查替代解释并写简报；68—75分钟核对文件和提交；75—90分钟完成知识自查。

## 运行与提交

从仓库根目录运行：

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

完成后，在 `submission.json` 中填写报告路径、支持结论的结果文件和运行命令，并将 `status` 改为 `complete`。运行 `python scripts/course.py check 01`，确认结果可以重新生成，再提交并创建最终标签 `v2-l01-final`。完整步骤见[操作与提交步骤](../docs/WORKFLOW.md)。自动检查只检查文件、路径和运行结果，不判断统计结论是否合理。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面显示第1课并按当前场次作答。不会的概念可以让AI解释，但请自己核对变量、分母和结论。
