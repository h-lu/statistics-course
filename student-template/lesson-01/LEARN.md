# 知识准备 · 从记录到有用的发现

## 必须理解：先说清数字描述谁

基础阅读建议7—10分钟。**观测单位**是记录所描述的对象；**分析单位**是结论针对的对象。本项目工单表一行一张工单，但不是所有表都“一行一个人”：接触表可有一工单多行，排班表按窗口日记录。

**变量**是记录的属性。等待分钟可作数值运算，中心和预约状态是分类变量，1—5级满意度是有序分类变量。类别编码看起来像数字，不意味着差距相等或5是1的五倍满意；采用平均评分需要说明解释及其限制。

**分布**描述数据的位置、分散和尾部。均值为有效值总和除以有效数；中位数为排序后的中间位置，偶数个值取中间两值的平均；分位数描述累计位置；四分位距IQR是第三与第一四分位数之差。比例要同时说明分子和分母。不要用一个均值代替整个分布，也不要把中位数称为大多数人的实际取值。

## 完整小例子：同样记录，不同分母

以下是另外构造的五张工单，不是正式项目数据。先判断有多少人、哪些等待止于获得服务，再看核算。

| 工单 | 来访者 | 队列中经过的分钟数 | 是否放弃 |
|---|---|---:|---:|
| E1 | P1 | 3 | 0 |
| E2 | P1 | 4 | 0 |
| E3 | P2 | 5 | 0 |
| E4 | P3 | 8 | 0 |
| E5 | P4 | 40 | 1 |

五张工单对应四个人。全部工单队列经过时间为60分钟，均值60/5=12，中位数5；四张已服务工单合计20分钟，均值20/4=5，中位数(4+5)/2=4.5；放弃比例1/5=20%。E5的40分钟止于离开，不能说它在40分钟后获得服务。P1贡献两张工单，按工单均值不能直接称为按人均值。

可以写：“四张已服务工单平均等待5分钟，另有一张等待40分钟后放弃，应进一步了解放弃经历。”不能写“所有人只需等5分钟”。后一句同时改变了单位、范围和结果含义。

## 描述、解释与因果

**描述性统计**概括已观察记录；**关联**是变量在记录中共同变化，**因果**则涉及改变因素会造成什么结果。下午记录等待较短，不直接证明把同一批人安排到下午就会缩短等待；业务复杂程度、预约、排班等可能同时影响比较组和结果。

**样本**是实际获得的资料，**目标总体**是希望描述的全部对象。第一期全部登记工单仍不含未取号来访者，也不自动代表其他月份。报告分开写观察事实、可能解释和待验证行动。

## 回到项目：提交前问自己

这张表的一行是什么，结论针对工单还是人？每个数字用了哪些记录、多少有效值、什么单位？放弃者和无评价工单去了哪里？一个合理替代口径或解释会改变哪一句结论？只用与你的问题有关的表，不必一次连接全部资料。

AI可以生成统计和图表，也可以提出候选问题；你要确认最终选择，核对结果与文字。可请AI用另一组记录解释分母，再检查自己的报告，无需保存对话。本课尚不要求置信区间或因果效果估计。

## 按需核算：五张工单的数字

下面只验证学习例子，不读取项目CSV；可以让AI逐步解释，也可以复制运行。不必为了核算而逐行背代码。

```python
# learning-example
import json
import statistics as st
rows = [("P1", 3, 0), ("P1", 4, 0), ("P2", 5, 0), ("P3", 8, 0), ("P4", 40, 1)]
all_wait = [r[1] for r in rows]
served = [r[1] for r in rows if r[2] == 0]
result = {"tickets": len(rows), "people": len({r[0] for r in rows}),
          "all_mean": st.mean(all_wait), "all_median": st.median(all_wait),
          "served_n": len(served), "served_mean": st.mean(served),
          "served_median": st.median(served), "abandon_rate": sum(r[2] for r in rows) / len(rows)}
print(json.dumps(result, ensure_ascii=False, allow_nan=False))
```
