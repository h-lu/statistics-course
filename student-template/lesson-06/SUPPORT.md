# 第6课支持路线：业务构成不同，怎样公平比较中心

先读[本课任务](README.md)，再按这里的步骤得到第一份可核对的结果；遇到概念时读[知识准备](LEARN.md)，最后回到 README 完成标准任务。

## 先知道今天要交出什么

报告写在 `lesson-06/report.md`，计算结果存入 `lesson-06/artifacts/`。需要交出各中心的实际办结比例和分层比例、两种共同业务构成下的结果、权重改变后的分析，以及给发布部门的建议。基础练习只帮助你起步，不能代替标准任务。

## 先做一个小判断

如果中心A承接的复杂业务更多，你预计它的合并办结比例会怎样？先写一句预测，再找数据核对；仅凭“复杂”二字不能判断哪个中心表现更好。

## 核心概念与原理

- **分析单位**是每次计算所数的对象。本课数登记工单，一张工单只算一次。**当日办结比例**的分子是当天办结的工单数，分母是全部登记工单数，包括未办结和放弃的工单。
- **合并比例**（也称边际比例）把常规、复杂业务合在一起计算；**分层比例**则先按业务类型分组，再在每组内部计算。两者回答的问题不同。
- **权重**是各类业务在指定构成中所占的份额，合计为1。**直接标准化**让所有中心用相同权重，对各自的分层比例加权；得到的是共同构成下的比较数。
- **辛普森悖论**指合并比较的方向与每一类业务内的比较方向相反。须先核对每类业务的分子、分母和构成，再判断有没有出现。

标准化结果不是中心实际发生的办结比例，也不能改写办结数；业务内部还可能有未记录的难度差异。

## 基础练习（可信起点）：入门跟做

### 1. 先预测，再运行

**动作：**在自己的学生仓库根目录运行；根目录是同时包含 `scripts/` 和 `data/` 的文件夹。

```bash
python scripts/course.py start 06
python scripts/course.py run 06
```

若终端提示找不到 `python`，改用 `python3`；若使用完整课程资料库，先进入 `student-template/`。**目的：**先取得原始计数，再检验你的预测。**成功信号：**终端显示 `lesson-06/artifacts/starting_overview.json`。**反思：**仅有这个输出，能直接判断哪个中心应排第一吗？

### 2. 核对一行，再扩展到一个中心

**动作：**打开输出文件的 `counts`，找到中心 A、`business_code` 为 `basic` 的一行。`basic` 表示常规业务，`case` 表示复杂业务；可到 `data/service/business_types.csv` 核对。`n` 是该组的登记工单数，`completed` 是其中当日办结数。计算 `completed ÷ n`。再找到 A 的 `case` 行，把两行的办结数相加，除以两行登记数之和。

**目的：**先核对分层比例，再从原始计数计算实际合并比例；不同大小的组不能直接平均百分比。**成功信号：**目前教学数据中，A 的常规业务是238张办结、252张登记，分层比例约94.44%；你还能算出 A 的复杂业务和全部业务比例。数据若不同，先检查是否读取本课第一期数据，不要照抄示例数。**反思：**94.44%能代表 A 的全部工单吗？直接平均两层百分比，相当于给两类业务怎样的权重？

### 3. 用小例子手算共同权重

**动作：**假设目标构成为复杂业务40%、常规业务60%，中心A复杂业务办结比例80%、常规业务90%，手算 `0.4×80%＋0.6×90%`，再读[知识准备](LEARN.md)中的 A、B 小例子。

**目的：**认识共同权重如何加权分层比例。**成功信号：**结果为86%，两类权重相加为100%；比较另一个中心时也使用同一组权重。**反思：**86%描述哪种假设构成？它能改变 A 实际的办结数吗？

## 入门反思

检查你是否能从“计数→分层比例→合并比例→共同构成下的比例”依次说明每一步的分母或权重；仍不明白时先核对[知识准备](LEARN.md)的数字。

## 标准任务（本课应完成）

### 4. 比较两种目标构成

**动作：**先把三个中心的复杂工单数相加，再除以三个中心全部登记工单数，得到本期全体工单的复杂业务权重；常规业务权重是1减去它。用这同一组权重分别加权三个中心的分层比例。另选一种有明确用途的共同构成，例如有依据的计划构成，或明说是假设的情境，再次对所有中心使用同一组权重。

**目的：**把实际办结情况和“如果业务构成相同”的比较分开回答。第二种构成要说明代表谁或用于什么判断，不能只为了得到想要的排序而选。**成功信号：**两种构成都写出常规、复杂权重和依据；每种构成下，每个中心都有标准化比例。用未四舍五入的分层比例计算，最后再显示小数。**反思：**本期全体工单的复杂业务权重，应由复杂工单总数除以全部工单总数，还是直接平均三个中心的复杂业务百分比？本期三个中心的工单数恰好相同，两种算法会碰巧相等；如果中心规模不同，还会相等吗？

### 5. 检查权重变化，再写发布建议

**动作：**比较两种共同构成下，至少一对中心的差异方向和大小；两个百分比相减，单位写“百分点”。只检查几个权重时，结论限于这些权重；想说明整个0到1的范围，就要依据两层差异的加权关系。随后在 `report.md` 分别写实际办结情况、同类业务比较、标准化比较和局限，提出怎样发布。可以拒绝单一排名，但不能省略计算。

**目的：**弄清排名或差距是否依赖所选构成，并防止把标准化值说成真实办结率。**成功信号：**报告能让读者看出每个结果回答的问题、使用的分母或共同权重、是否建议单一排名。**反思：**“检查的两个构成下方向相同”和“所有共同构成下方向相同”，需要一样的证据吗？

完成后对照 README：分层计数、两种共同构成、权重敏感性和发布建议都应有实际结果。`check` 通过只说明文件存在，不能判断共同权重和统计解释是否合理。

## 提高与拓展（提前完成后）

完成标准任务后，可任选一项：根据分层差异判断整个合理权重范围内方向能否改变；比较两个有明确使用者的目标构成；检查业务层缺失或记录较少时结论怎样限制；或独立复算分层计数与标准化结果。某中心没有某一业务层时，该层比例没有分母，不能填0或复制其他中心。先说明权重或范围的依据，再写新增结果是否改变发布建议。

## 卡住时按顺序排查

1. 找不到 `scripts/course.py`：先确认当前目录含 `scripts/` 和 `data/`；找不到 `python` 时试 `python3`。
2. 找不到输出：确认 `run 06` 执行成功，再打开 `lesson-06/artifacts/starting_overview.json`；改过程序要重新运行，避免看旧文件。
3. 数字对不上：依次核对业务代码、中心、`n`、`completed`、分母、权重，最后检查四舍五入。不要直接平均不同大小组的百分比。
4. 报告无从下手：按“实际结果→分层结果→共同构成→权重变化→发布建议”逐段写，每段说明分母或权重。
