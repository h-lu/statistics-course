## 先知道今天要交出什么

报告与计算应能区分实际、分层和共同构成结果，并解释构成与发布办法的取舍。文件结构自定，原始数据保留；满足 README 的证据要求即可。

## 核心概念与原理

合并比例用合计分子除以合计分母；分层比例在同类业务内算。直接标准化让所有中心使用同一组构成权重，得到共同目标下的比较值。它不改变实际办结数，也只调整已分层的因素。

## 基础练习（可信起点）：需要时选一项

**找不到可核对的数据。** 从学生仓库根目录运行：

```bash

```

打开 `lesson-06/artifacts/starting_overview.json`。动作的用途是取原始计数；成功信号是 `counts` 中中心、业务、`n`、`completed`、`rate`。反思：只看这张表，能直接决定用哪种共同构成吗？

**不懂合并与分层。** 核A常规层238÷252，再从两个层合计原始分子、分母。成功信号是常规层约94.44%，合并结果仍以全部登记数为分母。反思：平均两层百分比等于假设怎样的业务组合？

**不懂共同权重。** 先预测 LEARN 小表在复杂权重0.5与0.75下谁较高，再手算核对。成功信号是0.5下A75%、B65%，原始计数未改。反思：选择哪个构成，先要知道谁将使用结果？

## 入门反思

为“实际发生什么”“同类业务怎样”“共同构成下怎样”各写分母或权重。三个问题可以有不同答案，先分清目标再选择发布形式。

## 标准任务（本课应完成）：自己决定路线

默认程序只提供分层起点，不自动排列中心或生成全部比较。`load_counts()` 可读取核对后的计数；`weighted_rate(rates, weights)` 可按你提供的层比例与共同权重合并，正权重层为 `None` 时返回 `None`；`standardized(cells, case_weight)` 是当前两业务层的同一通用计算。你可复用或自行实现，不要求用指定函数。

至少自主决定两件会影响比较含义或建议的事，例如第二种构成代表谁、比较哪个范围、将差异视为多大才值得行动、是否采用单一排名。这些不是参数任填理由，而应由用途和资料支持，并实际比较合理备选。README 示例不限制其它方法。

不会判断权重稳定性时，可查 LEARN 的差值加权关系：两端点同号支持整个权重范围同向；仅算几个网格同向只支持这些点。不会处理缺层时，先区分正权重缺层与零权重层，再决定保留未知范围、限制共同有资料范围或采用有明确假设的估计。不同做法改变目标或增加假设，要比较后果。
