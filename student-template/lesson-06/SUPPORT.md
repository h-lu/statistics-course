本页按困难提供帮助，不要求照同一顺序完成。可以自行选构成、改比较方法、设计发布形式；LEARN 小例子用于学习，不是正式项目模板。

## 先知道今天要交出什么

报告与计算应能区分实际、分层和共同构成结果，并解释构成与发布办法的取舍。文件结构自定，原始数据保留；满足 README 的证据要求即可。

## 核心概念与原理

合并比例用合计分子除以合计分母；分层比例在同类业务内算。直接标准化让所有中心使用同一组构成权重，得到共同目标下的比较值。它不改变实际办结数，也只调整已分层的因素。

## 基础练习（可信起点）：需要时选一项

**找不到可核对的数据。** 从学生仓库根目录运行：

```bash
python3 scripts/course.py run 06
```

打开 `lesson-06/artifacts/starting_overview.json`，查看用于计算的原始计数。`counts` 中的 `center` 是中心，`business_code` 是业务代码；`basic` 表示常规业务，`case` 表示复杂业务。`n` 是该层登记工单数，`completed` 是当日办结数，`rate` 是 `completed ÷ n`。核对这些字段与计数后，你就有了可开始计算的资料。反思：只看这张表，能直接决定用哪种共同构成吗？

**不懂合并与分层。** 核对A中心常规层：238张当日办结工单除以252张登记工单，约为94.44%。再合计该中心两个业务层的办结数和登记数，计算合并比例；分母应仍是该中心全部登记工单数。反思：直接平均两层百分比，相当于让两类业务各占多少？

**不懂共同权重。** 先预测 LEARN 小表在复杂权重0.5与0.75下谁较高，再手算核对。成功信号是0.5下A75%、B65%，原始计数未改。反思：选择哪个构成，先要知道谁将使用结果？

## 入门反思

为“实际发生什么”“同类业务怎样”“共同构成下怎样”各写分母或权重。三个问题可以有不同答案，先分清目标再选择发布形式。

## 标准任务（本课应完成）：自己决定路线

默认程序只提供分层计数，不自动排列中心或生成全部比较。你可以复用以下通用函数，也可以自行实现，不要求使用指定函数：

- `load_counts()`：读取并核对分层计数。
- `weighted_rate(rates, weights)`：按你提供的分层比例 `rates` 与共同权重 `weights` 计算加权比例。`None` 表示比例未确定；若某层权重大于0而比例为 `None`，结果也为 `None`。
- `standardized(cells, weight)`：对常规、复杂两类业务作同样的加权计算；`cells` 保存各层结果，`weight` 是共同构成中复杂业务所占比例。

Python 中的 `None` 在 JSON 结果文件里显示为 `null`，表示没有可直接使用的数值，不是零。

至少自主决定两件会影响比较含义或建议的事，例如第二种构成代表谁、比较哪个范围、多大的差异才值得行动、是否采用单一排名。选择应由用途和资料支持，并实际比较合理备选，而不是任填参数后补写理由。README 示例不限制其它方法。

不会判断权重稳定性时，可查 LEARN 的差值加权关系。若复杂业务权重为0和1时，两中心差值都为正或都为负，可据此判断整个范围内的比较方向一致；只计算几个权重时，结论应限定到这些点。不会处理没有记录的业务层时，先查看它在共同构成中是否占有份额，再决定保留未知范围、只比较各中心都有资料的业务，或采用有明确假设的估计。不同做法可能改变目标或增加假设，要比较后果。
