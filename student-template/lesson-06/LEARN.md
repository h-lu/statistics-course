# 知识准备 · 比较之前先看构成

## 必须理解：合并比例隐含各自权重

基础阅读建议7—10分钟。**边际比例（合并比例）**是全部纳入记录的比例；**条件或分层比例**是在同一业务层的比例；**构成权重**是各层在目标集合中的份额。合并办结率应合计分子分母，或按各中心自身层内人数加权，不能简单平均百分比。

**直接标准化**让所有中心使用同一组非负、和为1的目标权重，回答共同构成下如何比较。**辛普森悖论**是合并方向与各层方向相反，提醒检查构成而不是立即判错。分层可改善特定维度的可比性，不保证记录了全部难度，标准化也不等于随机分配。

## 完整例子：实际、分层和共同构成

| 中心 | 常规办结/工单 | 复杂办结/工单 |
|---|---:|---:|
| A | 18/20 | 48/80 |
| B | 64/80 | 10/20 |

A常规90%、复杂60%，B常规80%、复杂50%，各层A均高。实际合并A为66/100=66%、B为74/100=74%，方向相反；A复杂业务占80%、B占20%。实际比例没有算错，只是业务组合不同。

共同常规/复杂各50%时，A为75%、B为65%；另设计划复杂占75%时，A为67.5%、B为57.5%。这些是共同目标构成下的比较值，不能改写原样本实际办结数；后一计划只是教学情境。

## 从两个权重点到整个范围

令w为共同复杂业务比例，0≤w≤1：

`R_A(w)=(1−w)×0.9+w×0.6`，`R_B(w)=(1−w)×0.8+w×0.5`。

两式相减恒为0.1，即10个百分点，故本例全范围内方向相同，无需制造反转。一般两层差值为 `(1−w)×常规层差+w×复杂层差`；若两层差异不同向，可判断有无零点。表格只检查了所列权重，线性关系可提供更广的论证，但不要求每人手推。

稳定仅针对这些分层率和共同构成；不自动推广到未来时期、未记录难度或干预效果。10个百分点是比例差，不等于相对增长10%。

## 数据支持与空层

层内办结率r=已知范围的办结数/该层工单数。正权重层没有工单时，率未定义，填0或100%都虚构信息。限制到共同有数据的层要说明目标改变，所有对象仍用同一组权重；不能各自删空层、各自归一化后仍称同构成比较。

用原计数计算、最后才四舍五入。只给一个中心换权重，不是共同标准化；根据标准化率反推实际计数也不成立。已登记未办结工单不能为提高默认办结比例随意排除。

## 回到项目与进一步学习

展示合并、分层、共同构成结果，至少选择当前总体与另一个有用途的共同构成，分析稳定性并写发布建议。拒绝单一排名也应给出实质比较。不预设方向必须变，也不以权重点或模型数量评价质量。

可让AI生成曲线或换情境解释权重，按需学习更细分层或回归；分层过细可能使单元没有数据。请核对目标和支持范围，无需交对话。

## 按需核算：计数与共同权重

```python
# learning-example
import json
counts = {"A": [(18, 20), (48, 80)], "B": [(64, 80), (10, 20)]}
rates = {c: [s/n for s, n in cells] for c, cells in counts.items()}
def standard(w):
    return {c: (1-w)*r[0]+w*r[1] for c, r in rates.items()}
result = {"actual": {c: sum(s for s,n in cells)/sum(n for s,n in cells) for c,cells in counts.items()},
          "w50": standard(.5), "w75": standard(.75),
          "endpoint_differences": [standard(w)["A"]-standard(w)["B"] for w in (0, 1)]}
print(json.dumps(result, ensure_ascii=False, allow_nan=False))
```
