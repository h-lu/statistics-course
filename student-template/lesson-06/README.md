# 第6课 · 业务构成不同的机构应如何比较

**以下数据全部为教学合成数据，不代表真实机构、个人或实际效果。** 可以全程使用AI提出候选问题、编程、分析、写作和协助提交；你需要确认最终采用的选择，核对结果、依据和适用范围。无需提交AI对话或证明代码由谁输入。先阅读[知识准备](LEARN.md)，再展开正式分析。

## 项目背景与数据

合作部门准备按当日办结率发布三个中心的比较，但复杂业务构成不同。你要审核比较的可比性，决定是否排序、附条件或改用分层展示。结果稳定也是有效发现，不预设必须反转。

使用第一期 `data/service/tickets.csv`、窗口与业务字典，见[数据说明](../data/service/README.md)。默认以登记工单为单位、办结状态为0/1；未当日办结和放弃工单仍属于默认分母，不为提高比例自动剔除。改变范围须说明目标也随之变化。

## 分析任务

1. **还原实际结果与构成。** 给出各中心办结数、登记数、业务分层分母与办结率。合并率按分子与分母合计，不把两层百分比简单平均。
2. **进行共同构成比较。** 对所有中心使用同一组非负且和为1的权重。至少比较当前全体业务构成与另一个有明确用途的共同构成；标明后者来自计划还是假设，不冒称观测事实。
3. **检查稳定性。** 展示差异的方向和大小随权重如何变化。可以使用表、曲线或两层差值公式；几个点只说明已检查点，两层同向时可进一步解释为何整个共同权重范围同向。无需为了完成任务制造反转或使用指定模型。
4. **形成发布版本。** 分别解释实际业务结果、同业务层内结果和共同构成比较。说明合并与分层方向是否相反及构成原因，不只贴“辛普森悖论”标签；决定单一顺序是否合适并说明剩余局限。

## 必须遵守的边界

共同权重代表哪个目标人群必须清楚；不能只给一个中心换权重，另一个仍用自身构成。使用原始分子分母计算，到展示时再四舍五入；比例差注明百分点，不与相对百分比变化混用。

某个正权重层没有数据，分层率未定义，不能填0、100%或直接复制另一中心的率。限制到共同有数据的层时，对所有中心使用相同的新目标并说明范围改变；模型补值需说明额外假设。

标准化率不是原样本实际办结率，不能反推后改写办结数。描述方向在指定权重下稳定，不证明未来仍如此，更不能识别调人、改名或制度干预的因果效果。

## 成果与提交前自核

交付分层计数表、共同权重与比较结果、稳定性分析、面向读者的发布文案和程序。拒绝排名不能免除合并、分层和标准化的实际比较；至少两个有含义的共同构成仍须完成。

进一步完善应解释稳定或变化的结构原因，量化差异并减少读者误解，而不是单纯增加权重点。成绩按[成果与评分](../docs/ASSESSMENT.md)。

## 90分钟建议安排

0—13分钟构成小例子；13—26分钟明确分母与目标；26—54分钟分层、标准化和稳定性；54—68分钟写发布说明；68—75分钟核对提交；75—90分钟自查。复用已有分组工具，不重做全部描述统计。

## 运行、核对与提交

以下“仓库根目录”指你自己的学生仓库中包含 `scripts/`、`data/` 的目录；在合并资料库中阅读时，对应 `student-template/`。先运行：

```bash
python scripts/course.py start 06
python scripts/course.py run 06
```

`analysis.py` 是可运行的数据概览，不是完整项目答案。按问题修改或替换它，将关键数值结果和图表写入本课 `artifacts/`，在 `report.md` 中引用。可以调整报告结构，不能只保留提示或粘贴默认输出。原始数据不改写；新增依赖写入 `requirements.txt`。

完成后，在本课 `submission.json` 中将 `status` 设为 `complete`，填写 `report`、支持结论的 `artifacts` 和非空命令参数列表 `run`。所有路径相对于学生仓库根目录。再执行：

```bash
python scripts/course.py run 06
python scripts/course.py check 06
git diff --check
git status
git diff
git add lesson-06 requirements.txt
git diff --cached
git commit -m "完成第06课项目"
git push
git tag v2-l06-final
git push origin v2-l06-final
```

**`run` 执行分析；`check` 只检查完成声明、路径和文件是否存在且非空，不会重新运行分析或判断结论。** 推送后查看 Actions 的重跑结果；配置了重现检查时，它会在临时副本移除所列结果文件、运行程序并比较内容。固定随机种子、排序和输出精度，避免将带生成时间的文件列入逐字节比较。程序运行成功和文件检查通过，都不等于统计解释正确。

新增共用程序也须核对后纳入提交。已有最终标签不要覆盖；修订保留原版本。网络、环境或检查故障时保存本地文件与提交，向教师说明，不把失败写成已通过。完整步骤见[项目工作流](../docs/WORKFLOW.md)和[成果与评分](../docs/ASSESSMENT.md)。
