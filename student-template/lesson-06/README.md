# 第6课 · 业务构成不同的机构应如何比较

发布部门要比较三个中心的当日办结情况。各中心承接的复杂业务比例不同，一个总体比例可能同时反映办理结果与业务构成。你要并列回答“实际发生什么”“同类业务怎样”“共同构成下怎样”，再决定怎样发布。

使用**教学合成数据**，不代表真实中心、工作人员或来访者。可以全程使用 AI，报告须说明比较对象、分母、权重和解释范围。

先用本页理解任务；按需要查 [SUPPORT](SUPPORT.md) 或 [LEARN](LEARN.md)，再按自己的路线完成标准任务。初次使用可读[阅读指南](../docs/READING_GUIDE.md)。

## 数据与比较对象

使用第一期 `data/service/tickets.csv`，以及 `windows.csv`、`business_types.csv`，见[数据说明](../data/service/README.md)。**分析单位**是登记工单，一张只算一次。**当日办结比例**是当日办结数除以全部登记工单数，分母保留未办结和放弃工单。改变范围可以，但须同时解释目标怎样改变。

**合并比例**把各类业务合在一起，用合计分子除以合计分母；**分层比例**在同类业务内部计算。**直接标准化**是给所有中心同一组业务构成权重，对各中心的分层比例加权，回答“按同一种构成比较会怎样”。这里不是将变量减均值除标准差。**权重**是每类业务在目标构成中所占的份额，均不小于零、合计为一。

## 基础练习（可信起点）

运行分层计数支架，核对一个中心的原始分子分母；用 LEARN 的小表手算合并与共同权重结果。能解释这两个数为什么不同，才返回完整比较；起始输出不代表标准任务已完成。

## 标准任务（本课应完成）：用途与证据要求

1. **保留实际结果与构成。** 列各中心登记、办结总数；列常规、复杂业务的工单数、办结数、分层比例与各自构成。用原始计数计算，最后再显示百分数；两个百分比相减使用“百分点”。解释合并比较和同类业务比较是否方向一致。
2. **比较两种有用途的共同构成。** 第一种采用本期所有工单的合计构成；第二种由明确使用者或计划情境决定，并注明是计划还是假设。各中心使用同一组权重。报告权重来源、标准化结果与它回答的问题，不能把标准化值称为中心实际办结比例，或据此改写实际办结数。
3. **说明方向与差距的稳定范围。** 对至少一对中心，检查共同复杂业务权重改变时差异方向和大小。两类业务的差值按相同权重加权；利用端点差值说明全范围方向，或清楚限定到已检查权重。方向不变也需解释差距会不会变化，不要求制造反转。
4. **比较一种合理发布办法。** 把单一实际排名，与并列分层结果、共同构成结果或带条件说明的排名相比较。说明哪种形式更符合读者用途、容易造成什么误解。可以拒绝单一排名，但仍需给完整计算。若合并方向与每一层相反，称为**辛普森悖论**，用计数和构成解释。
5. **交代公平比较的范围。** 共同权重只调整了所用业务类别，类别内部难度、人员与登记选择仍可能不同。检查是否存在零记录或很少记录的业务层；正权重层没有数据时不能直接计算完整标准化值，不能填零。说明目前结果适用于谁，以及还需要什么资料才能评价人员或制度的效果。

最低完整成果为分层计数、实际结果、两套权重与直接标准化、权重敏感性、两种发布办法的取舍和限制说明。拒绝排名、方向稳定或没有复杂模型，都可形成高质量成果。

路线、实现和呈现方式由你决定。至少自主作出两个会影响结果含义或使用建议的重要决定，说明依据并实际比较合理备选。上面的例子和下面的深入方向不是方法菜单，也不限定唯一结论。

## 提高与拓展（提前完成后）

可自行提出深入问题，说明新增证据是否改变发布或管理建议。以下仅是例子，也可以研究其它有依据的问题：

- **方向稳定，行动未必稳定。** 提出有用途的情境达标门槛，用分层比例算某中心在哪些共同权重下达到门槛。把“排名不变”与“是否达到要求”分开，门槛不得冒称统计学统一标准。
- **缺少业务层时能说什么。** 在另设情境中暂时缺少某中心复杂业务资料，比较限制到共同有资料的业务，和给缺层保留 0—1 范围两种办法。报告目标改变、范围宽度及是否还足以排序；不能当作正式数据事实。
- **细分业务是否更公平。** 提出需要新增的难度资料，说明细分如何可能减少构成差异，又如何增加稀疏或零记录组。制定可继续比较的条件，不用“层越多越公平”代替依据。

课后可把共同权重换成另一种明确目标，写给该使用者的一段发布说明，避免重复制作同一张表。

## 运行与提交

从学生仓库根目录（含 `scripts/` 与 `data/`）运行：

```bash
python3 scripts/course.py run 06
```

生成 `lesson-06/artifacts/starting_overview.json`，`counts` 保存各层的 `n`、`completed` 和 `rate`。可选通用计算帮助见 SUPPORT，全部使用 Python 3 标准库，可离线运行。可以修改或替换分析程序，原始数据保持不变。

完成后更新 `submission.json` 的状态、报告、结果列表及可复算命令。结果路径从学生仓库根目录写起；自行组织正式计算，不必把起始概览列为正式证据。

```bash
python3 scripts/course.py run 06
python3 scripts/course.py check 06
```

`check` 核对状态与文件，不评价权重和解释。保存版本的步骤见[WORKFLOW](../docs/WORKFLOW.md)，评分见[ASSESSMENT](../docs/ASSESSMENT.md)。已有标签不覆盖，修订另存。进入[知识自查](https://hblu.top/stat-check/)确认第 6 课，完成 A、学习、B 与反馈；离线先做 LEARN 的本地变式自检，线上记录仍以自查系统为准。
