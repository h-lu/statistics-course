# 第6课 · 业务构成不同的机构应如何比较

本课使用**教学合成数据**，即为学习而生成的数据，不是真实机构或个人的记录。你可以全程使用AI帮助理解概念、编程、分析和写作，但提交前要核对结果和结论。

第一次使用这些资料时，可先看[阅读材料与运行程序的小指南](../docs/READING_GUIDE.md)。

## 项目背景与数据

合作部门准备按当日办结比例比较三个中心，但各中心承接的复杂业务比例不同。你需要检查这种比较是否合适，并决定发布排名、补充条件，还是分别展示同类业务的结果。

使用第一期 `data/service/tickets.csv`、窗口和业务类型表，详见[数据说明](../data/service/README.md)。以登记工单为分析单位：一张已登记但未当日办结的工单仍应进入默认办结比例的分母，放弃者也不应为提高比例而随意剔除。

先阅读[知识准备](LEARN.md)，理解合并比例、分层比较和直接标准化。采用其他分析范围时，要说明结论针对的对象怎样改变。

## 分析任务

1. **计算实际结果与业务构成。** 列出各中心登记数、办结数，以及各业务类型的工单数和办结比例。合并比例用合计办结数除以合计工单数，不能简单平均不同大小组的百分比。
2. **进行直接标准化比较。** 用同一组业务构成权重计算各中心结果，权重均不小于0且合计为1。至少采用当前全体业务构成和另一个有明确用途的共同构成；说明后者是计划还是假设。当前全体中复杂业务的权重，等于所有纳入中心的复杂工单数之和除以全部工单数之和，常规业务权重为1减去这个比例。
3. **研究结果对权重的敏感性。** 报告权重变化时差异的方向和大小。可用表格、图或计算解释。若两层差异始终同向，可以说明为什么共同权重变化仍不会反转；不要求刻意找出反转。只计算几个权重时，结论应限于已检查的情况，除非另有完整理由。
4. **写出发布建议。** 区分当前实际办结情况、同类业务中的比较和共同构成下的结果。说明合并与分层方向是否不同及原因，而不是只贴“辛普森悖论”的名称。说明排名是否适当，还有哪些局限。

## 比较时需要注意

所有中心必须使用相同的目标构成。采用原始计数计算，最后再四舍五入；两个百分比相减的差异要用“个百分点”表示。

某层没有数据时，不能填0、100%或直接复制其他中心结果。限制到都有资料的业务类型时，应说明新范围，并仍对所有中心使用相同权重；通过模型估计缺少的比例，需要说明额外假设。

标准化结果不是原始记录的实际办结比例，不能用它改写办结数。业务构成调整后仍可能有其他难度差异，也不能据此断定调动工作人员会产生相同效果。

## 需要提交什么

提交分层计数表、共同权重及标准化结果、敏感性分析、面向读者的说明和可运行程序。至少比较两个有含义的共同构成。可以拒绝单一排名，但不能省略实际比较。

结论稳定与结论改变都可能有价值，重点是解释原因和适用范围。

## 课堂安排

0—13分钟阅读例子；13—26分钟明确分母与目标构成；26—54分钟比较和敏感性分析；54—68分钟写发布说明；68—75分钟检查提交；75—90分钟知识自查。

## 示例运行后，接下来做什么

初次运行会生成本课的 `artifacts/starting_overview.json`。JSON是一种按字段名保存结果的文本格式，可以用编辑器打开。终端打印的是文件位置，不是完整分析报告。

`counts` 每项对应一个中心的一类业务；`n` 是登记工单数，`completed` 是其中当日办结数。先用这两个数计算分层比例，再确定所有中心共用的权重。示例还没有完成直接标准化和敏感性分析。

先阅读输出中与你的问题有关的内容，再按上面的分析任务扩展程序。自己的计算结果可以另存文件；仅提交这个概览还没有完成作业。

## 运行与提交

在自己的学生仓库根目录运行命令，也就是包含 `scripts/` 和 `data/` 的文件夹。若使用完整课程资料库，先进入 `student-template/`。

```bash
python scripts/course.py start 06
python scripts/course.py run 06
```

`analysis.py` 只演示读取数据和简单统计，不是完整作业。根据本课问题修改或替换程序，将结果和图表保存到本课 `artifacts/` 文件夹，并在 `report.md` 中解释和引用。原始数据保持不变；程序使用的新软件包写入 `requirements.txt`。

完成后，在 `submission.json` 中将 `status` 改为 `complete`，填写报告路径 `report`、结果文件列表 `artifacts` 和运行命令 `run`。路径从学生仓库根目录写起；更换程序时要相应更新命令。然后重新运行并检查：

```bash
python scripts/course.py run 06
python scripts/course.py check 06
```

**`run` 执行程序；`check` 只检查完成状态、路径和文件是否存在且非空，不会重新运行分析，也不判断统计结论。** 按[操作与提交步骤](../docs/WORKFLOW.md)提交并推送到个人仓库，创建本课最终标签 `v2-l06-final`，再查看自动检查结果。自动检查可以核对程序能否重新生成所列结果，但不能代替对分母、方法和结论的判断。

已有最终标签不要覆盖，修改时保留原版本。遇到网络、环境或检查失败，保存本地文件和提交，并向教师说明。详细命令、结果文件设置和修订办法见上述操作说明，评分见[成果与评分](../docs/ASSESSMENT.md)。

最后约15分钟进入[知识自查](https://hblu.top/stat-check/)，确认页面为第6课。建议先完成A题，学习不熟悉的概念，再完成B题并阅读反馈。AI始终可用，不要求提交对话；正确率用于反馈，不直接计分。详见[知识自查说明](../docs/KNOWLEDGE_CHECK.md)。
