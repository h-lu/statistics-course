# 面向初学者的学生材料编写规范

制定日期：2026-09-19。适用于本课程所有面向学生的任务说明、知识准备、报告提示、示例程序说明、图表文字及自查反馈。本文供教师与课程编写助手使用，不作为学生的阅读任务。

## 1. 与现有规范的关系

编写或修改前，先读[课程设计标准](COURSE_DESIGN_STANDARD.md)、[课程总表](COURSE_MAP.md)、[术语与基础知识规范](TERMINOLOGY_AND_FOUNDATIONS.md)，再读本文。课程结构以总表为准，项目原则以课程设计标准为准，评分以[评分规则](GRADING.md)为准。本文补充学生材料的语言和组织要求，不另设课程、考核或发布制度。

修改一课时同时查看学生的 `README.md`、`LEARN.md`、`report.md`、有关数据说明和教师指导。先记录必须保留的任务，再修改表达，避免为了缩短文字而删除统计分析要求。

## 2. 写给谁看

默认读者第一次系统学习统计学，不能假定其已懂专业缩写、建模术语或软件开发流程。读者应能不依赖AI补讲，读懂本课必要概念、例子的计算和任务要求；AI仍可用于进一步解释和全部项目实现。

通俗不是把术语换成自创词，也不是只留下口号。采用“常见情境—规范术语—具体解释—完整例子—回到任务”的顺序。首次出现的关键概念要解释；复用前课知识时用一句话提醒，并在必要时链接前课。

## 3. 术语怎样选择

使用统计学社区、统计调查和通行教材采用的名称。优先核对国家统计学词汇标准及权威统计资料；新方法可参考原始论文或正式文档。一个术语有多个常见译名时，首次说明后选择一个贯穿课程。不要把课程用语偏好冒称为全行业唯一标准。

核心概念首次出现采用“中文名称＋简单解释＋本课例子”。英文与缩写仅在帮助查阅、理解软件输出或后文确实需要时给出。不能先写IQR、ECDF、FPR、MAR等缩写，再让学生自行查找含义。表格和图题也要遵守。

| 需要保留的区别 | 编写要求 |
|---|---|
| 总体、样本、已有记录 | 总体是研究对象的全体；样本由从总体中选取的部分单位组成。说明数据怎样取得，不把所有数据都叫随机样本，也不把某期全部登记记录说成覆盖所有可能人群。 |
| 观测单位、分析单位 | 用工单、来访者等具体对象解释。不能笼统规定所有表都“一行一个人”。 |
| 均值、中位数、分位数 | 首次写“算术平均数（简称均值）”；分位数用排序例子说明。计算方法存在不同约定时注明方法，不把一种算法说成唯一标准。 |
| 标准差、标准误 | 前者描述数据的离散程度，后者描述估计量的抽样变动。不可为了简短而统称“误差”。 |
| 统计口径、敏感性分析 | 说明纳入哪些记录、指标怎样定义和计算；敏感性分析要写明改变什么、有何理由、结果怎样变化。不要另造“口径闯关”等名称。 |
| 缺失值、无回答 | 缺失是信息未取得；无回答是调查对象未提供所需回答。未受邀与受邀后无回答须分开。课程统一用“无回答”，首次可说明也称“无应答”。 |
| 分层比较、直接标准化 | 用分层计数和共同权重解释。直接标准化不同于把变量减均值后除以标准差；不能只写含义不明的“标准化”。 |
| 假阳性率、假阴性率 | 同时给出中文含义与对应分母；不能只用含义可能不同的“误报率”“漏报率”。分母为零时说明不能计算，不填零。 |
| 比例差、相对变化 | 两个百分比相减用“个百分点”。比例从60%到70%增加10个百分点，相对增加约16.7%，两种量不可混用。 |
| 关联、因果关系 | 观察到的差异不自动证明干预效果；说明能够支持的结论及尚缺的条件，不用“不能证明因果”替代全部结果分析。 |

“主键”“一对多连接”等是必要的数据库术语，并非统计学自创概念。使用时解释它们与重复计数、均值或分母的关系，不让软件术语代替统计问题。

## 4. 句子、段落和标题

一段集中解释一件事。连续出现多个新概念时拆开，明确对象和动作，避免用斜线、箭头或缩写把完整句子压成提纲。标题直接说明读者要理解或完成什么。

先告诉学生可以怎样做，再解释常见错误及原因。保留必要限制，但不要整页都是“不能”“必须”。适用条件紧跟相关方法，不在前面堆积尚未学过的警告。

以下是表达示例，不是机械替换词表：

| 不宜直接给初学者的写法 | 建议写法 |
|---|---|
| 冻结规则后开展时间外评价 | 确定规则后不再调整，再用后14天的数据评价效果。 |
| 用开发回代结果证明有效 | 这批数据既用于制定规则，又用于评价规则，因此结果可能过于乐观。 |
| 检查连接基数与隐式加权 | 一张工单连接到三次接触后会出现三行。直接计算均值，就会把这张工单算三次。 |
| 交付证据并核对有效分母 | 提交分析报告和支持结论的计算结果，并说明每个比例以哪些记录为分母。 |
| 全登记队列经过时间 | 从开始排队到开始服务或放弃离开的时间。 |
| 分过程补采 | 分别考虑未受邀者和受邀后没有回答者，说明应优先向谁补充调查。 |

上述表达中有些是专业场景中的简称，问题是不适合未经解释就用于初学材料，不能一概宣布为错误术语。

## 5. 三类学生文档的分工

`README.md` 说明问题背景、数据、分析任务、需要提交的内容和操作步骤。必要的项目术语在本页简单解释，进一步知识链接到 `LEARN.md`。保留学生有意义的选择，不提供唯一方法或预填结论。

`README.md` 还要明确标出三层学习路线：基础练习先得到一份可核对的结果；标准任务列出本课应完成的主项目；提高与拓展面向提前完成者，深入方法、敏感性、复现或决策。三层不是三份相互重复的作业；基础练习不得写成“已完成本课”，提高任务也不得暗中包含原标准任务的必做内容。

`LEARN.md` 负责教会概念。核心阅读部分先解释本课少量必要概念，再完整计算一个小例子，最后说明怎样用于项目。基础阅读约7—10分钟是设计目标，不是未经试教即可宣称的结果。复杂公式、代码和额外方法放在明确标注的“按需阅读”部分，不能把主任务移为选做。

`SUPPORT.md` 是每课的陪做与排错路线。它从一个小例子或一条记录开始，对每个主要步骤写明动作、目的、成功信号和反思问题，再过渡到正式数据。它说明命令所在目录、输出路径、常见错误的排查顺序和提交前检查，但不提供正式项目的标准结论。

`report.md` 提供面向本课的写作问题，例如“这个比例的分母是什么”“换一种合理方法后结论是否改变”。不要复制教师评分表、写成已完成报告，或要求学生填满与问题无关的固定表格。

操作说明写清命令在哪个目录运行、会做什么、成功说明什么。运行程序、检查文件和评价统计结论是不同事情。基础正文不反复讲解Git内部、持续集成实现或课程维护过程；详细步骤可链接现有工作流。

## 6. 公式、例子和代码

先用中文说明计算什么，再给公式。紧邻公式解释所有符号、分母、单位和适用条件。概率和比例使用0到1还是百分数要保持一致。明确阈值是否包含等号、缺失怎样处理，以及并列值怎样处理。

小例子使用另设的简单数据，顺序为“先判断—列数据—逐步计算—解释结果—指出一个相关限制”。手算过程足够完整，不以程序输出替代解释。必要时用相同数字说明两个指标即使数值相同，分母也可能不同。

保留正式数据的原样，区分数据事实、教学情境假设和分析建议。情境给定的业务门槛不是统计学标准，合成数据的生成机制也不证明现实中的因果关系。

代码是可选的计算帮助，不是首次理解概念的前提。保留清晰注释和已使用的测试入口；修改文字后核对代码、表格和例子的数字一致。未测试的部分如实注明。

## 7. 每次修改的审校步骤

1. **核对任务。** 对照原任务、教师指导与评分，确认比较、假设分析、数据范围和提交要求没有被删减或暗中增加。
2. **逐段通读。** 检查每个新术语是否解释，是否把多个概念塞进一句，是否出现面向教师或维护者的文字。不能只做关键词替换。
3. **核算例子。** 重算分子、分母、单位、阈值及结论；说明通俗表达省略了什么，不能省略改变结论的条件。
4. **检查文件。** 核对标题、链接、字段名、命令、代码与报告提示，运行相关测试。文本检查和数值测试不能证明初学者一定读懂。
5. **记录修订。** 在提交说明或教师审核记录中写清修改范围、核验结果和未验证事项，不把审核记录塞进学生讲义。

发现不确定术语时，先核对来源再使用；缺少可靠依据时保留原意、改用完整中文解释，不创造新名词。AI生成内容与人工内容采用同一标准。
