# 第5课教学指导 · 有限复核名额下的告警策略

## 本课目标与前后衔接

把第4课“指标对应什么目标”推进到“在每日容量内选择行动”。学生交付的不是最高准确率，而是维护团队可以按日执行、能追溯成本与损失的复核规则。重点判断：分数、概率、损失和行动不是同一件事；减少漏报数量与减少漏报损失也不等价。

任务以[学生项目](../../student-template/lesson-05/README.md)为准，知识入口为[LEARN](../../student-template/lesson-05/LEARN.md)。AI可以完成编程、分析、写作与提交；教师评价规则和结论依据，不检查作者输入比例。本课计入模块一，完成与代表作质量均按[GRADING](../GRADING.md)，不增加考核或改变分值。

## 课前准备与运行

确认前42天用于制定规则，后14天用于确定规则后的评价；每日有90条设备记录，容量工作日20、周末15。学生可以看到全部文件，无需隐藏标签或课中分批发数据；评价要求是名单生成过程遵守信息时点。

从统计学仓库根目录运行：

## 90分钟组织与可观察进度

| 时间 | 学生工作 | 教师从成果中检查什么 |
|---|---|---|
| 0—13分钟 | 读情境，核算下方名单与损失例子 | 分数不是概率；两类错误各以谁为分母 |
| 13—24分钟 | 写目标、备选规则、并列办法和可用字段 | 名单规则是否能在不知道当天故障标签时执行 |
| 24—53分钟 | 开发比较，固定规则，评价后14天 | 先查一天容量，再查每日容量；开发与评价分开 |
| 53—68分钟 | 改变一个重要条件，写试运行建议 | 条件改变的是成本评价、规则参数还是实际名单 |
| 68—75分钟 | 重跑、核对结果与报告、提交 | 本地文件检查不等于统计质量通过 |
| 75—90分钟 | A题、概念学习、B题和反馈 | 即时正确率仅作反馈，不证明稳定掌握 |

进度通过草稿、名单和结果表了解，不要求逐人答辩。环境受阻时可先用小表核算、形成规则草案，再按现有故障规则补齐程序。时间不足优先复用读表和统计工具，不能取消备选比较、后期评价或条件变化分析；提前完成者深化真正影响建议的群体后果，不增加无关工作。

## 可直接讲解的完整例子

### 1. 在看到结果之前生成名单

以下为另设的教学小例子，不是正式数据或参考答案。同日4台设备，最多复核2台，均按每次复核成本3、故障损失100、可避免比例85%计算。

| 设备 | 行动前分数 | 行动后才知道的故障标记 |
|---|---:|---:|
| D1 | 80 | 1 |
| D2 | 40 | 0 |
| D3 | 40 | 1 |
| D4 | 20 | 0 |

教师先只展示前两列，规则定为“分数降序，同分按设备编号升序，最多2台”，选中D1、D2。再展示标签用于计算后果。不能看到D3故障后把并列规则改成优先D3，还称这一批是独立评估。

ECDF在40处为3/4：它表示分数不超过40的记录比例。采用“分数≥40”会选3台，超过容量；采用“分数>40”只选1台。分位数不能替代并列和名额分配规则。设备编号只是本例预先声明的确定性并列方法，不代表优先级具有业务意义。

### 2. 从名单到四格表、分母和总损失

此名单TP=1、FP=1、FN=1、TN=1。假阳性率为1/(1+1)=50%，假阴性率也为50%。本例复核名单中的无故障比例恰好也是50%，**数值相同不代表分母相同**。再用LEARN中的100条记录例子核对：TP=6、FP=14、FN=4、TN=76时，FPR=14/90≈15.56%，而名单中无故障比例为14/20=70%。

四台设备例子的损失为：漏报1×100＋真阳性剩余损失1×100×15%＋复核2×3＝121。不复核为2×100＝200。解释为“在给定85%效果假设下，对这些记录计算的损失减少79”，不能写成“实验证明降低79”。LEARN另一个例子采用80%，其580的结果不能直接搬到正式项目；同样的100条记录改成85%时，损失是550。

### 3. 解释分数与风险转换的区别

若有依据估计某设备故障概率为p，故障损失为L、复核成本为c，则本情境的期望净收益为 `p×0.85×L−c`，单位为教学成本单位。这里p不是风险分数除以100。排序只是可选路线；学生也可提出有理由的阈值或最低覆盖规则。不能因为还有名额就强迫复核负收益对象，也不能为了总损失更低而隐去长期不被覆盖的设备群体。

## 巡视、纠错与反馈

| 看到的问题 | 反馈与复核动作 |
|---|---|
| 只检查14天总复核数不超260 | 要求查看每日“选中数≤当天容量”，周末剩余名额不能借给工作日 |
| 把FP除以复核人数称FPR | 在四格表上圈出全部真实非故障记录；零分母标未定义，不填0 |
| 用后期标签计算风险再评估同一期 | 标为探索修订；不能继续称独立评估，不要求另建防作弊系统 |
| 开发期结果被称为逐日样本外表现 | 参考校准使用整个42天标签，开发回代不等于每天只用此前信息 |
| 敏感性只改85%这个数字，却不说明名单是否改变 | 分清固定名单重算后果、重新按新假设决策；都可做，但含义不同 |
| 总损失下降就宣布普遍改善 | 查看设备类别的覆盖、漏报和损失，说明最低保障或撤回条件 |

课末或下次开头选一段匿名文字，改写成“在哪个时期、哪些假设、哪类设备、哪些监测条件下试运行”。不要求学生口头证明自己没有使用AI。

## 知识、项目与自查对齐

ECDF对应阈值覆盖；分位数对应容量及并列；FPR与FNR分别对应真实非故障、真实故障分母；代价比较对应总损失与剩余风险。这五组概念沿用现行A/B自查。信息时点、后期使用记录和群体后果还须从项目成果检查，不能仅凭选择题答对确认。

## 评价与发布前六问

最低完成要求保持学生任务原意：可执行规则、一个有意义的备选、逐日容量检查、冻结后评价、分母明确的后果表、一项影响建议的条件变化，以及监测条件。高质量不是多加模型，而是能解释不同目标的代价、总体与群体的冲突，并据此修改适用范围或保障办法。条件变化不是仅供高分作品选做。

1. **谁使用、做什么？** 维护团队据规则生成下一周期每日复核名单。
2. **哪些选择开放？** 目标、优先级转换、同分处理、是否用满名额及覆盖保障，依据是成本、损失和容量。
3. **计算后仍需判断什么？** 风险估计与损失假设是否支持行动，历史表现能推广到哪里。
4. **知识在哪里使用？** 名单阈值、四格表分母、损失分解和后期评价；自查核对基础概念。
5. **合格与高质量怎样区分？** 前者完成上述论证，后者用敏感性和群体结果实质修订建议，不以数字恰好等于参考为准。
6. **推进了什么？** 从评价指标走向资源约束下的行动，复用第4课目标取舍，衔接第6课分组比较。
