从仓库根目录运行 `python instructor-guide/lesson-04/reference.py`；在教师目录可运行 `python lesson-04/reference.py`。独立学生仓库加 `--student-root /path/to/student-repository`。仅用标准库，输出JSON，不修改CSV。

## 一条完成项目的示范路线

[walkthrough.py](walkthrough.py)按字段说明独立实现，不导入reference.py，也不读取生成器中的潜在真值。运行：

```bash
python instructor-guide/lesson-04/walkthrough.py --output /tmp/lesson04-work
```

路径换成教师自己的结果目录。程序保存逐工单核对表、中心指标表、规则结果和模拟报告；不写进学生模板，不规定学生必须采用相同文件数量。

两套办法都公布中位数、P90、放弃数量与比例、业务构成及记录数，并明确只描述已登记范围。办法甲对已服务工单统一用15分钟，办法乙用业务15/30分钟；假设超时比例严格大于10%时先调查长等待。甲的调查组为A/B/C，乙为B。未触发只表示不满足这项条件，不称全面合格；调查组也不自动构成质量排名。

8%代表更重视及早发现并愿意承担更多核查，12%代表优先调查超时更集中的情形；二者只是用于检验建议的管理假设，不是数据估出的最优标准。按业务参考时间，8%和10%仍为B，12%为无；统一15分钟三种门槛均为A/B/C。评价不变也是有效敏感性结果，不要求制造反转。两套办法的比较已经涉及长等待阈值，额外门槛表是演练深化，不擅自增加学生任务数量。

## 小例子、综合分与使用限制

X=[4,5,5,6,40]、Y=[8,9,10,11,12]得到均值12/10、中位数5/10、四分位距1/2、超15分钟比例20%/0%。删除40后X均值5不是服务改善；40变80时中位数和四分位距不变，总等待增加40、均值增至20。总和与均值、数量与比例须分别说明记录数。

综合分选读例子为平均等待分钟数/10＋放弃比例，比例取0—1。12分钟和10%得到1.30；换成720秒后须除以600，仍为1.30。这只是说明尺度和取舍，并非推荐该权重；如不接受各项补偿，应另列门槛。分别报告指标、等级或条件排名同样可接受。

“放弃或超业务线”不包含全部服务质量。不同业务时间线没有固定各中心业务构成，不等于直接标准化，也不识别人员的因果效果。当前数据没有未登记申请与拒接记录，不能声称已经测出拒接率或排除了选择容易业务的可能。可以建议补记申请/受理/拒接并比较同类业务，但不能编造这些数据。

参考输入为已整理第一期。命令入口和复用函数都核查已知中心、0/1状态和有效非负等待；发现不符应提示核实，不能为凑齐结果静默删除。换成有未知状态的数据，应先明确能判断哪些事件及其分母；参考报错不意味着现实分析必须丢弃整张工单。

## 评价与核验

最低要求仍是明确使用者、可执行办法、日常与长等待结果、保留放弃/构成/记录数、实际替代比较与敏感性、可检查防范及调整条件。高质量能说明哪些建议依赖规则，哪些资料尚不能支持；不另设分数上限，不按模型、图数或是否选A为第一评价。

一页指规则摘要，不是把完整证据挤成一页。详见[教学指导](RUNBOOK.md)和[专项审核](REVIEW_FULL.md)。程序测试与模拟解题不证明真实学生已经理解或能在90分钟内完成。已发布r2十题保留原样；新增讲解及测试不修改历史答案。
