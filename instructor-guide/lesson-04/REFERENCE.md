# 第4课参考分析与评价要点 · 设计服务质量评价办法

本文件用于判断证据与结论是否相配，不是唯一答案。学生可全程使用AI；不按代码由谁输入评分，不因结论与参考不同自动扣分。

## 可重复计算

从本仓库根目录运行（Python 3.10或以上、仅标准库）：

```bash
python instructor-guide/lesson-04/reference.py
```

也可从 `instructor-guide/` 运行 `python lesson-04/reference.py`。使用独立学生仓库时传入 `--student-root /path/to/student-repository`；显式路径无效时不会悄悄改读其他数据。默认先定位本仓库的 `student-template/`，再兼容原有相邻目录。输出为标准输出上的JSON；需要保存时重定向到教师自己的结果目录，不修改学生数据。

共享读取与统计函数位于第1课 `reference.py`。分位数采用线性插值 `(n−1)p`；`std_n` 用分母n描述已有记录，不是标准误；空集合的统计量或零分母比例返回JSON的 `null`，不是0。结果带有教学合成数据标记。

## 固定数据下的核对证据

已服务超15分钟比例A=29.2241%、B=20.3735%、C=28.1570%，顺序B、C、A（低好）；按常规15/复杂30参考线则A=5.8621%、B=10.9508%、C=7.6792%，顺序A、C、B。把放弃或超过业务线都记为不良经历，全登记比例A=9.0000%、B=12.5833%、C=9.8333%。

数值按固定生成种子核算，显示时允许合理四舍五入。学生若选不同对象、变量定义或指标，不应强行匹配这些数字；应追查其分子分母、规则和输入是否支持所报结果。

## 指标规则、分母与并列

`served_over15_count / n`的阈值为严格大于15分钟；`served_over_business_line_count / n`按常规15、复杂30分钟比较，恰好等于阈值不算超过。两项n均为已服务工单数。`registered_bad_experience_count / registered`把放弃或超业务线记一次，不重复累加既放弃又超时的工单。

“不良经历”只是参考声明的复合定义，不涵盖满意度等全部质量维度。业务等待线也只是情境约定，不等于共同业务权重标准化，不说明哪一个中心具有因果上的能力优势。

排序仅描述本批观测。`lower_is_better_tiers`把精确相同的数值放在同一组；零分母的指标列入`undefined_centers`，不参加排序。原有`lower_is_better_orders`保留为展平显示，组内顺序不代表优劣；它也不是统计显著性检验。若使用者希望把接近的数值视为并列，需另行预先说明业务容差，不能通过四舍五入暗中改变规则。

## 可接受的分析方法

可做多指标面板、底线+等级、明确价值权重的综合分；不要求合成单一排名。采用业务不同等待线与共同分层标准化不是同一方法，应解释前者是对业务目标的政策约定。

## 解释结果时应说明的适用条件与局限性

参考数字故意展示制度后果，并非教师偏好A的理由。放弃者排除会改变目标人群；IQR小不表示尾部受保护；删除最慢记录必须有测量或目标依据，不能仅为稳健而掩盖服务经历。

## 如何区分质量

合格需可执行规则、尾部处理、另一套评价办法后果和防护；高质量呈现哪些结论依赖规则，并设计防止删难例或拒接的可检查办法。

先检查报告是否回答分析问题、关键数字能否重新计算，以及备选分析是否实际影响结论解释，再按[统一评分规则](../GRADING.md)评价；只有被选为模块代表作品时才评代表作品质量分，不擅自增加分值上限或扣分项目。绘图数量、模型数量与界面复杂度不单独加分。对统计上合理的暂缓发布、补充调查或不进行排名的建议同样认可；缺少证据的“各种情况都有可能”不构成充分结论。
