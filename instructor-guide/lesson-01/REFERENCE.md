# 第1课参考分析与评价要点 · 服务数据的探索性分析

本文件用于判断证据与结论是否相配，不是唯一答案。学生可全程使用AI；不按代码由谁输入评分，不因结论与参考不同自动扣分。

## 可重复计算

从本仓库根目录运行（Python 3.10或以上、仅标准库）：

```bash
python instructor-guide/lesson-01/reference.py
```

也可从 `instructor-guide/` 运行 `python lesson-01/reference.py`。使用独立学生仓库时传入 `--student-root /path/to/student-repository`；显式路径无效时不会悄悄改读其他数据。默认先定位本仓库的 `student-template/`，再兼容原有相邻目录。输出为标准输出上的JSON；需要保存时重定向到教师自己的结果目录，不修改学生数据。

共享读取与统计函数位于第1课 `reference.py`。分位数采用线性插值 `(n−1)p`；`std_n` 用分母n描述已有记录，不是标准误；空集合的统计量或零分母比例返回JSON的 `null`，不是0。结果带有教学合成数据标记。

## 固定数据下的核对证据

第一期3,600张工单、1,986个来访者编号；各中心1,200张。放弃数A=40、B=22、C=28。已服务等待均值A=13.4813、B=11.4885、C=12.6741分钟；上午14.0578、下午9.9360分钟。

数值按固定生成种子核算，显示时允许合理四舍五入。学生若选不同对象、变量定义或指标，不应强行匹配这些数字；应追查其分子分母、规则和输入是否支持所报结果。

## 逐项核对分母

`registered`是本中心工单数；`served_wait.n`是未放弃且进入该等待描述的工单数；二者之差应等于`abandoned`。`same_day_completed / registered`对应办结比例，`abandoned / registered`对应放弃比例。中心内的`unique_people`不能直接相加作为全体去重人数，同一人可能在不同中心出现。

参考选择“已服务等待”不是建议隐去放弃者。正式报告可以选择全登记的队列经过时间，但必须写明它混合了开始服务与放弃离开两种终点；来访者均值还必须声明如何汇总同一人的多张工单。探索发现、原因解释和待核实行动应分别评价，不要求本课另做显著性检验。

## 可接受的分析方法

可以从尾部等待、时间安排、预约差异或办结—满意度关系切入。不同路线不必报告上述全部数字。若使用来访者为分析单位，应先汇总其多张工单，并说明这与工单体验目标的差别。

## 解释结果时应说明的适用条件与局限性

“上午已服务记录平均等待更长”有描述证据；“改到下午必然缩短同一人的等待”没有被当前设计识别。建议补充人流或业务难度信息是可以使用的成果，但应指出具体缺口。

## 如何区分质量

合格是有用途分析结论、可重复运行证据及实质替代解释；高质量会揭示聚合遗漏、把下一步核实落实到变量与对象。

先检查报告是否回答分析问题、关键数字能否重新计算，以及备选分析是否实际影响结论解释，再参照[统一评分维度](../GRADING.md)给出形成性反馈。本课为不计分的入门项目，不据此另加完成分或作品分。绘图数量、模型数量与界面复杂度不单独加分。对统计上合理的暂缓发布、补充调查或不进行排名的建议同样认可；缺少证据的“各种情况都有可能”不构成充分结论。
