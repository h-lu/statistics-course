## 原文、卡点与影响

1. 根README原文：“已发布但本地还没有的第1–8课”“第9–32课的大纲占位不会同步、运行或发布。”与本课start/run09冲突。独立代理需读工具源码并实际运行才能排除；已修为本地1–14可用、只有实际发布内容能同步、15–32仍占位，补入新数据目录。
2. 原LEARN已有“预计查出r×p台故障；全部故障数减去查出数就是预计未发现故障数”；数据说明已有“预算只计初筛”“复核每台成本3”“复核无误”。概念没有缺失，但频数小例到正式分组预算政策的连接分散，AI补建了可行筛查组合、先预留后排序、名额随情境重算和多行证据表。原默认程序成功本身不能完成这些判断。
3. 原任务“执行名额仍取整数；不能复核超过预计阳性数”遇到67.5阳性产生67/68与现场执行歧义。两次试做独立采用向下取整，并明确这是静态期望规划近似，不能冒称每日动态政策的精确期望。原教师REFERENCE虽已有边界，但学生当时看不到。已把规划/实际人数区别放入学生任务，教师RUNBOOK及总表L09对应句同步。
4. “数字追溯到随机种子”容易诱使确定性任务硬加模拟，已补“如有随机抽取”。跨情境保持的是规则，名额按新风险重算，现明确写出。

## 两项决定的实际后果

主代理先固定2×2政策，再代入低/基准/高基础率。以给定损失为目标，推荐两组sensitive、按每名额可避免损失排序；选择routine至少40作为有服务用途的备选，不是声称40由概率唯一决定。独立代理先定30作另一个合理备选。两者的推荐与共同方案数值一致。

基准：sensitive+损失排序预计未发现19.1542台、未发现损失1362.5871、总成本3132.5871。priority改precise后未发现18.0912台，但损失1503.4513，总成本3773.4513；“少漏台数”与“少损失”不等价。保留routine40将其复核由23增40，损失增加859.3035；保留30增加353.8308。低情境保障可能不改变结果，高情境代价更明显，不能要求每种选择在每个情境都不同。

一份能运行、可提交的作品已经完成，但理解证据只限于文本能正确解释：18/67的分母、复核23×18/67、未复核阳性如何漏掉、同一性能为何不同PPV、以及服务保障为什么需要业务理由。不能由AI生成这些解释推断普通学生本人已经理解。

## 最小修订与教师目标对照

只补一个20台、两组各10台、敏感度50%/特异度75%、4个复核名额的另设微例，放LEARN，README/SUPPORT作可选链接；analysis.py可重算。它连续给出预算、频数、PPV、组内随机复核、两类未发现、损失与保障代价。示范只比较“甲1乙3”和“甲0乙4”，没有搜索正式政策，也没有填正式1500台项目答案。教师开场仍10分钟，微例供有需要者阅读，不要求再集中长讲。

修改后同一独立代理仅重读学生文字，明确作为第二轮而非第一次盲读。它独立核对甲/乙PPV=1/3、3/4，首政策未发现65/12=5.4167，第二政策5，代价5/12；确认预算20与复核12分开，整数边界清楚、没有新增提交负担或标准答案泄漏。新analysis数值另实际运行并核验。

试做结束后对照教师目标：两个选择、公平比较、条件方向、完整未发现口径与限制均能在作品中落实；标准任务不要求全局优化，90是给定约束，第10课才模拟随机需求与容量。全部正式作品只存教师核验目录，学生模板保持not_started和空artifacts声明。学生仍可选择其他政策、工具、不同结论或暂缓。
