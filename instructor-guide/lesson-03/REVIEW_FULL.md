## 审核范围与方法

顺读学生README、LEARN、report、analysis.py、示例输出与submission.json，核对服务数据说明、相关操作和评分约定；随后检查本课RUNBOOK、REFERENCE、reference.py及两处现行r2题库。依据根目录和教师AGENTS指定的四份现行规范。原始数据、主项目、分值、AI使用原则及提交状态不变。

模拟读者会基本算术，读过前两课，但没有系统学过统计学。先将讲义转换成明确的处理步骤，做手算，再独立编写一次实际项目解答，最后逐题求解A/B并检查网页流程。这里的“学生疑问”是对文本的模拟，不是采集的学生原话。同一助手参与过前版编写，不能声称独立盲评；程序通过也不证明真实学生能在90分钟完成。

## 冷读发现与同步修订

| 阅读或操作节点 | 模拟疑问／确认的问题 | 处理 |
|---|---|---|
| 认识单位 | 同一个人重复出现，是否也应去重？ | 先解释本课按工单分析，不按来访者删掉真实不同工单；区分原始导出与整理后的主键。 |
| 判断数据有效 | 有内容就算完整吗？空白是否都要补？ | 区分缺失、无效取值、离群值和不适用的服务时长；解释查字典、单位与二元状态。 |
| 处理顺序 | 可以先统一单位再找999吗？去掉副本是否等于删掉工单？ | 用完整五行例子先识别重复和版本，再解释缺失编码与单位；明确去掉导出副本与排除某项计算不同。 |
| 选择指标 | 窗口缺失后能否保留办结？工作量就是人数或工时吗？ | 逐用途列出所需字段、有效集合、分母和范围；窗口工单数量不代表实际劳动时间。 |
| 比较方案 | 学生举例要求三项信息，教师参考为什么给出另一个分母？ | 新增三项信息的实际参考结果；保留原五项信息结果但逐一列清要求，不再只写“完整案例”。 |
| 阅读代码 | 增加一列空白备注会不会改变分母？ | 学习代码由遍历所有values改为明确的required_fields；加入回归验证无关字段不改变结果。 |
| 写报告 | 所有用途都必须做插补，或得到排名反转吗？ | 保留至少两个用途、一种合理替代处理；说明比较至少一个指标即可，插补可选，结果不变也须解释。 |
| 数量核对 | 原始45行秒记录为何只有42次转换？43个问题是否是43张工单？ | 说明原始行和最新工单的区别、问题可以重叠，补实际核算。 |
| 运行起点 | import就写文件，空编号也算一个工单；缺列可能误导检查。 | 学生程序拆为read/build_overview/main，增加必要列与空编号检查；仍只是概览，不自动完成项目。 |
| 参考解析 | 办结状态2是否只是“没有记录”？ | 明确missing与invalid的不同标记，均不作为有效二元结果，不猜填0。 |
| 课末选择题 | “登记等待”和未讲解的图形界限是什么意思？ | 新r3题干用具体等待定义，取消依赖箱线图界限的错误选项；补齐记录、分母和条件。 |

## 已完成的学习练习

五行例子：R1取第2版，180秒＝3分钟；R2的999为未测量；R3保留60分钟。5行＝3张工单＋1行完全重复＋1行旧版本。三张均未放弃这一条件已在题前说明。

已服务且有测量的平均等待为(3＋60)/2＝31.5分钟；办结比例为2/3；已确认属于A1的为2张，另1张窗口未知。若同时要求等待、办结、窗口有效，办结比例为1/2。不是处理提高或降低了实际办结能力。

新增两道不计分的阅读判断：3张缺等待、2张窗口未知、1张重叠，共4张至少有一项问题；等待12分钟但是否放弃未知，不能纳入已服务均值；没有可用等待记录时均值未定义，不是0。答案折叠，先判断再核对，不增加正式提交任务。

## 实际项目演练：独立程序与结果

教师目录的[walkthrough.py](walkthrough.py)按公开数据字典独立实现，不调用reference.py，也不读取生成器中的潜在真值。它只是一次可重跑的模拟作业，不是通用生产数据清洗库，不发布到学生目录。

```bash
python instructor-guide/lesson-03/walkthrough.py \
  --student-root student-template --output /tmp/lesson03-practice
```

生成cleaned.csv（保留原字段、另加规范化值及用途标记）、row_handling.csv（原始每行如何处置）、issues.csv（逐问题记录）、summary.json和practice_report.md。原始CSV不改，输出不能放入原数据目录。

当前数据的核对：1,265行＝1,200张工单＋39行完全重复＋26行旧版本；最新工单中42个等待值由秒换算。19张未测等待、7张窗口未知、10张业务未知、7张办结缺失，共43项问题，但只有42张不同工单，因为T04394同时缺等待与业务。

| 用途或方案 | 分子／总量 | 有效分母 | 结果 |
|---|---:|---:|---:|
| 已服务且等待有效 | 等待分钟合计 | 1,122张 | 平均15.2114分钟 |
| 只要求办结状态有效 | 945张办结 | 1,193张 | 79.2121% |
| 同时要求等待及单位、办结、窗口有效 | 927张办结 | 1,167张 | 79.4344% |
| 另要求业务、放弃状态有效 | 922张办结 | 1,158张 | 79.6200% |
| 已确认窗口归属 | A1为198张，其余五个窗口各199张 | 合计1,193张 | 另7张窗口未知 |

办结有效数和已知窗口数都恰为1,193，但不是同一批工单。三项／五项条件分别对应四个／六个原字段，因为等待需要数值和单位共同判断。原complete_case字段保持原数值，新增清楚命名的三项信息结果及字段说明，不因修正文案而覆盖历史核对依据。

模拟报告建议：办结采用该指标本来能用的已知状态集合；等待限于已服务且测量有效集合；窗口数量单列未知归属。三种办结比例的差异不足以证明实际管理改善。优先核实会影响相应用途的字段，而不是为整表追求零缺失。

原r2十题已逐题审核；答案按题组顺序为A版D、A、C、A、D，B版B、C、C、B、A。其主要计算没有发现必须改判的错误；本次改善题干自足性、干扰项和题对联系，不原地修改答案。

另存新版本`v2-l03-r3`，两份YAML逐字节一致，仍为5组、A/B各5题，时间保持300／240／300秒。新题在教师审核中的解答如下，不复制到学生课次目录：

| 题组 | A题解答 | B题解答 | 核对重点 |
|---|---|---|---|
| 重复与版本 | B：保留第2版，另计1重复、1旧版 | D：两张真实订单各保留一份 | 副本、版本与分析单位 |
| 缺失与单位 | A：(120/60＋0)/2＝1分钟 | C：(0＋12)/2＝6件，分母2 | 真实零保留，缺失不填0 |
| 离群与无效 | D：保留90并核实影响 | B：负长度标无效，先核实 | 大不等于错，无效不猜改 |
| 用途与分母 | C：办结有效分母100−2＝98 | A：测得12分钟不证明已服务 | 所需信息而非整行完整 |

这套解答先按题义确定，再用于自动测试评分与反馈；不把题库自身的answer字段再抄回数据库来证明评分正确。另设每版一题故意选错的请求序列，验证错答反馈，不模拟或声称某个真实学生犯过这些错误。
