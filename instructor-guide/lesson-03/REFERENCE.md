# 第3课参考分析与评价要点 · 业务数据质量与适用性评估

本文件用于判断证据与结论是否相配，不是唯一答案。学生可全程使用AI；不按代码由谁输入评分，不因结论与参考不同自动扣分。

## 可重复计算

从本仓库根目录运行（Python 3.10或以上、仅标准库）：

```bash
python instructor-guide/lesson-03/reference.py
```

也可从 `instructor-guide/` 运行 `python lesson-03/reference.py`。使用独立学生仓库时传入 `--student-root /path/to/student-repository`；显式路径无效时不会悄悄改读其他数据。默认先定位本仓库的 `student-template/`，再兼容原有相邻目录。输出为标准输出上的JSON；需要保存时重定向到教师自己的结果目录，不修改学生数据。

共享读取与统计函数位于第1课 `reference.py`。分位数采用线性插值 `(n−1)p`；`std_n` 用分母n描述已有记录，不是标准误；空集合的统计量或零分母比例返回JSON的 `null`，不是0。结果带有教学合成数据标记。

## 固定数据下的核对证据

1,265原行→1,200工单；39完全重复行，26工单有较高修订版；最终42条由秒换算。19工单等待未测量，7窗口未知、10业务未知、7办结缺失。办结字段有效n=1,193，比例79.2121%；完整案例n=1,158，比例79.6200%。等待有效且已服务n=1,122，均值15.2114分钟。

数值按固定生成种子核算，显示时允许合理四舍五入。学生若选不同对象、变量定义或指标，不应强行匹配这些数字；应追查其分子分母、规则和输入是否支持所报结果。

## 行数核对和按用途限用

`raw_rows`、`exact_duplicate_rows`和`superseded_revision_rows`都计“行”，`unique_tickets`及`tickets_with_revision`计“工单”。本批核对式为1265＝1200＋39＋26；这里26个修订工单恰各有一条被替代的非重复旧行，换数据后两个计数不必相同。不能把质量标记数相加当作异常工单数，同一工单可有多个问题。

`completion_successes / completion_specific_denominator`与完整案例中的对应分子分母一起提供；比例仅描述各自有效集合，不保证缺失可忽略。`window_ticket_counts`统计归属已知的工单，并单列未知归属数，不把工单数解释为实际工作努力。`unresolved_records`保留全部待核工单编号及原因，`unresolved_examples`仅为前10条预览。

等待编码先于单位换算；空白等待标为未测量，非数值、NaN、无穷大、非法负值或未知单位标为无效；长但有限且非负的等待不因极端而删除。未知放弃状态不进入“已服务”等待集合，但其他字段仍可按用途使用。工单编号缺失、修订版本非法或最新版本冲突时停止并报告，不能自行猜测。

这些额外输入检查是边界测试，不应被描述成当前CSV已发现的新错误。参考清洗函数返回保留原字段的记录及审计计数；采用其他合理处理时，核对目标单位和处理假设，而不要求得到相同的完整案例集合。

## 可接受的分析方法

参考保留全部1,200个工单对象，对每个指标按需限制。完整案例分析可作为敏感性分析的一种方案，不应默认对所有指标都采用相同的完整记录集合。插补可以接受，但不能把插补值标成观察真值；需要与不插补报告比较。

## 解释结果时应说明的适用条件与局限性

缺失编码规则与版本优先是已知技术约定，不是学生可任意改变的偏好。极端60分钟之类若没有额外证据仍有效。新期与旧期时间不同，差异不能归因于清洗或管理效果。

## 如何区分质量

合格需两个用途、可复现处理和核对及有实际意义的对照；高质量能限用而非整表删除，并把待核问题对应到发布影响。

先检查报告是否回答分析问题、关键数字能否重新计算，以及备选分析是否实际影响结论解释，再按[统一评分规则](../GRADING.md)评价；只有被选为模块代表作品时才评代表作品质量分，不擅自增加分值上限或扣分项目。绘图数量、模型数量与界面复杂度不单独加分。对统计上合理的暂缓发布、补充调查或不进行排名的建议同样认可；缺少证据的“各种情况都有可能”不构成充分结论。
