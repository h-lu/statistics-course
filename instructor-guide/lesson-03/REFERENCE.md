# 第3课参考分析与评价要点 · 业务数据质量与适用性评估

2026-10-09现行版本。学习例子、五组线下迁移题、正式项目过程和允许替代解见[EXERCISE_SOLUTIONS](EXERCISE_SOLUTIONS.md)；本次检查见[AUDIT_REDESIGN](AUDIT_REDESIGN.md)。课堂采用教师开头10分钟、学生独立65分钟、末尾选择题15分钟，不以补充长讲消耗独立任务时间。

本文件用于核对计算与解释，不是唯一答案。学生可全程使用AI；不按谁输入代码、是否得到教师偏好的结论或采用多少方法评分。

## 多路线评价框架

本页数值是核验依据，不规定全班分析步骤或菜单。至少两个用途、可重跑处理、一项合理替代实算和逐用途建议仍保留。

| 合理路线 | 学生需论证的重要选择 | 可接受成果与边界 |
|---|---|---|
| 每指标使用自身有效信息 | 用途为什么需要这些字段，其他缺失为何无关 | 限状态已知或有效已服务记录的结果，另列未知信息 |
| 多指标共用必要字段集合 | 为什么需同一批工单，损失的信息是否可接受 | 明确共同字段并实际比较，较高比例不自动更正确 |
| 目标是全部登记而资料不完整 | 限范围、逻辑可能、补核或有依据插补怎样支持决定 | 可暂缓或带条件发布，插补不是查实，逻辑界限不是置信区间 |
| 以窗口归属或补核优先级为主 | 未知字段影响哪项行动，补核能恢复哪些用途 | 已确认数量及核实清单，工单量不冒称人员工时 |

可以组合或另提有依据的路线。差集追踪、按类别核查与逻辑界限均为可选证据方法，不强制所有学生采用。最低合格是全部原标准任务完整，较高质量来自用途依据、范围与信息取舍能影响实际建议，而非更多代码、图数或符合某个参考比例。

## 运行与文件分工

从完整课程仓库根目录运行，Python标准库即可：

```bash

```

参考程序复用第1课的读取与统计函数，输出JSON到标准输出，不改数据。使用独立学生仓库时替换 `--student-root` 路径。从教师目录运行则用 `python lesson-03/reference.py --student-root ../student-template`。

学生 `analysis.py` 仅保留原始行概览及单值等待解析基础函数，不选择版本、范围或完整处理方案。此前候选的一键清洗/比较支架已撤回；学生可自行实现或改写方法。`submission.json` 仍须由学生完成后填写最终可重跑命令。教师的[独立演练程序](walkthrough.py)仅在独立目录核验数字，不是学生步骤模板：

```bash
python instructor-guide/lesson-03/walkthrough.py --student-root student-template --output /tmp/lesson03-walkthrough
```

替换成教师自己的输出目录即可，不向实际学生仓库写参考答案。该程序没有调用本课 `reference.py` 或生成器的内部真值，便于独立核对；它仍由同一编写助手编写，不是独立人员盲评。

## 固定数据的数量核对

1,265行＝1,200张工单＋39行完全重复＋26行被替代的非重复旧版本。本批26张工单有更高版本，每张恰好有一行旧版本；更换数据后，“有修订的工单数”不必等于旧版本行数。

原始单位为秒的行数是45，选取每张工单的最新记录后，实际转换42张。这两个计数的单位分别为原始行和处理后工单。

最终有19张等待未测量、7张窗口未知、10张业务未知、7张办结状态缺失，共43个问题标记，但只有42张不同工单。T04394同时有等待未测量和业务未知，因此不能把19＋7＋10＋7当作不同工单数。未放弃且等待有效的1,122张工单，均值为15.2114分钟。

## 三种字段要求不能混称一个“完整案例”

| 办结比例的记录条件 | 办结数 | 有效分母 | 比例 | 输出位置 |
|---|---:|---:|---:|---|
| 仅要求办结状态有效 | 945 | 1,193 | 79.2121% | `completion_specific_*`及`completion_successes` |
| 同时要求等待及单位、办结状态、窗口归属有效 | 927 | 1,167 | 79.4344% | `shared_three_information` |
| 在上一条件上，再要求业务类型、放弃状态有效 | 922 | 1,158 | 79.6200% | 原有`complete_case_*` |

第二行对应学生任务中的替代处理例子；第三行保留原教师参考的较广字段要求。1,167与1,158不相等不是计算错误；不能让学生猜出教师另加了哪些字段。三种输出都明确列出 `required_fields` 或对应字段列表；“等待及单位”需要原来的 `wait_minutes` 和 `wait_unit` 两列，窗口还需在字典中有归属。

完整案例分析是相对于本次所需字段没有缺失的记录，不等于全表任一列空白就排除。代码还先核查单位、合法状态和字典匹配：UNKNOWN虽是非空文字，也不提供有效窗口归属。放弃工单的面对面服务时长不适用，不列入这里的有效性要求。

主用途为办结比例时，945/1,193保留了该指标本来能用的资料，但仍只描述状态已知者；另7张状态未知。多指标共用记录便于并列表达，可能损失某项指标本来能用的信息；应根据用途解释取舍，而不是选择较高的比例。现有记录筛选不能证明消除了选择偏差，也不能代表发生了管理改善。

仅要求办结有效与三项信息共同有效的差集为26张，其中18张已办结；差集业务为复杂15、常规10、未知1。差集追踪是可选的信息损失解释。全部1200工单办结比例的逻辑界限为945/1200=78.75%至952/1200=79.3333%，不是置信区间，也不处理未登记者或测量错误。界限与办结用途均不强制采用，其他用途可用适当证据论证未知影响。

## 等待与窗口数量的适用范围

`served_valid_wait` 要求等待有效且 `abandon == 0`，未知放弃不能当已服务。原较广共同集合中的已服务等待为1,100张、均值15.2599分钟；这与1,122张的结果也描述不同范围。分母为0时输出 `null`，不是0分钟。

`window_ticket_counts` 为A1的198张及其余五个窗口各199张，共1,193张；另7张窗口未知。已确认数量不能冒称完整窗口总量，也不等于工作人员投入或生产率。办结分母与已知窗口数量恰好都是1,193，但它们的工单集合不同，不能只凭数量相同认定范围一致。

`unresolved_records` 列全部待核实工单和标记，`unresolved_examples` 仅显示前10条。单一字段无效不使整个工单对象消失。

## 代码处理约定与限制

先识别完全重复、按数值版本选最新，再识别缺失编码和统一单位。999、−1和空白等待表示未测量；无法解析的文字、非有限数、其他负值或未知单位标为无效。长但有效的测量不因极端而删除。

办结和放弃状态中，空白或None标为 `missing_completion`／`missing_abandonment`；非法取值另标 `invalid_completion`／`invalid_abandonment`。它们都不猜作0，但核实原因不同。原字段仍保留。

工单编号缺失、修订版本非法或最新版本冲突时，参考程序停止并提示。学生也可有依据地单列冲突记录并继续不受影响的分析，前提是明确未解决范围；不额外要求复杂异常处理系统。边界测试不能被描述成现有CSV已发现所有这些问题。

## 评价与反馈

保持原要求：至少两个用途、可重跑处理、数量核对，以及至少一项有实际结果的合理替代比较。并不要求对每个用途都换一次方法，也不要求插补或排名反转。

较高质量的区别在于：能解释选择怎样影响描述对象，哪些待核实记录会改变建议，并区分按约定处理与真正取得额外来源的核实。没有额外证据时，不要求编造“已查实修正”。缺失值变少不自动说明报告更可靠。

按[统一评分](../GRADING.md)执行；只有被选为模块代表作才评价代表作品质量。暂缓某项发布可以是合理结论，但要给出数据依据。学生程序与结果仍只需满足原任务，不强制复刻本文件。
