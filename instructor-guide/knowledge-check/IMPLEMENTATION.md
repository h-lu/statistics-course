# 知识自查实现与维护

继续使用既有FastAPI + SQLite + Gitea OAuth服务，不新建平台。学生入口`https://hblu.top/stat-check/`，教师入口`https://hblu.top/stat-check/teacher`。

## 已有与新增

保留账号识别、教师切课、A/学习/B/反馈、提交锁定、倒计时、学生自动跟随和CSV导出。当前使用32课语言修订版题库；原6套V1题库和32套V2初版题库仍加载，以便解释和导出旧场次记录。新建场次下拉框只列当前32套题，数据库中的旧场次不变；学生页面只显示当前场次。

服务导出的CSV是个人完成与总正确数汇总，不含逐题概念明细。教师页面显示当前场次的概念正确率；需要后续复习时当堂记录一个概念即可。知识自查不自动合成平时总分。

## 内容发布

教师权威题库在`question-bank/lesson-v2rX-NN.yml`，其中`X`为逐课修订号；服务运行副本在`stat-check/app/question_bank/`。当前版本见[题库约定](question-bank/SCHEMA.md)。发布前检查两份字节一致、5概念/10题、ID唯一和正确选项有效。V1原版在`question-bank/legacy/`，V2初版为`question-bank/lesson-v2-NN.yml`；这些已发布文件及服务中的对应副本保持原字节内容。

部署前确认当前场次不是A/学习/B，做SQLite在线备份，更新代码和题库后重建容器。保留`.env`、数据库目录与OAuth配置，不删除或重建答题数据。服务器路径与备份位置记录在本次发布记录，不在课程规范里写私密配置。

## 测试

在隔离测试环境运行`pytest -q`，使用测试数据库验证新旧题库、完整A/学习/B流程、权限、CSRF、迟到提交、旧场次保留和切课后的过期答案。测试登录只在`testing=True`启用，不能在生产开启。

## 故障

短暂网络故障允许刷新；教师没切阶段则学生等待。自查服务不可用时使用纸质概念练习或统一豁免，不挤占课堂末尾进行服务器修复。活动场次期间暂缓部署，不自动关闭学生场次。
