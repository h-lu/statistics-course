# Gitea 驱动的高密度开放项目制统计学课程

## 一、边界与总体结构

- 学期：16 周，每周 2 次，每次 90 分钟，共 32 次课。
- 平时成绩：50%，评价 AI 增强环境下的统计项目、决策过程与交付质量。
- 期末考试：50%，由教师另行设计，本方案不涉及。
- 学生：每人自带笔记本，默认允许并鼓励使用 AI。
- 课堂形态：教师不依赖学生口头回应、讨论热度或课后自觉；学生大部分时间直接完成项目。

课程不再让一个项目拖三周。第 1 周完成两次工具启动；第 2–16 周的 30 次课，**每次课完成一个独立、可发布的开放统计项目**。五个模块只用于组织知识，每个模块包含六次不同委托：

| 阶段 | 周次 | 逐课项目 | 平时成绩 |
|---|---:|---|---:|
| 启动 | 第 1 周 | Gitea、Python、AI 和可复现工作流训练 | 0 分，必须通过 |
| 模块 1 | 第 2–4 周 | 数据、测量与描述：6 个独立冲刺 | 10 分 |
| 模块 2 | 第 5–7 周 | 概率、抽样与估计：6 个独立冲刺 | 10 分 |
| 模块 3 | 第 8–10 周 | 比较、检验与实验：6 个独立冲刺 | 10 分 |
| 模块 4 | 第 11–13 周 | 回归、预测与部署：6 个独立冲刺 | 10 分 |
| 模块 5 | 第 14–16 周 | 因果、时序与决策：6 个独立冲刺 | 10 分 |
| **合计** | **16 周** | **30 个课堂项目** | **50 分** |

30 个项目统一使用同一种 90 分钟节奏、仓库接口和评分框架。每次都有完整的“问题—证据—变化—更新—决定—发布”闭环，而不是把定义问题、做图和写报告各拖成一节课。

### 本课程不解决“是不是学生亲手做的”

如果一个 AI 代理可以操作仓库、终端、CI 和文档，它当然也可以生成分阶段 commit、修复检查、写报告并提交。提高题目难度不能改变这一点，往往只会使整体委托 AI 更划算。

因此，本课程明确分工：

- **30 个课堂项目**评价“学生账户所负责的人—AI 系统能否交付合格统计产品”。不以代码由谁输入、文字由谁起草为评分依据。
- **期末考试**承担学生个人基础统计能力的受控评价。本方案不重复设计第二套隐蔽考试。
- Gitea 记录的是版本、决策、证据和责任链，不被解释为“学生本人理解”的证明。

如果 AI 完成了仓库中的全部工作，而最终作品确实满足要求，项目成绩应承认该作品。学生承担的是采用与提交责任，而不是证明每一行都由本人完成。课末知识自查提供低利害的学习反馈，同样允许使用 AI；个人掌握程度仍由学校规定的期末考试评价，不在平时课堂中另建一套反 AI 签收。

### 开放，但不失控

每个逐课项目采用四层结构：

1. **开放问题空间**：每次提供 2–4 个领域数据包，学生选择利益相关者、具体问题、目标量、方法和行动阈值。
2. **统一能力约束**：每次规定所有人必须展示的统计核心，避免项目沦为任意作品。
3. **标准化交付接口**：所有冲刺使用相同的 `contract.yml`、`submission.yml`、`sNN-final` tag 和可复现命令，便于 CI 与统一评分。
4. **课中信息变化**：第 50 分钟统一发布客户来信、新数据或约束，要求保留原决定并更新。它不以“答对才解锁”为条件。

开放不等于每次让学生从互联网临时找数据。课程准备五个可重复使用的“数据世界”，每个支撑六次不同任务；自带合法数据作为扩展。最实用的边界仍是：**开放研究选择，封闭交付接口**。

### 每节课不是一个检查点，而是一个完整项目

每次冲刺至少完成 Core 与 Event；完成快的学生沿着连续队列继续：

`Core 最低产品 → Upgrade 两项证据增强 → Event 客户来信 → Transfer 新样本迁移 → Explore 自定扩展`

任何静态任务都无法保证强 AI 恰好工作 90 分钟，因此不以“耗满时间”为目标。课程保证的是任务队列不会耗尽：AI 很快完成基础层的学生可以继续迁移、扩展或产品化；速度较慢者完成 Core 与 Event 仍可获得当堂完成分。这些层级形成工作节奏，不是抓 AI 犯错。

## 二、课堂运行：用项目状态代替学生反馈

学生不说话、不给回应并不妨碍课程运行。每节课只观察三个客观信号。这些信号用于组织课堂，不用于证明个人学习：

- **绿色**：本节冲刺已经发布，自动检查通过。
- **黄色**：已经提交，但自动检查失败或仍在运行。
- **红色**：本节尚无有效提交。

### 每次 90 分钟的固定流程

| 时间 | 教师动作 | 学生动作 | Gitea 证据 |
|---|---|---|---|
| 0–6 分钟 | 发布当日完整委托和 2–4 个数据入口 | 选择情境并认领任务 | Gitea issue |
| 6–13 分钟 | 只处理共同入口问题 | 定义总体、目标量、行动阈值和边界 | `contract.yml` |
| 13–30 分钟 | 查看交通灯 | 完成 Core：可复现最低分析和第一版图表 | 第一次绿色 CI |
| 30–43 分钟 | 只处理共同阻塞 | 完成 Upgrade：任选两项证据增强，形成第一版决定 | 初步产物及 commit |
| 43–47 分钟 | 统一发布客户来信、新数据或约束 | 拉取事件，保留原决定 | 服务器记录到达时间 |
| 47–60 分钟 | 观察事件响应状态 | 更新分析，保留、修改或撤回建议 | `update.md` |
| 60–70 分钟 | 提供 Transfer 数据/接口 | 完成迁移/压力测试与短备忘录 | 迁移结果 |
| 70–75 分钟 | 冻结服务器收到的 SHA | 从干净环境重跑，提交 `sNN-final` | tag 与 CI |
| 75–80 分钟 | 开放知识自查 A 版 | 建议先凭自己的判断作答并标信心；允许使用 AI | 服务器锁定 A 版 |
| 80–84 分钟 | 开放概念学习 | 用 AI 解释概念、举例和追问，推荐辅导模式而非直接索要选项 | 概念学习完成 |
| 84–89 分钟 | 开放 B 版平行题 | 把刚学到的判断规则用于新情境；允许使用 AI | 服务器锁定 B 版 |
| 89–90 分钟 | 展示个人与班级聚合反馈 | 查看解释和待复习概念 | 个人掌握记录 |

不要求每节课展示、互评、答辩或提交提示词反思。代码、产物、服务器接收时间和 SHA 是项目过程证据，不是“没有使用 AI”的证据。

### 每节课末的基础知识自查

项目课程不按教材章节讲授，不等于放弃基础概念。每次只检查 4–5 个“本节项目中必须知道”的知识点，并加入一个较早内容的间隔复习题。题目以单选、判断＋理由、数字解释和主张边界为主，不检查 Python 语法或手工长计算。

采用“**先答锁定—AI 学习—平行题再答**”：A 版首次答案提交后不可修改；学习阶段只显示知识点和误解标签，学生可以让 AI 解释概念、举例和追问；B 版换情境与数值，检查能否迁移刚形成的判断规则。不能只把 A 版选项重排成 B 版。

学生可以在任何阶段询问 AI；课程只明确建议不要把题干和选项原样交给 AI 索要字母答案。系统不监控切屏、不禁复制，也不检测 AI。直接代答无法完全避免，但这部分正确率不直接计分，期末考试另行检验个人掌握，因此没有必要把形成性自查做成 AI 攻防。

自查不放进学生仓库。推荐独立轻量 Web 服务，以 Gitea OAuth 识别学生；题库和答案在教师私有仓库，服务负责计时、随机平行题、锁定、自动评分和班级误区仪表盘。Gitea README 只提供入口链接。

### 课堂完成激励

每个模块有 6 个独立冲刺，取其中完成分最高的 5 个：

- 当节课结束前完成项目交付：0.8 分；完成 A 版和 B 版知识自查：0.2 分。
- 在下一次课开始前补完：0.5 分。
- 再晚完成：不再获得当堂完成分，但作品仍可进入个人作品集。

这不是签到分。每模块舍去最低一次，可以容纳一次缺席、技术故障或选题失败，但不能用前一模块的高分替代后一模块。

## 三、Gitea 课程结构

### 1. 推荐组织方式

建立一个课程组织，例如 `stat-2026`：

```text
stat-2026/
├── course-materials          # 只读：项目说明、公共数据、示例
├── course-template           # 学期仓库模板
├── course-ci                 # 教师维护的检查脚本/工作流
├── s20260001                 # 学生 1 的私有学期仓库
├── s20260002                 # 学生 2 的私有学期仓库
└── ...
```

建议**每名学生一个私有学期仓库**，而不是每个项目新建一个仓库：仓库数量少，进度历史连续，教师更容易汇总。学生可以互相讨论和共享思路，但每人维护自己的最终仓库和提交记录。

Gitea 支持从模板仓库生成新仓库；若已部署的版本支持 Scoped Workflows，可把统一检查集中维护在 `course-ci`，让组织内所有学生仓库自动执行。若版本不支持，则把 `.gitea/workflows/check.yml` 放进课程模板，并由教师脚本额外核对工作流文件哈希。

### 2. 学生仓库固定结构

```text
s20260001/
├── README.md
├── environment.yml           # 或 requirements.lock
├── STATUS.yml                # 当前冲刺、层级和最终提交 SHA
├── sprints/
│   ├── S01/
│   │   ├── brief.md          # 当日委托、能力约束和可选数据
│   │   ├── contract.yml      # 总体、目标量、行动、阈值与边界
│   │   ├── src/              # 可复现代码/notebook
│   │   ├── artifacts/        # metrics.json、图表和生成文件
│   │   ├── update.md         # 客户来信前后的决定及理由
│   │   ├── memo.md           # 400 字以内最终产品
│   │   └── submission.yml    # 主张、证据位置、边界和撤回条件
│   ├── S02/
│   └── ... S30/
└── tests/
```

### 3. 每次 push 自动检查什么

绝大部分检查应当透明。只有在未来信息本来就不应提前出现时，例如预测模型的未来批次或实验第二波结果，服务器才保留未见数据；隐藏信息不是用来诱使 AI 答错。

- 必需文件和标题是否存在。
- 已冻结数据快照或下载脚本的哈希是否与服务器记录一致。
- notebook 能否在干净环境从头运行。
- 是否固定随机种子。
- 数据行数、变量类型、缺失比例和连接结果是否处于合理范围。
- 必需的表、图和模型结果是否成功生成。
- 报告中的关键数字是否与程序生成的结果一致。
- `submission.yml` 中每个主要主张是否链接到实际证据，是否写明范围和撤回条件。
- 项目特定的统计要求是否完成。
- 是否创建了本节 `sNN-final` tag。

自动检查负责即时反馈和机械验收，不应试图自动判断所有统计论证。开放判断仍由教师用简短量表抽查。

### 4. 教师交通灯面板

利用 Gitea API 汇总每个学生仓库：

- 最近一次 commit 时间和 SHA；
- 当前冲刺、已完成层级与 `sNN-final` tag；
- 最新 commit 的 Actions 综合状态；
- 最终提交 tag 指向的 SHA；
- 是否晚交；
- 已获得的过程分。
- 事件发布前 commit、最终服务器接收时间、数据哈希和选择摘要。

课堂只展示学号和绿/黄/红，不公开成绩。教师看到大面积黄色时，针对共同失败项讲 5 分钟；只有少数红色时，直接走到对应学生处。无需反复问“大家会了吗”。

### 5. 提交冻结

- 每节课结束时用 `s01-final` 至 `s30-final` 标记当堂版本。
- 截止时由教师脚本记录 tag 对应 SHA 和服务器接收时间，之后学生可以继续修改仓库，但评分仍针对被冻结的 SHA。不能只依据 Git author time，因为本地时间可以修改。
- 补交使用 `s01-resubmit-1`，不覆盖原始提交，修改过程完整保留。

### 6. 服务器只做三件事

1. **保存权威状态**：记录收到时间、commit SHA、数据快照、事件前版本和最终版本。它不评价是谁完成的。
2. **第 50 分钟统一发布客户来信**：事件不以“答对上一层”为前提。为降低管理成本，第一轮全班使用同一种事件；未提交者也按时收到。
3. **保管真正尚未到达的信息**：例如新抽样、实验第二波、预测未来批次或迁移数据。公开 CI 可无限运行；正式留出评估在提交锁定后运行并返回汇总结果。

这些机制使学生不能在看见后续结果后改写先前选择，却不能也不试图阻止学生在每个阶段继续调用 AI。服务器模拟真实工作的时间和信息边界，不是 AI 鉴定器。

## 四、第 1 周：工作流启动，不计分但必须通过

### 第 1 次课：从登录到第一次绿色提交

目标：所有学生完成账号、仓库、Git 和 Python 环境验证。

课堂任务：

1. 登录 Gitea，进入自己的私有仓库。
2. clone 仓库，运行环境检查脚本。
3. 修改指定文件并完成 commit、push。
4. 查看 Gitea Actions 日志，修复一个预设失败项。
5. CI 变绿，创建 `p0-c1` tag。

教师只解决三类问题：无法登录、无法 clone/push、环境无法运行。不在这一节讲统计学。

### 第 2 次课：迷你项目 0

用一份很小的数据完成完整闭环：读取数据、计算两个统计量、画一张图、写两句话、从头运行、提交 tag。

本节同时明确课程 AI 原则：

> AI 可以完成代码和分析。仓库的所有者负责问题定义、输入数据、验收标准、最终采用和提交后果。评分不判断是哪一个模型写了代码，只判断仓库中的成果是否满足要求。

通过标准：`p0-final` CI 为绿色。未通过者必须在第 2 周前补完，否则无法进入正式项目。

## 五、模块 1：数据、测量与描述（第 2–4 周，6 个项目）

### 项目情境

六次课分别完成六个独立委托，使用同一批熟悉的数据世界，但每次都有不同客户、统计问题和产品。

### 统计内容

传统内容：变量类型、频数、均值、中位数、分位数、方差/标准差、分布图、列联表、相关、分组比较。

新增内容：数据字典、缺失机制、异常与重复、数据连接、可复现管道、自动断言、多变量可视化、Simpson 现象、数据适用性。

### 六次独立冲刺

| 冲刺 | 当堂完整委托 | 统计核心 | 最终产品 |
|---|---|---|---|
| S01 | 判断一份业务数据能否用于人员调整 | 分析单位、变量、重复、范围、数据合同 | 数据审计卡与采用/限用/拒绝决定 |
| S02 | 为等待时间或客单价选择“典型值”并制定标准 | 均值、中位数、分位数、IQR、标准差、稳健统计 | 指标选择与行动差异表 |
| S03 | 根据监测或履约分布制定报警阈值 | 分布、ECDF、偏态、多峰、离群与变换 | 阈值、误报率和单位变化后的修订 |
| S04 | 判断总体排名在分层后是否反转 | 分组统计、条件比例、加权、标准化、Simpson 现象 | 排名稳定性产品 |
| S05 | 判断群体差异是否由缺失机制改变 | 缺失模式、MCAR/MAR/MNAR、插补、敏感性 | 两种处理结果与结论边界 |
| S06 | 判断多表连接后的单位排名能否发布 | 主键、连接基数、重复传播、数据血缘 | 连接对账、稳定性和发布决定 |

开放扩展包括模糊连接、地理/时间数据、SQL、交互式工具、缺失敏感性和公平审计；只在确实改善证据或决定时提高代表作品质量。

## 六、模块 2：概率、抽样与估计（第 5–7 周，6 个项目）

### 项目情境

每次课解决一个不同的不确定性决策：从单个阳性结果、随机需求，到总体推广、区间和抽样预算。

### 统计内容

传统内容：概率、随机变量、常见分布、期望与方差、抽样分布、中心极限定理、点估计、标准误、置信区间。

新增内容：Monte Carlo、bootstrap、覆盖率模拟、分层抽样、加权、设计效应、偏差—方差权衡；可选比较贝叶斯后验区间。

### 六次独立冲刺

| 冲刺 | 当堂完整委托 | 统计核心 | 最终产品 |
|---|---|---|---|
| S07 | 由一次阳性结果决定是否昂贵复核 | 条件概率、基础率、Bayes、敏感度与特异度 | 自然频数表与复核规则 |
| S08 | 用模拟在库存、排班或营销方案中作选择 | 随机变量、分布、期望、方差、Monte Carlo | 可修改模拟器与损失分布 |
| S09 | 判断自愿样本究竟代表谁 | 抽样框、选择偏差、响应率、权重 | 入样机制、加权估计和可推广范围 |
| S10 | 判断正态近似何时失效 | 抽样分布、标准误、CLT、偏态、重尾 | 模拟网格与适用规则 |
| S11 | 判断区间是否越过实际行动阈值 | 点估计、置信区间、bootstrap、覆盖率 | 区间、覆盖实验和行动建议 |
| S12 | 在预算变化下分配分层样本 | 分层抽样、Neyman 分配、设计效应、样本量 | 两套分配与精度—成本取舍 |

开放扩展包括稳健/贝叶斯区间、复杂抽样、校准加权、成本敏感分配和离散事件模拟。

## 七、模块 3：比较、检验与实验（第 8–10 周，6 个项目）

### 项目情境

六次课分别处理设计、分析、比较结构、功效、多重性和序贯停止。每次都有完整实验决定，而不是连续六节只完成一个 A/B 测试。

### 统计内容

传统内容：零假设、p 值、单/双样本比较、配对设计、比例检验、卡方、ANOVA、效应量。

新增内容：随机化检验、功效与样本量、预分析计划、多重比较、序贯查看、异质性效应、决策阈值。

### 六次独立冲刺

| 冲刺 | 当堂完整委托 | 统计核心 | 最终产品 |
|---|---|---|---|
| S13 | 设计一个能回答现实问题的随机实验 | 实验单位、随机化、区组、目标量、污染 | 实验协议、分配脚本和分析计划 |
| S14 | 根据已完成随机实验决定推广或停止 | 效应量、随机化/置换检验、区间、ITT | 结果卡和推广决定 |
| S15 | 在配对、改革前后和独立组之间选择方法 | 配对与独立样本、Welch、效应量、假设检查 | 方法选择与丢失配对敏感性 |
| S16 | 在固定预算下决定实验是否值得做 | 一/二类错误、功效、MDE、样本量 | 功效曲线与做/不做建议 |
| S17 | 从大量比较中决定发布什么 | 多重比较、FWER、FDR、选择性报告 | 校正结果与公开发布规则 |
| S18 | 决定在线实验何时停止 | 重复查看、序贯监测、流失、ITT | 停止规则、中期更新与最终决定 |

开放扩展包括集群/因子实验、回归调整、Bayesian 或 always-valid inference、异质性效应、护栏指标和非劣效设计。

## 八、模块 4：回归、预测与部署（第 11–13 周，6 个项目）

### 项目情境

六次课从关系解释推进到模型部署，但每次都针对新的客户决定，均可独立发布。项目不是排行榜；“不部署”也可以是高质量结论。

### 统计内容

传统内容：相关、简单/多元线性回归、分类变量、交互、残差、logistic 回归、系数解释。

新增内容：训练/验证/测试划分、交叉验证、正则化、数据泄漏、基线模型、评价指标、概率校准、阈值、子组表现、模型卡。

### 六次独立冲刺

| 冲刺 | 当堂完整委托 | 统计核心 | 最终产品 |
|---|---|---|---|
| S19 | 量化一个变量与结果的关系并处理影响点 | 相关、简单回归、斜率、残差、R² | 关系解释、诊断与非因果边界 |
| S20 | 为特定群体建立多变量关系模型 | 多元回归、分类变量、交互、非线性、共线性 | 嵌套模型与边际效应产品 |
| S21 | 按错误成本选择分类阈值 | logistic、ROC/PR、混淆矩阵、类别不平衡 | 阈值后果表与干预规则 |
| S22 | 参加只允许一次正式测试的模型竞赛 | 训练/验证/测试、CV、泄漏、指标选择 | 锁定管道、未来成绩和复盘 |
| S23 | 在关键特征停止供应后决定复杂模型是否值得 | 偏差—方差、Ridge/Lasso、稳定性 | 性能—复杂度图与降级方案 |
| S24 | 决定模型部署、试用或拒绝 | 校准、Brier、分组表现、公平、漂移 | 模型卡、监控和撤回条件 |

开放扩展包括 GAM/树模型、集成、conformal prediction、时间验证、解释性、代价敏感学习、公平阈值和漂移监控。

## 九、模块 5：因果、时序与决策（第 14–16 周，6 个项目）

### 项目情境

最后六次仍是六个完整项目：从因果问题、观察数据调整、政策前后，到时间预测、信息价值和综合证据发布。

### 统计内容

传统内容：观察研究与实验区别、混杂、相关与因果、多元回归、交互和分组比较。

新增内容：因果问题与目标量、DAG、回归调整、匹配/倾向得分/IPW、双重差分、安慰剂检验、敏感性分析、政策决策。

### 六次独立冲刺

| 冲刺 | 当堂完整委托 | 统计核心 | 最终产品 |
|---|---|---|---|
| S25 | 把“参加者结果更好”改写成可辩护的因果问题 | 潜在结果、目标试验、DAG、混杂/中介/碰撞 | 目标试验协议、DAG 与识别声明 |
| S26 | 从观察数据估计处理效应并处理重叠不足 | 标准化、倾向得分、匹配/IPW、平衡 | 调整估计、平衡图和支持人群边界 |
| S27 | 判断政策前后变化是否由政策造成 | DiD、平行趋势、事件研究、安慰剂 | 趋势、估计、诊断和因果措辞 |
| S28 | 判断事件后变化是趋势还是异常 | 趋势、季节、自相关、滚动回测、预测区间 | 基线预测、异常判断和容量建议 |
| S29 | 在证据不确定时决定行动还是继续采样 | 期望损失、效用、阈值、信息价值 | 决策表与买信息建议 |
| S30 | 为新利益相关者发布一个完整证据产品 | 目标量、证据、不确定性、边界和行动的综合 | 一页简报、一张核心图和一键复现 |

开放扩展包括双重稳健估计、负对照、合成控制、断点、变点、EVSI、稳健决策和交互式证据产品。

每个冲刺的完整情境、课中客户来信、交付要求和开放扩展见配套清单：[30 个逐课开放项目冲刺](30个逐课开放项目冲刺.md)。

## 十、平时成绩 50 分：高频完成 25 + 代表作品 25

### 1. 高频完成：25 分

- 每次冲刺暂计 1 分；每个模块六次中取最高五次，五个模块共 25 分。
- 当堂版本同时具备 `contract.yml`、可重跑 Core、客户来信响应、最终决定和边界，得 0.8 分；按时锁定知识自查 A 版得 0.1 分，完成概念学习和 B 版得 0.1 分。
- 下一次课开始前补交得 0.5 分；再晚仍可完善作品，但不再得当堂完成分。
- 此项主要由服务器时间、CI 和结构化文件判定。它证明按节奏交付，不证明个人理解。
- 知识自查正确率不直接计平时分，只进入个人掌握记录和教师误区统计，避免用准确率制造直接调用 AI 的动机。个人掌握仍由期末考试检验。

### 2. 代表作品质量：25 分

每个模块结束后，学生从该模块六个课堂冻结版本中选择一件代表作，每件 5 分；教师每名学生全学期只深评五件，而不是 30 件。

| 维度 | 分值 | 判断问题 |
|---|---:|---|
| 问题与目标量 | 1 | 总体、对象、利益相关者和行动是否明确？ |
| 方法与证据 | 1 | 数据和统计方法是否适合该问题？ |
| 不确定性与替代解释 | 1 | 是否处理不确定性、关键假设或合理替代路线？ |
| 更新与压力测试 | 1 | 客户来信后是否有证据地保留、修改或撤回决定？ |
| 负责发布与复现 | 1 | 主张可否追溯，边界、撤回条件和一键重跑是否清楚？ |

代表作必须来自当堂冻结版本，不能在模块结束后整件重做；允许附不计分的后续修订。CI 负责结构、运行和数值一致性，人工只看五个代表作的统计选择与发布质量。AI 可以先生成量表化评阅建议，教师按同一量表确认。

高级方法不单独加分；只有它与问题匹配，并实质改善证据、压力测试或决定，才提高代表作品质量。

## 十一、内容升级：相比传统入门统计增加什么

| 传统课程常见内容 | 项目中保留 | 新增内容 |
|---|---|---|
| 描述统计与图表 | 模块 1 | 脏数据、连接、缺失、断言、可复现数据管道、多变量聚合 |
| 概率与分布 | 模块 2–3 | Monte Carlo、模拟实验、用计算替代大量查表 |
| 抽样分布与区间 | 模块 2 | bootstrap、覆盖率、复杂抽样、权重、贝叶斯比较 |
| 假设检验、t/χ²/ANOVA | 模块 3 | 效应量、功效、随机化检验、多重比较、序贯决策 |
| 线性回归 | 模块 4 | logistic、交叉验证、正则化、校准、阈值、模型卡 |
| 相关不等于因果 | 模块 5 | DAG、倾向得分/IPW、DiD、安慰剂、时序与决策 |
| 软件操作 | 所有冲刺 | Git、Gitea、CI、自动测试、冻结 SHA、可复现发布 |
| 统计伦理 | 所有冲刺 | 数据适用性、隐私、子组表现、使用者责任和部署边界 |

需要减少的是手工算术、查表、公式目录和 Python 语法默写。需要增加的是数据工程、计算实验、现代建模、因果推断、可复现性以及对实际决策的连接。

## 十二、AI 在项目中的位置

AI 可以：

- 解释项目说明；
- 生成、重构和调试代码；
- 提议统计方法和可视化；
- 编写测试；
- 起草报告；
- 根据 CI 日志定位失败原因；
- 在学生授权的范围内操作本地仓库、创建 commit 和提交 tag。

本课程不设置“找出 AI 犯的错误”任务，也不把模型表现作为评分对象。如果最终分析不合格，归因顺序是：学生是否定义清楚任务、提供正确输入、设置必要约束、建立验收标准并采用了合适结果。

因此每次冲刺先在 `contract.yml` 中定义问题，最终在 `submission.yml` 中接受具体主张：

```text
委托方、使用者与待作决定：
研究对象、目标人群与目标量：
数据来源、快照哈希及限制：
主要主张及证据文件：
关键假设与压力测试：
适用范围与不能支持的主张：
什么新证据会使我撤回或修改结论：
若判断错误，主要代价是什么、由谁承担：
```

不要求提交完整 AI 对话，也不统计 prompt 数量、commit 数量或代码行数。只需保留足以重现成果并追溯采用决定的数据、代码、配置和说明。所谓“负责”，在本课程中是：提交者明确采用哪些主张、允许怎样使用、知道哪些边界，并接受这些选择的项目后果；它不是声称 AI 会犯本科统计错误。

## 十三、实现时最值得先做的五件事

1. 做好 `course-template`，让第 1 周所有人完成一次完整绿色提交。
2. 先准备五个可重复使用的数据世界，每个支撑六个委托；不要准备 30 套互不相干的数据。
3. 写一个 Gitea API 状态服务，记录服务器收到的事件前 SHA、最终 SHA、数据快照和 CI 状态；第一学期不必做复杂网站。
4. 为学生代码准备隔离的 Actions runner：不放 SSH 私钥或服务器管理凭证，不使用特权模式或危险主机挂载，限制时间和资源。具体运行位置由教师另行指定；不要直接让学生提交的任意代码在 Gitea/课程网站主机的高权限环境中执行。
5. 第一轮每次课只做一个全班统一的客户来信，并复用预算、缺失、漂移、成本、口径和子群等事件模板。只在新抽样、实验第二波和预测未来批次中保留真正后到的信息；不要加入学号随机题、秘密语法测试或复杂闯关。

## 十四、依据与实现参考

- ASA 本科统计课程指南强调真实复杂数据、计算、数据管理、多样化解释/预测模型、沟通和统计实践：[Curriculum Guidelines for Undergraduate Programs in Statistical Science](https://www.amstat.org/education/curriculum-guidelines-for-undergraduate-programs-in-statistical-science-)

- 项目式统计课程研究报告学生更能感受到统计与真实应用的联系；近年的课程案例也已把 ChatGPT 与数据清洗、软件输出解释和项目评价结合：[Project-Based Learning in Engineering Statistics](https://doi.org/10.1080/26939169.2022.2128119)、[PBL and the emergence of ChatGPT](https://doi.org/10.1111/test.12405)

- 新版本支持从中央源仓库向组织内仓库分发统一工作流；使用前需核对实际部署版本：[Scoped Workflows](https://docs.gitea.com/usage/actions/scoped-workflows)
- Gitea API 可以按时间查询 commits 并读取某个 SHA/tag 的综合状态，足以构建课堂交通灯面板：[List Commits](https://docs.gitea.com/api/operations/repo-get-all-commits/)、[Combined Commit Status](https://docs.gitea.com/api/operations/repo-get-combined-status-by-ref/)
