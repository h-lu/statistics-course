# Stat Check

小班统计学项目课使用的课末知识自查服务。它只完成一件事：在每节课最后 15 分钟运行“A 版基础题 → AI 学习 → B 版变式题 → 反馈”。

## 当前范围

- Gitea OAuth 登录；
- 32次课各保留一套当前题库，每课五组概念、十道A/B题；本仓库第5课为r4，第1—4、6—8课为r3，第9—32课为r1。目录另保留旧版，共87套；
- 首次提交锁定和信心记录；
- 教师选择课次并创建全新场次，旧场次与作答继续保留；
- 教师手动切换阶段，学生页面自动检测并跟随当前场次与阶段；
- 服务器按阶段截止时间拒绝过期作答；
- 完成人数、概念正确率和 CSV 导出；
- SQLite 单文件存储。

不包含题库编辑器、班级名单系统、AI 检测、自动监考、排行榜或复杂前端框架。

## 本地运行

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
uvicorn app.main:app --reload
```

应用固定使用 `/stat-check` 路径，健康检查为 `/stat-check/healthz`。

## 部署

1. 在 Gitea 创建 OAuth2 应用，回调地址填写 `https://hblu.top/stat-check/auth/callback`；
2. 从 `.env.example` 创建只存在于服务器的 `.env`；
3. 执行 `docker compose up -d --build`；
4. Nginx 将 `/stat-check/` 代理到 `127.0.0.1:8895`。

生产密钥、OAuth client secret 和 SQLite 数据库都不进入 Git。

已有服务升级时，不重新配置 OAuth、不重建数据库。先确认没有正在作答或学习的场次，使用 SQLite 在线备份接口备份数据库，再快进更新代码并重建容器。保留 `.env`、数据目录和已有用户。本仓库部署后，新建第5课场次使用 `v2-l05-r4`，第1—4、6—8课使用r3，第9—32课使用r1；线上实际版本取决于部署状态。新建场次下拉框按课次只列已安装的最高修订号（按数字比较，不按字符串排序）；旧场次仍按原lesson_id读取原题，不改写旧答案或得分。历史记录可通过教师 CSV 导出访问；学生页面只跟随当前场次，没有额外历史浏览界面。

验证命令：`python -m pytest -q`。测试覆盖题库结构、历史题目字节一致性、旧数据库记录保留，以及登录、阶段、过期提交与新场次隔离。

两处题库副本应逐字节一致；现行版本和历史保护规则见[题库约定](../instructor-guide/knowledge-check/question-bank/SCHEMA.md)。代码合并不等于已完成线上部署；不要在正在作答的场次中换题。

## 课堂操作

1. 学生可提前登录并留在等待页；
2. 教师在控制页选择当节课，点击“新建本课自查（暂不开放）”；
3. 教师依次开放 A 版、AI 学习、B 版和反馈；
4. 学生页每 3 秒查询一次状态，场次、阶段或截止时间改变后自动刷新；答题倒计时归零也会刷新到超时提示；
5. 教师页每 5 秒自动更新完成人数，表单获得焦点时暂停刷新。

倒计时结束不会替教师切换教学阶段；教师仍保留切换时机，但服务器会拒绝过期作答或学习提交。
