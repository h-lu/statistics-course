# 第8课 · 多表数据整合与统计指标核查

本课使用**教学合成数据**，编号和机构均为虚构。可全程使用AI，计算与文字之外，需要说明分析对象、规则选择、证据和发布范围。

先读本页了解任务，再按 [SUPPORT.md](SUPPORT.md) 获得第一份可核对的结果；遇到概念读 [LEARN.md](LEARN.md)，最后回本页完成标准任务。[练习与挑战](EXERCISES.md) 给出独立问题，[提示](HINTS.md) 可按需查看。

## 问题与先修

管理者需要合并两期运营报告，分别了解工单结果、接触工作量和计划工时，并决定哪些结果可发布。直接把表展开连接，可能重复计算工单；只留下匹配行，可能让尚待核实的记录消失。

复习第3课的缺失编码、数值型修订号与单位换算，第4–6课的指标用途与比较范围，第7课的调查邀请和无回答。无需重做旧作业；本课提供独立的可运行工具。

## 七张表

详见 [数据说明](../data/service/README.md)。第一期3600行工单，第二期1265行导出、1200个工单编号；调查4800行、接触8921行、窗口6行、业务2行、排班240行。行数、不同工单数和某指标的有效分母分别回答不同问题。

| 表 | 记录单位与键 | 本课判断 |
|---|---|---|
| tickets / tickets_raw | 工单；整理后ticket_id唯一 | 两期先统一口径再按行追加，不能按ID内连接两期 |
| satisfaction | 调查登记；ticket_id | 缺登记、未知邀请、未受邀、受邀无回答、有效评分分开 |
| visits | 接触；contact_id | 同工单多次接触，先按工单汇总再接入工单指标 |
| windows / business_types | 窗口/业务类别；对应编号 | 检查字典键唯一，未知归属保留原因 |
| staffing | 窗口日；date+window_id | 排班累计一次，保留无业务日及有业务无排班日 |

## 基础练习（可信起点）

为七表写出记录单位和候选主键。先预计两张工单等待2与10分钟、接触次数3与1时，展开后的均值会怎样变；再按SUPPORT手算并运行微例。获得七表清单和一项能复算的检查。这是起点，尚未完成本课。

## 标准任务（本课应完成）

1. **说明用途与整合规则。** 选容量安排、流程改善或体验报告作为主用途。写清输入和输出单位/键、数值修订顺序、冲突规则、单位换算及两期ID核对；整合完整两期，保留4800个工单的存在事实。
2. **分别完成三层分析。** 在工单层报告有效已服务等待、办结比例、已有回答的满意比例；在接触层报告次数与工作人员分钟；在窗口日层报告计划有效人时及接触工作量。每个结果写明时期、分子、分母和单位。指标可各有有效集合。
3. **实际执行核对。** 证明接触先汇总再连接，核对工单数、接触数、分钟总量和唯一排班日；报告差额与去向。至少一项检查有输入、输出和实际结果，不能只写“运行成功”。
4. **比较一个合理替代方案。** 先预计替代方案影响哪项分母或覆盖，再用同一数据比较左/内连接，或逐指标有效集合/共同完整集合。只改变一个规则，保存两份输出；解释为什么采用原方案或改用替代方案。
5. **作发布判断。** 区分未知窗口、缺排班、缺调查登记和无回答；说明可发布、需附条件或暂缓的结果。调查缺失与未知值不统一删除或填0。为下一期写一项会停止相关指标发布的条件。

工单登记量按date，接触工作量按contact_date。接触表缺实际办理窗口，用工单窗口归属工作量是一项需声明的替代假设。工作人员分钟/60才与计划人时同单位；计划人时不等于实际劳动时间，不能称为测得的个人生产率。

## 提高与拓展（提前完成后）

从 [EXERCISES.md](EXERCISES.md) 选一项：修订9/10与最新版本冲突；同工单多次接触的权重解释；无业务排班日/有业务无排班日；从异常发布数字反向追到原记录。先写预计，再运行教学反例，最后说明反例如何改变正式报告的核对或使用条件。反例与正式数据均明确标注，不用反例结果冒充正式机构事实。

## 程序与选择

从学生仓库根目录运行，那里应有scripts与data；完整资料库先进入student-template。仅需Python3标准库，不安装软件。

```bash
python3 scripts/course.py start 08
python3 lesson-08/analysis.py --stage inventory
python3 lesson-08/analysis.py --stage clean
python3 lesson-08/analysis.py --stage join
python3 lesson-08/analysis.py --stage indicators
```

每个阶段从原数据重算所需前阶段，不依赖旧输出。结果在lesson-08/artifacts/main。config-alternative.json提供inner候选方案，你可以改选另一个有依据的规则；原始数据不修改。默认run仅生成概览；报告前须运行indicators。config.json记录可改变的规则：

| 设置 | 选项和含义 |
|---|---|
| revision_conflict | stop遇最新冲突停止；quarantine只保留一致字段、冲突字段未知并列标记 |
| window_join | left保留全部工单；inner仅保留已匹配窗口工单，差额仍在审计中 |
| metric_scope | per_metric逐指标有效；common_complete要求等待/单位、放弃、办结、窗口、业务、登记日期及修订一致共同有效，调查回答另行判断 |
| staffing_coverage | union保留计划与活动日期并集；activity_only只保留已知窗口活动日期，用于检查范围变化 |

配置初值是一条可探索路线；请依据用途选择并写理由。全部计算完成也不能替你解释比较、未匹配影响与发布决定。

## 提交与自查

提交report.md、配置、程序、三层结果、连接关系、核对及替代方案证据。报告末从第3–8课选一件模块一代表作并说明理由；需修订时写统计问题与依据，截止下一次课前，保留原final，用v2-lNN-revision-1；评分沿用 [成果与评分](../docs/ASSESSMENT.md)。不要求当天重做六课。

submission.json中的report保持 `lesson-08/report.md`，run设为 `["python3", "lesson-08/reproduce.py"]`，artifacts只列实际使用的结果文件路径（不把report重复列入）。reproduce从两配置重算main与alternative；如提高成果需列入提交，run增加 `--experiment` 和所选案例名。完成标准任务后status改complete。

```bash
python3 scripts/course.py run 08
python3 scripts/course.py check 08
```

run执行所声明程序，check只检查完成状态/路径/文件，不判断统计结论。提交按 [工作流](../docs/WORKFLOW.md) 进行，不覆盖已有final。完成后进入 [知识自查](https://hblu.top/stat-check/)，确认第8课和教师开放的场次，完成A、概念学习、B与反馈；AI可用，正确率用于反馈。
